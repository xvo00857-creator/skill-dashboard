## 二、最小改动方案

### 2.1 改动原则

遵循"兼容既有接口和目录结构、不升级主版本、不引入新依赖"的约束：

1. **不修改 CLI 接口**：`template_scaffolder.py` 的命令行参数、输出格式、函数签名均保持不变。
2. **不新增第三方依赖**：仅使用 Python 标准库 `xml.sax.saxutils.escape`（标准库，非新依赖）。
3. **不改变目录结构**：在既有 `scripts/`、`references/` 之外新增 `generated/`（产物目录）和 `docs/`（文档目录），不移动或重命名既有文件。
4. **补丁级版本**：修复属于 patch 级别（1.0.1 性质：格式修正），不涉及结构变更或新增/删除章节。

### 2.2 具体改动

**脚手架补丁（`scripts/template_scaffolder.py`，3 处）**：

- 新增导入：`from xml.sax.saxutils import escape as _xml_escape`
- `_section()` 函数：对 `title` 参数做 XML 转义（`content` 参数包含 XHTML 宏标记，不转义）
- `_table()` 函数：对表头 `headers` 做 XML 转义（单元格可能包含宏输出，不转义）

**新增文件（不影响既有接口）**：

- `generated/` 目录：存放脚手架输出的模板文件
- `scripts/regenerate.sh`：批量重新生成脚本
- `docs/部署与维护指南.md`：本文档

### 2.3 部署步骤（需在有 MCP 连接的环境执行）

以下步骤来自 SKILL.md 的 MCP Operations 章节，本次环境无 Atlassian MCP 连接，**尚未执行**：

1. 通过 `mcp__atlassian__getAccessibleAtlassianResources` 获取 `cloudId`。
2. 对每个模板，读取 `generated/<name>.json` 中的 `body` 字段，调用：
   ```
   mcp__atlassian__createConfluencePage(cloudId, space=<目标空间>,
     title="Template: <模板名>", body=<body>)
   ```
3. 部署后立即调用 `mcp__atlassian__getConfluencePage(cloudId, pageId=<返回ID>)` 验证。
4. 在 Confluence UI 中为每页添加标签（MCP 无标签工具）：`template` + 模板专属标签。
5. 部署 `template-index.json` 作为模板索引页。
6. 若需注册为空间级正式模板（而非"复制自"页面），需在 Space settings > Templates 中手动操作——MCP 不支持创建一等模板/蓝图。

## 三、回滚办法

### 3.1 脚手架代码回滚

补丁仅改动 3 行，回滚方式：

```bash
# 方式一：Git 回滚（若在版本控制中）
git checkout -- scripts/template_scaffolder.py

# 方式二：手动还原
# 删除第 20 行的 from xml.sax.saxutils import ...
# 将 _section 中 _xml_escape(title) 改回 title
# 将 _table 中 _xml_escape(h) 改回 h
```

### 3.2 已部署页面回滚

若部署后发现宏渲染错误，按 SKILL.md 的验证检查点回滚：

1. 调用 `mcp__atlassian__getConfluencePage(cloudId, pageId=<id>)` 获取当前版本号 `version`。
2. 准备上一版本的 body（部署前应备份原始 body）。
3. 调用 `mcp__atlassian__updateConfluencePage(cloudId, pageId=<id>, version=<当前版本+1>, body=<上一版本body>)`。
4. 再次 get 验证回滚成功。

### 3.3 生成产物回滚

`generated/` 目录为重新生成的产物，删除后运行 `bash scripts/regenerate.sh` 即可重建。若需回滚到补丁前的产物，需在补丁应用前备份（补丁前的 project-kickoff 产物含未转义 `&`，不建议回滚）。

## 七、维护流程（摘要）

依据 `references/governance-framework.md`：

- **版本号规则**：主版本号.次版本号.补丁号（结构变更升主版本，内容更新升次版本，错字/格式升补丁）。
- **更新模板**：修改脚手架中对应函数 → 运行 `bash scripts/regenerate.sh` → 本地 XML 校验 → 通过 MCP `updateConfluencePage` 部署（version+1）→ 验证。
- **废弃模板**：加 `{warning}` 废弃横幅 → 30 天过渡期 → 归档（不删除）→ 90 天后确认无使用。
- **使用量追踪**：通过 CQL `type = page AND label = "template-<name>" AND created >= "now-30d"` 按月统计。
- **审查周期**：模板负责人每季度审查；委员会每半年审查全量目录。
