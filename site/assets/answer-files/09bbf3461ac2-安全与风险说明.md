# 安全与风险说明（bar-chart-visualization 评测）

## 一、事实 / 推断 / 待确认项

### 事实（已核实）
1. 用户上传的附件 `bar-chart-visualization.zip` 内仅含 1 个文件：
   `bar-chart-visualization/SKILL.md`（4668 字节）。**未包含任何业务数据文件**。
2. SKILL.md 声明的 name 为 `excel-bar-chart-visualization`，是一个四步代码骨架：
   合并清洗 → 交叉分析 → 结果输出 → 柱状图绘制。
3. SKILL.md 的示例列名（题型、流程描述、项目阶段、控制要点、题目分类）面向
   "审计/检查清单"领域，与用户描述的销售字段（日期、地区、品类、订单量、销售额）不匹配。
4. SKILL.md Step3 调用了 `invoke_skill("file_service.get_download_url", ...)`，
   该函数是 Skill 运行时内部函数，在当前 MainAgent 工具集中**不存在**，无法调用。
5. SKILL.md Step4 配置字体 `SimHei`，在当前 macOS 系统上**不存在**；
   实测可用中文字体为 Hiragino Sans GB、Arial Unicode MS、Songti SC、Heiti TC。
6. SKILL.md Step1 使用 `fillna(method='ffill')`，在 pandas 2.3.3 中
   已弃用 `method` 参数（产生 FutureWarning），应改用 `.ffill()`。
7. 当前环境已安装 Python 3.9.6、pandas 2.3.3、matplotlib 3.9.4、openpyxl 3.1.5。
8. SKILL.md 提到"see the parent workflow SKILL.md"，但该父文件**不在 ZIP 中**，无法读取。

### 推断（基于事实的合理判断，需用户确认）
1. 用户描述的"一份包含日期、地区、品类、订单量和销售额的多工作表数据"**尚未提供**，
   可能是遗漏上传，也可能是期望我用示例数据演示流程。
2. SKILL.md 中的分类映射字典（`'碎片值1'→'标准分类A'`）是模板占位符，
   不可直接用于任何真实数据，必须替换为业务方确认的映射表。
3. `invoke_skill("file_service.get_download_url")` 若在真实运行时中可用，
   会将结果文件上传至文件服务并生成可访问 URL，存在数据外泄风险。

## 三、停止条件（遇到以下任一情况立即停止，不继续执行）
1. 用户未明确授权前，不处理任何含真实个人信息或商业机密的数据文件。

   立即停止并提示用户，不将其写入任何输出。

## 五、回滚方案
1. 本演示所有文件均为**新建文件**，未修改或删除任何已有文件，无需回滚。
2. 处理真实数据时：
   - 原始文件设为只读（`chmod 444` 或复制副本后操作副本）；
   - 所有输出写入独立子目录（如 `./output_时间戳/`），不与原文件混放；
   - 若结果有误，直接删除输出目录即可，原始数据不受影响；
   - 不使用 `invoke_skill` 外发，因此不存在"已上传到外部服务需撤回"的问题。
3. 每一步清洗操作均记录在 `计算口径说明.md` 中，可逐条追溯、逐条撤销。

## 六、人工复核点
1. **数据读取后**：核对工作表数量、行列数、字段名是否与预期一致。
2. **合并单元格填充后**：抽查前向填充是否正确（特别是跨地区/跨日期边界处）。
3. **品类归并后**：检查归并映射是否覆盖所有原始值，"其他/未知"类别占比是否异常。
4. **缺失值处理后**：确认被剔除的记录数是否在可接受范围内。
5. **汇总表生成后**：核对小计、总计是否与明细求和一致（可交叉验证）。
6. **图表生成后**：确认中文显示正常、数值标签与表格一致、颜色/图例可读。
7. **交付前**：确认输出文件中不含未脱敏的敏感信息。
