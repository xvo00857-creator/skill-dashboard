# 实施计划：受限预算与窗口下的迁移决策与执行

## 概述

在年度预算上限 12 万元、迁移窗口仅 6 周、且当前缺少准确使用量数据的约束下，对迁移方案做约束下的选项比较，建立"先验证、后承诺"的分阶段决策机制，并把通过决策门槛后的迁移工作拆成可独立验证、可独立回退的垂直切片。本计划只覆盖规划与验证阶段的任务拆解；在使用量数据和试点结果补齐前，不批准全量迁移。

> Skill 边界说明：本计划按 `planning-and-task-breakdown` 的要求产出，只做任务拆解与检查点安排，不包含实际迁移实施、不做财务建模、不替业务拍板。文中所有成本/工期数字在 Phase 0 数据补齐前一律标注"待实测/待确认"，不作为承诺。

## 关键约束与已知未知

### 硬约束
- 年度总预算上限：12 万元（是否含一次性迁移成本、人力、数据出口费，口径待确认）
- 迁移窗口：6 周（自启动日起算）
- 决策机制：每阶段设 Go/No-Go 门槛，未达标即回退或缩小范围

### 关键未知（不得编造，须在 Phase 0 补齐）
- 现有系统实际使用量：均值/峰值计算、存储量、出口流量、请求量
- 现有年度支出基线（含隐性成本：人力、运维、停机损失）
- 目标方案正式报价（须书面，口头报价不进入门槛判断）
- 业务可接受的中断窗口与性能退化阈值
- 合规与数据驻留要求
- 决策人及回退决策人（待指定）

## 架构/方案决策记录

### ADR-1：采用"先验证后承诺"的分阶段策略，而非直接全量迁移
- 背景：使用量数据缺失，全量迁移的成本与工期无法可靠估计；6 周窗口与 12 万预算均无缓冲。
- 决策：前 2 周用于数据采集与最小验证试点，第 3 周末设 Go/No-Go 门槛；通过后才按垂直切片迁移。
- 理由：缺失数据下的全量承诺是不可逆高风险；试点以最小成本获得真实数据，符合"高风险任务前置、快速失败"。
- 后果：若试点未达门槛，6 周内不强行迁移，保留现状并进入回退/延期方案（O3）。

### ADR-2：按垂直切片迁移，而非按水平层（先全部数据、再全部服务、再全部切换）
- 决策：以"一个可独立切流、可独立回退的业务工作负载"为一个切片，端到端完成。
- 理由：每个切片交付可验证、可回退的功能；水平切片会把风险堆积到最后联调。
- 后果：须先定义切片边界与依赖；共享契约（接口、数据格式）先行约定。

### ADR-3：全程保留回退路径，切流采用可快速回切的灰度方式
- 决策：迁移期间原系统保持运行；采用双写/双跑 + 灰度切流；设定明确回退触发条件。
- 理由：6 周窗口内没有足够时间做"破釜沉舟"式切换；回退能力本身是 Go/No-Go 门槛的一部分。

## 选项比较（约束下，数据待补齐）

> 说明：以下为方案原型比较，不含任何虚构价格、用量或厂商信息。所有"成本/工期"在 Phase 0 数据补齐前只能标"待实测"，不得作为承诺。

| 维度 | O0 维持现状+优化 | O1 部分迁移（非核心切片） | O2 全量迁移 | O3 延期（窗口内只验证） |
|---|---|---|---|---|
| 年度成本是否可能 ≤12 万 | 取决于现状基线，待核实 | 待试点外推 | 待试点外推，超支风险最高 | 本年度不产生新运行成本 |
| 6 周内可交付性 | 高（无迁移） | 中高（切片数可控） | 低/不确定（依赖用量与复杂度） | 高（只做验证） |
| 业务中断风险 | 低 | 低（逐切片切流/回退） | 高 | 无 |
| 可逆性 | 不适用 | 高（逐切片回退） | 低（全量回退代价大） | 完全可逆 |
| 对缺失用量数据的敏感度 | 低 | 中（试点可校准） | 高（全量承诺） | 低 |
| 适用前提 | 现状成本已在预算内且无强制迁移动因 | 试点外推成本 ≤ 预算门槛且切片可在剩余窗口完成 | 试点证明成本与工期均有充足缓冲 | 试点未达门槛或发现重大未知 |

### 比较结论（条件性）
- 在用量数据补齐前，**O1（部分迁移）为默认推荐路径**，因为它把不可逆承诺推迟到真实数据之后。
- O2 仅在试点外推年度成本 ≤ 预算门槛且剩余窗口充足时才进入候选。
- O0 与 O3 是合法的回退/延期选项，不是失败。

## 敏感因素

| 因素 | 为何敏感 | 对决策的影响 |
|---|---|---|
| 实际使用量（峰值/均值/存储/出口流量） | 直接线性决定目标方案年度费用 | 用量超某阈值则 O1/O2 均可能破 12 万，须回 O0/O3 |
| 迁移人力成本（内部投入或外包） | 占用 12 万中的一次性部分 | 人力估算过高将压缩运行成本空间 |
| 目标方案正式报价与折扣 | 报价未锁定前外推均为区间 | 须以书面报价为准，口头报价不得进入门槛判断 |
| 业务可接受中断窗口 | 决定能否灰度切流及是否需双跑 | 中断窗口过短会增加双跑成本与复杂度 |
| 性能退化幅度（P95 延迟/错误率） | 影响业务体验与是否需扩容 | 退化超阈值即触发回退或扩容（增成本） |
| 数据出口/迁移传输费 | 常被遗漏的一次性成本 | 可能吃掉预算缓冲 |
| 合规/数据驻留要求 | 可能直接排除某些方案 | 具有一票否决性 |

## 最小验证（前 2 周）

目标：用最小代价获得真实数据，把"待实测"变成决策依据。

1. **基线采集**：从现有系统导出最近一个完整账单周期的用量与费用（计算、存储、流量、请求量、人力运维投入）。
2. **试点选择**：选 1 个非核心、低流量、边界清晰的工作负载。
3. **试点迁移**：在目标环境完成该切片的端到端迁移与切流。
4. **测量**：记录试点实际迁移工时、切流后性能（P95/错误率）、目标侧单位用量费用、回退耗时。
5. **外推**：以试点数据按用量占比外推全量/部分迁移的成本与工期，给出区间（非点估计），并写明外推假设。

## 决策门槛（Go/No-Go，第 3 周末）

以下条件须**全部**满足才进入 Phase 3；任一不满足则回退或转 O3。阈值中带"建议"字样的为待业务确认值：

- [ ] 试点外推年度总成本 ≤ 12 万 × 0.85（建议预留约 15% 缓冲，系数待业务确认）
- [ ] 试点外推迁移工期 ≤ 剩余窗口（约 3 周）× 0.8，且关键路径已识别
- [ ] 试点切流后 P95 延迟退化 ≤ 20%（建议值）、错误率无显著上升（阈值待业务确认）
- [ ] 回退演练成功：可在约定时间内回切原系统且数据一致
- [ ] 已取得目标方案书面报价，报价口径覆盖试点实测到的全部费用项
- [ ] 合规/数据驻留要求已核实并满足
- [ ] 业务方书面确认可接受中断窗口与灰度方案

门槛判断须由决策人（待指定）书面记录，不得口头放行。

## 回退方案

- **切片级回退**：每个切片切流后设观察期（建议 ≥3 天，待确认），期间原系统保持热备；触发条件包括错误率/延迟超阈值、成本异常、业务投诉。
- **流量回切**：通过灰度开关（DNS/负载均衡/特性开关）在秒级~分钟级把流量切回原系统。
- **数据一致性**：双写期间维护反向同步或重放机制；回退后以原系统为准，目标侧数据按保留期留存以便复盘。
- **全量回退**：若多个切片连续触发回退或发现系统性问题，停止后续迁移，已迁移切片全部回切，进入 O3 延期方案。
- **回退决策人与时序**：明确谁有权宣布回退、回退操作顺序、通知对象（待指定，不得空缺）。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 使用量数据拿不到或不可信 | 高 | Phase 0 不完成则不进入试点；以账单+监控双源核对 |
| 试点外推超预算 | 高 | Go/No-Go 门槛拦截，转 O1 缩小范围或 O3 延期 |
| 6 周窗口不够 | 高 | 切片化交付，未完成切片保留在原系统，下窗口继续 |
| 切流后性能退化 | 中 | 灰度+观察期+自动回切阈值 |
| 数据不一致 | 高 | 双写/反向同步，回退后以原系统为准 |
| 报价口径与实际不符 | 中 | 书面报价须覆盖试点实测全部费用项 |
| 关键人力不可用 | 中 | 试点前确认人力投入；回退操作手册不依赖单人 |

## 待确认问题
- 12 万预算是否含一次性迁移成本、人力、数据出口费？
- 业务可接受的单次中断窗口、累计中断窗口是多少？
- P95 延迟、错误率的可接受退化阈值？
- 谁是 Go/No-Go 决策人、谁是回退决策人？
- 是否存在强制迁移的外部动因（合规、合同到期、硬件退役）？这会改变 O0/O3 的可行性。
- 目标方案是否已有候选？若有，需提供书面报价与合规材料。
- 现有系统是否可导出完整账单周期数据？若不能，最小可用替代数据源是什么？
