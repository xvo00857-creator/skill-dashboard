# 智能随行杯新品——两周功能需求分析与优先级方案

> 本文档基于 `analyze-feature-requests` Skill 框架与 `product_brief.md` 编制。
> 所有结论与假设严格分开；附件未提供的信息均标注为【假设】或【待补】。

## 一、目标澄清

### 1.1 产品目标（来自简报，已确认）

| 维度 | 内容 |
|------|------|
| 产品 | 智能随行杯新品 |
| 目标用户 | 一二线城市通勤人群 |
| 核心卖点 | 12 小时保温、重量 280g、可拆洗杯盖 |
| 建议零售价 | 199 元 |
| 已确认素材 | 产品白底图、基础规格、品牌主色 #176B87 |

### 1.2 两周工作目标（本方案目标）

按 Skill 要求，完成"客户功能需求 → 主题归类 → 战略一致性评估 → Top 3 机会优先级排序 → 最小验证方案"的全流程，输出一份数据可追溯的优先级决策文档，供产品团队进入设计/开发排期。

### 1.3 Skill 执行前提与当前输入缺口（关键）

Skill 的核心输入是**客户功能需求列表**（spreadsheets / CSVs / documents with feature requests），并要求用 **Opportunity Score = Importance × (1 − Satisfaction)**（归一化 0–1）评估机会。

经核查，`product_brief.md` **不包含任何客户功能需求数据**，也没有 Importance / Satisfaction 评分。因此：

- Skill 步骤 2–4（归类、评估、排序）**当前无法基于真实数据执行**；
- 本方案将两周第 1 周设计为"需求收集"，先补齐该输入，第 2 周再执行 Skill 分析；
- 下文第四节出现的主题与优先级均为**基于简报推导的假设性框架**，用于指导收集方向，**不是已完成的分析结论**。

## 四、两周可执行方案

### 4.1 范围

**在范围内：**
- 收集并整理通勤人群对随行杯的真实需求/痛点
- 按主题归类，评估战略一致性
- 用 Opportunity Score + Impact/Effort/Risk 框架排序，产出 Top 3 机会
- 为 Top 3 机会设计最小努力验证方案
- 输出优先级决策文档（Markdown）

**不在范围内：**
- 工业设计与结构设计定稿
- 硬件开发与固件开发
- 第三方检测送检（仅提出需求，不执行）
- 营销物料制作
- 编造任何被禁止的数据（C1）

### 4.2 假设性主题框架（指导第 1 周收集方向，非结论）

以下主题基于简报中"通勤人群 + 12h 保温 / 280g / 可拆洗杯盖 + 199 元 + 智能"推导，**用于指导需求收集的覆盖面**，不代表已从客户数据中验证：

| 主题 | 与简报卖点的关联 | 收集重点 |
|------|-----------------|----------|
| T1 温度体验 | 12h 保温 | 通勤途中温度期望、烫嘴/变凉场景、是否需要温度可视 |
| T2 便携与适配 | 280g 轻量 | 包内放置、车载杯架适配、通勤握持、防漏 |
| T3 清洁维护 | 可拆洗杯盖 | 清洗频率、死角、异味、洗碗机兼容、拆装便捷性 |
| T4 智能功能价值 | 标题"智能"但未定义（U5） | 用户是否需要水温提醒/饮水记录/App 联动；付费意愿 |
| T5 安全与耐用 | 防水等级（U3）、材质报告（U4） | 材质信任、防摔、漏水担忧、食品接触安全 |
| T6 外观与认同 | 品牌主色 #176B87、199 元价位 | 颜色偏好、办公场景审美、个性化需求 |

### 4.5 验收标准

1. **输入完整性**：需求清单中每条机会均标注来源（客服/访谈/评论/其他），可追溯；无来源的条目标记为【假设】并排除出排序。
2. **Opportunity Score 可复现**：每条机会有 Importance 与 Satisfaction 原始评分，Score 计算过程可复核。
3. **Top 3 合规**：每个 Top 机会包含理由、替代方案、高风险假设、最小努力验证方法四要素（C6）。
4. **禁止编造核查**：文档中不出现无来源的第三方检测结论、销量、用户评价、竞品价格（C1）；所有外部数据附真实来源链接或标注【待补】。
5. **结论与假设分离**：文档明确区分"已验证结论"与"假设/待补项"（C2）。
6. **战略对齐可解释**：每个主题的战略一致性评分有书面理由，非主观打分。
7. **交付物**：终版 Markdown 决策文档，含需求清单、评分表、Top 3 卡片、验证计划。

## 五、Top 3 机会假设性框架（待真实数据验证）

> **以下内容严格为假设性框架**，基于简报推导，用于 D8 真实排序时的对照参考。
> 真实 Top 3 须以 D5–D7 的 Opportunity Score 与四维评分为准，不得直接采用本节内容作为结论。

### 机会 A：通勤途中的温度预期管理（关联 T1）

- **假设理由**：12h 保温是核心卖点，但通勤场景中"保温"与"入口可饮用温度"可能存在矛盾（水太烫无法立即喝）；这是与核心卖点强相关的高频问题。
- **替代方案**：杯口降温结构 / 温度指示盖 / 分区控温 / 仅靠材质保温不附加功能。
- **高风险假设**：用户愿意为温度管理功能接受 199 元价位下的额外复杂度或重量。
- **最小验证**：5 名通勤用户情境访谈 + 杯盖温度指示概念草图反馈，1 天内完成。

### 机会 B：杯盖拆洗的实际清洁体验（关联 T3）

- **假设理由**：可拆洗杯盖是已确认卖点，但"可拆"不等于"好洗"；密封圈、缝隙是保温杯常见差评点，直接影响口碑与复购。
- **替代方案**：更少零件的翻盖结构 / 全开盖设计 / 附赠清洁刷 / 材质抗污涂层。
- **高风险假设**：现有可拆洗结构在真实使用中不存在清洁死角；用户不会因零件多而丢失。
- **最小验证**：让 5 名用户连续使用样杯 3 天（如有样杯）或做拆装可用性测试，观察清洗行为。

### 机会 C："智能"功能的用户付费意愿验证（关联 T4）

- **假设理由**：产品名含"智能"但简报未定义任何智能功能（U5）；若加入电子部件将影响重量（280g）、防水（U3）、成本（199 元）和续航，是最大的范围不确定性。
- **替代方案**：无电子件的纯机械杯 / 仅温度显示（无连接）/ 全功能 App 联动 / 智能杯盖配件。
- **高风险假设**：通勤用户愿意为智能功能付费且接受充电/配对维护；智能功能不牺牲 280g 轻量卖点。
- **最小验证**：8 人概念测试——展示 3 种智能程度不同的方案与对应价格区间，测量购买意愿与功能取舍；2 天内完成。
