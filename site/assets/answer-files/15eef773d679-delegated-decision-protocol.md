# 负责人失联期间代理决策机制

**生效日期：** 2026-08-10
**适用场景：** 负责人（CEO/创始人）暂时失联，两项高风险决策待决，团队需在不越权前提下维持运营
**机制性质：** 临时治理协议，负责人恢复后自动失效，所有代理决策须事后追认或推翻
**制定依据：** Chief of Staff 编排框架（决策复杂度评分、路由矩阵、综合框架、决策日志规范）

---

## 一、核心原则：不越权的四条红线

代理决策的本质是**托管**，不是**授权接管**。以下四条红线不可逾越：

1. **不可逆事项不擅自决定。** 任何一旦执行难以撤回、撤回成本显著高于等待成本的决策，一律暂停或升级。
2. **不改变战略方向。** 代理期间只做"维持列车运行"的决策，不做"变轨"决策。产品方向、融资策略、组织架构等战略级议题冻结。
3. **不突破已授权边界。** 代理权限以负责人事前书面授权、公司治理文件（章程/董事会决议/授权矩阵）明确授予的范围为上限。无明确授权 = 无权限。
4. **全程留痕、可追溯、可推翻。** 每一项代理决策必须记录决策依据、可选方案、选择理由、潜在风险，供负责人回来后逐条审查。

> **底层逻辑：** 代理期间犯错的代价远大于延迟决策的代价。宁可暂停被批评"不够果断"，不可越权造成不可逆损失。

## 二、事项三色分类与处理流程

### 2.1 分类判定标准

| 类别 | 信号特征 | 典型事项 | 处理权限 | 时限要求 |
|------|----------|----------|----------|----------|
| **🟢 可继续（Green）** | 日常运营、已授权范围内、可逆、不改变资源分配、不产生新承诺 | 已排期的常规发布、例行审批（报销/请假）、已签合同的执行、客户常规支持、按既定OKR推进的工作 | 值班负责人/各职能负责人按既有流程自行处理 | 按正常节奏 |
| **🟡 需暂停（Yellow）** | 有决策窗口但非小时级紧急、需要负责人判断或更多信息、可逆但有中等成本、跨职能协调 | 新供应商签约（非紧急）、非关键岗位offer发放、中等金额支出、产品功能优先级微调、营销活动排期调整 | 值班负责人可做"维持现状"决定，不做新承诺；记录后等负责人回来或升级 | 设定检查点（每24-48h复核） |
| **🔴 必须升级（Red）** | 不可逆、战略级、法律/合规/财务重大、超出授权边界、影响2+部门资源、有外部法律约束时效 | 融资/term sheet签署、裁员/高管任免、重大合同（金额超授权阈值）、并购/ pivot、安全事故响应、监管回应、股权变更 | 任何人不得擅自决定；立即启动升级路径 | 立即，不超过4小时 |

### 2.2 判定流程（每个待决事项走一遍）

```
事项进入
  │
  ├─ Q1: 是否在负责人事前书面授权范围内？
  │     └─ 否 → 🔴 升级
  │
  ├─ Q2: 是否可逆？（撤回成本 < 等待成本？）
  │     └─ 不可逆/撤回成本极高 → 🔴 升级
  │
  ├─ Q3: 是否改变战略方向或重大资源分配？
  │     └─ 是 → 🔴 升级
  │
  ├─ Q4: 是否有外部硬性时效（法律/合同/监管）？
  │     ├─ 有且在24h内 → 评估是否🟡维持现状/🔴升级
  │     └─ 无 → 继续判断
  │
  ├─ Q5: 是否为日常运营且有既定流程？
  │     └─ 是 → 🟢 继续
  │
  └─ 其余 → 🟡 暂停，设定复核点
```

### 2.3 紧急例外：当 Red 事项无法等到负责人恢复

若某 Red 事项存在**外部硬性时效**（如监管答复期限、合同违约窗口、安全事故处置黄金时间），且确实无法联系到负责人：

1. **立即启动升级路径**（见第四节），联系董事会指定联系人/投资人/法律顾问。
2. 由**至少两人联名**（建议：COO + CFO 或 GC + 一位董事）做出"最小必要行动"决定——只做防止损失扩大的动作，不做趁机关联决策。
3. 全程记录：时间线、参与人、可选方案、选择理由、已知风险、为何不能等。
4. 负责人恢复后**第一时间**专项汇报，该决策自动进入追认/推翻审查。

### 两项决策的综合判断

按 Chief of Staff 综合框架：

**共识主题（代理团队可独立推进的）：**
1. 两项决策均属高复杂度（4-5分），涉及多职能、不可逆或有重大资源影响——这不是代理层能决定的。
2. 代理期间的正确动作是**准备而非决策**：把信息、方案、风险分析做到位，让负责人（或升级决策人）回来后能在最短时间内做出判断。
3. 任何"趁负责人不在把生米煮成熟饭"的倾向都必须抵制——这是越权，不是担当。

**潜在冲突（需负责人或升级层裁决的）：**
- 若两项决策之间存在资源竞争或方向矛盾（如决策A要求扩张、决策B要求收缩），这本身就是需要负责人判断的战略取舍，代理层不应自行调和。

**代理期间行动项：**
1. **为决策A准备完整决策包**（方案对比、风险清单、财务/法律影响）—— 对应职能负责人 —— 负责人恢复前完成
2. **为决策B准备完整决策包** —— 对应职能负责人 —— 负责人恢复前完成
3. **确认升级路径联系人可达**（董事会/投资人/法律顾问）—— 值班负责人 —— 今日内
4. **设定每12小时状态检查点**，确认负责人是否恢复、是否有新时效压力 —— 值班负责人 —— 持续
5. **向团队传达"维持现状、不做新承诺"原则**，避免下属在压力下自行越权 —— 值班负责人/CHRO —— 今日内

**负责人决策点（恢复后）：**
> 两项高风险决策的最终判断权归属负责人。代理团队已完成材料准备，不做倾向性建议——因为这两项决策的本质是战略取舍，只有负责人掌握完整上下文和公司方向判断。

## 四、升级路径

当出现 🔴 Red 事项且负责人无法联系时，按以下顺序升级：

| 优先级 | 升级对象 | 触发条件 | 联系方式 |
|--------|----------|----------|----------|
| 1 | 董事会指定联系人/董事长 | 战略级、融资级、治理级事项 | [待填写：姓名/电话/邮箱] |
| 2 |  lead investor / 投资人董事 | 融资、现金流、重大资本决策 | [待填写] |
| 3 | 常年法律顾问 / GC | 法律、合同、合规、监管事项 | [待填写] |
| 4 | CFO + COO 联名 | 运营/财务紧急事项，无法等待以上 | 内部 |
| 5 | 联合创始人/二把手（如有） | 日常紧急事项 | [待填写] |

**升级规则：**
- 升级不是"把问题甩出去"，而是带着方案和分析升级：陈述事实、列出选项、说明风险、给出最小必要行动建议。
- 升级决策同样需要记录，适用第五节决策记录格式。
- 若升级对象也联系不上，继续按优先级往下找，同时记录所有尝试联系的时间线。

## 五、决策记录规范

代理期间的**每一项**决策——包括"决定不决定"（暂停/冻结）——都必须记录。按 Chief of Staff 两层决策记忆格式：

### 5.1 原始记录（Layer 1: raw）

每个决策事项建一个文件/条目，包含完整审议过程：

```markdown
## 代理决策记录：[决策名称]
日期：[YYYY-MM-DD HH:MM]
记录人：[姓名/角色]
事项类型：🟢 Green / 🟡 Yellow / 🔴 Red

### 背景
[发生了什么，需要做什么决定，为何在代理期间提出]

### 可选方案
1. [方案A] —— 利：___ / 弊：___ / 可逆性：___
2. [方案B] —— 利：___ / 弊：___ / 可逆性：___
3. [维持现状] —— 利：___ / 弊：___ / 风险：___

### 决定
[选择了什么；若选择"暂停/不决定"也明确写出]

### 决定理由
[为何选这个，依据什么授权/原则/信息]

### 已知风险
[如果这个决定错了，最坏情况是什么，影响范围多大]

### 参与人
[谁参与了讨论/判断，各自意见]

### 后续
[负责人恢复后是否需要追认/审查；是否有复核时间点]
```

### 5.2 批准记录（Layer 2: approved）

负责人恢复后，对代理决策逐条审查：
- **追认：** 决策有效，转入 approved 层。
- **推翻/修正：** 记录修正内容，已执行的采取补救措施。
- **问责（如适用）：** 若代理决策明显越权或存在重大过失，按治理流程处理。

## 六、团队沟通指引

**对内部团队：**
- 明确传达："负责人暂时联系不上，期间所有非日常运营决策暂停，日常工作按既定计划推进。有疑问找值班负责人。"
- 不要制造恐慌，不要猜测原因，不要对外（含投资人/客户/媒体）提及负责人失联。
- 若外部方追问负责人去向，统一口径："[负责人]目前不方便联系，相关事项由团队按既定流程处理，如有紧急事项可联系[值班负责人/指定联系人]。"

**对外部相关方（客户/投资人/合作伙伴）：**
- 已签合同/已承诺事项照常执行（🟢）。
- 新承诺、新谈判、新签约一律暂缓，用"正在内部走流程"等中性措辞争取时间。
- 若对方有合同权利要求限时回应（如排他期、答复期），记录时效，按升级路径处理。

## 七、限制与假设

1. **假设：** 负责人失联是暂时性的（小时级到天级），而非永久性（如离职/意外）。若为后者，本机制不够用，须立即启动董事会治理程序。
2. **假设：** 公司存在基本的治理文件（章程/授权矩阵/董事会结构）。若无，代理权限更加受限——默认"无明确授权=不可决定"。
3. **假设：** 两项高风险决策的具体内容本机制未知，第三、四节中占位符需由实际了解情况的人填写。本机制提供的是**处理框架**，不是具体决策建议。
4. **限制：** 本机制不替代法律意见。涉及法律/合规事项必须咨询专业法律顾问。
5. **限制：** 本机制不替代董事会治理。若负责人失联时间超过预期（如 >72小时）或涉及重大治理真空，须由董事会正式决议指定临时负责人，而非继续靠本机制的非正式代理。
6. **限制：** 本机制基于 Chief of Staff skill 框架设计，但该 skill 假设的是"创始人在场、AI辅助路由"的正常场景；本机制是其在"创始人缺席"异常场景下的延伸，部分规则（如 board meeting 协议）被改造为升级路径，而非真正召集虚拟董事会。

## 八、负责人恢复后的交接清单

- [ ] 提交完整决策日志（Layer 1 原始记录）
- [ ] 逐项汇报两项高风险决策的准备情况和当前状态
- [ ] 汇报代理期间所有 🟡/🔴 事项的处理结果
- [ ] 提交升级路径上发生的所有外部联系记录
- [ ] 确认是否有已执行但需追认/修正的决策
- [ ] 本临时机制正式失效，恢复正常决策流程

---
