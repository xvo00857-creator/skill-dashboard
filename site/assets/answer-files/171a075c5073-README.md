# 输入清单处理流水线 — 最小可用版（只读预演）

## 一、这是什么

把"读取输入清单 → 校验字段 → 生成结果 → 人工确认后提交"做成可重复运行的流程。
当前版本默认 **dry-run（只读预演）**：只读取、校验、出报告，不访问网络、不写数据库、不调用任何生产接口。

## 三、快速开始

```bash
# 1) 只读预演（默认，安全）
python3 pipeline.py --input sample_input.csv

# 2) 预演并把报告写到文件
python3 pipeline.py -i sample_input.csv --report report.json

# 3) 真实提交（本版本为占位实现，仍不会访问外部系统）
#    需要：--execute + 与报告指纹一致的 --confirm-token + --config 凭据文件
python3 pipeline.py -i sample_input.csv --execute \
    --confirm-token <预演输出的指纹> --config credentials.example.json
```

## 四、输入格式

CSV，UTF-8，必需列：

| 列 | 说明 |
|---|---|
| id | 行唯一标识 |
| action | 动作类型（update/send/delete 等） |
| target | 操作对象 |
| payload | 内容（敏感信息会被自动识别并脱敏） |
| verified | 是否已核实：true/1/yes/已核实 才算通过 |

## 五、风险分级与处理

| 等级 | 触发条件 | 处理 |
|---|---|---|
| BLOCK | 命中个人敏感信息（邮箱/手机号/身份证/银行卡）；命中不可逆操作关键词；必填 id/action 为空 | 拦截，永不自动提交 |
| REVIEW | verified 非真；target 为空等 | 挂起，需逐条人工确认 |
| OK | 全部校验通过 | 可提交，但仍需整体确认门禁 |

不可逆操作关键词包括（可在脚本 `IRREVERSIBLE_KEYWORDS` 中按业务调整）：
delete/drop/truncate/purge/rm -rf/永久删除/清空/销毁/注销账户/批量发送/打款/转账 等。

## 六、停止条件（满足任一即停）

1. 输入文件不存在或缺少必需列；
2. 存在任意 BLOCK 记录；
3. 人工确认门禁未通过（交互模式下任一 REVIEW 被拒，或整体确认被拒）；
4. `--execute` 未提供 `--confirm-token`，或令牌与本次预演报告指纹不一致；
5. 未提供 `--config` 凭据文件；
6. 凭据文件不存在或提交阶段抛出异常。

## 七、授权清单（真实提交前必须逐项确认）

- [ ] 已明确本次操作的 **授权范围**（哪些系统、哪些表/对象、哪些动作）；
- [ ] 已获得 **书面审批**（审批人、工单号、有效期）；
- [ ] 已获取 **最小权限凭据**（只读预演用只读账号；提交账号仅限本次范围，事后回收）；
- [ ] 已确认输入清单中每一行的 `verified=true`，且事实来源可追溯；
- [ ] 已确认不含个人敏感信息，或已按合规要求脱敏/取得授权；
- [ ] 不可逆操作已单独评估并取得 **专项授权**；
- [ ] 已在 **测试/预发环境** 跑通相同输入；
- [ ] 已通知相关干系人并选定执行窗口。

## 八、回滚方案

本版本的回滚能力：
- 每次运行生成 `audit_<时间戳>.jsonl`，记录报告与提交回执，可用于审计与定位；
- 提交为占位实现，不产生真实副作用，因此无需回滚。

接入真实系统后必须补齐：
1. **提交前备份**：对被修改/删除的数据导出 before-image（建议按行快照）；
2. **幂等键**：每行带唯一 id，重复提交不产生重复效果；
3. **事务/分批**：小批量提交，单批失败可整批回滚；
4. **回滚脚本**：根据 before-image 自动生成逆向操作，并在同权限下验证；
5. **不可逆操作**：默认禁用；如必须执行，要求双人复核 + 备份留存 + 明确回滚窗口；
6. **回滚演练**：上线前在预发环境演练一次完整回滚。

## 九、人工复核点

1. **预演后**：人工阅读报告，确认 BLOCK/REVIEW 项与统计数字；
2. **REVIEW 逐条**：交互模式下对每条 REVIEW 输入 y/N；
3. **整体确认**：对全部 OK 项做一次总确认；
4. **令牌核对**：`--confirm-token` 必须与刚生成的预演报告指纹一致，防止"看过旧报告就提交新数据"；
5. **不可逆操作**：本版本直接 BLOCK，不提供放行参数；如需放行，必须改代码并加专项审批（刻意设计，避免命令行绕过）。

## 十、凭据文件示例（credentials.example.json）

真实凭据不得提交到代码库。建议通过密钥管理系统注入，文件权限 600。

```json
{
  "endpoint": "https://example.invalid/api/submit",
  "token_env": "PIPELINE_TOKEN",
  "timeout_seconds": 10,
  "dry_run": true
}
```

`token_env` 指向环境变量名，脚本从环境变量读取令牌，不在文件中明文保存。

## 十一、已知限制

- 提交阶段为占位实现，不访问任何外部系统；
- PII 正则为通用规则，业务侧应按合规要求补充（如住址、工号等）；
- 不可逆关键词为黑名单，可能漏判，不能替代人工评估；
- 未做并发/限流控制，接入真实接口时需补；
- references/ 下 8 个引用文件缺失（psychology/quotes/companies/philosophy/communication/management/government/education），不影响本流程，但说明该 Skill 包不完整。
