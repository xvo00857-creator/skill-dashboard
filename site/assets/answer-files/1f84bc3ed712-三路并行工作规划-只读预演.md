### 4.2 三路任务拆分

#### 路线 A：竞品调研

| 项 | 内容 |

| 输入 | 竞品名单（待确认）、调研维度清单、时间范围 |

## 五、输入输出契约

### 5.1 通用契约

所有路线的输入输出须遵循：

- **格式**：结构化文档（Markdown 或表格），UTF-8 编码
- **来源标注**：每条事实性陈述附来源链接或引用标识
- **验证状态**：标注"已核实 / 待核实 / 推断"
- **版本号**：语义化版本（v0.1 草稿 → v1.0 定稿）
- **脱敏**：不含个人姓名、邮箱、电话、身份证号等敏感信息

### 5.2 路线间依赖契约

```
路线 A（竞品调研）──┐
                   ├──→ 汇总合并 ──→ 项目负责人评审
路线 B（反馈归类）──┤
                   │
路线 C（原型方案）──┘（依赖 A、B 的 v0.9+ 版本）
```

- 路线 C 在路线 A、B 产出 v0.9 以上版本后方可启动最终设计
- 路线 A、B 可完全并行
- 任一路线的重大变更（v0.x → v1.0）须通知其他路线

### 5.3 数据交接格式

每条交接记录包含：

```json
{
  "route": "A|B|C",
  "version": "0.1",
  "timestamp": "ISO-8601",
  "author": "角色名（不含个人敏感信息）",
  "summary": "一句话摘要",
  "artifacts": ["相对路径或链接"],
  "known_gaps": ["未覆盖项"],
  "verification_status": "draft|reviewed|approved"
}
```

## 七、监控点

| 监控点 | 频率 | 检查内容 | 异常处置 |
|---|---|---|---|
| 输入验证 | 启动时 | 数据来源是否合法、是否含敏感信息 | 暂停，退回数据提供方 |
| 进度检查 | 每日 | 各路是否按计划推进、是否有阻塞 | 记录阻塞原因，升级至项目负责人 |
| 来源抽检 | 每路线至少 1 次 | 随机抽取 20% 事实陈述，验证来源可访问且内容一致 | 不一致率 > 10% 则该路线退回重验 |

| 版本一致性 | 每次交接 | 依赖的上游版本是否为最新批准版 | 使用旧版须说明理由并获批准 |
| 审计日志 | 实时 | 所有关键决策、变更、授权记录 | 日志缺失则暂停相关操作 |
