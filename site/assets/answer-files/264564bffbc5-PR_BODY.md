## Problem

The VSCode extension's `parseChangelog` function only recognised the
"Keep a Changelog" heading format (`## [1.2.3] - date`). When a
`CHANGELOG.md` was generated by Changesets — which uses headings like
`## cc-wf-studio@1.2.3` or `## @cc-wf-studio/core@1.2.3` — every entry
was silently skipped, so the changelog panel appeared empty.

### Current Behavior
1. Open a package whose `CHANGELOG.md` uses the Changesets heading format.
2. ❌ No version entries are parsed; the changelog view is empty.

### Expected Behavior
1. Open the same `CHANGELOG.md`.
2. ✅ All version entries are listed, including Changesets-format and
   scoped-package (`@scope/name@x.y.z`) headings, while the existing
   Keep a Changelog format continues to work.

## Solution

Replaced the single global regex with a line-by-line parser that tries
two patterns:

1. Keep a Changelog: `## [1.2.3] - date` / `## 1.2.3 - date`
2. Changesets: `## <pkg>@<version>` (scoped or unscoped names)

Prerelease versions (e.g. `2.0.0-beta.1`) are handled by both patterns.

### Changes

**File**: `packages/vscode/src/changelog.ts`
- Rewrote `parseChangelog` to iterate lines and match both heading
  formats instead of one global regex.
- Added support for Changesets headings with scoped (`@scope/name`) and
  unscoped package names.

**File**: `packages/vscode/src/changelog.test.ts`
- Added regression tests covering Keep a Changelog, Changesets
  (scoped + unscoped), prerelease versions, and non-heading false
  positives.

**File**: `.changeset/fix-changesets-changelog.md`
- Added a `patch` changeset for `cc-wf-studio`.
