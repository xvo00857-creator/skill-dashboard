# 代码生成智能体评分 Rubric（锚点版）

本 rubric 借鉴 `evaluation-methodology` Skill 的 0.0–1.0 五档锚点格式与字母等级，
针对“代码生成智能体”场景定义六个维度。运行器 `run_eval.py` 的 Layer 1（确定性）
与 Layer 2（规则评委）按本文件锚点打分；Layer 3（蒙特卡洛）提供统计修正。

每个维度 0.0–1.0，字母等级：A ≥ 0.90，B ≥ 0.80，C ≥ 0.70，D ≥ 0.60，F < 0.60。

---

## 维度 1 — functional_correctness（功能正确性）

**权重：0.30（最高）**

衡量生成代码通过隐藏功能测试的比例。这是代码生成智能体的首要价值。

| 分段 | 锚点描述 |
|---|---|
| 0.00–0.19 (F) | 代码无法解析，或全部功能测试失败；运行即崩溃 |
| 0.20–0.39 (F/D) | 仅最基础用例通过，多数功能测试失败 |
| 0.40–0.59 (D/C) | 约半数功能测试通过，核心逻辑存在明显错误 |
| 0.60–0.79 (C/B) | 绝大多数功能测试通过，仅个别非核心断言失败 |
| 0.80–1.00 (A/B) | 全部功能测试通过，输出符合需求规格 |

## 维度 2 — intent_understanding（意图理解）

**权重：0.20**

衡量是否正确理解 prompt：实现了要求的入口函数、满足显式约束（如“不要递归”“返回字典”）。

| 分段 | 锚点描述 |
|---|---|
| 0.00–0.19 (F) | 未实现入口函数，或完全偏离需求 |
| 0.20–0.39 (F/D) | 函数名/签名不符，或违反 prompt 中的显式约束 |
| 0.40–0.59 (D/C) | 入口函数存在但关键约束未满足（如要求迭代却用递归） |
| 0.60–0.79 (C/B) | 入口函数与主要约束满足，少量隐含要求遗漏 |
| 0.80–1.00 (A/B) | 入口函数、签名、显式约束、返回类型全部正确 |

## 维度 3 — code_quality（代码质量）

**权重：0.15**

衡量可读性与可维护性：文档字符串、嵌套深度、函数长度、命名。

| 分段 | 锚点描述 |
|---|---|
| 0.00–0.19 (F) | 代码不可读，嵌套过深，函数超长 |
| 0.20–0.39 (F/D) | 无文档，结构混乱，存在大量魔法数字 |
| 0.40–0.59 (D/C) | 基本可读但缺少文档，嵌套偏深 |
| 0.60–0.79 (C/B) | 结构清晰，函数长度合理，有文档字符串 |
| 0.80–1.00 (A/B) | 简洁、自文档化、嵌套≤3、函数长度≤40 行 |

## 维度 4 — boundary_robustness（边界鲁棒性）

**权重：0.15**

衡量空输入、单元素、极值、非法输入等边界场景的处理。

| 分段 | 锚点描述 |
|---|---|
| 0.00–0.19 (F) | 边界用例全部崩溃（IndexError/递归溢出等） |
| 0.20–0.39 (F/D) | 多数边界用例失败 |
| 0.40–0.59 (D/C) | 部分边界处理，空输入等常见边界未覆盖 |
| 0.60–0.79 (C/B) | 主要边界用例通过，有显式边界检查 |
| 0.80–1.00 (A/B) | 全部边界用例通过，含显式空值/极值处理 |

## 维度 5 — scope_fit（范围契合）

**权重：0.10**

衡量“不多做不少做”：不引入无关第三方依赖，不实现需求外功能，不遗漏需求。

| 分段 | 锚点描述 |
|---|---|
| 0.00–0.19 (F) | 严重跑题，或引入大量无关依赖/功能 |
| 0.20–0.39 (F/D) | 引入无关第三方库，或实现多个无关函数 |
| 0.40–0.59 (D/C) | 基本聚焦但有轻微越界 |
| 0.60–0.79 (C/B) | 范围准确，允许 1–2 个辅助函数 |
| 0.80–1.00 (A/B) | 精确实现需求，无冗余依赖与功能 |

## 维度 6 — security_executability（安全与可执行性）

**权重：0.10**

衡量代码可安全执行：语法正确、无硬编码密钥、无危险执行、无 SQL 拼接、无裸 except。

| 分段 | 锚点描述 |
|---|---|
| 0.00–0.19 (F) | 语法错误无法执行，或存在严重安全反模式 |
| 0.20–0.39 (F/D) | 含硬编码密钥或 eval/exec |
| 0.40–0.59 (D/C) | 可执行但存在 SQL 拼接或裸 except |
| 0.60–0.79 (C/B) | 可执行且无严重反模式，有轻微调试残留 |
| 0.80–1.00 (A/B) | 语法正确、无任何安全反模式、可直接运行 |

## 反模式与乘法惩罚

静态扫描检测以下反模式，每个使综合分乘以 `max(0.5, 1.0 − 0.05 × n)`：

| 反模式 | 说明 |
|---|---|
| HARDCODED_SECRET | 硬编码密码/令牌/API 密钥 |
| DANGEROUS_EVAL | 使用 eval/exec |
| BARE_EXCEPT | 裸 except 吞掉所有异常 |
| SQL_STRING_CONCAT | SQL 用 f-string/拼接构造 |
| PRINT_IN_FUNCTION | 函数体内残留 print 调试 |

## 失败类型分类

| 失败类型 | 含义 |
|---|---|
| SYNTAX_ERROR | 生成代码无法通过语法解析 |
| FUNCTIONAL_FAILURE | 功能测试未通过 |
| BOUNDARY_FAILURE | 边界用例未通过 |
| ROBUSTNESS_FAILURE | 异常/非法输入导致崩溃或智能体调用失败 |
| SECURITY_ANTIPATTERN | 存在安全反模式 |
| SCOPE_OVERREACH | 引入无关依赖或实现需求外功能 |
| SCOPE_UNDERDELIVERY | 缺少入口函数或关键行为 |
| NON_REPRODUCIBLE | 多次运行结果不一致（CV > 0） |

## 综合分与通过线

```
composite = Σ(dimension_weight × blended_dimension_score) × 100 × anti_pattern_penalty
```

- **通过线**：综合分 ≥ 70（等级 C 及以上）
- **发布建议**：≥ 80（B）可进入生产候选；≥ 90（A）可作为金标准样本
- 层混合按可用层归一化（quick 仅 static；standard 为 static+judge；deep 三层全开）
