## 二、发现摘要

日志中存在 **1 条 critical、1 条 high、2 条 warning、1 条 info、1 条异常记录**。最严重的发现是：同一来源 IP `203.0.113.8` 在 09:04:02 触发 API token 权限不匹配（high）后，于 09:07:30 对数据库发起了一次"未知用户"的异常导出（critical），两次事件相隔约 3 分 28 秒，构成疑似"越权 → 数据外传"攻击链 ⚠️。此外，IP `198.51.100.23` 在 4 秒内连续两次对 `admin` 账号登录失败，存在暴力破解前兆 ⚠️；最后一条日志字段缺失，存在日志完整性问题。

**优先级结论**：
1. **立即处置**：critical 级数据库异常导出（疑似数据外传）
2. **尽快处置**：high 级 token 权限不匹配（疑似越权尝试）
3. **计划处置**：admin 账号短时连续登录失败、日志记录畸形

## 四、修复建议（按优先级）

### P0 — 立即处置（针对风险 1、2）

1. **吊销并轮换 `service-a` 的 token/密钥**：立即失效当前 token，重新签发最小权限 token；审查该 token 近期的全部 API 调用记录。
2. **核查数据库导出内容**：在数据库审计日志中确认 09:07:30 前后 `unexpected_export` 涉及的库表、行数与字段，判定是否包含个人信息或敏感商业数据；如确认泄露，按内部数据泄露响应流程上报。
3. **临时阻断 IP `203.0.113.8`**：在 WAF/防火墙/安全组临时封禁该 IP，待排查完成后评估是否永久封禁。⚠️ 本建议为处置建议，需由有权限的运维人员执行，本审计未执行任何阻断操作。
4. **重置 `unknown` 关联账号**：若 `unknown` 对应可识别的数据库账号，立即强制改密并吊销活跃会话。

### P1 — 尽快处置（针对风险 3）

5. **对 admin 账号启用登录限速与账户锁定策略**：如连续失败 N 次（建议 5 次/10 分钟）临时锁定并告警。
6. **核查 IP `198.51.100.23` 的历史登录记录**：确认该 IP 是否有更多失败尝试或成功登录记录。
7. **admin 账号启用多因素认证（MFA）**。

### P2 — 计划处置（针对风险 4 及长期改进）

8. **修复日志采集管道**：排查 `malformed_record` 产生原因，确保 severity/user/source_ip 等必填字段不为空；增加日志格式校验与丢弃告警。
9. **建立日志完整性保护**：对安全日志启用追加写入/防篡改存储，定期校验日志哈希。
10. **配置关联告警规则**：将"token_scope_mismatch 后短时间内出现 db unexpected_export 且同源 IP"设为高危关联告警规则。
11. **落实最小权限原则**：审查所有服务账号的 token scope，确保服务账号仅拥有完成功能所需的最小数据库与 API 权限，禁止服务账号直接具备导出权限。
