# 营销视频交付说明 —— 面向 50 岁以上首次使用智能手机用户

> 交付物：`output.mp4`（1080×1920，9:16 竖版，约 41 秒，H.264 + AAC，13 MB）
> 触点：线下社区活动现场播放 + 微信群/朋友圈转发
> 发布窗口：14 天 ｜ 制作预算：8,000 元

---

## 一、约束变化如何改变原方案

| 维度 | 原方案（桌面网页 / 常规用户 / 长窗口 / 高预算） | 本次（线下社区+微信 / 50+首次智能机 / 14天 / 8000元） | 对方案的影响 |
|---|---|---|---|
| **目标用户** | 有互联网经验的用户，能理解 App 术语、能自己摸索 | 50 岁以上、**第一次用智能手机**，数字素养低，怕点错、怕扣钱、字小看不清 | 文案必须**口语化、无术语**；语速放慢；字号放大；用"叔叔阿姨""咱们"拉近距离；先打消"怕扣钱"顾虑再讲功能 |
| **触点** | 桌面网页 hero 视频，16:9，可点击跳转，可静音自动播放 | 线下社区电视/投影（有声音、可能多人围观）+ 微信手机端（竖屏、常静音转发） | 主版本做 **9:16 竖版**（微信优先）；**必须烧录大字幕**（静音也能看懂，线下嘈杂也能看）；旁白必须有（线下听得到）；CTA 不能放"点击链接"，改为"来社区活动室""找志愿者"等线下行动 |
| **发布窗口** | 充足，可多轮拍摄/抽卡/修改 | **14 天**，含社区测试 | 放弃真人拍摄（排期不可控）和按秒计费的 AI 视频 API（多轮抽卡耗时）；改用**确定性程序化渲染**（HTML→MP4），1–2 天出片，留时间给社区试看和修改 |
| **预算** | 较充裕 | **8,000 元** | 工具成本趋近于零（开源渲染 + 内置 TTS + 本地 ffmpeg）；预算主要留给社区协调、志愿者工时、线下小礼品/打印二维码，而非视频制作本身 |
| **内容重心** | 展示功能、UI、酷炫动效 | 建立信任、降低恐惧、给出明确的线下下一步 | 视频结构从"功能展示"改为**"共情痛点 → 打消顾虑 → 三步好处 → 线下行动"**；不展示真实 UI（避免老人觉得复杂），用温暖插画代替 |

## 二、调整后的执行步骤、优先级与取舍

### 执行步骤（14 天排期）

| 天 | 事项 | 产出 |
|---|---|---|
| D1–D2 | 脚本/钩子/分镜定稿，TTS 旁白录制，程序化渲染出首版 | 视频 v1 |
| D3 | 内部评审 + 找 2–3 位目标用户（社区里 50+ 长辈）试看，观察哪里没看懂、哪里觉得"是说我" | 修改清单 |
| D4–D5 | 按反馈调整文案/节奏/字幕，出 v2 | 视频 v2 |
| D6–D7 | 社区活动室小范围试放，收集口头反馈；同步准备线下物料（二维码立牌、大字海报、志愿者话术） | 视频终版 + 物料 |
| D8–D12 | 正式投放：社区活动现场循环播放 + 志愿者在微信群转发 + 入户/活动时一对一帮装 | 上线 |
| D13–D14 | 统计到店/扫码/帮装人数，复盘 | 数据复盘 |

### 优先级（必须做 → 可做 → 不做）

1. **必须（P0）**：大字幕烧录、口语化旁白、"怕扣钱"顾虑前置、线下 CTA、9:16 竖版、文件小（便于微信转发）。
2. **应该（P1）**：温暖真实的视觉风格（避免酷炫动效让老人觉得"这是年轻人的东西"）、慢节奏、镜头编号提供进度感。
3. **可以（P2）**：如社区反馈好，再追加一版 16:9 供投影全屏；再做一条 15 秒精剪版用于朋友圈。
4. **不做（取舍）**：
   - 不做真人拍摄（14 天/8000 元下排期和成本不可控，且老人对"广告脸"有戒心，插画反而更亲切）。
   - 不用按秒计费的 AI 视频生成做正片（不可控、多轮抽卡吃窗口）；AI 只用于生成静态 B-roll 插画。
   - 不在视频里放二维码/电话号码（9:16 小屏 + 线下远距离拍不清，改为"来社区活动室找我们"，二维码放在线下立牌上）。
   - 不做英文、不做网络流行语、不做快剪。

### 关键取舍说明

- **确定性 > 惊艳度**：选择 HTML 程序化渲染而非 AI 视频抽卡，是因为 14 天窗口里"按时出片、字幕绝对清晰"比"画面可能很炫但可能抽崩"更重要。
- **信任 > 功能堆砌**：50+ 首次智能机用户最大的障碍不是"功能不够多"，而是"不敢用"。所以视频把"不扣钱、有人教"放在功能之前。
- **线下行动 > 线上转化**：触点是社区和微信，CTA 必须是线下可执行的动作，而不是"点击下载"。

## 五、验收说明

### 目标
让 50 岁以上、第一次用智能手机的社区长辈，在 1 分钟内：① 感到"这是说给我听的"；② 知道这东西"字大、简单、不扣钱、有人教"；③ 知道下一步"去社区活动室找人帮装"。

### 依据
- **用户研究层面（常识性，非编造数据）**：老年智能机新用户的核心障碍是"看不清、怕出错、怕扣钱、没人教"，这是适老化传播的通用共识，因此文案把这四点前置。
- **Skill 依据**：`video/SKILL.md` 明确"85% 的社交视频在静音下观看，必须加字幕"（适用于微信转发场景）；"不要让 AI 生成可读文字，用程序化叠加"；"前 2 秒钩子决定留存"；explainer 视频遵循 problem→solution→CTA 结构。
- **约束依据**：14 天 / 8000 元 / 线下+微信触点，直接决定了竖版、确定性渲染、线下 CTA 的技术与内容选择。

### 步骤（实际执行）
1. 解压并阅读 `video/SKILL.md`、`references/ai-video-prompting.md`、`references/edit-anatomy.md`、`evals/evals.json`。
2. 检查 `product-marketing` 上下文——工作目录内**不存在**该文件，因此不依赖额外产品上下文，按题面约束设计。
3. 因 Hyperframes 要求 Node ≥ 22（当前为 20），改用其底层同思路的程序化方案：puppeteer-core（用系统 Chrome）把 HTML 帧截图为 1080×1920 PNG，再用本地 ffmpeg（`@ffmpeg-installer/ffmpeg`）合成 MP4。字幕全部由 HTML/CSS 渲染烧录。
4. 用图像生成模型产出 5 张统一暖色扁平插画作为 B-roll（图片内不含任何依赖阅读的文字）。
5. 用 TTS 生成温暖中年女声中文旁白（语速偏慢、咬字清晰）。
6. ffmpeg 为每个镜头加缓慢推近（Ken Burns）与首帧淡入，拼接后混入旁白，末尾音频淡出，输出 `output.mp4`。
7. 抽取 1s/8s/15s/25s/35s/40s 多帧人工核验字幕与画面。

### 关键取舍
见第二节。核心三条：确定性渲染优先于 AI 抽卡；信任/不扣钱优先于功能堆砌；线下行动优先于线上点击。

### 风险
1. **产品未具名**：题面只说"同一产品"未指明具体产品，视频中用"小应用"泛称，功能点（挂号/付钱/视频）为适老化常见场景示例。**实际上线前必须替换为真实产品名与真实功能**，否则有误导风险。
2. **插画中人物形象**：AI 生成插画为通用中国人形象，不涉及真实人物授权；但若产品方有品牌 IP/吉祥物，建议替换以统一品牌。
3. **TTS 旁白 vs 真人配音**：当前为合成女声，温暖度可接受但不如真人亲切。若预算允许，建议 D3 前请一位声音亲和的社区工作者真人录制，成本可控。
4. **线下播放适配**：主版本为 9:16，在社区 16:9 电视上播放会有左右黑边但字幕仍清晰；若现场反馈黑边观感差，需另出 16:9 版（P2）。
5. **微信转发文件大小**：13 MB 对微信转发友好；若加 16:9 版本需注意总大小。
6. **"不扣钱"表述**：如产品实际有付费项，必须改为"明明白白不乱扣"等真实表述，避免合规风险。

### 衡量方式（上线后）
- **到店/接触量**：社区活动室因视频而来咨询/帮装的人次（志愿者登记）。
- **微信侧**：视频在社区群的转发次数、完播率（若用视频号发布可看后台数据）。
- **转化**：帮装成功人数、7 天后仍在使用的留存（志愿者回访）。
- **定性**：现场观察长辈是否能复述"字大、不扣钱、有人教、去活动室"这四点。

### 下一步
1. 把"小应用"替换为真实产品名与真实功能，核对"不扣钱"表述合规性。
2. D2 内找 2–3 位目标长辈试看，按反馈改 v2。
3. 准备线下配套物料：大字海报、二维码立牌（链接到下载/教程页）、志愿者一句话话术。
4. 如预算允许，换真人旁白；如现场需要，补 16:9 版和 15 秒朋友圈精剪版。
