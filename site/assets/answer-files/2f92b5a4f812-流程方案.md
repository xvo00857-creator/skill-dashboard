# expo-api-routes Skill 受约束工具流程方案

## 一、Skill 能力边界

本方案严格依据上传的 `expo-api-routes` Skill（risk: critical）执行。该 Skill 是**指南类 Skill**，提供 Expo Router API Routes 的编写规范与 EAS Hosting 部署指引，本身不包含可执行脚本或 CLI。

**Skill 覆盖范围：**
- API Routes 的适用/不适用场景判断
- `+api.ts` 文件结构与命名规范
- HTTP 方法（GET/POST/PUT/DELETE）、动态路由 `[id]`、查询参数、Headers、JSON Body 处理
- 环境变量（`process.env`）与密钥管理
- CORS、错误处理、认证中间件、外部 API 代理模式
- 本地测试（`npx expo serve`）与 EAS Hosting 部署（`eas deploy`）
- Cloudflare Workers 运行时限制（无 Node fs、30 秒超时、Web Crypto 等）

**Skill 不覆盖（不扩张职责）：**
- 不提供数据库迁移、Schema 管理
- 不提供认证服务本身的实现（仅中间件模式）
- 不提供 CI/CD 流水线配置
- 不提供前端组件或页面生成
- 不执行实际的云资源创建或费用操作

## 二、可复用工具流程

工具文件：`tools/expo-api-route-gen.js`（纯 Node.js，无外部依赖）

### 2.1 命令一览

| 命令 | 功能 |
|------|------|
| `preflight` | 运行环境预检，不做任何修改 |
| `generate <path> --template <name>` | 幂等生成 API Route 文件 |
| `list-templates` | 列出所有可用模板 |
| `deploy --dry-run` | 部署前检查（不执行部署） |
| `deploy` | 实际部署（需人工确认） |

### 2.2 可用模板

| 模板 | 对应 SKILL.md 章节 | 说明 |
|------|-------------------|------|
| `basic` | Basic API Route / HTTP Methods / Error Handling | GET + POST，含输入校验与 try/catch |
| `dynamic` | Dynamic Routes | `[id]` 动态路由 |
| `proxy` | Environment Variables / Proxy External API | 代理外部 API，密钥经 `process.env` 注入 |
| `webhook` | Webhook endpoints | Webhook 接收端，含签名校验占位与幂等提示 |
| `cors` | CORS Headers | 含 OPTIONS 预检响应 |
| `auth` | Authentication Middleware | 受保护路由 + `utils/auth.ts` 中间件 |

### 2.3 预检（Preflight）

生成或部署前自动执行以下检查，任一失败即中止：

1. **Node.js 版本** ≥ 18（Web Crypto / fetch 支持，对应 Cloudflare Workers 运行时）
2. **package.json 存在**且包含 `expo` 依赖
3. **expo-router 依赖**存在（API Routes 需要 Expo Router）
4. **app/ 目录存在**（Routes 必须位于 `app/` 下）
5. **tsconfig.json 存在**（SKILL.md Rules 要求 TypeScript 类型安全）
6. **.gitignore 包含 .env**（防止密钥提交到仓库）

### 2.4 幂等（Idempotency）

- 生成前检查目标文件是否已存在
- 已存在时**默认跳过**，不覆盖，并提示使用 `--force`
- `--force` 覆盖前在日志中明确标注将覆盖的文件
- 路径遍历检查：拒绝 `..` 等非法路径段

### 2.5 重试（Retry）

- `withRetry` 工具函数对网络操作（如 `eas deploy`）提供指数退避重试
- 默认 3 次尝试，重试间隔递增（1s → 2s → 3s）
- 重试耗尽后返回明确错误码（6）

### 2.6 人工确认点

| 操作 | 确认方式 | 依据 |
|------|---------|------|
| 覆盖已有文件 | 需显式 `--force` | 不静默覆盖 |
| 实际部署 `eas deploy` | 交互式 y/N 确认（或 `--yes` 跳过） | SKILL.md Limitations：用户对破坏性/昂贵操作的批准 |
| 部署默认 dry-run | `--dry-run` 只检查不执行 | 防止误操作产生费用 |

## 四、未执行的操作与待确认项

以下操作因权限、凭证或安全约束**未执行**，需人工确认后才能进行：

| 项目 | 原因 | 后续步骤 |
|------|------|---------|
| `npm install` 安装依赖 | 演示不需要，且会产生大量文件 | 在真实项目中执行 |
| `npx expo serve` 本地启动 | 未安装 node_modules，无法启动 | 安装依赖后执行，再用 curl 验证 |
| `eas login` / `eas deploy` | 无 EAS 账号凭证，且部署可能产生费用 | 需用户登录并确认后执行 |
| `eas env:create` 设置生产密钥 | 无凭证，且密钥不应由工具明文传入 | 用户通过 EAS 控制台或 CLI 手动设置 |
| TypeScript 类型检查 | 未安装 typescript 和 expo 类型定义 | 安装依赖后运行 `npx tsc --noEmit` |
| 签名校验逻辑（webhook/auth 模板） | 需按具体服务文档实现 | 代码中标注 TODO，需开发者完成 |

**重要假设（需核实）：**
- SKILL.md 中 `npx expo serve` 启动在 `http://localhost:8081`——实际端口以 Expo 官方文档和本地运行为准
- SKILL.md 中 EAS Hosting 基于 Cloudflare Workers——部署前应核对当前官方文档
- 演示项目中的 expo/expo-router 版本号（~51.0.0 / ~3.5.0）为示例值，实际项目应使用兼容版本

## 六、影响交付结果的 SKILL.md 规则

**规则：** SKILL.md 末尾 Limitations 第 3 条：
> "Do not treat generated examples as a substitute for environment-specific tests, security review, or user approval for destructive or costly actions."

**对交付结果的实际影响：**
1. 工具默认 `deploy --dry-run`，实际部署必须经过交互式人工确认（y/N），不能自动执行
2. 预检中强制检查 `.gitignore` 是否忽略 `.env`，防止密钥泄露
3. proxy 模板中密钥仅通过 `process.env` 引用，不硬编码，并在缺失时返回 500 而非崩溃
4. webhook/auth 模板中的签名校验和 token 验证留为 TODO，不提供虚假的"已验证"实现
5. 本方案明确标注未执行的操作和待确认假设，不将生成的代码等同于已通过环境测试

**另一条关键规则：** SKILL.md Rules 第 1 条 "NEVER expose API keys or secrets in client code"——工具的 proxy 模板和预检流程均围绕此规则设计。
