# KubeSphere ServiceMesh 运维速查 — 设计规范与一致性检查

## 一、关键设计规范

### 1. 品牌色板（仅三色 + 必要中性色）

| 角色 | 色值 | 用途 |
|------|------|------|
| 深蓝 | `#0F2B46` | 页头/页脚背景、章节编号底、表头、流程条背景、标题文字 |
| 米白 | `#F7F2E8` | 页面主背景 |
| 亮橙 | `#FF6A00` | 强调线、标签、步骤圆点、卡片顶边、代码块左边框、链接/警告 |
| 白（中性） | `#FFFFFF` | 卡片/表格内容区底色，非第四品牌色 |
| 深蓝暗调（中性） | `#0B1F33` | 代码块背景，为深蓝的暗色变体 |
| 正文文字 | `#1A2332` | 米白底上的正文，保证对比度 |
| 次要文字 | `#5A6577` | 说明性文字 |

### 2. 字体

- 中文：PingFang SC / Microsoft YaHei
- 英文/代码：SF Mono / Fira Code / Consolas
- 正文字号：桌面 15px，手机 14px；行高 1.7
- 代码字号：13px（手机 12px），行高 1.6

### 3. 布局

| 维度 | 桌面横屏 | 手机竖屏 |
|------|----------|----------|
| 视口宽度 | 1920px | 390px |
| 内容最大宽度 | 1200px 居中 | 100% 撑满 |
| 卡片网格 | 2-3 列 | 单列堆叠 |
| 页头布局 | 左图右文横排 | 上图下文居中 |
| 流程条 | 横向排列 | 纵向排列，箭头旋转 90° |
| 内边距 | 40px | 16px |

### 4. 组件规范

- **卡片**：白底、8px 圆角、1px 米白暗调边框、3px 亮橙顶边
- **代码块**：深蓝暗调底、米白文字、6px 圆角、3px 亮橙左边框、横向可滚动
- **步骤条**：亮橙圆形序号 + 白色卡片
- **状态标签**：圆角药丸形，语义色（绿/红/黄/蓝）仅用于状态区分，非品牌色
- **表格**：深蓝表头、米白文字；斑马纹使用极浅米白；手机端外层可横向滚动
- **警告条**：浅橙底、亮橙左边框、⚠ 前缀

### 5. 响应式断点

- `≤540px`：手机竖屏布局，所有多列网格折叠为单列，流程条纵向排列
- `>540px`：桌面横屏布局，2-3 列网格

### 6. 主题配图

- 由 Seedream 5.0 Pro 生成，服务网格拓扑示意图
- 严格使用深蓝底、米白节点、亮橙连线三色
- 无文字，避免 AI 生图文字乱码风险

### 颜色占比（程序化分析）

| 色系 | 桌面横屏 | 手机竖屏 |
|------|----------|----------|
| 米白/白系（背景+卡片） | ~73.6% | ~58.7% |
| 深蓝系（页头+代码块+页脚） | ~22.5% | ~30.6% |
| 亮橙系（强调元素） | ~0.6% | ~1.2% |
| 其他（抗锯齿/阴影过渡） | ~3.3% | ~9.5% |

> 手机端深蓝占比更高，因为单列布局下代码块和页头占画面比例更大；橙色占比更高因为纵向流程条的箭头更多。属正常适配差异，非颜色不一致。

### 发现并修复的问题

1. **手机端文字右裁切**：首版手机截图中正文被右侧截断。原因是未设置 `overflow-x: hidden` 和 `max-width: 100%`。已修复并重新截图验证。
2. **表格在窄屏溢出**：配置项表格在 390px 宽度下溢出。已添加 `table-layout: fixed`、`word-break: break-word` 和外层滚动容器。

## 三、需明确标注的假设与限制

1. **未连接真实集群**：当前环境无 `kubectl`，所有命令均为 SKILL.md 中定义的操作步骤，未实际执行，未伪造任何输出。
2. **Skill 能力边界**：该 Skill 实质为 kubectl 命令行运维指南，不含视觉设计能力。本交付物的视觉层（HTML/CSS/截图）是依据 SKILL.md 内容另行制作的呈现层，非 Skill 本身产出。
3. **Jaeger 默认凭据**：SKILL.md 引用的 extension-values.md 中默认 ES 密码为 admin/admin，页面中已加安全警告提示生产环境必须修改。
4. **状态标签语义色**：状态药丸使用了绿/红/黄/蓝四色用于状态语义区分，这些是功能性状态色而非品牌装饰色；如需严格仅三色，可改为深蓝/米白/亮橙三态。
5. **配图为 AI 生成**：主题拓扑图由 Seedream 5.0 Pro 生成，为示意图，不代表真实集群拓扑。

## 五、实际影响交付结果的 SKILL.md 规则

**规则：卸载前必须与用户确认（"Always confirm with the user before proceeding"）；从指定集群卸载时不得删除 InstallPlan，只能 patch placement 列表。**

这条规则直接影响了交付物中"卸载"章节的内容设计：页面将"从所有集群卸载"和"从指定集群卸载"分为两张卡片，并在后者用亮橙加粗文字明确标注"不要删除 InstallPlan，仅从 placement 中移除目标集群"，同时给出了 patch 命令而非 delete 命令。此外，页面顶部的环境说明和卸载章节的警告条都体现了"需确认"这一规则。如果忽略此规则，交付物可能会错误地展示 `kubectl delete` 用于部分集群卸载，造成运维事故。
