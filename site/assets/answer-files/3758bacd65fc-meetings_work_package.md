## 0. Gate 结论（先说结果）

按 `scripts/meeting_cost_calculator.py` 的三态判定，**当前状态为 NOT-READY（exit 3）**，不构建议程、不发送邀请。

判定依据（已实跑验证）：

| Gate 检查项 | 状态 | 说明 |
|---|---|---|
| 有明确决策（`--has-decision`） | **否** | 场景描述为"团队对范围存在冲突"，但未给出可投票/可批准的具体决策命题。冲突 ≠ 决策。 |
| 有时限议程（`--has-agenda`） | **否** | 无议题、无期望结果、无时间盒。 |
| 有会议负责人（`--has-owner`） | **否** | 无具名召集人/主席。 |

> 若强行把"范围冲突"当作决策，脚本输出为 NOT-READY（缺 agenda + owner）；若连决策都不成立，则为 ASYNC（exit 2）——即应写备忘录/线程，而非开会。两种路径都不直接产出 MEET。

**因此本工作包的核心动作不是"开这个会"，而是"把会议推到可开的状态，或判定它不该开"。**

## 1. 事实 / 推断 / 待确认

严格按 Skill 的诚实原则（`action_item_discipline.md`："a fuzzy extractor that infers actions from vibes recreates the original problem"），不把推断当事实。

### 1.1 事实（来自题目与 Skill 文件，可直接引用）

- 团队对"范围"存在冲突（题目原文）。
- 现有会议记录中，部分行动项缺少负责人和/或截止日期（题目原文）。
- 资料中包含手机号等敏感个人信息（题目原文）。
- 约束：不得替团队做未经授权的决定；不得发送消息（题目原文 + Skill 规则 "Never auto-send"）。
- 本次需要覆盖：准备议程、控制会议节奏、输出决策/责任人/行动项（题目要求）。
- Skill 规则：gate 不通过不得构建议程；无期望结果的议题被拒绝；每个行动项必须有负责人和日期，否则标记 ORPHAN / NO-DUE，绝不自动补全。

### 1.2 推断（基于 Skill 经典文献的合理判断，非事实）

- "范围冲突"大概率是一个需要同步决策的 mission meeting（Grove 分类），但这只是推断——具体决策命题需要团队确认。
- 缺负责人/截止日期的会议记录，用 `action_item_extractor.py` 跑后会出现 ORPHAN 和 NO-DUE 标记（已用 sample 验证该行为）。
- 含手机号的资料若直接进入预读材料或会议纪要分发，存在个人信息泄露风险；Skill 本身不做脱敏，需额外步骤。

### 1.3 待确认（缺这些就无法推进到 MEET）

| # | 待确认项 | 为什么需要 | 确认方式（建议） |
|---|---|---|---|

| Q2 | **会议负责人**是谁？（具名，负责主持、追行动项） | gate 第三项 | 团队指定或自荐 |

## 2. 风险识别

| 风险 | 来源 | 后果 | 缓解 |
|---|---|---|---|
| **越权决策** | 题目明确禁止"替团队做未经授权的决定" | 做出团队不认可的范围取舍，后续返工 | 本工作包只列选项和流程，不替团队选；决策必须在会上由有权人做出 |
| **自动发送** | Skill 硬规则 "Never auto-send" | 未经授权发出邀请/消息/纪要 | 所有产出为文本；不调用任何发送/日历/IM 工具 |
| **敏感信息泄露** | 资料含手机号 | 个人信息泄露、合规风险 | 预读材料和纪要分发前必须脱敏（见 §5.3）；不在本工作包中抄录任何真实手机号 |
| **信息不全强行开会** | gate 规则 | 浪费 $747（6 人 × 60 分 × $90 + refocus，已实跑数字）却无决策 | gate NOT-READY 时不构建议程；先补 Q1–Q4 |
| **编造行动项/负责人/日期** | `action_item_discipline.md`："a name typed by a script is not a commitment" | 虚假进度感，真正该做的事无人认领 | extractor 只做模式匹配，不推断；ORPHAN/NO-DUE 必须由人在会上当面分配 |
| **把"对齐/同步"当会议目的** | `meeting_cost_canon.md`："If you wrote 'share an update', 'align', or 'sync' — stop" | 状态更新冒充会议 | 决策命题必须以 decide/choose/approve 开头，否则走异步备忘录 |

## 3. 最小可执行方案（现有信息下可安全做的事）

原则：**只做不替团队做决定、不发送消息、不泄露敏感信息的准备动作。**

### 步骤 A：跑 gate（已完成，结果 NOT-READY）

```bash
# 在 meetings_extracted/meetings/ 目录下
python3 scripts/meeting_cost_calculator.py \
  --attendees <Q3人数> --minutes <Q4时长> --avg-rate <Q5费率，默认90> \
  --include-refocus \
  [--has-decision] [--has-agenda] [--has-owner]   # 仅在对应项已确认时才加
```

当前无任何一项可确认，故不带三个 `--has-*` 标志，verdict = ASYNC（exit 2）。这本身是有效结论：**先写备忘录，不发邀请。**

### 步骤 B：写"范围冲突"异步备忘录（替代会议的首选）

按 Amazon 叙事备忘录传统（`meeting_cost_canon.md` 来源 4），由提议者书面回答：

1. 范围冲突的两方（或多方）主张各是什么？
2. 各自的依据/约束/代价是什么？
3. 需要做的**一个具体决策**是什么？（例："决定 v2 范围是否包含 X 功能"，而非"讨论一下范围"）
4. 若本周不决策，会发生什么？
5. 建议谁来拍板？

备忘录发出后：
- 若团队在线程中达成一致 → 无需开会，直接记录决策和行动项。
- 若仍有分歧且确需同步讨论 → 回到 gate，此时 Q1（决策）和 Q2（负责人）应已明确，可重跑 gate。

### 步骤 C：若 gate 通过到 MEET，再构建议程

仅当 gate 输出 MEET（exit 0）后，才运行：

```bash
python3 scripts/agenda_builder.py --length <分钟> \
  --topic "议题:以动词开头的期望结果:分钟:负责人" \
  --topic "..."
```

硬约束（脚本会强制）：
- 每个议题必须有非空期望结果，否则 exit 2（已实跑验证："范围对齐::15:待确认" 被 REFUSED-NO-OUTCOME 拒绝）。
- 议题时间 + 5 分钟收尾 recap 必须 ≤ `--length`，否则 exit 3。
- decide/choose/approve 开头的议题自动排到最前。
- 必须保留 5 分钟收尾"actions recap"。

### 步骤 D：会后提取行动项（含脱敏）

```bash
# 1. 先对原始笔记做敏感信息脱敏（见 §5.3），再喂给 extractor
python3 scripts/action_item_extractor.py --input notes_sanitized.md
```

- 输出按负责人分组的 checklist，ORPHAN 和 NO-DUE 会被显式标记。
- **分配 ORPHAN 和补 NO-DUE 必须在会上当面完成**（`action_item_discipline.md`："Assign every orphan before posting"）。
- extractor 不自动分配、不自动补日期——这是设计，不是缺陷。

## 4. 停止条件（什么情况下不再推进开会）

1. **决策命题无法写出**（Q1 无答案）→ 停止，走异步备忘录或升级上级。
2. **无人愿当会议负责人**（Q2 无答案）→ 停止；无主席的会议按 Grove 规则必败。
3. **gate 连续两次 NOT-READY 且缺口相同** → 停止，说明团队尚未准备好，改为书面决策流程。
4. **范围冲突在备忘录线程中已解决** → 停止开会，记录决策即可。
5. **敏感信息处理授权不明确**（Q8 无答案）→ 停止分发预读材料；先解决合规问题。
6. **行动项无法在会上分配到具名负责人和具体日期** → 会议不算结束，继续当场分配；若有人拒绝认领且无替代，升级而非散会。

### 5.2 议程模板（gate 通过后填入实值，勿提前发送）

```markdown
# 议程 — <时长> 分钟，<N> 个议题

```

> 注意：decide/choose/approve 开头的议题必须排在 discuss/inform 之前（脚本自动排序，但人工填写时也应遵循）。

### 5.3 敏感信息脱敏处理流程（Skill 未内置，本场景必须加）

Skill 的三个脚本均不做脱敏。在将任何资料喂给 extractor 或作为预读分发前：

1. **手机号**：替换为 `[手机号已脱敏]` 或保留前 3 后 4（如 `138****1234`）。
2. **其他个人信息**（邮箱、身份证、住址等）：同样处理。
3. **脱敏后再入脚本**：`action_item_extractor.py` 的输入应为脱敏后的文件。
4. **原始含敏感信息的文件**：不放入共享目录、不进入预读包、不粘贴到聊天工具。
5. 本工作包中**不包含**任何真实手机号或个人信息示例。

## 7. 衡量方式（怎么算这件事做对了）

- **过程指标**：gate 三态判定与脚本输出一致；议程若产出，每个议题有动词开头的期望结果且时间盒不超限；行动项 0 ORPHAN、0 NO-DUE。
- **结果指标**：若开会，会议产出至少一个明确决策 + 全部行动项有具名负责人和具体日期；若不开会（ASYNC），备忘录线程中达成书面决策。
- **反向指标**：出现以下任一即为失败——发了邀请但 gate 没过；会上没做决策；行动项有人名无日期或反之；敏感信息进入分发材料；本工作包之外有人被自动发了消息。

2. 若 Q1 写不出具体决策命题 → 走步骤 B 写异步备忘录，本工作包结束。
