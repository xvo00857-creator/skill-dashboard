# deck-product-launch 受约束使用流程方案

> 本方案基于随附 Skill 的真实文件编写，所有结论可对照 `SKILL.md` 与 `example.html` 复核。
> 生成时间：2026-08-12（Asia/Shanghai）。

---

## 0. Skill 能力边界（先于一切）

| 项 | SKILL.md 实际值 | 说明 |
|---|---|---|
| name | `deck-product-launch` | 产品发布 Keynote 模板 |
| category | `slides` | **幻灯片模板类**，非"自动化与工具" |
| scenario | `marketing` | 营销发布场景 |
| aspect_hint | `16:9` | 建议比例 |
| 布局 | Cover → Why we built this → Introducing → Feature cards(3-6) → Pricing tiers → CTA | 见 SKILL.md 第 16-22 行 |
| 设计 | 暗 hero + 亮内容；accent 暖橙→桃渐变 | 见 SKILL.md 第 23-24 行 |
| 交付形态 | 自包含 HTML deck（example.html 为参考实现） | 无后端、无数据抓取、无外部发布能力 |

**与题设的冲突（以文件规则为准）：**
1. 题面称表格分类为"自动化与工具"，但 SKILL.md frontmatter 明确 `category: slides`。本 Skill 不执行自动化流程、不调用外部 API、不创建/删除线上资源。
2. 题面要求"用户旅程、需求澄清、产品验证"——这些**不是 Skill 内置能力**，而是使用该模板产出 deck 前后必须由人完成的环节。本方案把它们设计为模板填充流程的**门禁阶段**，不扩张 Skill 职责。
3. Skill 不提供真实产品数据。任何具体产品名、价格、参数、评价都必须由需求方提供；本方案不编造。

## 1. 用户旅程（使用该 Skill 产出发布 deck 的人）

```
[需求方] 提出发布需求
   │
   ▼
[执行人/AI] 预检 Skill 与环境 ──► 不通过则停止并告知
   │
   ▼
[需求方] 需求澄清会（填写内容清单）──► 人工确认点 A
   │
   ▼
[执行人/AI] 基于模板填充 HTML（只写本地新文件，不改模板原件）
   │
   ▼
[执行人/AI] 自检（结构/设计/文案占位符扫描）
   │
   ▼
[需求方] 预览评审 ──► 人工确认点 B（可回退修改）
   │
   ▼
[需求方] 决定是否发布/分享 ──► 人工确认点 C（本 Skill 不代执行任何外部发布）
   │
   ▼
[交付] 本地 HTML 文件 + 核验报告
```

**关键原则：** Skill 只负责"把已确认的内容套进合规的视觉模板"；内容从哪来、是否真实、能否发布，都由人决定。

## 2. 需求澄清（填充模板前必须确认的清单）

以下任一项缺失，**不得开始填充**，标记为"待确认"并停在人工确认点 A。

| 编号 | 必确认项 | 对应模板位置 | 缺失时的处理 |
|---|---|---|---|
| R1 | 产品名、品牌名、发布日期 | Cover 品牌位 / kicker | 留 `{{产品名}}` 占位，不编造 |
| R2 | 一句话价值主张（≤42ch） | Cover lede | 占位 |
| R3 | "Why we built this"问题陈述 | SKILL.md 要求但 example.html 缺失此页 | **需人工决定**：补一页还是沿用 example 的 8 页结构 |
| R4 | Hero shot（产品图） | Introducing / Cover | example 用 CSS 渐变圆占位；真实图片需提供 URL 或本地文件 |
| R5 | 3-6 个特性：标题+描述+图标 | Feature cards | 缺数据则不生成对应卡 |
| R6 | 定价档：名称/价格/特性清单（≥1 档） | Pricing tiers | 价格不得臆测 |
| R7 | CTA 文案与链接 | CTA 页 | 链接默认 `#`，真实跳转需确认 |
| R8 | 客户评价/背书（可选） | Testimonial | 无真实授权不得使用人名/媒体名 |
| R9 | 语言（中/英） | 全站文案 | 默认跟随需求方 |
| R10 | 字体与离线要求 | Google Fonts 外链 | 离线场景需告知会回退系统字体 |

## 3. 产品验证（产出 deck 后的自检项）

复用本次演示中的核验逻辑（见 `verify_deck.py`），对产出文件做客观检查：

1. **结构**：幻灯片数量、各页 `data-title`、是否覆盖 SKILL.md 布局段落。
2. **设计令牌**：`.tpl-product-launch` 作用域内 `--accent` 为暖橙（本次实测 `#ff5a36`，rgb(255,90,54)）；`--grad` 为橙→桃渐变；不得误用 base.css 的蓝色默认值。
3. **暗/亮节奏**：Cover 为 `dark`；内容页为亮底；CTA 页可为 dark。
4. **占位符扫描**：不得残留 `{{...}}`、`TODO`、`lorem`、示例产品名（除非需求方确认沿用示例）。
5. **外部依赖**：Google Fonts 为外链，离线降级可接受；不得出现未经确认的第三方脚本/追踪。
6. **可打开性**：本地双击可在浏览器渲染；静态预览模式下所有 slide 可见、可打印。
7. **比例**：16:9 下排版不溢出；非 16:9 屏幕允许留白但不得错位。

## 4. 预检、幂等、重试、人工确认点

### 4.1 预检（Pre-flight，开始前必过）
- [P1] 确认 `SKILL.md` 与 `example.html` 存在且可读（本次已确认：27910 字节）。
- [P2] 确认 `category: slides`，不把它当自动化/发布工具使用。
- [P3] 确认输出目录可写；**只写新文件**，不覆盖 `example.html` 与模板原件。
- [P4] 确认需求清单 R1-R10 状态；缺失项列入"待确认"。
- [P5] 确认网络状态：Google Fonts 需联网；离线时接受字体回退。

### 4.2 幂等（Idempotency）
- 输出文件命名带版本/时间戳，例如 `launch-<产品>-vYYYYMMDD-HHMM.html`；重复运行不覆盖已有产物。
- 核验脚本只读不写，可安全重复执行，结果应一致。
- 不修改、不移动、不删除解压出的 Skill 原始文件。
- 同一份内容重复生成，字节级允许差异（时间戳），但结构核验结果必须一致。

### 4.3 重试（Retry）
- 字体加载失败：不重试生成，接受系统字体回退（CSS 已指定 `-apple-system` 等后备字体）。
- HTML 解析/核验失败：重新读取源文件再跑一次脚本；连续 2 次失败则停止并报告，不"改数据让它通过"。
- 浏览器渲染异常：重新打开本地文件一次；仍异常则保留截图作为问题凭证。
- 任何重试都**不得**通过编造内容、跳过检查项来"成功"。

### 4.4 人工确认点
- **A. 内容确认**：R1-R10 清单由需求方签字/回复确认后才填充。
- **B. 预览确认**：产出后在浏览器打开，需求方确认视觉与文案；可回退修改，重跑核验。
- **C. 外部动作确认**：上传、发布、分享、发邮件等任何超出本地文件的动作，必须逐次获得明确指令；本 Skill 本身不具备且不代执行这些动作。

## 5. 本次演示的约束与边界声明

- 本次**仅使用已提供的数据**：`SKILL.md` 与 `example.html`，未联网取产品资料，未编造任何产品事实。
- 未创建、删除、覆盖任何 Skill 外部资源；仅在工作目录新增了核验脚本与本方案文档。
- 未发布、未上传、未发送任何文件到外部系统。
- example.html 中的 "Halo v2"、价格、参数、评价均为**模板自带示例内容**，不代表真实产品，不得直接用于真实发布。
- 已知差异（需人工确认）：
  1. SKILL.md 布局含 "Why we built this（问题）" 页，example.html 实际未包含（核验脚本判定 FAIL）。
  2. example.html 依赖 Google Fonts（8 个字体请求），离线环境字体降级。
  3. slide 本体为 `100vh` 流式布局，未强制固定 16:9 画布；仅缩略图用了 `aspect-ratio:16/9`。
  4. example.html 内联注释显示其页序规划有过调整（第 448 行注释），以实际 8 页为准。

## 6. 可核验的演示结果

见同目录 `verify_deck.py` 运行结果（实测，非编造）：

- 幻灯片总数：**8 张**，顺序 Cover / Introducing / Sound / Fit / Intelligence / How it works / Pricing / Ship。
- 暗背景页：3 张（Cover、Fit、Ship）；其余为亮内容页——符合"暗 hero + 亮内容"。
- 特性卡：5 个；定价档：3 档；CTA 按钮：存在。
- 模板生效主色 `--accent: #ff5a36`（rgb(255,90,54)，暖橙）；`--grad: linear-gradient(120deg,#ff5a36,#ff8c5a 60%,#ffb36b)`（橙→桃）。
- 浏览器渲染截图已确认：暗封面大标题 + 橙桃渐变 hero 圆 + "rewritten." 渐变字；亮内容页特性卡图标为橙桃渐变方块。
- 唯一未通过项：缺少 "Why we built this" 问题页——属模板文件与 SKILL.md 描述的真实差异，已标注待人工决定。
- 核验结论：**19/20 项通过**；example.html 作为模板参考实现可正常渲染，但用于真实产品时需补齐内容并决定是否增加问题页。

