# 书邻计划团队知识库整理方案

> 基于 knowledge-ops Skill v2.8.0 方法论与工具，为"书邻计划"社区图书交换报名系统（8 人跨职能团队、6 周上线）制定的知识库整理方案。
>
> 方案中所有工具输出来自真实执行；未确认项明确标注，不编造数据或已完成动作。

---

## 一、目标与输入

### 1.1 目标

让书邻计划团队的重要信息**可查、可更新、不过期**。具体而言：

- 每个 SOP / Runbook 有**具名负责人**（named owner），不是"团队"。
- 每个 Runbook 步骤有**可观察的成功/失败信号**和**回滚路径**，上线前验证分数 ≥ 80。
- 知识库无孤儿页面（导航根除外）、无术语漂移、无过期文档。
- 建立 12 个月评审节奏，使文档不随项目推进而腐烂。

### 1.2 已知输入（题目事实）

| 项 | 值 |
|---|---|
| 项目 | 书邻计划——社区图书交换报名系统 |
| 团队 | 8 人跨职能团队 |
| 周期 | 6 周内上线 |
| 场地人数上限 | **未确认**（blocking dependency） |
| 交付物 | 可查、可更新、不过期的团队知识库 |

### 1.3 未决输入（需启动会/场地方确认）

- **场地人数上限**：直接阻塞报名确认逻辑、候补触发条件、Runbook 熔断阈值。
- **各文档具名 owner**：题目未提供团队成员姓名，本方案中以角色邮箱占位，需启动会指定真人。
- **技术栈与系统 of record**：报名系统后端/通知渠道尚未在题目中明确，SOP 的 Where 段留空待填。

## 二、依据（Skill 方法论与引用来源）

本方案严格遵循 knowledge-ops Skill 的四步工作流与纪律，核心依据：

1. **5W2H 方法**（Ishikawa 1985）：SOP 必须覆盖 Who / What / When / Where / Why / How / How-much 七段，缺一段即为不完整。
2. **Runbook 六属性**（Google SRE Workbook Ch.8; AWS Well-Architected OPS04-BP02）：每步骤必须具名 owner、具体时长、可观察成功信号、可观察失败信号、回滚路径、升级联系人。
3. **Checklist 纪律**（Gawande 2009, *The Checklist Manifesto*）：无具名 owner 的文档 12 个月内必然腐烂；owner 是文档不腐烂的免疫系统。
4. **受控文档评审**（ISO 9001:2015 §7.5.3）：受控文档需 last-reviewed 日期与评审周期。
5. **Runbook 衰减**（Majors 2022, *Observability Engineering*）：12 个月未触碰的 Runbook 60% 是错的，故 stale 阈值默认 365 天。
6. **Happy-path-only 反模式**（Fowler 2016, *Production-Ready Microservices*）：只写正常路径的文档导致 60%+ 事故时间浪费。
7. **孤儿页面率**（Atlassian Team Playbook）：orphan rate > 20% 是 wiki 蔓延的首要信号。

## 五、优先级排序

按 Skill 纪律（owner 优先 > 阻塞项 > 安全项 > 卫生项）排序：

| 优先级 | 事项 | 依据 | 负责人 |
|--------|------|------|--------|
| **P0** | 启动会指定各文档具名 owner（真人，非角色） | Gawande：无 owner 文档 12 个月内 100% 腐烂 | 项目负责人 |
| **P0** | 确认场地人数上限 | 阻塞 SOP Step 2、Runbook Step 4、系统名额配置 | 项目负责人+场地方 |
| **P1** | 修复 Runbook Step 1 的 5 个 MUST-FIX，使总分 ≥ 80 | SRE Workbook：< 60 分 NOT-SAFE，上线前必须 ≥ 80 | 运营负责人 |
| **P1** | 填充 SOP How 段 6 步骤的 owner/duration/signal/rollback | 5W2H 七段必须完整；生成器只出脚手架 | 运营负责人 |
| **P1** | SOP 补充 top-2 失败模式（如：用户重复报名、通知发送失败） | Fowler 2016：happy-path-only 导致 60%+ 事故时间浪费 | 运营负责人 |
| **P2** | glossary.md 补充 SOP/Runbook 等术语定义 | ingester 检出 glossary candidate | 项目负责人 |
| **P2** | 确认 index.md 作为导航根接受 orphan 状态，或从其他页加反链 | Atlassian：orphan > 20% 才是问题，当前 16.7% 且 index 是根 | 项目负责人 |
| **P3** | 填充 SOP Where 段（系统 of record、支撑工具） | 依赖技术栈确认 | 技术负责人 |

## 六、关键取舍

| 取舍 | 选择 | 理由 |
|------|------|------|
| Profile 选择 | `ops` 而非 `regulated` | 社区图书交换不涉及 PHI、财务控制、受监管器械；报名收集的姓名/联系方式不构成 Skill 定义的 regulated overlay。若后续涉及未成年人信息或支付，需重新评估。 |
| Owner 占位 | 用角色邮箱而非编造人名 | 题目未提供团队成员姓名；Skill 严禁编造，且 forcing question 1 要求 owner 必须是同意承担的真人。 |
| 场地人数上限 | 不硬编码默认值，SOP Step 2 标注阻塞并升级 | 编造数字会导致上线后超员或名额浪费；Skill 要求不编造数据。 |
| Orphan 处理 | 不删除 index.md | Skill 反模式："不要把 orphan 当垃圾"——index 是导航根，被搜索和直接访问找到即可。 |
| Runbook 中文信号 | 接受 validator 对中文的启发式局限，人工复核 | validator 的 observable hints 和动词正则基于英文；中文"显示""收到""状态变为"是可观察的，但工具不识别。不因此改写为别扭的英文。 |
| 不批量生成 SOP | 只为最核心流程（报名审核）生成一个 SOP | Skill 反模式："不要批量生成无 owner 的 SOP"——8 人团队 6 周周期，先保证核心 SOP 有 owner 且完整，再扩展。 |
| Validator 不当 checkbox | 60 分不停留在"及格" | Skill 反模式："validator 抓结构缺失，不抓内容错误"——60 分只是结构分，上线前必须到 80 且人工审内容。 |

## 七、风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 场地人数上限迟迟不确认 | 报名确认逻辑无法实现，6 周周期后段被迫延期 | SOP Step 2 已设阻塞升级路径；若上线前 2 周未确认，先用保守值 30 人标注"待调整"（见 venue-capacity.md） |
| Owner 不指定或指定后不知情 | 文档无人维护，12 个月内腐烂（Gawande 数据） | 启动会必须指定真人并获得书面同意；frontmatter 写邮箱 |
| Runbook < 80 分上线 | 事故时操作员无法判断步骤是否成功，延长恢复时间 | 上线前卡点：所有 runbook 必须 ≥ 80；Step 1 的 RED 必须修 |
| 6 周周期压缩文档时间 | SOP/Runbook 停留在脚手架状态未填充 | 将文档填充纳入 DoD（Definition of Done），每个功能交付时对应 SOP 步骤已填 |
| 中文 runbook 误判为不可观察 | 团队过度信任工具分数，忽视实际可观察性 | 人工复核 Step 2-5 的中文信号；工具分数是结构检查非内容审批 |
| 术语漂移（如"报名确认"vs"报名成功"混用） | 新成员和用户理解不一致 | glossary.md 已建，ingester 可定期扫描；新增术语必须先入 glossary |

## 八、衡量方式

Skill 强调衡量"unfindable docs"和"unsafe runbooks"，而非页面数量。本项目的核心指标：

| 指标 | 目标 | 当前值 | 衡量方法 |
|------|------|--------|----------|
| Unsafe runbooks（validity < 60） | 0 | 0（当前 60，刚好 ≥ 60） | `runbook_validator.py` 总分 |
| Runbooks ≥ 80 分（上线前） | 100% | 0% | 同上 |
| Missing-owner pages | 0 | 0 | `kb_ingester.py` |
| Orphan rate（导航根除外） | < 20% | 0%（index 除外） | `kb_ingester.py` |
| Stale pages（> 365 天未评审） | 0 | 0 | `kb_ingester.py` |
| Glossary drift | 0 | 0 | `kb_ingester.py` |
| SOP 5W2H 完整度 | 7/7 段填充 | 5/7（How/Where 待填） | 人工检查 + `sop_generator.py` 验证 |

**上线前卡点**：unsafe runbooks = 0 且所有 runbook ≥ 80；missing owner = 0；场地人数上限已确认并写入 SOP/Runbook。

   - 全量运行三个工具
   - 人工审阅内容正确性（validator 不查内容对错）

   - 每 12 个月运行 `kb_ingester.py` 做卫生扫描
