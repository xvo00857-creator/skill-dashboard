# 交付说明：Button 与 Tabs 组件

## 一、交付物清单

| 文件 | 说明 |
|------|------|
| `src/utils.ts` | 轻量 `cn()` 类名合并工具（若项目已有同类工具可删除） |
| `src/Button.tsx` | 按钮组件：三种变体、三种尺寸、加载态、图标插槽、forwardRef |
| `src/Tabs.tsx` | 复合组件 Tabs / Tabs.List / Tabs.Tab / Tabs.Panel，支持受控与非受控 |
| `src/components.css` | 原生 CSS 样式：交互状态、焦点环、响应式断点、CSS 变量主题 |
| `src/example-usage.tsx` | 使用示例（可删除） |
| `demo.html` | 独立可运行演示，双击即可在浏览器打开，无需安装任何依赖 |

---

## 二、最小改动方案

1. 将 `src/` 下的 4 个文件（`utils.ts`、`Button.tsx`、`Tabs.tsx`、`components.css`）复制到既有 React + TypeScript 项目的组件目录中。
2. 若项目中已存在 `cn` 工具（如 `@/lib/utils`），删除 `utils.ts`，将 `Button.tsx` 和 `Tabs.tsx` 中的 `import { cn } from "./utils"` 改为项目已有的导入路径。
3. 样式通过 `import "./components.css"` 引入；若项目使用 CSS Modules，可将文件重命名为 `components.module.css` 并将类名改为 `styles.btn` 等形式，或直接将样式合并进全局样式表。
4. **不新增任何 npm 依赖**，不升级 React 主版本。组件仅使用 React 18 内置 API（`forwardRef`、`useId`、`useContext`、`useCallback`、`useState`、`createContext`）。
5. 组件通过 `className` 和 `...props` 透传支持外部样式与属性覆盖，不破坏既有接口。

## 六、约束如何改变了实现选择

| 约束 | 影响 |
|------|------|
| 不能引入未经批准的新依赖 | 未使用 `class-variance-authority`、`clsx`、`tailwind-merge` 等库，变体通过手写 `cn()` 函数 + CSS 类名拼接实现 |
| 不能升级主版本 | 仅使用 React 18 兼容 API（`forwardRef`、`useId`、`useCallback` 等），未使用 React 19 特性 |
| 兼容既有接口和目录结构 | 组件通过 `...props` 透传所有原生属性，`className` 可外部覆盖；`cn` 工具可替换为项目已有实现；样式可合并进全局表 |
| 零运行时样式方案 | 选用原生 CSS（零运行时开销），而非 styled-components / Emotion（有运行时）或 Tailwind（需构建配置） |
| Skill 要求同时支持受控与非受控 | Tabs 组件同时实现 `value/onValueChange`（受控）和 `defaultValue`（非受控），通过 `isControlled` 判断 |
| Skill 要求 forwardRef | Button 使用 `forwardRef` 包裹，允许父组件获取底层 button 节点 |
| Skill 无障碍要求 | Tabs 实现完整 ARIA 角色与属性、roving tabindex、键盘方向键/Home/End 导航；Button 实现 `aria-busy`、`:focus-visible` 焦点环 |

## 七、实际读取的 Skill 文件

以下文件均来自解压后的 `web-component-design` Skill 目录（相对路径基于 Skill 根目录）：

1. `SKILL.md` — 主文件，包含组件 API 设计原则、最佳实践、CSS 方案对比
2. `references/component-patterns.md` — 复合组件、Render Props、受控/非受控、forwardRef 等模式
3. `references/accessibility-patterns.md` — Modal/Dropdown/Combobox/FormField 等无障碍模式与键盘交互
4. `references/css-styling-approaches.md` — CSS Modules、Tailwind+CVA、styled-components、Emotion、Vanilla Extract 对比

### 实际影响交付结果的 SKILL.md 规则

**SKILL.md「Best Practices」第 4 条："Controlled vs Uncontrolled: Support both patterns when appropriate."**

这条规则直接决定了 Tabs 组件的 API 设计：组件同时接受 `value` + `onValueChange`（受控模式）和 `defaultValue`（非受控模式），内部通过 `isControlled = value !== undefined` 判断当前模式，受控时不更新内部 state 仅调用回调，非受控时更新内部 state。两种模式共用同一套 Context 和子组件，调用方按需选择。

此外，SKILL.md「Component API Design」中"语义化 prop 名（如 `isLoading` 而非 `loading`）"、"始终支持 `className` / `style` 覆盖"、"使用 `forwardRef` 转发 DOM"等原则均体现在 Button 组件的实现中。SKILL.md CSS 方案表中 CSS Modules 标注的"Zero runtime / Minimal / Existing CSS, gradual adoption"直接影响了样式方案选择——采用零运行时原生 CSS，不引入 CSS-in-JS 库。
