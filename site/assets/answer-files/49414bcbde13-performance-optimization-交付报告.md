## 四、可扩展数据处理方案

> 说明：以下方案是把 SKILL.md 的"先度量—定位—修复—验证—防护"纪律**迁移**到数据质量场景的工程设计，不是 SKILL.md 原文规定的数据规程。SKILL.md 本身不提供数据清洗步骤。

### 4.1 设计原则（SKILL.md 规则 → 数据处理映射）

| SKILL.md 规则（原文要点） | 在数据处理中的映射 |
|---|---|
| Measure before optimizing；没有证据不要优化 | 清洗前先做数据画像建立基线，不凭感觉动手 |
| Identify the actual bottleneck, not assumed | 用统计证据区分"真重复/真缺失/真异名"与"看起来像" |
| Change one thing at a time | 每条清洗规则单独上线、单独度量，可归因、可回滚 |
| Correctness gates the metric | 不为让汇总数"好看"而丢记录、把未知填 0、强行合并门店 |
| "Neutral" is a revert；log every attempt | 无效规则回滚；所有规则（含回滚）记入台账，防止重复试错 |
| Verify the same way as baseline | 清洗后用同一套画像脚本复跑，前后对比守恒 |

### 4.2 处理流水线（五个阶段，可扩展、可重跑）

**阶段 0：接入与分区（SCALE）**
- 按 `日期 + 门店` 分区落盘（Parquet 或分区表），避免单文件过大。
- 用 polars / pyarrow 或数据库批量 SQL 处理；禁用逐行 Python 循环；门店别名映射表为小表，用 broadcast join。
- 每批记录批次号、输入行数、源文件指纹（sha256），保证可追溯、幂等。

**阶段 1：度量基线（MEASURE）——对原始数据出画像，不修改任何值**
- 总行数、订单数、时间范围。
- 每列缺失率（NULL 与空字符串分开统计）。
- `order_id` 重复计数：完全重复行 vs 同 ID 不同内容。
- 门店名称 distinct 数；按可逆标准化键（trim + 全半角统一 + 大小写统一 + 去标点）聚合后的疑似别名簇。
- 数值列（金额/数量）的 min/max/分位数、负值与零值计数。
- 产出 `profile_raw.json` 作为基线。

**阶段 2：识别异常（IDENTIFY）——只标记不修复，产出异常清单**
- A. 重复订单：以 `order_id` 为主键，分"完全重复"与"同 ID 内容冲突"两类。
- B. 门店名称不一致：先做可逆标准化再聚簇；簇内是否同一门店须经映射表确认，**不自动合并**。
- C. 缺失值：区分"结构上允许为空"与"应有却缺失"；金额/数量为 NULL 记为未知，**不填 0**。
- D. 格式/越界：非法日期、负数量、金额落在分位数异常区间，进人工复核队列。
- 产出 `anomalies.csv`（每条异常带类型、严重度、定位键、原始值）。

**阶段 3：修复（FIX）——每条规则独立、可配置、可回滚**
- 门店名：确定性标准化（trim/全半角/大小写）自动应用；别名合并仅依据**版本化映射表** `store_alias_map.csv`（字段：canonical_id、variant、source、confirmed_by、confirmed_at）；未命中进 quarantine，不静默合并。
- 去重：完全重复保留 1 行（按 `updated_at` 取最新；无时间戳则保留首行并记录策略）；同 ID 内容冲突不自动删，进复核队列。
- 缺失值：NULL 保持 NULL；聚合用 NULL-safe 语义（sum 跳过 NULL、count 区分 `count(*)` 与 `count(列)`），结果表中单独列示有效样本量 `n`；0 仅在原始值确为 0 时使用。
- 每条规则有独立开关与版本号，写入台账。

**阶段 4：验证（VERIFY）——同脚本复跑，前后守恒**
- 用阶段 1 同一脚本对清洗后数据出 `profile_clean.json`。
- 守恒核对：清洗后金额合计 = 原始合计 − 被移除/隔离记录金额（逐笔可对）；订单数变化可逐条解释（去重 N 条、隔离 M 条）。
- 抽样核对：每类异常抽 ≥5 笔或 1%（取大），脚本/人工双验，记入 `sample_check.csv`。
- 任一守恒断言失败或抽样错误率超阈值 → **回滚该规则**（对应 SKILL.md："Improved, but a test went red → Revert"）。

**阶段 5：防护（GUARD）**
- 把画像断言固化为流水线测试：`order_id` 唯一性、门店名全部命中映射表、NULL 未被填 0 等。
- 每次数据更新重跑；新增异常自动进复核队列。
- 台账 `rules_ledger.csv` 永久保留，含已回滚规则，防止同一无效做法下次再试。

### 4.3 扩展性要点
- 流式/分块读取，内存占用恒定；小表广播 join。
- 规则与代码分离（映射表、阈值配置化），新增门店或规则无需改代码。
- 幂等：以批次号 + 输入指纹去重，重跑不产生重复结果。
- 全链路血缘：每个输出值可追溯到原始行与所应用规则版本。
