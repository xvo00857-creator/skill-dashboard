# 高管教练工作单：当战略工作总被救火挤占

> 角色：Executive Mentor（对抗性思考伙伴，不是安慰者）
> 对象：新任产品负责人
> 困境：战略工作（重要不紧急）持续被救火（紧急不重要 / 紧急且重要）挤占
> 日期：2026-08-10（周一）
> 用法：本文档是一次 60–90 分钟自我教练会话的脚本。**加粗的问题必须自己写答案**，不要跳过。空着的表格就是你的家庭作业。

---

## 0. Bottom Line（先给结论）

🔴 **假设**：你不是"没时间做战略"，你是**在用救火逃避战略**——因为战略思考会逼你回答几个你还没准备好回答的问题（方向对不对、资源够不够、要不要砍掉某些东西、要不要和上级谈预期）。救火给你一种"我在干活"的道德优越感，让你可以推迟那些真正困难的判断。

如果这个判断错了，那是好消息——下面的诊断会很快证伪它。如果对了，那也是好消息——因为问题是可解的，但解不在时间管理里，在**你愿不愿意做几个硬决定**里。

> 信心：🟡 medium（基于"新任 + 战略被挤占"这一典型模式的通用判断；需你用第 1 节的答案确认或推翻）

---

## 1. 目标澄清（Goal）——你到底要什么

先别急着排日程。回答这些问题，**写下来**，不要在脑子里"大概清楚"。

### 1.1 战略北极星

| # | 问题 | 你的答案 |
|---|------|---------|
| G1 | 90 天后，如果你"战略工作做到位了"，**具体会发生什么**？哪 3 件事会不一样？（不是"想清楚方向"这种虚词——是可观察的结果，比如"Q4 路线图已对齐到 X 业务目标并获上级签字"、"团队不再为优先级吵架"、"砍掉了 2 个低 ROI 项目释放出 30% 人力"） | |
| G2 | 这 3 件事里，**哪一件不做，6 个月后你会被解雇 / 被替换 / 业务明显掉队**？（这是你真正的战略优先级——其他都是装饰） | |
| G3 | 你**上级**（徐峰或你的汇报对象）认为你这个季度最重要的 1 件事是什么？和你 G2 的答案一致吗？如果不一致，你们谈过吗？ | |
| G4 | 你**团队**认为你这个角色最该提供的是什么？（方向？决策？资源？保护？）你上一次问他们是什么时候？ | |

### 1.2 反目标（Pre-mortem）——假设 90 天后你失败了

🔴 假设：现在是 2026-11-10，你回头看，发现这 90 天战略工作几乎没推进。**最可能的 3 个原因是什么？** 不要写"被打扰"这种外部借口——写你自己的行为/选择。

| # | 失败原因（pre-mortem） | 最早的预警信号是什么？ | 现在最便宜的对冲动作是什么？ |
|---|----------------------|----------------------|--------------------------|
| F1 | | | |
| F2 | | | |
| F3 | | | |

> 教练提示：常见答案长这样——"我没和上级谈清楚优先级，所以什么都接"、"我没授权，下属升级的事我都自己处理"、"我把'忙'当成了'有产出'"。如果你的答案全是外部因素（其他团队、上级、客户），你还没开始诚实。

## 2. 约束识别（Constraints）——什么在真的限制你

区分**真实约束**和**你以为的约束**。这一节的目的是把"我没时间"这个模糊抱怨拆成可操作的具体项。

### 2.1 时间审计（先量再管）

🔴 假设：你**没量过**自己的时间。在量之前，任何"我被 X 占了 Y%"的说法都是故事，不是事实。

**本周必做**：连续 3 个工作日，每 30 分钟记一次你在做什么（用日历、备忘录、番茄钟都行）。然后分类：

| 类别 | 定义 | 实际占比（你猜） | 实际占比（量完后填） |
|------|------|----------------|-------------------|
| A. 真救火 | P0 事故、线上故障、关键客户/上级当天必须回应 | __% | __% |
| B. 假救火 | "紧急"但不做也不会出事的事（被拉进的会、可委派的答疑、可异步的同步） | __% | __% |
| C. 战略思考 | 路线图、方向判断、资源取舍、关键人事、向上对齐 | __% | __% |
| D. 深度执行 | 你作为负责人**必须**亲自做的设计/评审/决策 | __% | __% |
| E. 管理/1:1/团队 | 人员培养、反馈、招聘 | __% | __% |
| F. 其他 | 邮件、IM、行政 | __% | __% |

**判断标准**：
- 如果 A（真救火）> 30%，你的系统/团队设计有结构性问题，不是时间管理问题——跳到 2.3。
- 如果 B（假救火）> 20%，问题在你**不会说不 / 不会委派 / 怕错过**——跳到 2.2 和第 3 节。
- 如果 C（战略）< 15%，无论你怎么"挤时间"都救不了——这是优先级和授权问题，不是日历问题。

### 2.2 你在回避什么（The Hard Thing）

🟡 通用模式：新任负责人用"忙"来回避几个具体的硬对话。对照检查：

| 你在回避的硬对话 / 硬决定 | 是 / 否 / 部分 | 如果是，你在等什么？ |
|--------------------------|---------------|-------------------|
| 告诉上级"我接不了这么多，我们得砍" | | |
| 把某类决策彻底授权给下属（并接受他们会犯错） | | |
| 把某个表现不达标的人放到 PIP 或换岗 | | |
| 砍掉一个你或团队投入很多但战略上不该继续的项目 | | |
| 和某个强势的跨部门 partner 划清边界 | | |
| 承认你现在的方向可能错了，需要重新想 | | |

> Skill 原则（来自 hard_things.md）：**多数领导者行动得太晚。到你行动时，团队其他人早就知道问题在哪了。** 如果你对上面任何一项的反应是"我再观察观察"，问自己这个魔法问题：
>
> **"如果这个人/项目/问题明天 magically 消失，我会松一口气还是会想念？"** 如果是松口气——你已经知道答案了。

### 2.3 结构性约束（如果真救火 > 30%）

🔴 假设：如果你的时间真的被 P0 占了大头，根因通常是以下之一。对照打勾：

- [ ] 团队 on-call / 升级路径设计有问题，所有事都升级到你这
- [ ] 你是唯一知道某块系统/业务上下文的人（bus factor = 1）
- [ ] 质量/稳定性债没还，所以天天炸
- [ ] 你没明确"什么才算 P0"的标准，团队把"重要"当"紧急"
- [ ] 上级或关键客户习惯直接找你，绕过你的团队

每一项对应的动作都不同——但共同的第一步是：**把"减少 A 类时间"本身当成一个战略项目来做**，而不是期望它自己变好。

## 3. 选项生成（Options）——你能做什么

下面是 4 个典型应对路径。**不要选"全都做"——那等于没选。** 用决策矩阵打分（脚本：`scripts/decision_matrix_scorer.py`，可 `--interactive` 或 `--file`）。

### 3.1 四个候选选项

| 选项 | 它是什么 | 它隐含的硬决定 |
|------|---------|--------------|
| **O1. 锁日历** | 每周固定 2 个 3 小时"战略块"，写进日历，像对待董事会一样捍卫它；其他时间留给反应式工作 | 你愿意在这些时段**真的不看 IM/邮件**，并让团队知道"这几个小时天塌了也找 XX 不找我" |
| **O2. 授权 + 升级路径重设计** | 明确哪些决策下属可以自己做，哪些必须升级；建立 on-call / DR1 轮换；你只处理真正升级到你的事 | 你愿意接受下属做的决定和你做的不一样，并忍住不事后诸葛亮 |
| **O3. 向上重新谈判 scope** | 找上级谈："这季度我能交付 X，但 Y 和 Z 需要推到下季度或加人，否则三件都做不好。" | 你愿意承认你**不是**无限产能，并接受上级可能的失望/质疑 |
| **O4. 砍项目 / 砍人事** | 停掉 1–2 个低 ROI 项目释放人力；处理掉那个你已经"在观察"3 个月的人 | 你愿意承受短期的难受和关系成本 |

### 3.2 决策矩阵模板（用你自己的权重和分数替换示例）

> 下面的分数是 🔴 **示例**（基于通用经验，不是你的真实情况）。请用 `python3 scripts/decision_matrix_scorer.py --interactive` 输入你自己的评分。
>
> 评分 1–10；权重之和 = 1.0。

**建议的 5 个评判维度**（你可以改）：

| 维度 | 示例权重 | 它在问什么 |
|------|---------|----------|
| 90 天战略产出影响 | 0.30 | 这个选项能多大程度把 C 类时间拉到 > 25%？ |
| 执行可行性（你能在 2 周内启动） | 0.20 | 你真的会做吗？还是又会"下周开始"？ |
| 对团队的影响（10 = 正向） | 0.15 | 团队会更有方向感还是更焦虑？ |
| 对你个人精力的可持续性 | 0.20 | 3 个月后你是更有劲还是更 burnout？ |
| 与上级期望的对齐度 | 0.15 | 上级会支持还是会阻挠？ |

**示例评分（🔴 假设，仅作格式示范，请替换）**：

| 维度 | O1 锁日历 | O2 授权 | O3 向上谈判 | O4 砍项目/人 |
|------|---------|--------|-----------|------------|
| 战略产出影响 | 5 | 7 | 8 | 9 |
| 执行可行性 | 8 | 5 | 4 | 3 |
| 团队影响 | 6 | 8 | 5 | 4 |
| 个人可持续性 | 6 | 8 | 7 | 7 |
| 上级对齐 | 5 | 6 | 9 | 6 |

> 用脚本跑一下你自己的版本。注意 sensitivity analysis——如果某个维度权重 ±20% 就翻盘，说明你**其实还没想清楚**什么最重要，回到第 1 节。

### 3.3 对抗性压力测试（Stress-test）

在你选定一个选项前，回答：

1. **如果这个选项 6 周后失败了，最可能怎么失败？** （不是外部原因——是你自己会怎么破坏它：比如"我会破例在战略块接上级电话"、"我会忍不住又插手下属的决策"）
2. **你的团队里谁会不喜欢这个选项？为什么？他们的反对里有多少是合理的？**
3. **这个选项需要你**停止**做什么？** （每个"开始做"都对应一个"停止做"——否则就是在加任务而不是在做选择）

### 3.4 干系人地图（Stakeholder Map）

用 `python3 scripts/stakeholder_mapper.py --interactive` 把下面这些人（和你自己想到的人）按 influence / alignment 打个分：

- 你的直接上级
- 你团队里的 2–3 个核心下属（包括那个你"在观察"的）
- 你最常被拉进救火的跨部门 partner
- 你团队的产品/设计/研发/数据对口 lead
- （如果适用）关键客户或业务方接口人

**重点看**：
- 谁是 🔴 high-influence / low-alignment 的 blocker？你不先和他们谈，任何选项都会被拖死。
- 谁是 high-influence / high-alignment 但你没激活的 champion？他们可以帮你扛事。
- 谁是 swing vote？一杯咖啡的事。

## 6. How to Act（怎么用这份文档）

1. **今天（周一）**：花 30 分钟，把第 1 节（G1–G4）和 1.2（pre-mortem）填了。不要追求完美——写第一反应。
2. **周二到周四**：做时间审计（2.1）；跑决策矩阵（3.2）；发起那个你在回避的对话（4.1 #5）。
3. **周五**：和上级对齐（4.1 #3）；周末前回看本周，填 4.2（不做清单）。
4. **下周一**：用 4.3 的触发条件检查——如果信号出现，重新走一遍第 2 节。

> 记住：**这份文档的价值不在它写了什么，在你回答了什么。** 空着的表格就是你的行动项。

### 影响结果的具体规则

1. **Voice 规则**（SKILL.md L46–56）：direct, uncomfortable when necessary, not mean — honest。所以本文用了"你在逃避战略"、"如果答案全是外部因素你还没诚实"、"你已经在做你一直在做的事"这类表达，而不是温和的时间管理建议。
2. **Adversarial reasoning**（SKILL.md L125–127）："Assume the plan will fail. Find the three most likely failure modes... Never say 'this looks good' without finding at least one risk."——这直接产生了第 1.2 节的 pre-mortem 和第 3.3 节的 stress-test。
3. **输出格式**（SKILL.md L135）：Bottom Line → What (with confidence) → Why → How to Act → Your Decision——本文档第 0、1–3、4、6、7 节严格对应这个结构。
4. **信心标签**（SKILL.md L136）：🟢 verified / 🟡 medium / 🔴 assumed——全文所有判断都打了标签，第 5 节集中说明了假设和未知，避免编造用户的具体事实。
