## 一、流程总览

```
预检（环境/依赖/权限/网络）
  → 幂等检查（输出目录/今日文件）
  → 人工确认点①（确认执行范围）
  → 采集（点众公开页 / 黑岩需登录）
    ├─ 点众：自动采集，失败重试≤2次
    └─ 黑岩：人工确认点②（登录），未登录则 SKIP
  → 质量门（脚本内置 + 人工抽检）
  → 分析（仅基于真实采集数据，历史数据标注为候选假设）
  → 输出报告（标注样本日期/可信度/复扫时间）
```

## 三、幂等设计

1. **输出目录隔离**：所有产物写入 `./scan-output/`，不写入 Skill 目录或系统目录。
2. **文件命名去重**：按脚本内置规则 `{平台}{类型}_{YYYYMMDD}.md`，同一榜单同一天只保留一份。
3. **写前检查**：执行前检查输出目录是否已有今日文件：
   - 不存在 → 正常采集
   - 已存在 → 暂停，提示"今日已采集，是否覆盖？"（人工确认点③）
4. **日期戳取本地日**：脚本使用 `localDateStamp()` 取北京时间日期，避免 UTC 日期导致文件名回退到昨天（cdp-utils.js 第 178–192 行的明确规则）。
5. **不删除任何文件**：失败重试不清理已有产物；SKIP 的平台不产生空文件。

**本次执行**：输出目录为空，无今日文件，直接采集，未触发覆盖确认。

## 四、重试策略

| 场景 | 最大重试 | 策略 |
|------|----------|------|
| 点众页面打开失败/超时 | 2 次 | 重新 open + 等待 3 秒后重试 |
| 点众提取 0 条 | 2 次 | 重新加载页面，等待更久（6 秒），再执行提取 |
| 点众书名解析率 <50% | 0 次（不重试） | 脚本质量门判定为结构异常，输出带 `[书名解析异常]` 标记的文件，提示人工确认页面结构 |
| 黑岩 401 未授权 | 0 次 | 停止，提示重新登录（人工确认点②） |
| 黑岩单页超时 | 0 次（跳过该页） | 脚本跳过出错页，已有数据继续处理 |
| agent-browser ENOENT | 1 次 | 修正 PATH 后重试（本次实际发生：PATH 指向包 bin 目录而非 npm global bin，修正后成功） |

**本次执行**：

- 女频：首次 0 条（AJAX 时序），第 1 次重试仍 0 条，第 2 次重试成功（10/10）
- 黑岩：未登录，直接 SKIP，未重试

## 六、不做的事（约束边界）

- 不创建、删除、覆盖 Skill 目录之外的任何文件（输出目录除外）
- 不尝试绕过黑岩登录（不伪造 token、不使用他人凭证）
- 不采集 SKILL.md 未列出的平台（知乎/七猫/番茄无脚本支持，不臆造数据）
- 不将 `references/real-market-data.md` 中的历史数据当作当前市场事实
- 不修改脚本源码来"修复"采集问题（女频时序问题通过重试解决，未改脚本）
- 不静默安装依赖（agent-browser 从已有会话目录定位，未执行 npm install）
