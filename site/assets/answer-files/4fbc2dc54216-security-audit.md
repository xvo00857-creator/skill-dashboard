## 2. 风险分级 Finding

### F-1　数据库异常导出（疑似令牌滥用导致的数据外泄）

- **风险等级**：**严重（Critical）**
- **位置**：`incident_log.csv` 第 6 行（数据行第 5 条），`2026-08-12T09:07:30Z`，system=`db`，event=`unexpected_export`，user=`unknown`，source_ip=`203.0.113.8`
- **证据 / 数据流（人工验证）**：
  - 同一 IP `203.0.113.8` 在 **3 分 28 秒前**（09:04:02）刚触发 `api` 层 `high` 级 `token_scope_mismatch`（service-a 令牌作用域不匹配）。
  - 随后该 IP 在 `db` 层触发 `unexpected_export`，且操作者为 `unknown`——说明导出操作未绑定到有效身份，与前一步令牌作用域异常在时间、来源上强关联。
  - 合理推断链路：**服务令牌作用域校验失败/被绕过 → 使用该令牌访问数据库并执行未授权导出 → 数据外泄**。仅凭日志无法确认是否已成功落盘外带，故定性为"疑似已发生外泄"，需立即核查。
- **CWE / ATT&CK**：CWE-863 Incorrect Authorization、CWE-285 Improper Authorization；ATT&CK T1078 Valid Accounts（服务账号）、T1537 Transfer Data to Cloud Account / T1020 Automated Exfiltration
- **修复建议**：
  1. 立即吊销/轮换 `service-a` 令牌，核查该令牌在 09:04–09:10 的全部调用记录与导出内容范围。
  2. 数据库导出接口强制二次鉴权与审批，导出操作必须绑定可审计的真实身份（禁止 `unknown`/匿名）。
  3. 服务令牌启用最小权限与作用域强校验，`scope_mismatch` 应直接拒绝并告警，而非仅记日志放行。
  4. 对导出量、导出时间窗设置基线与异常阈值告警。

### F-2　服务账号令牌作用域不匹配

- **风险等级**：**高（High）**
- **位置**：第 5 行，`2026-08-12T09:04:02Z`，system=`api`，event=`token_scope_mismatch`，user=`service-a`，source_ip=`203.0.113.8`
- **证据 / 数据流（人工验证）**：
  - 服务账号 `service-a` 持有的令牌请求了超出其允许作用域的资源/操作，API 层识别为 `high` 级事件。
  - 该事件是 F-1 的前置可疑动作：同一来源 IP 在数分钟内从"作用域越权"推进到"数据库异常导出"，构成攻击链而非孤立告警。
  - 注意：日志未记录该次 mismatch 后请求是被拒绝还是放行——这是关键缺口（见修复建议第 1 条）。
- **CWE / ATT&CK**：CWE-269 Improper Privilege Management、CWE-863；ATT&CK T1078.001 Valid Accounts: Service Accounts
- **修复建议**：
  1. 确认 `token_scope_mismatch` 的处置动作是**拒绝请求**（fail-closed），若当前仅告警未拦截需立即改为拒绝。
  2. 服务令牌按用途细分作用域，禁止"一牌多用"；建立令牌清单与定期轮换/审计机制。
  3. 对同一服务账号短时间内连续 scope mismatch 触发自动熔断/封禁来源 IP。

### F-3　管理员账户短时连续登录失败（暴力破解迹象）

- **风险等级**：**中（Medium）**
- **位置**：第 3、4 行，`09:03:45Z` 与 `09:03:49Z`，system=`web`，event=`login_failed`，user=`admin`，source_ip=`198.51.100.23`
- **证据 / 数据流（人工验证）**：
  - 同一 IP `198.51.100.23` 在 **4 秒内**对 `admin` 账户连续 2 次登录失败，频率符合自动化撞库/暴力破解特征。
  - 样本仅 2 次，未达常见锁定阈值，单凭日志不能判定攻击成功；但 admin 为高价值账户，应作为早期预警处置。
  - 该 IP 与后续 F-1/F-2 的 `203.0.113.8` 不同，暂未发现直接关联。
- **CWE / ATT&CK**：CWE-307 Improper Restriction of Excessive Authentication Attempts；ATT&CK T1110 Brute Force
- **修复建议**：
  1. 对 admin 等特权账户启用登录失败限速与账户锁定/二次验证（MFA）。
  2. 对 `198.51.100.23` 做历史回溯，确认是否存在更长时间窗口内的持续尝试。
  3. 管理员登录强制走独立入口与 MFA，禁止公网直连管理面。

### F-4　畸形日志记录（日志完整性/管道缺陷）

- **风险等级**：**中（Medium）**
- **位置**：第 7 行，`2026-08-12T09:09:00Z`，system=`web`，event=`malformed_record`，severity/user/source_ip 均为空
- **证据 / 数据流（人工验证）**：
  - 该记录严重度、用户、来源 IP 三个关键字段全部缺失，仅时间戳、系统、事件类型有值。
  - 两种可能：(a) 日志采集/解析管道故障导致字段丢失；(b) 攻击者注入畸形记录以干扰审计或掩盖痕迹。发生在 F-1 之后约 1.5 分钟，时间上可疑，但无更多证据支持恶意注入。
  - 无论哪种原因，关键字段缺失都会削弱审计与告警有效性。
- **CWE / ATT&CK**：CWE-117 Improper Output Neutralization for Logs、CWE-778 Insufficient Logging；ATT&CK T1070 Indicator Removal（若确认为伪造）
- **修复建议**：
  1. 在日志采集端对 severity/user/source_ip 等关键字段做非空校验，畸形记录单独入死信队列并告警。
  2. 对写入日志的用户输入做转义/长度限制，防止日志注入。
  3. 核查 09:09 前后 web 系统与采集管道状态，区分是管道故障还是人为注入。

### F-5　正常登录（基线，无风险）

- **等级**：**信息（Info）**
- **位置**：第 2 行，`09:00:12Z`，alice 从 `192.0.2.10` 登录成功。
- **说明**：作为正常基线记录，未见异常；IP 与其他告警无关联。

## 3. 攻击链关联结论

`203.0.113.8` 在 9 分钟窗口内呈现 **"服务令牌越权（high）→ 数据库异常导出（critical，身份 unknown）"** 的递进关系，是本次审计最核心的风险结论：**高度疑似 service-a 服务令牌被滥用，导致未授权数据库导出**。建议按 F-1/F-2 优先处置。`198.51.100.23` 的 admin 暴力破解迹象为独立事件，并行处置。畸形记录需先排除日志管道故障再判断是否为对抗行为。
