## 3. 详细发现

### F-1 严重：越权令牌 + 数据库未知用户导出（关联攻击链）
- **证据**
  - `2026-08-12T09:04:02Z, api, high, token_scope_mismatch, service-a, 203.0.113.8`
  - `2026-08-12T09:07:30Z, db, critical, unexpected_export, unknown, 203.0.113.8`
- **分析**：同一源 IP `203.0.113.8` 在 3 分 28 秒内先触发 API 层 `token_scope_mismatch`（服务账号 `service-a` 令牌权限范围不匹配，疑似被滥用或篡改），随后在 DB 层以 `unknown` 用户身份触发 `unexpected_export`。两事件时间相邻、来源一致，构成"越权令牌 → 未授权数据导出"的可疑攻击链，是本批数据中最高风险信号。
- **影响**：若属实，可能导致敏感数据批量外泄；`unknown` 用户能执行导出说明 DB 层存在认证/授权缺口。
- **处置建议**
  1. 立即吊销/轮换 `service-a` 的令牌，审查其签发来源与最近调用。
  2. 调取 DB 审计日志，确认 09:07:30 前后导出的表、行数、目标位置与执行者身份。
  3. DB 导出操作强制二次认证与最小权限授权，禁止匿名/`unknown` 执行导出。
  4. 对 `token_scope_mismatch` 配置实时告警与自动熔断（连续触发即吊销令牌）。
  5. 对 `203.0.113.8` 在时间窗口内的全部活动做溯源排查。
- **复测方法**
  - 使用权限范围不匹配的令牌请求 API → 应被拒绝并告警，不得放行到下游。
  - 以未认证/未知用户尝试 DB 导出 → 应被认证层拦截。
  - 验证 `token_scope_mismatch` 告警在 1 次触发内即通知值班人员。

### F-2 高：CSV 公式注入（CWE-1236）
- **证据**
  - edge_cases 第 5 行：value = `=HYPERLINK("https://example.invalid","do not execute")`（CSV 中以双引号包裹，首字符为 `=`）。
  - edge_cases 第 4 行：value = `-999`，首字符 `-` 同为电子表格公式触发字符（`-` 开头可被解释为公式/负号表达式），需按上下文区分处理。
- **分析**：当系统把用户可控数据导出为 CSV 并用 Excel/WPS/表格打开时，以 `=`、`+`、`-`、`@`、Tab、CR 开头的单元格会被当作公式执行。`=HYPERLINK(...)` 可诱导点击外链，更危险的变体可执行本地命令探测或数据外带。虽然载荷域名为保留测试域，但漏洞类别真实存在。
- **影响**：导出链路的客户端代码执行/钓鱼风险，影响所有打开该 CSV 的人员账号。
- **处置建议**
  1. 导出 CSV 时对每个单元格做输出中和：若首字符属于 `= + - @ \t \r`，前置单引号 `'` 或去除触发字符。
  2. 对 `-999` 这类合法负数值，按字段类型白名单处理（数值字段允许负号，文本字段一律中和），避免"一刀切"破坏数据。
  3. 导出接口设置 `Content-Type: text/csv` 与 `Content-Disposition: attachment`，必要时追加 `X-Content-Type-Options: nosniff`。
  4. 在文档中提示用户以"数据导入"方式打开 CSV，而非直接双击。
- **复测方法**
  - 构造含 `=HYPERLINK(...)`、`+cmd`、`@SUM` 的记录并导出 → 在 Excel/表格中打开，单元格必须显示为纯文本，不得生成可点击链接或公式结果。
  - 数值字段的 `-999` 导出后仍应被识别为数值 -999，未被错误加引号。

### F-3 中：admin 短时多次登录失败（暴力破解迹象）
- **证据**
  - `2026-08-12T09:03:45Z, web, warning, login_failed, admin, 198.51.100.23`
  - `2026-08-12T09:03:49Z, web, warning, login_failed, admin, 198.51.100.23`
- **分析**：同一 IP 在 4 秒内对 `admin` 账户连续两次登录失败，符合自动化撞库/暴力破解的早期特征。当前样本仅 2 次，未观察到成功登录，但 admin 为高价值账户，应按中危处置。
- **影响**：admin 凭据一旦被破解将导致系统沦陷。
- **处置建议**
  1. 对 admin 账户启用多因素认证（MFA）。
  2. 配置登录失败速率限制与指数退避/临时锁定（如 5 次失败锁定 15 分钟）。
  3. 对同一 IP 多账户失败登录配置聚合告警。
  4. 核查该时间点前后是否有来自该 IP 的成功登录或密码重置行为。
- **复测方法**
  - 对 admin 连续发起 5 次失败登录 → 应触发锁定/退避与告警。
  - 验证失败后无法直接登录成功，且告警中包含正确的 IP 与用户名。

### F-4 中：日志记录畸形（完整性/可检测性缺口）
- **证据**
  - `2026-08-12T09:09:00Z, web,,malformed_record,,`（severity、user、source_ip 均为空）
- **分析**：该记录关键字段缺失，无法用于归因与检测。成因可能有三类：日志采集/解析器 bug、上游事件本身不完整、或日志被篡改/截断。在 F-1 攻击链之后约 1 分半出现，不能排除攻击者掩盖痕迹的可能，需排查。
- **影响**：检测盲区；若为篡改则影响取证可信度。
- **处置建议**
  1. 日志接入层增加 schema 校验：缺失必填字段（severity/user/source_ip）的记录一律转入隔离区并告警，不得静默入库。
  2. 对日志采集器（forwarder/parser）做健康检查与解析失败计数监控。
  3. 关键日志启用防篡改：集中式存储、只追加权限、完整性校验（如哈希链/WORM）。
  4. 排查 09:09 前后 web 系统的原始访问日志，确认该记录的真实来源。
- **复测方法**
  - 向采集端发送缺字段的畸形事件 → 应被隔离并产生告警，且不进入正常检索索引。
  - 验证解析失败指标在异常发生时可见。

### F-5 低：数据质量问题（重复/缺失/异常值）
- **证据**
  - 第 2、3 行：`record_id=2` 完全重复（status=ok, value=120）。
  - 第 4 行：`record_id=3`，status 与 value 均为空。
  - 第 5 行：`record_id=4`，status=error，value=`-999`（异常负值/哨兵值）。
- **分析**：重复主键破坏唯一性约束；空字段违反非空预期；`-999` 常作为"缺失/错误"哨兵值混入数值字段，会污染统计与告警阈值。三者均为输入校验/数据治理问题，本身安全影响有限，但可被用于绕过业务规则或制造统计偏差。
- **处置建议**
  1. `record_id` 加唯一约束，重复写入应拒绝或去重。
  2. 必填字段在写入前做非空校验，不合法记录拒绝入库并返回错误。
  3. 数值字段定义合法范围，`-999` 等哨兵值应在入库前转换为 NULL 或显式错误标记，而非混入业务数值。
- **复测方法**
  - 插入重复 `record_id=2` → 应被拒绝。
  - 插入 status/value 为空的记录 → 应被拒绝。
  - 插入超范围负值 → 应被拒绝或按约定转换为 NULL。
