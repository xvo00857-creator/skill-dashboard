# Sentinel Telegram 通知通道

基于 `telegram-notifications-setup` Skill 工作流的独立兼容实现。当团队工作流（CI 构建、部署审批、数据任务等）卡住或需要人工确认时，通过 Telegram Bot 发送通知并接收回复指令。

## 依赖

仅使用 macOS 自带工具，**不新增任何依赖**：

- `bash`（macOS 自带 3.2）
- `curl`（调用 Telegram API）
- `python3`（JSON 处理与模拟服务器）

## 文件说明

| 文件 | 说明 |
|------|------|
| `sentinel_setup.sh` | 主脚本，实现 status / store_token / detect_chat / configure / test / notify / listen 全部动作 |
| `examples/notify_team.sh` | 团队工作流通知示例：发送通知 → 轮询回复（continue/abort/status） |
| `verify.sh` | 可重复验证脚本（模拟模式，无需真实 Telegram 账号） |
| `README.md` | 本文档 |

## 快速验证（无需 Telegram 账号）

```bash
bash verify.sh
```

该命令在本地启动模拟 Telegram API 服务器，依次验证全部动作和异常路径，输出 26 项检查结果。

端到端示例：

```bash
bash examples/notify_team.sh --mock --timeout 8 "构建 #1234 失败，请回复"
```

## 命令用法

```bash
./sentinel_setup.sh [--mock] [--config-dir DIR] [--api-base URL] <action> [参数]
```

| 选项 | 说明 |
|------|------|
| `--mock` | 启动本地模拟 Telegram API（用于测试，无需真实账号） |
| `--config-dir DIR` | 指定配置目录（默认 `~/.sentinel`） |
| `--api-base URL` | 自定义 Telegram API 地址（默认 `https://api.telegram.org`） |

### 动作一览

| 动作 | 说明 |
|------|------|
| `status` | 查看当前配置状态（token 掩码显示） |
| `store_token --token TOKEN` | 通过 getMe 校验后存储 Bot token |
| `detect_chat` | 调用 getUpdates 检测最近一条消息的 chat_id 和 sender_id |
| `configure --chat-id ID [--allowlist IDS] [--enabled true]` | 配置通知目标和白名单 |
| `test` | 向已配置的 chat_id 发送测试消息 |
| `notify --text TEXT` | 发送工作流通知（供外部脚本调用） |
| `listen` | 长轮询监听回复，校验白名单后输出指令 |

## 真实账号使用步骤

> 以下步骤需要真实 Telegram 账号和 @BotFather，脚本只做"确认前"的校验和配置，不代替登录。

1. **创建 Bot**：在 Telegram 中搜索 @BotFather（应用内搜索，不用 t.me 链接），发送 `/newbot`，按提示创建，获取 token。
2. **存储 token**：
   ```bash
   ./sentinel_setup.sh store_token --token "123456789:AAExxxxxxxxxxxxx"
   ```
   脚本会调用 getMe 校验 token 有效性，通过后存入 `~/.sentinel/credentials.json`（权限 600）。
3. **激活对话**：在 Telegram 中向你的 Bot 发送 `/start`（Bot 不能主动发起对话）。
4. **检测 chat**：
   ```bash
   ./sentinel_setup.sh detect_chat
   ```
   输出 `CHAT_ID=...` 和 `SENDER_ID=...`。若返回 PENDING，说明未检测到消息，请先向 Bot 发消息后重试。
5. **配置通道**：
   ```bash
   ./sentinel_setup.sh configure --chat-id "987654321" --allowlist "987654321"
   ```
   chat_id 以字符串形式存储（符合 Skill 规范）。
6. **测试**：
   ```bash
   ./sentinel_setup.sh test
   ```
7. **集成到工作流**：在需要通知的脚本中调用：
   ```bash
   ./sentinel_setup.sh notify --text "部署 #42 卡住，请回复 continue 继续"
   ```

## 异常处理

| 场景 | 退出码 | 行为 |
|------|--------|------|
| token 格式错误（非 `数字:字符串`） | 2 | 本地拒绝，不发起网络请求 |
| token 无效（API 返回 401） | 4 | 输出错误信息，不存储 |
| detect_chat 无消息 | 4 | 返回 PENDING，引导用户发消息 |
| 未配置 chat_id 就 test/notify | 3 | 提示先执行 configure |
| 非数字 chat-id | 2 | 本地拒绝 |
| 网络不可达 | 5 | 提示网络错误 |
| 未知 action | 2 | 列出用法 |

脚本不手动 curl getUpdates 解密 token，不截图 OCR，不替用户登录 Telegram——这些约束均来自 Skill 规范。

## 配置文件

- `~/.sentinel/credentials.json`：存储 Bot token 和 bot 信息，权限 600
- `~/.sentinel/config.json`：存储通知目标、白名单、启用状态

## 与原 Skill 的差异说明

原 Skill 依赖 `sentinel_setup` 工具和 `hive-browser` CLI（来自 `hive.browser-automation` Skill），当前环境均未安装。本实现用 bash + curl + python3 复现了相同的工作流和动作语义：

- `sentinel_setup` 工具的六个动作 → 本脚本的同名动作
- `hive-browser` 驱动 Telegram Web 创建 Bot → 需用户手动在 Telegram 中操作（脚本不代替登录）
- 新增 `--mock` 模式，在本地模拟 Telegram API，使全流程可离线重复验证
