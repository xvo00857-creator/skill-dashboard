## [LRN-20250115-001] correction

**Logged**: 2025-01-15T10:30:00Z
**Priority**: high
**Status**: pending
**Area**: tests

### Summary
错误地假设 pytest fixture 默认是函数级作用域

### Details
编写测试 fixture 时，我假设所有 fixture 都是函数级作用域。用户纠正：虽然函数级是默认值，但该代码库约定对数据库连接使用模块级 fixture 以提升测试性能。

### Suggested Action
创建涉及昂贵初始化（数据库、网络）的 fixture 时，先检查已有 fixture 的作用域模式，不要默认使用函数级。

### Metadata
- Source: user_feedback
- Related Files: tests/conftest.py
- Tags: pytest, testing, fixtures

## [LRN-20250115-003] best_practice

**Logged**: 2025-01-15T16:00:00Z
**Priority**: high
**Status**: promoted
**Promoted**: CLAUDE.md
**Area**: backend

### Summary
API 响应必须包含来自请求头的 correlation ID

### Details
所有 API 响应应回传请求中的 X-Correlation-ID 头，这是分布式链路追踪所必需的。缺少该头的响应会破坏可观测性流水线。

### Suggested Action
在 API handler 中始终包含 correlation ID 透传。

### Metadata
- Source: user_feedback
- Related Files: src/middleware/correlation.ts
- Tags: api, observability, tracing

## [LRN-20250118-001] best_practice

**Logged**: 2025-01-18T11:00:00Z
**Priority**: high
**Status**: promoted_to_skill
**Skill-Path**: skills/docker-m1-fixes
**Area**: infra

### Summary
Docker 构建在 Apple Silicon 上因平台不匹配而失败

### Details
在 M1/M2 Mac 上构建 Docker 镜像时，基础镜像没有 ARM64 变体导致构建失败。这是影响众多开发者的常见问题。

### Suggested Action
在 docker build 命令中添加 `--platform linux/amd64`，或在 Dockerfile 中使用 `FROM --platform=linux/amd64`。

### Metadata
- Source: error
- Related Files: Dockerfile
- Tags: docker, arm64, m1, apple-silicon
- See Also: ERR-20250115-A3F, ERR-20250117-B2D
