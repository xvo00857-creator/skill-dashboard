# Linear 渠道集成 —— 最小配置与验证交付

本目录是依据 `add-linear` Skill（分类：自动化与工具）为开发团队配置 Linear 消息/协作渠道集成的交付物。

## 一、约束导致的方案变化

Skill 原始流程假设在一个完整的 NanoClaw 项目内执行（复制 channels 分支适配器、注册 barrel、pnpm 安装、构建、vitest、ncl 接线、重启服务）。本次新增约束改变了执行方式：

| 约束 | 对原流程的影响 | 本次做法 |
|------|----------------|----------|
| 不新增非必要依赖 | 原流程要求安装 `@chat-adapter/linear@4.29.0` 到 NanoClaw 项目 | 未在本地全局或空目录安装该包；仅通过 `npm view` 确认锁定版本 4.29.0 存在且可获取（shasum `8bba103a…`）。验证脚本仅用 Node 内置模块（`crypto`/`fs`/`path`），零 npm 依赖 |
| 不改动无关文件 | 原流程要写入 `src/channels/index.ts`、`src/channels/linear.ts` 等 | 当前环境无 NanoClaw 项目，所有交付物放在独立的 `linear-integration/` 目录，不触碰任何项目文件；`verify-project.sh` 设计为在真实项目根目录执行时才检查/报告，不做写入 |
| 本地/沙盒可重复验证 | 原流程依赖 `pnpm run build`、`vitest`、`ncl`、运行中的服务 | 提供三个可重复运行的验证脚本：配置结构校验、webhook 签名链路模拟、项目集成检查；均无需外部账号或网络 |
| 外部账号只做安全模拟或确认前步骤 | 原流程要求创建 Linear OAuth 应用、webhook、写入真实凭证 | 使用 Skill 自带 `apply-fixtures.json` 中明确标注为 fake 的模拟值（`fake-client-id` 等）；OAuth 应用创建、webhook 创建、`ncl` 接线等交互步骤仅在文档中列出确认前操作，未实际点击或调用 |

## 二、交付物清单

| 文件 | 说明 |
|------|------|
| `.env.example` | 最小环境变量配置模板，含必填项与两种认证方式 |

| `verify-webhook.mjs` | 零依赖 webhook 签名模拟验证脚本 |
| `verify-project.sh` | 在真实 NanoClaw 项目根目录执行的集成检查脚本 |

最后一项"失败"是**预期行为**：脚本检测到凭证含 `fake` 标记并明确警告不可连接真实 Linear，证明模拟值检测逻辑生效。

### 3.2 Webhook 签名链路模拟

```
$ node verify-webhook.mjs

  ✓ 正常 Comment 事件签名验证通过
  ✓ 篡改 body 后签名验证失败（篡改被正确拒绝）
  ✓ 错误密钥签名验证失败（错误密钥被正确拒绝）
  ✓ 过期时间戳（超过 60 秒）验证失败（防重放）
  ✓ 签名长度不一致验证失败
  ✓ action=remove 事件验签通过但业务层应忽略
```

签名算法严格复刻 `@linear/sdk/webhooks` 的 `LinearWebhookClient.verify`：HMAC-SHA256(rawBody, secret) hex 摘要 + `timingSafeEqual` 常量时间比较 + 60 秒时间戳容差。

## 四、缺失项与未完成范围（如实报告）

以下 Skill 步骤因环境/依赖不足**未能执行**，不假装成功：

1. **复制适配器文件**（Apply 步骤 1）：`src/channels/linear.ts` 和 `src/channels/linear-registration.test.ts` 需从 NanoClaw 仓库的 `channels` 分支复制。ZIP 中不含这两个文件，当前环境也没有该 git 仓库/分支，无法获取真实适配器源码。
2. **注册 barrel**（Apply 步骤 2）：无 `src/channels/index.ts` 文件，无法追加 `import './linear.js';`。
3. **安装依赖与构建测试**（Apply 步骤 3-4）：无 NanoClaw 项目的 `package.json`、`pnpm-lock.yaml`、TypeScript 配置和 vitest 配置，无法执行 `pnpm run build` 和注册测试。`ncl` CLI 在本机不可用。
4. **Linear OAuth 应用与 Webhook 创建**（Credentials）：需要真实 Linear 账号和工作区管理员权限，属外部交互步骤，按约束仅做到确认前文档。
5. **消息组接线**（Wiring）：`ncl messaging-groups create` 和 `ncl wirings create` 需要运行中的 NanoClaw host 服务（Unix socket），本机无此服务。
6. **服务重启与端到端验证**（Next Steps）：依赖上述全部步骤完成。

### 在真实 NanoClaw 项目中完成集成的步骤

```bash
# 1. 在项目根目录复制适配器（从 channels 分支）
git checkout channels -- src/channels/linear.ts src/channels/linear-registration.test.ts

# 2. 注册 barrel（幂等）
grep -q "import './linear.js'" src/channels/index.ts || echo "import './linear.js';" >> src/channels/index.ts

# 3. 安装锁定版本依赖
pnpm add @chat-adapter/linear@4.29.0

# 4. 构建并运行注册测试
pnpm run build
pnpm exec vitest run src/channels/linear-registration.test.ts

# 5. 填写真实凭证到 .env（参考 .env.example），然后接线
ncl messaging-groups create --channel-type linear --platform-id linear:ENG \
  --is-group 1 --unknown-sender-policy public --name ENG
ncl wirings create --channel-type linear --platform-id linear:ENG \
  --agent-group <agent_folder> --engage-mode pattern --engage-pattern . --session-mode per-thread

# 6. 重启服务后按 test-message-plan.md 执行端到端验证
```

### 实际影响执行的 SKILL.md 规则

1. **锁定版本规则**（第 60-64 行）："Pinned to an exact version — the supply-chain policy rejects ranges and `latest`" → 确认并验证 `@chat-adapter/linear@4.29.0` 精确版本，未使用 `latest` 或范围。
2. **幂等性规则**（第 15-16 行）："Every directive is idempotent, so the whole skill is safe to re-run" → `verify-project.sh` 中的 barrel 注册检查和文档中的接线命令均设计为可重复执行。
3. **set-if-absent 凭证规则**（第 106-107 行）：凭证写入不覆盖已有值 → `.env.example` 模板和文档中强调不覆盖已有 `.env`。
4. **OAuth 优先规则**（第 20 行）：推荐 OAuth 应用身份以避免自身评论过滤 → `.env.example` 将 OAuth 列为方式 A（推荐），API Key 列为备选；permissions.md 说明差异。
5. **pattern engage mode 规则**（第 164-170 行）：Linear 无法 @提及，使用 `--engage-mode pattern --engage-pattern .` 响应所有评论，`per-thread` 会话隔离 → 接线命令和 permissions.md 均按此设置。
6. **发送者策略规则**（第 153-155 行）：私有工作区用 `public`，公开工作区用 `strict` → permissions.md 明确两种策略的选择条件。
7. **Webhook 签名密钥必填规则**（第 98 行 + 适配器类型定义）：signing secret 用于 HMAC 验证 → verify-webhook.mjs 复刻该验证链路。
8. **fixture 假值规则**（apply-fixtures.json 第 2 行）："shaped fake values only, never real credentials" → `.env.linear` 使用这些假值，并在 verify-config.mjs 中增加模拟值检测警告。
9. **新 webhook 延迟说明**（第 100 行）：1-5 分钟延迟属正常 → test-message-plan.md 的 TC-01 注明等待 5 分钟。
10. **Client credentials grant type 必须启用**（第 26-27 行、Troubleshooting 第 202 行）：不启用则 401 → permissions.md 明确标注此步骤。
