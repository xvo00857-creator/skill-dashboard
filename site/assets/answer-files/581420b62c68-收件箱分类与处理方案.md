# 收件箱分类与日常处理方案（变化场景版）

> 场景：可用时间临时减半 + 周三增加不可移动评审会 + 结果需交接给另一位同事
> 日期：2026-08-10（周一）
> 依据：inbox-setup Skill v1.0.0 的 7 文件知识库契约与 8 段访谈纪律

---

## 一、目标

在可用时间减半、且周三有不可移动评审会的条件下，建立一套**简单、可维护、可交接**的收件箱分类体系、处理规则和日常习惯，使接手同事能在不依赖原负责人实时指导的情况下，独立完成日常邮件分类与回复，同时不遗漏关键事项。

---

## 二、约束变化如何改变原方案

原 inbox-setup Skill 设计的是一个 **25–31 个问题、8 个 Section、逐题访谈** 的完整入职流程，产出 7 个文件的完整知识库。三个约束变化对原方案的影响如下：

### 约束 1：可用时间减半

| 原方案 | 变化后调整 |
|---|---|
| 8 个 Section 全部走完（~30 题） | 压缩为 5 个核心 Section，跳过 Section 4（评估框架）和 Section 8（完整确认），Section 1 从 6 题压缩为快速判断 |
| 分类 5–7 类 | 压缩为 **5 类**，减少记忆负担和分类决策时间 |
| 每节逐题访谈（grill-me 一题一问） | 本场景为方案设计而非真实访谈，直接给出推荐分类与规则，接手同事可按需微调 |
| 回复风格采集 3–5 封真实邮件样本 | 本场景无法采集样本，标记 `[calibration may need iteration]`，用保守默认值，后续补充 |
| 每日 2 次 triage（9h 重叠窗口） | 改为**每日 1 次**（固定时段），周三仅做评审相关邮件的最小处理 |

### 约束 2：周三不可移动评审会

| 原方案 | 变化后调整 |
|---|---|
| 无日历约束，运行频率均匀 | 周二为"清空日"（处理完所有"需立即行动"邮件）；周三仅处理评审相关邮件；周四为"追赶日"（处理周三积压） |
| tracker.md 仅记录待办项 | tracker.md 新增 **本周日程约束表**，明确每天能做什么、不能做什么 |
| 报告偏好无特殊置顶规则 | 报告置顶规则增加"周三评审会相关待办" |

### 约束 3：交接给另一位同事

| 原方案 | 变化后调整 |
|---|---|
| Persona 为 single-user 或 assistant-as-user | 改为 **delegated (handoff)** 模式：同事以原负责人名义处理，但不确定时不替原负责人承诺 |
| 知识库是个人参考，可用速记 | 每个文件增加**交接备注**，规则写全称、不写个人暗语；默认值偏保守 |
| 无升级路径 | 明确**升级路径**：不确定 → flag → 联系原负责人 → 再回复 |
| tracker.md 主要给自己看 | tracker.md 成为**最重要的交接文件**，新增"交接备注"区块（接手人、范围、不可代决策项、原负责人可用时间） |
| 报告交付给本人 | 报告格式改为 file-in-workspace（写入 triage-log/），便于同事查阅历史记录 |

## 三、分类体系（5 类）

| # | 类别 | 触发信号 | 默认动作 | 占比估算 |
|---|---|---|---|---|
| 1 | 需立即行动 | "请确认/审批/回复/截止/deadline/ASAP/紧急"；上级或核心项目人；"评审/排期/上线/故障" | 分类 + 起草回复，24h 内回复 | ~25% |
| 2 | 活跃对话 | Re:/Fwd: 多次往返；项目讨论、方案对齐 | 分类，按需回复（被 @ 或直接提问才回） | ~30% |
| 3 | 信息周知 | "FYI/周知/周报/通知/公告"；群发、CC | 跳过，标已读 | ~30% |
| 4 | 个人/重要 | HR/行政/IT/财务；"合同/薪资/报销/权限/账号"；1:1 非项目邮件 | 标记人工确认，不自动处理 | ~10% |
| 5 | 低优先级/忽略 | "unsubscribe/退订/营销/活动/问卷"；newsletter | 自动跳过（blocklist 拦截） | ~5% |

**设计取舍**：原方案的"新机会(New Opportunities)"和"财务(Financial)"两类被合并或省略。内部产品经理的收件箱以内部协作为主，不涉及外部商务机会邮件（故跳过 Section 4 评估框架）；财务相关邮件归入"个人/重要"类。5 类比 7 类更容易让接手同事记住，分类决策更快。

## 四、日常处理习惯

### 每日流程（约 15–20 分钟，时间减半后的压缩版）

1. **打开 tracker.md**：先看逾期项和本周日程约束（1 分钟）
2. **扫描收件箱**：按 5 类快速分类，blocklist 自动拦截第 5 类（5 分钟）
3. **处理"需立即行动"**：用模板起草回复，不确定的标记 flag（8 分钟）
4. **浏览"活跃对话"**：只回复直接 @ 或提问的（3 分钟）
5. **更新 tracker.md**：新增待办、标记完成、记录交接事项（2 分钟）
6. **"信息周知"和"低优先级"**：不单独花时间，批量标已读

### 本周特殊安排

| 日期 | 处理方式 |
|---|---|
| 周一 (8/10) | 完成分类体系搭建 + 交接文档（本方案） |
| 周二 (8/11) | **清空日**：所有"需立即行动"邮件处理完毕，为周三评审腾出时间 |
| 周三 (8/12) | **评审日**：仅处理评审相关邮件；其余邮件不做常规 triage，顺延至周四 |
| 周四 (8/13) | **追赶日**：处理周三积压 + 常规 triage |
| 周五 (8/14) | 常规 triage + 周报 |

## 六、关键取舍

1. **分类数 5 vs 7**：选 5。少分类 = 少决策 = 快，但可能有少量邮件"不太好归"。取舍：不好归的邮件默认进"需立即行动"（宁可多看一眼，不要漏）。
2. **自动拦截激进 vs 保守**：选激进。blocklist 多拦一些营销/通知类邮件，误拦风险低（这些邮件本来就不需要回）；如果误拦了重要邮件，在 "Recently Removed" 中记录即可恢复。
3. **回复模板完备 vs 简单**：选简单但覆盖高频场景。5 个模板覆盖 80% 日常回复，复杂情况一律用"我确认后回复你"模板，不硬凑。
4. **声音校准精度 vs 速度**：选速度。未采集真实邮件样本，用保守默认（中等正式、短段落），标记需后续校准。前几封回复可能需要同事手动调整，但比花 30 分钟访谈采集样本更符合时间减半约束。
5. **同事自主权 vs 风险控制**：选风险控制。同事可以自主回复信息周知类和简单确认类，但涉及承诺、人事、合同、未确认排期的邮件一律 flag 给原负责人。宁可多问一句，不要替原负责人做决定。
6. **周三处理邮件 vs 专注评审**：选专注评审。周三只看评审相关邮件，其余全部顺延。评审是不可移动的硬约束，邮件可以等一天。

## 七、风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|---|---|---|---|
| 接手同事误分类重要邮件 | 中 | 高 | 分类规则中"不好归的默认进需立即行动"；前 3 天原负责人每天花 5 分钟抽查 |
| blocklist 误拦关键邮件 | 低 | 中 | 误拦记录在 Recently Removed；重要发件人（上级、HR）不在 blocklist 中 |
| 周三评审期间有紧急邮件被忽略 | 中 | 高 | tracker.md 明确周三仍处理评审相关邮件；设置邮件过滤规则将上级邮件标星 |
| 回复风格与原负责人差异大 | 中 | 低 | 用保守默认风格；硬规则明确"不确定就说确认后回复"；前几封同事起草后原负责人过目 |
| 同事不知道什么该 flag | 中 | 中 | email-patterns.md 硬规则列出 4 条"绝对不做"；tracker.md 写明升级路径 |
| 时间减半导致 triage 质量下降 | 高 | 中 | 每日只做 1 次但固定时段；30 秒摘要模式；blocklist 激进拦截减少处理量 |
| tracker.md 未及时更新导致信息不同步 | 中 | 高 | 每次 triage 最后一步必更新 tracker；交接备注中写明"tracker 是唯一事实来源" |

## 八、衡量方式

| 指标 | 目标 | 衡量方法 |
|---|---|---|
| 每日 triage 耗时 | ≤ 20 分钟 | 接手同事记录每次处理时间 |
| "需立即行动"邮件 24h 回复率 | ≥ 90%（周三评审日除外） | tracker.md 中状态变更时间 |
| 误分类率（原负责人抽查发现分错的） | ≤ 10% | 前 3 天每日抽查，之后每周抽查 |
| blocklist 误拦数 | ≤ 2 封/周 | Recently Removed 中的记录数 |
| 接手同事独立处理率（不需要问原负责人的比例） | ≥ 80% | 同事记录每次 flag/询问的次数 |
| 周三评审日零遗漏 | 评审相关邮件全部处理 | 周四早晨检查 |
| 逾期项数量 | 0（或持续下降） | tracker.md Overdue 区域 |

## 十、下一步

1. **原负责人填写 tracker.md**：将实际进行中的项目、截止日期、接手同事姓名填入 Active Follow-Ups 表
2. **接手同事阅读 4 个 KB 文件**：重点看 tracker.md（交接备注）和 email-patterns.md（硬规则）
3. **周二（8/11）执行清空日**：原负责人和接手同事一起做一次 triage，走一遍流程
4. **周三（8/12）评审日**：接手同事仅处理评审相关邮件，其余顺延
5. **周四（8/13）起接手同事独立运行**：每日固定时段做一次 triage，原负责人前 3 天抽查
6. **一周后复盘**：检查衡量指标，调整分类规则/blocklist/模板
7. **补充声音样本**：时间恢复后，原负责人提供 3–5 封真实已发送邮件，运行 voice_sample_analyzer.py 校准回复风格
