## 三、风险分级与证据

### F-INC-01【严重/Critical】疑似令牌越权后的数据外传链

- **证据块（最小控制链）**：
  - 不可信/异常输入：`203.0.113.8` 使用 `service-a` 身份调用 API
  - 可见异常：`2026-08-12T09:04:02Z, api, high, token_scope_mismatch, service-a, 203.0.113.8`（令牌权限范围不匹配）
  - 副作用：`2026-08-12T09:07:30Z, db, critical, unexpected_export, unknown, 203.0.113.8`（同一 IP 在 3 分 28 秒后以 `unknown` 身份触发数据库非预期导出）
- **分析**：同一源 IP 在短时间内先出现令牌范围越权（high），随后以未知身份触发数据库关键导出（critical），构成"令牌异常 → 身份丢失/伪造 → 数据外传"的可疑链路。`user=unknown` 表明导出操作未关联到有效主体，可能为令牌被滥用后身份映射失败。
- **置信度**：中（日志证据强关联，但无运行时数据确认导出内容、令牌主体及实际影响）。
- **影响面（假设）**：若导出包含真实业务数据，可能构成数据泄露。

### F-INC-02【高/High】admin 账户暴力破解迹象

- **证据块**：
  - `2026-08-12T09:03:45Z, web, warning, login_failed, admin, 198.51.100.23`
  - `2026-08-12T09:03:49Z, web, warning, login_failed, admin, 198.51.100.23`
- **分析**：同一 IP 对 `admin` 账户在 4 秒内连续两次登录失败，符合自动化暴力破解/口令喷洒的早期特征。样本量小（仅 2 次），尚不足以确认完整攻击，但应作为告警触发点。
- **置信度**：中低（频次未达典型爆破阈值，但目标为高权限账户，需提级关注）。

### F-INC-03【中/Medium】日志记录畸形，存在字段缺失

- **证据块**：
  - `2026-08-12T09:09:00Z, web, , malformed_record, , `（severity/user/source_ip 均为空）
- **分析**：该条日志三个关键字段缺失，可能原因：(a) 日志采集/序列化管道缺陷；(b) 上游事件本身字段不全；(c) 日志被篡改或截断。在安全审计语境下，字段缺失会降低可追溯性，且该事件发生在 F-INC-01 之后约 1.5 分钟，时序上需排除关联。
- **置信度**：高（缺失事实确定）；原因待定。

### F-INC-04【信息/Info】正常登录基线

- **证据块**：`2026-08-12T09:00:12Z, web, info, login_success, alice, 192.0.2.10`
- **分析**：单次成功登录，无异常，作为正常基线记录。

### F-EDGE-01【高/High】CSV 公式注入（含解析差异）

- **证据块（最小控制链）**：
  - 不可信内容：`record_id=5` 的 `value` 字段为 `=HYPERLINK("https://example.invalid","do not execute")`
  - 变为可执行输入的节点：该值以 `=` 开头，当文件被 Excel/WPS/Numbers 等电子表格程序打开时，公式引擎会将其解析为公式而非纯文本
  - 潜在副作用：`HYPERLINK` 可诱导点击跳转外部站点；若环境允许，同类以 `=`/`+`/`-`/`@` 开头的载荷可触发 DDE/外部数据连接等更危险行为
- **附加发现——解析差异**：该字段使用 `\"` 转义内嵌引号（非 RFC 4180 标准，标准应为 `""`）。实测 Python `csv` 模块将该行错误拆分为 5 个字段（标准为 4 列），公式被截断分散到 `value`/`notes`/额外列；而宽容解析器可能还原完整公式。不同解析器对同一载荷的可见性不同，可能导致部分检测工具漏报。
- **置信度**：高（载荷与转义异常均为文件中客观存在）；是否被实际执行未知。

### F-EDGE-02【中/Medium】重复记录

- **证据块**：`record_id=2` 出现两行，内容均为 `2,ok,120,重复记录`。
- **分析**：主键重复，可能导致下游统计/聚合计算翻倍（如求和、计数），在安全指标场景下可能误报或掩盖真实趋势。

### F-EDGE-03【中/Medium】关键字段缺失

- **证据块**：`record_id=3` 的 `status`、`value` 为空，`notes="-"`。
- **分析**：业务关键字段缺失，下游若未做空值防护可能引发异常或误判。

### F-EDGE-04【低/Low】异常负值

- **证据块**：`record_id=4, status=error, value=-999`。
- **分析**：`value` 出现负值且状态为 error，可能为业务错误码或传感器异常值；需结合业务语义确认是否合法。注意：该值以 `-` 开头，在电子表格中同样可能被解析为公式（负值通常安全，但应统一做单元格注入防护）。

## 五、修复建议

### 针对 F-INC-01（令牌越权 + 数据外传）
1. 立即吊销/轮换 `service-a` 相关令牌，核查令牌 scope 配置是否遵循最小权限原则。
2. 对数据库导出操作强制二次鉴权与审批，禁止 `unknown`/匿名主体执行导出。
3. 对 `203.0.113.8` 进行临时封禁或加严验证，排查该 IP 是否为内网/可信地址。
4. 核查 09:07:30 前后 DB 导出任务的内容、目标存储与访问日志。

### 针对 F-INC-02（admin 爆破）
1. 对 admin 账户启用登录失败锁定/速率限制与 MFA。
2. 对 `198.51.100.23` 启用 CAPTCHA 或临时封禁。
3. 避免使用 `admin` 等通用高权限用户名，改为具名管理员账户。

### 针对 F-INC-03（畸形日志）
1. 修复日志采集管道，确保 severity/user/source_ip 为必填或有默认值。
2. 增加日志格式校验与丢弃/告警机制，防止畸形日志进入分析链路。
3. 排查该畸形记录是否与 F-INC-01 时序相关。

### 针对 F-EDGE-01（CSV 公式注入）
1. 导出 CSV 时对以 `=`、`+`、`-`、`@`、Tab、回车开头的单元格进行转义（前缀单引号 `'` 或移除特殊字符）。
2. 统一 CSV 转义规范为 RFC 4180（内嵌双引号写为 `""`），避免 `\"` 导致的解析差异。
3. 下游解析器增加列数校验，对列数不匹配的行告警而非静默截断。
4. 打开不受信 CSV 时禁用自动公式计算/外部连接。

### 针对 F-EDGE-02/03/04（数据质量）
1. 以 `record_id` 为主键去重，建立唯一约束。
2. 对 `status`、`value` 等关键字段设置非空校验与入库前 schema 验证。
3. 明确 `value` 取值范围，对负值/越界值按业务规则校验或拒绝。

## 七、结论

在授权的只读分析范围内，两个模拟日志文件共发现 **1 个严重、2 个高危、3 个中危、1 个低危** 问题（不含信息项）：

- 最核心风险为 **F-INC-01**：同一 IP 在令牌越权后短时间内触发匿名数据库导出，构成疑似数据外传链，需按 P0 处置。
- **F-INC-02** 显示 admin 账户遭暴力破解尝试，应立即加固。
- **F-EDGE-01** 的 CSV 公式注入叠加非标准转义导致的解析差异，是典型的"不可信内容变为可执行工具输入"链路，需在导出与解析两侧同时修复。
- 数据质量问题（重复、缺失、畸形、负值）本身不直接构成入侵，但会削弱检测与追溯能力，应纳入输入校验治理。

所有发现均基于日志静态证据，未在运行时确认；标注为"无法完成"的核查项需在授权系统中由具备权限的人员按复测清单执行。本次分析未执行任何破坏性、探测性或越权操作。
