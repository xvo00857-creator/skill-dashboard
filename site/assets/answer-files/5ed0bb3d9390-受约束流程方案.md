# ai-ready 受约束流程方案

> 本方案严格依据上传的 `ai-ready/SKILL.md`（安装引导包装器）与公开的 `johnpapa/ai-ready` 说明编写。
> 核心边界：**包装器 Skill 本身不分析代码库、不生成文件**；真正的分析与生成由用户自行安装的完整 `johnpapa/ai-ready` 在 Copilot CLI 中完成。代理不得代替用户执行安装命令。

## 一、角色与边界

| 角色 | 职责 | 禁止事项 |
|------|------|----------|
| 用户 | 在 Copilot CLI 中执行安装、审阅、确认生成 | — |
| 本代理（豆包） | 解读 Skill、做只读预检、给出流程方案、在用户授权下基于本地可见文件做受限演示 | 不代跑 `/skills add`；不静默创建/删除/覆盖外部资源；不伪造 GitHub API 数据或 PR 评审记录 |
| 完整 ai-ready（Copilot CLI 内） | 调用 GitHub API + 扫描本地代码库，生成 12 类资产，评分，提议 PR | 不覆盖已存在文件（仅建议更新） |

## 二、标准流程（来自 SKILL.md，不得篡改）

1. 用户在 **Copilot CLI** 中执行：`/skills add johnpapa/ai-ready`（重复执行即更新到最新版）。
2. 用户加载前先审阅：`head -20 ~/.copilot/skills/ai-ready/SKILL.md`。
3. 用户确认审阅并安装后，执行 `/skills reload`，然后说 `make this repo ai-ready`。
4. 代理**不得**代替用户运行上述命令。

## 三、预检（Pre-checks，全部只读，失败即停）

| 编号 | 检查 | 通过标准 | 失败处理 |
|------|------|----------|----------|
| P1 | `command -v copilot` | 存在且可执行 | 提示用户先安装 Copilot CLI，停止 |
| P2 | `copilot --version` / 登录态 | 版本可读、已登录 GitHub | 引导用户完成登录，停止 |
| P3 | `git rev-parse --is-inside-work-tree` | 当前目录为 git 仓库 | 请用户切换到目标仓库目录，停止 |
| P4 | `git remote -v` | 存在 GitHub 远程 | 无远程则 GitHub API 自动发现不可用，降级为仅本地扫描并明确告知 |
| P5 | `git status --porcelain` | 工作区干净或用户已知晓未提交改动 | 建议先 commit/stash 作为回滚点，等待用户确认 |
| P6 | 盘点已有 AI 资产 | 记录 `AGENTS.md`、`.github/copilot-instructions.md`、`.github/workflows/`、Issue/PR 模板等是否存在 | 已存在的文件在后续步骤中只审计、不覆盖 |
| P7 | Skill 审阅确认 | 用户已执行 `head -20` 并确认内容可信 | 未确认则不进入生成阶段 |

## 四、幂等（Idempotency）

- **安装幂等**：`/skills add johnpapa/ai-ready` 重复执行 = 安装或更新到最新版，无副作用。
- **生成幂等**：完整 ai-ready 设计为可重复运行——首次创建缺失资产；再次运行只审计漂移（过时的构建命令、目录结构变化、新的 PR 评审模式），**不覆盖**用户文件，只给出更新建议。
- **本地演示幂等**：本目录下的演示文件写入前先检查目标路径是否存在；存在则不覆盖，改为写 `*.候选.md` 并提示人工对比。
- **回滚点**：正式生成前要求 git 工作区干净，所有改动可通过 `git checkout` / `git restore` 回滚。

## 五、重试（Retry）

| 场景 | 策略 | 上限 |
|------|------|------|
| GitHub API 网络失败/限流 | 指数退避（如 2s、4s、8s）后重试 | 3 次；仍失败则降级为仅本地扫描并标注缺失数据 |
| Skill 加载失败 | `/skills reload` 后重试 | 2 次；仍失败则停止并提示用户排查安装 |
| 文件写入冲突（生成期间文件被外部修改） | 重新读取磁盘内容 → 重新生成建议 → 不强制覆盖 | 2 次；仍冲突则交人工处理 |
| 代理侧只读预检命令失败 | 原样展示错误，不伪装通过 | 不重试破坏性操作 |

## 六、人工确认点（Human-in-the-loop）

1. **安装前**：用户自行执行 `/skills add johnpapa/ai-ready`（SKILL.md 强制，代理不得代劳）。
2. **审阅后**：用户确认已 `head -20` 审阅 Skill 内容。
3. **预检后**：用户确认 P5 工作区状态、P4 远程降级等告知项。
4. **生成前**：完整 ai-ready 输出"将要创建/修改的文件清单"与预期评分，用户明确同意后才落盘。
5. **PR 前**：是否创建 PR、PR 内容与目标分支，需用户确认。
6. **任何覆盖/删除**：默认不覆盖；如用户明确要求覆盖，须单独确认目标文件与备份方式。
