## 四、风险分级与证据

### 风险 1：数据库异常导出（Critical）

| 项目 | 内容 |
|---|---|
| 风险等级 | **严重（Critical）** |
| 对应记录 | 第 5 条：09:07:30Z, db, critical, unexpected_export, unknown, 203.0.113.8 |
| 事件描述 | 数据库系统报告一次"异常导出"操作，执行用户标记为 `unknown`，源 IP 为 203.0.113.8 |

**证据链分析：**

- 同一 IP 203.0.113.8 在 3 分 28 秒前刚触发过 `token_scope_mismatch`（第 4 条），时间上紧邻，构成较强的关联证据。
- 执行用户为 `unknown`，说明该操作未关联到已知身份，可能原因：(a) 使用了未正确映射身份的服务令牌；(b) 身份认证被绕过；(c) 数据库直连绕过了应用层审计。
- `unexpected_export` 表明该导出不在预期操作范围内，可能涉及数据外泄。

**置信度**：中。日志明确记录了 critical 级别事件且与前序 high 事件同源 IP，但缺少导出内容、数据量、目标位置等关键信息，无法确认实际影响范围。

**潜在影响**：若导出包含用户数据、凭证或业务敏感信息，可能构成数据泄露，需触发数据泄露响应流程。

### 风险 2：服务令牌权限范围不匹配（High）

| 项目 | 内容 |
|---|---|
| 风险等级 | **高（High）** |
| 对应记录 | 第 4 条：09:04:02Z, api, high, token_scope_mismatch, service-a, 203.0.113.8 |
| 事件描述 | 服务账号 `service-a` 的令牌尝试访问其授权范围之外的资源，被 API 层拦截并记录 |

**证据链分析：**

- `token_scope_mismatch` 表示令牌的 scope 声明与请求资源不匹配。可能原因：(a) service-a 令牌被盗用，攻击者尝试越权；(b) service-a 的令牌配置错误（scope 过宽或资源权限变更未同步）；(c) 合法的服务变更但令牌未更新。
- 该事件发生后 3 分 28 秒，同一 IP 即出现数据库异常导出。若令牌未被有效拦截（或拦截后仍有其他访问路径），则两起事件可能构成同一攻击链。
- 注意：`token_scope_mismatch` 是 high 级别而非 critical，说明 API 层可能已拦截该请求。但拦截不等于消除风险，需确认拦截是否彻底、是否有重试或绕过。

**置信度**：中高。事件本身确凿，但"被盗用"vs"配置错误"两种解释无法仅凭日志区分。

## 五、约束、冲突与关键取舍

### 约束 1：Skill 领域错配（已在第一节详述）

提供的 Skill 是前端设计规范，不含安全分析流程。取舍：不编造该 Skill 未提供的安全方法论，仅迁移其证据纪律类规则；安全分析采用行业通用实践，并在报告中明确区分。

### 约束 2：证据有限性与应急紧迫性的冲突

日志仅覆盖 8 分 48 秒、3 个系统、6 条记录。Critical 级别的数据库导出事件要求快速响应，但现有证据不足以确认：

- 导出了什么数据、数据量多大、流向何处
- `unknown` 用户的真实身份
- service-a 令牌是被盗用还是配置错误
- malformed_record 是否为日志篡改

**关键取舍**：

- 建议立即采取**可逆的遏制措施**（如临时吊销 service-a 令牌并轮换、暂停数据库导出权限），而非等待完整调查。理由：critical 事件 + 同源 high 事件的关联证据已达到"合理怀疑"阈值，延迟响应的风险（数据继续外泄）大于误报的业务影响。
- 但同时明确：若 service-a 是关键业务服务，吊销令牌可能导致服务中断。建议在业务低峰期或准备好备用令牌后执行，并通知 service-a 的负责人。这是一个**安全性与可用性的权衡**，需由业务方确认。

### 约束 3：授权测试范围限制

任务要求"仅在授权测试范围内分析"且"禁止破坏性操作"。本报告仅提供分析和建议，**未执行**以下任何操作：

- 未登录任何系统、数据库或云控制台
- 未封禁 IP、未吊销令牌、未修改任何配置
- 未访问 incident_log.csv 以外的任何文件或数据源
- 未对任何目标发起扫描或探测

所有修复建议均需由具备相应权限和授权的团队执行。

### 约束 4：日志完整性存疑导致"缺席证据"不可信

第 6 条 malformed_record 意味着日志可能不完整。因此：

- "日志中没有 admin 登录成功记录"不能等同于"admin 未被攻破"
- "日志中只有 2 次登录失败"不能等同于"攻击只尝试了 2 次"
- "日志中没有其他异常"不能等同于"没有其他异常发生"

这一约束直接影响了风险 3 和风险 4 的置信度评估。

| DEP-4 | 网络层日志（VPC Flow / 防火墙 / WAF），覆盖 203.0.113.8 和 198.51.100.23 | 确认数据外传目标和攻击路径 | 网络团队 |
| DEP-5 | 日志采集管道自身日志（09:08-09:10Z） | 判断 malformed_record 根因 | 平台/运维 |
| DEP-6 | 扩大时间窗口（前后 24 小时）的全量安全日志 | 发现更早的入侵痕迹和后续横向移动 | SIEM/日志平台 |
| DEP-7 | service-a 的业务负责人和令牌申请记录 | 确认令牌合法用途和近期变更 | 服务负责人 |

## 九、残余风险

在上述修复和复测完成前，以下风险持续存在：

1. **数据泄露范围未明**：在 DEP-1 和 DEP-4 获取前，无法确认是否有数据已外泄以及外泄范围。若涉及个人信息，可能触发法律法规下的通报义务。
2. **攻击者可能仍在环境中**：仅吊销 service-a 令牌不足以确认攻击者已被清除。若攻击者通过其他入口（如 admin 账户）建立了持久化，风险仍然存在。
3. **日志可信度受损**：在 malformed_record 根因查明前，基于现有日志的任何否定性结论（"没有其他异常"）均不可靠。
4. **业务中断风险**：吊销 service-a 令牌可能影响依赖该服务的业务流程，需与业务方协调执行窗口。
