## 0. 阅读指引：事实、假设与待补项分离

本方案严格遵循 `product_brief.md` 的交付要求——结论与假设分开，需要外部数据时明确列为待补项；同时遵循 `tiktok-shop-analytics` Skill 的"无实时数据时的限制"条款：分析只能基于手动提供的指标，趋势分析需要历史数据，ROI 计算需要归因设置。因此本方案**不包含任何虚构的销量、GMV、转化率、用户评价或第三方检测结论**；所有数值型指标在 MVP 阶段以"采集口径 + 决策阈值（假设，待首周数据校准）"的形式给出。

### 0.1 已确认事实（来自 `product_brief.md`）

- 目标用户：一二线城市通勤人群。
- 核心卖点：12 小时保温、重量 280g、可拆洗杯盖。
- 建议零售价：199 元。
- 已确认素材：产品白底图、基础规格、品牌主色 #176B87。
- 禁止编造：第三方检测结论、销量、用户评价、竞品价格。

### 0.2 待补项 / 阻断性缺失输入

## 1. 目标受众

基于已确认事实（一二线城市通勤人群），在不引入外部人群数据的前提下，将受众拆分为可在 TikTok 内容中区分的三类内容受众，用于指导素材方向，而非用于声称市场规模：

| 受众分层 | 典型画像（内容层面） | 核心痛点（基于卖点推导，非用户调研结论） | 首要沟通卖点 |
|---|---|---|---|
| 通勤白领 | 地铁/公交通勤、办公桌放杯、早咖啡/茶 | 包重、漏水顾虑、杯盖难清洗有异味 | 280g 轻量、可拆洗杯盖 |
| 户外/健身人群 | 通勤叠加跑步、骑行、健身房 | 保温时长、携带便利性 | 12 小时保温、轻量 |
| 颜值/礼赠人群 | 关注配色与桌面美学、节日送礼 | 外观、配色一致性 | 品牌主色 #176B87 视觉、可拆洗结构 |

> 注：以上痛点为基于产品卖点的**推导假设**，不代表真实用户反馈；需在 MVP 内容评论区与私信中验证（见第 6 节验收标准）。

## 2. 信息结构（卖点 → 用户利益 → 内容钩子）

将三个已确认卖点转译为可在短视频/直播/商品页中一致使用的信息层级。所有表述不得超出已确认事实，未提供检测报告的项（防水、材质安全）不做宣称。

### 2.1 核心信息层级

1. **一句话定位**：为通勤人设计的轻量保温随行杯（280g / 12 小时保温 / 杯盖可拆洗）。
2. **三大利益点**（与卖点一一对应，不添加未证实功效）：
   - 轻：280g，放进通勤包无负担（仅陈述重量事实）。
   - 久：12 小时保温（仅陈述规格事实，不做"更久/远超同类"等比较性宣称）。
   - 净：杯盖可拆洗，减少清洁死角（仅陈述结构事实）。
3. **视觉锚点**：品牌主色 #176B87 贯穿封面、字幕、商品页主视觉。
4. **信任信息（待补，不得提前使用）**：防水等级（P2）、食品接触材料报告（P3）在报告到位前，详情页与口播中**不得出现**相关字样。

### 2.2 渠道信息分工

- 短视频：用 3 秒钩子打一个利益点（轻 / 久 / 净 三选一），不堆砌。
- 直播：按"场景演示 → 规格讲解 → 拆洗演示 → 下单引导"四段式循环。
- 商品页：白底图 + 规格表 + 三大利益点图文；信任模块留空待 P2/P3 补齐。
- 达人内容：提供统一卖点口径卡，禁止达人自行添加未证实宣称。

## 3. 渠道动作（对齐 Skill 四大能力支柱）

Skill 的四大能力为：生意表现分析、内容表现智能、直播分析、达人与联盟追踪。MVP 阶段对应四类动作，每类动作都以"能采集到数据"为前提（对齐 Skill 最佳实践中的归因跟踪与 A/B 测试）。

### 3.1 店铺与商品页（对应"生意表现分析"）

- 完成商品页：标题含核心规格词、白底图主图、规格表、三大利益点图文；品牌主色 #176B87 用于价格栏与按钮。
- 上架前检查：不出现防水、食品级材质等无报告支撑的词（P2/P3 未补齐前）。
- 配置转化漏斗埋点：商品页曝光 → 点击 → 加购 → 下单 → 支付，确保每一层可统计（对应 Skill"转化漏斗优化"能力与"归因跟踪"最佳实践）。
- 价格：199 元零售价上架；促销机制待 P1/P6 确认后再定。

### 3.2 短视频内容（对应"内容表现智能"）

- 首批素材矩阵（基于已确认白底图与规格，不引入外部素材）：
  - 类型 A 产品演示：称重展示 280g、保温计时演示、杯盖拆洗演示。
  - 类型 B 场景内容：通勤包取放、办公桌摆放、健身后饮用。
  - 类型 C 开箱/细节：杯盖拆解结构、配色 #176B87 特写。
- A/B 测试（对齐 Skill 最佳实践"A/B testing：测试内容形式、发布时间与信息"）：
  - 钩子测试：同一卖点做 2 个不同前 3 秒钩子。
  - 形式测试：产品演示 vs 场景内容各发等量条数。
  - 发布时间测试：早通勤时段（假设 7:30–9:00）与午休时段（假设 12:00–13:30）各发等量条数，时段为假设，待数据校准。
- 每条视频挂商品卡，使用统一 UTM/渠道参数，确保内容表现能关联到下单（对齐 Skill"content correlation：将内容表现与生意结果关联"）。

### 3.3 直播（对应"直播分析"）

- MVP 阶段先跑 1 场验证场，时长建议 1–2 小时（具体日期待 P1 确认）。
- 四段式话术循环：场景演示 → 规格讲解（仅讲已确认三项）→ 拆洗演示 → 下单引导。
- 直播前确认：不得口播防水等级、材质检测结论（P2/P3）。
- 采集口径：场观、峰值在线、平均停留、商品点击、下单转化、场均 GMV（对应 Skill 直播指标体系；首屏只建基线，不设考核值）。

### 3.4 达人与联盟（对应"达人与联盟追踪"）

- 首批小批量寄样：数量待定（需结合库存与预算，当前未提供，列为待补）。
- 达人筛选口径（内容层面，不承诺销量）：通勤/办公/健身/好物分享垂类，粉丝量级分层以中腰部为主（具体门槛待预算确认）。
- 给达人统一卖点口径卡与禁用词清单（无报告项不得提）。
- 每位达人使用独立追踪链接/优惠码，以便后续计算达人内容 ROI（对应 Skill"creator content ROI measurement"；ROI 需归因数据，首月只采集不判断）。

## 4. 指标体系（对齐 Skill 输出格式，全部为采集口径，不填虚构实际值）

Skill 报告模板中的 GMV、收入、订单数、转化率等字段，在无历史/实时数据时**不得填值**（依据 Skill"Limitations without real-time data"）。MVP 阶段只定义"采什么、怎么采、用什么阈值做决策"。

### 4.1 生意表现指标

| 指标 | 采集口径 | MVP 阶段用途 |
|---|---|---|
| GMV / 收入 | TikTok Shop 后台已支付订单金额 | 首周建立基线，不做同比/环比 |
| 订单数 | 已支付订单笔数 | 基线 |
| 客单价（AOV） | GMV / 订单数 | 验证 199 元价格带是否需要组合/赠品策略 |
| 转化率 | 支付买家数 / 商品页访客数 | 漏斗优化依据 |
| 获客成本（CAC） | 广告花费 / 广告带来新客数 | 仅在广告账户与归因就绪后采集（P6） |

### 4.2 内容表现指标

| 指标 | 采集口径 | 决策用途 |
|---|---|---|
| 播放量、完播率 | 视频后台 | 筛选钩子与形式 |
| 互动率（赞评藏转/播放） | 视频后台 | 判断内容共鸣 |
| 商品点击率 | 视频挂链点击 / 播放 | 内容→商品页衔接 |
| 内容引导下单数 | 归因到视频的订单 | 对齐 Skill"内容与生意结果关联" |

### 4.3 直播指标

场次数、场均观看、峰值在线、平均停留、直播转化率、场均 GMV——首场均为基线值，不设达标线。

### 4.4 达人与联盟指标

每位达人的内容形式、带来销售额、支付佣金、ROI——首月只采集，ROI 需归因数据齐备后计算（P6）。

### 4.5 归因与监测要求（上线前必须完成）

- 所有渠道（短视频、直播、达人、广告）使用可区分的追踪参数。
- 活动期每日记录一次核心指标（对齐 Skill 最佳实践"Regular monitoring：活动期间每日跟踪关键指标"）。
- 未完成归因配置前，不启动付费投流，避免无法计算 ROI（依据 Skill"ROI calculations need attribution setup"）。

## 5. 最小可验证版本：关键步骤与验收标准

MVP 的目标不是"卖多少"，而是**用最小成本验证"卖点—内容—转化"链路是否打通，并建立第一版数据基线**。每一步都有可客观判定的验收标准。

### Step 0：输入与基建就绪（上线前，阻塞项）

- 关键动作：确认首发日期（P1）；获取防水等级说明（P2）与食品接触材料报告（P3）；确认店铺/类目/广告账户/归因工具状态（P6）；拿到与本产品匹配的发布说明或确认 P4 缺失。
- 验收标准：
  - [ ] P1 有明确日期，或书面确认"日期未定，先做基建"。
  - [ ] P2、P3 报告到位，或书面确认"首发不做相关宣称"。
  - [ ] P6 店铺与归因工具状态已确认，漏斗埋点可采集。
  - [ ] 商品页无禁用词（防水、食品级等无报告项）。

### Step 1：素材与商品页就绪

- 关键动作：基于白底图产出首批 6–9 条短视频素材（A/B/C 三类各 2–3 条）；完成商品页；准备直播话术与口径卡。
- 验收标准：
  - [ ] 商品页上线，含白底图、规格表、三大利益点，品牌主色 #176B87 已应用。
  - [ ] 6–9 条视频成片通过禁用词检查。
  - [ ] 直播话术与达人口径卡完成，且不含无报告宣称。

### Step 2：小流量内容 A/B 测试

- 关键动作：按 3.2 节矩阵发布，每条挂链并带追踪参数；每日记录数据。
- 验收标准：
  - [ ] 每个变量（钩子/形式/时段）至少有 2 条对等素材上线。
  - [ ] 连续记录 ≥7 天数据，形成首版内容基线表。
  - [ ] 能识别出"完播率与商品点击率同时领先"的素材组合（即胜出组合），或明确判定"无显著差异，需扩量再测"。

### Step 3：首场验证直播

- 关键动作：在 Step 2 数据基础上，用胜出内容的卖点做 1 场直播。
- 验收标准：
  - [ ] 直播完成，四段式话术执行。
  - [ ] 直播指标（场观、峰值、停留、商品点击、转化、GMV）全部有记录。
  - [ ] 直播全程无违规/无报告宣称。

### Step 4：小批量达人验证

- 关键动作：按 3.4 节寄样并发放独立追踪链接/优惠码。
- 验收标准：
  - [ ] 每位达人有独立追踪标识。
  - [ ] 回收至少一批达人内容并可统计其带来的点击与订单。
  - [ ] 达人内容未出现禁用宣称。

### Step 5：复盘与 go/no-go 决策

- 关键动作：汇总生意、内容、直播、达人四类基线数据，对照 Skill 三步法进入"优化策略"阶段。
- 验收标准：
  - [ ] 产出首版数据基线表（真实数据，无填充值）。
  - [ ] 明确胜出内容形式与卖点钩子，作为扩量依据。
  - [ ] 对未达标链路给出具体优化项（商品页/钩子/话术/价格机制）。
  - [ ] 决策结论三选一：扩量、调整后再测、暂停——并写明依据的真实指标。

> MVP 周期建议：Step 0–1 为就绪期，Step 2–4 为 2–3 周测试期（具体日期待 P1），Step 5 为复盘。周期为假设，待首发日期确认后锁定。

## 6. 风险与应对

| 风险 | 来源 | 影响 | 应对 |
|---|---|---|---|
| 合规风险：防水、食品接触材质无报告却被宣称 | P2、P3 缺失 | 平台处罚、下架、法律风险 | 报告到位前全渠道禁用相关词；达人口径卡同步约束；Step 0 设为阻塞项 |
| 数据缺失风险：无历史数据导致无法判断好坏 | P5、Skill 限制 | 误判内容/选品效果 | 首周只建基线不设考核；用 A/B 对等组做相对比较；所有阈值标注为待校准假设 |
| 输入不匹配风险：发布说明文件属于另一产品 | P4 | 售后/包装/配件信息缺失 | 不臆造发布说明内容；向产品侧索取正确文件；缺失项留空待补 |
| 排期风险：首发日期未定 | P1 | 渠道动作无法排期 | 先完成 Step 0–1 基建；日期确认后 48 小时内锁定排期 |
| 素材单一风险：仅有白底图 | 已确认素材有限 | 内容形式受限、CTR 偏低 | MVP 用实拍演示/场景补充，不编造第三方素材；如素材不足，扩量前申请新增拍摄 |
| 归因风险：渠道无法区分来源 | P6 | ROI 无法计算（Skill 明确限制） | 归因配置完成前不启动付费投流；全渠道挂追踪参数 |
| 冷启动风险：新链接无权重 | 平台机制 | 初期曝光低 | 以内容自然流量 + 小额测试为主，不预设销量目标；依据真实数据再决定投流 |

- 不把工作假设（A1–A4）当作结论对外传播。
