## 3. 建议（基于事实与假设的方案选择）

### 3.1 建表方案（见 `schema.sql`）

- 三张表：`orders`（订单，按月分区）、`order_items`（明细）、`refunds`（退款，按月分区）。
- 用 `IDENTITY` 代理主键、`numeric(12,2)` 存金额、`timestamptz` 存时间；用 CHECK 约束保证金额非负/为正、数量为正、退款处理时间不早于申请时间。
- 外键引用分区表 `orders` 时，按 PostgreSQL 规则在子表冗余 `order_created_at` 并组成复合外键。
- 建常用索引（客户+时间、状态、SKU、订单号）；`updated_at` 用触发器自动维护。
- 预建 2026-08、2026-09 及 default 分区；生产建议用定时任务或 pg_partman 预创建未来分区。

### 3.2 可复用查询（见 `queries.sql`）

- `v_daily_orders`：每日成交（订单数、付费客户数、GMV），口径 paid+completed。
- `v_daily_refunds`：每日退款申请与已处理笔数/金额。
- `v_daily_refund_rate`：每日退款率（退款金额/GMV），核心统一口径。
- `v_refund_aging`：未结清退款账龄分桶（0-1/1-3/3-7/7 天以上）。
- `fn_refund_rate(start,end)`：任意时间段退款率函数。
- `v_monthly_summary`：月度汇总，复用日视图口径。
- 报表/分析查询应路由到读池（见 3.4），避免冲击主实例。

### 3.3 权限边界（见 `permissions.sql` 与 `infra.sh` 第 7-8 步）

- **控制平面（IAM）**：应用服务账号仅授 `roles/alloydb.client` + `roles/serviceusage.serviceUsageConsumer`；不用 `alloydb.admin` 连库（最小权限，来源见事实表）。管理操作另用受限管理员账号。
- **数据库内（标准 PostgreSQL roles and privileges）**：
  - `app_rw`：订单服务读写订单/明细/退款。
  - `refund_svc`：退款服务仅读订单、写退款，且列级回收 `orders.total_amount` 修改权。
  - `analyst_ro`：分析只读，仅能查 5 个分析视图，回收对基表（含 `customer_id`）的 SELECT。
  - 用 `ALTER DEFAULT PRIVILEGES` 保证未来新表自动授权。
- **认证**：生产用 IAM 数据库认证；IAM 用户先经 `gcloud alloydb users create --type=IAM_USER` 注册（不能仅用 SQL 创建），再在库内 `GRANT alloydbiamuser`。
- **连接**：强制 Auth Proxy 或语言连接器（IAM 认证 + 自动 mTLS）；新部署用 PSC；Cloud Run 必须配 Serverless VPC Access 或 Direct VPC Egress；若开公网 IP，Authorized Networks 收紧到具体网段，绝不 `0.0.0.0/0`。

### 3.4 成本控制（数字均有来源/算式）

**成本杠杆（来自 Skill）：**
- 垂直选型：非生产用 2 vCPU（`SKILL.md` Quick Start 即 2 vCPU），按需 `--cpu-count` 升降配（`cli-usage.md` 第74-77行）。
- 读池水平扩缩：分析负载用读池，节点数按负载调整（`cli-usage.md` 第67-70行）；可评估读池自动扩缩容（Preview，`core-concepts.md` 第129行）。
- 备份保留：连续备份/PITR 窗口默认 14 天（`core-concepts.md` 第58行），非生产可降到 1-7 天以减少日志存储费（事务日志前 7 天免费，定价页）；自动备份按 `30d` 保留（`cli-usage.md` 示例）。
- 存储共享：加读节点不增加存储费（定价页），所以扩读分析能力时存储成本不线性增长。
- 承诺使用折扣：稳定负载用 1 年/3 年 CUD（定价页）。
- 注意：恢复会新建集群（`core-concepts.md` 第59/76行），演练后及时删除恢复出的临时集群；离散备份独立计费直到删除/过期（定价页）。

**示例测算（假设 A2-A4：us-central1、N2/C4A、主实例 2 vCPU/16 GiB、100 GiB 存储、100 GiB 标准备份）：**

| 项 | 算式 | 月费（美元） |
|---|---|---|
| 主实例 vCPU | 2 × $0.06608 × 730 | 96.4768 |
| 主实例内存 | 16 × $0.0112 × 730 | 130.8160 |
| 存储 | 100 × $0.0004109 × 730 | 29.9957 |
| 标准备份 | 100 × $0.000137 × 730 | 10.0010 |
| **合计（按需）** | | **267.2895** |

- 若加 1 个 2 节点读池（每节点 2 vCPU/16 GiB），计算费增加 2 × 227.2928 = 454.5856 美元/月（存储不重复计费）；算式：每节点 2×$48.2384 + 16×$8.176 = 227.2928。
- 若主实例计算签 1 年 CUD：2×$36.1788 + 16×$6.132 = 170.4696 美元/月，较按需 227.2928 节省 56.8232 美元/月（约 25%）。
- 以上算式均经计算器工具复核；价格随区域、机型、时间变化，落地前应以官方定价页/计费计算器为准。

## 4. 数据管理与运维要点

- **备份**：连续备份（PITR）保留 14 天 + 自动备份每周一三五 01:00、保留 30 天 + 重大变更前手动按需备份（命令见 `infra.sh` 第 5 步）。
- **恢复演练**：PITR/离散备份恢复都会创建新集群，演练后删除临时集群避免持续计费。
- **扩缩容**：读池节点数与主实例 CPU 均可在线调整（`infra.sh` 第 6 步）；读池自动扩缩容为 Preview，生产评估后再启用。
- **连接管理**：用内置 PgBouncer 或连接池库控制并发连接（`core-concepts.md` 第46-47行）。
- **配额**：在 Console 配额页（AlloyDB API 过滤）查看与申请提升配额（`core-concepts.md` 第134-136行）。
- **分区维护**：每月预创建下月分区，避免落入 default 分区。

## 8. 落地步骤建议（供用户执行）

1. 准备 GCP 项目、VPC（新部署建议 PSC），安装并 `gcloud auth login`。
2. 替换 `infra.sh` 中占位符后执行第 1-5 步建集群、实例、备份策略。

4. 执行 `verify.sql` 确认结构、约束、权限、口径全部符合预期。
5. 用 `gcloud alloydb users create --type=IAM_USER` 注册 IAM 用户，再在库内 `GRANT alloydbiamuser` 与对应业务角色。
6. 业务放量后用读池承载报表查询，按负载调整节点数/CPU，并评估 CUD。
