## 二、Skill 能力边界与题目假设的冲突说明

**重要事实：本次随消息只上传了 Skill ZIP，没有提供任何既有 React Native 项目代码。** 题目中"同一项目必须兼容既有接口和目录结构"暗示存在一个既有项目，但该项目在当前环境中不可访问，我没有编造其目录结构、接口或依赖版本。

因此我采取的策略是：**交付一个纯新增（additive）的独立组件模块 `rn-design-kit/`，不修改、不覆盖任何既有文件**。该模块严格遵循 Skill 给出的模式与依赖范围，可整体复制进既有 RN 项目的 `src/` 下使用，对既有代码零侵入。

Skill 的真实能力边界是：React Native 样式（StyleSheet/主题/响应式）、React Navigation 6+ 导航、Reanimated 3 动画与 Gesture Handler 手势。题目未要求搭建导航栈，且没有既有路由结构可兼容，因此我**没有**擅自引入 `@react-navigation/*` 的实际导航配置，只在演示页注释中保留了接入点；这符合"以 Skill 真实能力边界为准，不因题目推断扩张职责"的要求。

## 四、前端组件、交互状态与响应式实现

### 组件
- **Button**：三种 variant（filled/outlined/ghost）、三种 size（sm/md/lg）、disabled、loading（ActivityIndicator）、leftIcon/rightIcon。
- **ItemCard**：图片 + 标题（单行截断）+ 副标题（两行截断），采用 SKILL.md Quick Start 的 `AnimatedPressable` + `withSpring` 按压缩放。
- **Input**：label、聚焦时主色边框、错误时错误色边框 + 错误文案、左右图标插槽。
- **Text / Container / VStack / HStack / Spacer**：基础排版与布局原子组件。

### 交互状态
- 按下：Reanimated 3 `useSharedValue` + `useAnimatedStyle` + `withSpring(0.97)`，worklet 运行在 UI 线程（Skill Best Practice #3）。
- 禁用/加载：`opacity: 0.5`、屏蔽 onPressIn/Out、`accessibilityState` 同步。
- 输入框聚焦/错误：React state 管理边框色，未使用动画（避免无意义 worklet 开销）。
- 全部可点击元素带 `accessibilityRole`/`accessibilityLabel`/`accessibilityState`。

### 响应式
- 使用 `useWindowDimensions`（**不是** `Dimensions.get`），保证旋转/分屏实时更新。
- `useBreakpoint`（sm/md/lg/xl，断点 768/1024/1280）+ `useResponsiveValue` 向下回退。
- 演示页 `numColumns` 随断点 1→2→3→4 列变化，图片高度与间距同步响应；通过 `key={`cols-${numColumns}`}` 让 FlatList 在列数变化时正确重建。

## 五、约束如何改变了实现选择

| 约束 | 对实现的影响 |
|---|---|
| 兼容既有接口/目录、不随意升级主版本 | 全部文件为新增，不改动既有文件；组件 props 设计为可选插槽（leftIcon/rightIcon/style），便于渐进接入；不锁定 React Navigation 版本，未强依赖它。 |
| 不引入未经批准的新依赖 | 仅使用 Skill 示例中出现的依赖：`react-native`、`react-native-reanimated`、`react-native-safe-area-context`。**未引入** `@expo/vector-icons`（Expo 专属，裸项目可能没有）、`styled-components`（Skill 提及但非必需）、`@react-navigation/*`（无既有路由可接）。图标一律用 `React.ReactNode` 插槽由调用方传入。 |
| 以 Skill 能力边界为准 | 没有扩展到后端、状态管理库、Web 适配等 Skill 未覆盖的领域；手势部分只用到 Pressable + Reanimated，未引入 Gesture.Pan 等更重的手势（演示场景不需要，避免增加接入成本）。 |
| 最小改动 | 单文件可独立删除；`src/index.ts` 统一导出，既有页面按需 import 即可，不强制全局改造。 |

## 六、实际影响交付结果的 SKILL.md 规则（至少一条）

**SKILL.md Best Practice #7："Use FlatList for Lists — Never use ScrollView with map for long lists"** 直接决定了 `ShowcaseScreen` 的实现：卡片网格使用 `FlatList` + `numColumns`，而不是 `ScrollView` + `map`。这同时影响了 `renderItem`/`keyExtractor` 的 `useCallback` 记忆化方式（Best Practice #2）。

另一条是 **Best Practice #3："Run Animations on UI Thread — Use Reanimated worklets for 60fps"**，决定了 Button 和 ItemCard 的按压动画全部用 `useAnimatedStyle` worklet 实现，而不是 JS 线程的 `Animated.Value`。

## 七、回滚办法

本模块为纯新增目录，回滚零风险：

```bash
# 在项目根目录执行，删除整个新增模块即可
rm -rf src/rn-design-kit   # 若复制到了 src 下
# 或直接删除本交付目录 rn-design-kit/
```

- 没有修改 `package.json`、`babel.config.js`、既有 `src/` 下任何文件。
- 若既有项目此前未安装 `react-native-reanimated` 或 `react-native-safe-area-context`，则需要 `npm uninstall` 这两个包（仅当它们是本次新增时）；Reanimated 3 的 babel 插件配置若为此新增，一并移除 `babel.config.js` 中的 `react-native-reanimated/plugin`。**注意：这两个包是 RN 生态极常见依赖，删除前请确认既有项目没有其他地方在用。**

## 九、仍待确认项 / 无法访问的资源

1. **既有项目不存在**：当前环境未提供任何 RN 项目代码，无法核对既有目录结构、TS 配置路径别名、依赖版本、导航结构。组件中的相对 import 假设模块位于 `src/rn-design-kit/`，若既有项目使用路径别名（如 `@/components`）需调整。
2. **Reanimated 3 babel 插件**：Reanimated 3 要求在 `babel.config.js` 插件列表末尾添加 `react-native-reanimated/plugin`。既有项目是否已配置未知，需确认；未配置会导致动画 worklet 运行时报错。
3. **react-native-safe-area-context**：Container 依赖 `SafeAreaProvider`。既有项目根部是否已包裹未知；App.example.tsx 展示了包裹方式，若已有则不要重复包裹。
4. **RN 版本与 `gap` 属性**：Stack 组件使用了 flex `gap`，需 RN ≥ 0.71。若既有项目版本更低，需改为 margin 方案——请确认最低支持版本。
5. **图片占位 URL**：演示页使用 `placehold.co` 占位图，需联网；离线环境图片区域只显示主题底色。这是示例数据，非真实业务数据。
6. **设计稿基准尺寸**：`responsive.ts` 的等比缩放以 375×812 为基准，若团队设计稿基准不同需调整 `guidelineBaseWidth/Height`。
7. **未实际运行/构建**：未执行 tsc、Metro 构建、真机测试，代码为按 Skill 模式编写的静态交付，运行结果需在项目环境验证。
