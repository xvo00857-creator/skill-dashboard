# Reflect 变化场景执行方案（约束调整版）

> 场景：通过结构化提问复盘经历，归纳有效方法和下一步改进。
> 制定日期：2026-08-10（周一）
> 约束变化：可用时间临时减半；周三（8/12）增加一场不可移动的评审会；结果需移交另一位同事接手。

---

## 一、目标

在时间减半、周三有评审会、且需交接的三重约束下，完成一次有实质价值的 reflect 复盘——不是走过场，也不是追求完整版面面俱到——产出一份接手同事可直接继续的结构化记录，核心包含：方向判断（是否继续/转向/暂停）、已识别的有效方法、关键偏差预警、以及下一步具体动作。

## 二、依据

本方案依据随附 `reflect` Skill 的以下规则制定，调整均为对原规则的有意识偏离而非忽略：

- **SKILL.md 核心流程**：Stop directive → 重读全程 → 5 维度分析 → 散文输出 → Continue/Pivot/Pause 结尾。
- **5 维度框架**（SKILL.md「The 5-Dimension Analysis Framework」）：宏观视角、差距分析、反思性探究、偏差检查、情境对齐。
- **偏差检查是底线**（`references/cognitive_bias_canon.md`）：「A reflection that doesn't check for cognitive bias is just a summary.」5 种偏差为确认偏差、沉没成本、锚定、复杂性偏差、近因偏差。
- **诚实输出纪律**（`references/honest_output_discipline.md`）：不制造问题、不模糊安慰、每条观察须有具体证据、结尾必须具体。
- **重读全程而非仅看最近**（`references/conversation_reflection_practice.md`）：最常见失败是「近因偏差式反思」——只看最近几轮。
- **输出格式规范**（SKILL.md「Tone and Format Rules」）：标准输出为流畅散文、无标题、无列表；结尾三选一。
- **三个检查脚本**（`scripts/`）：`bias_pattern_detector.py`、`conversation_depth_analyzer.py`、`directional_recommendation_validator.py`，均为纯 Python 标准库启发式工具。

## 三、约束变化如何改变原方案

| 原方案假设 | 变化后现实 | 对执行的影响 |
|---|---|---|
| 时间充裕，可完整重读全程+5 维度全做 | 时间减半 | 5 维度不能等权分配；必须按价值砍维度；重读从「全程逐轮」改为「锚点跳读」 |
| 输出面向当前对话参与者，上下文共享 | 接手同事无前序上下文 | 散文体不够用，需要结构化元数据包装（背景、状态、待办、决策理由） |
| 输出是即时对话文本，不需要持久化 | 结果需交接 | 必须产出文件；必须标记「已完成/未完成/待确认」 |
| 无外部里程碑打断 | 周三不可移动评审会 | 倒排工期：周二结束前须有可交接初版；评审会可能注入新信息，周三后方向可能调整 |
| 5 种偏差全扫 | 时间只够重点扫 | 优先扫「赶工时最易犯」的偏差：确认偏差（只看支持证据）、复杂性偏差（加层不加理由）、近因偏差（忘了原始目标） |

**核心判断**：时间减半不等于质量减半。reflect 的核心价值是「发现方向漂移」和「识别认知偏差」，这两项保住，其余维度可压缩。最危险的失败模式不是「维度做少了」，而是「为了赶时间跳过偏差检查，把当前方向合理化」——那恰好是 confirmaton bias 本身。

## 四、调整后的执行步骤

### 阶段 A：周一剩余时间——锚定与骨架（约占可用时间 30%）

1. **Stop directive**：暂停手头正在做的细节工作，不边做边反思。
2. **写下原始目标**（1-2 句）：这次复盘最初要回答什么问题？写下来，作为后续所有判断的锚点——这是对抗近因偏差的关键动作。
3. **锚点跳读而非全程逐读**：从记录中抽取 3-5 个关键节点（起点、1-2 个转折、最近状态），不逐轮重读。每个节点标注：当时目标是什么、做了什么决定、为什么。
4. **快速偏差扫描**（重点 3 种）：
   - 确认偏差：目前引用的证据是否只支持当前方向？有没有反例被忽略或 dismiss 掉？
   - 复杂性偏差：复盘过程中是否层层加了步骤/检查/包装，但说不清每一层防止什么具体失败？
   - 近因偏差：最近几轮在做的事，是否还连着原始目标？还是已经漂移到「解决最近冒出来的子问题」？
   - （沉没成本、锚定：快速过一眼，没有强信号就不深挖。）

### 阶段 B：周二——核心分析与交接文档（约占可用时间 50%）

5. **3 维度核心分析**（取代原 5 维度等权分配）：
   - **宏观视角（必做）**：原始目标 vs 当前方向——是收窄还是漂移？引用具体节点证据。
   - **偏差检查（必做，阶段 A 扫描的深化）**：对发现的每个偏差，命名、引证据、给纠正动作。没发现的也要明确说「检查过，未发现」。
   - **反思性探究（精简为 3 个问题）**：问题框定对了吗？有没有更简单的路被过度复杂化了？有没有更难但更值的路被回避了？
   - 差距分析和情境对齐：合并为一段快速检查——有无未验证的关键假设？有无遗漏的利益相关者？有无外部约束没考虑？有就记，没有就过。
6. **撰写内层散文分析**：按 SKILL.md 的散文规范写核心 reflect 段落——无标题、无列表、有具体证据、有明确方向判断。这段是思考质量的载体，不因交接而牺牲。
7. **包装外层交接元数据**（这是对 SKILL.md「纯散文」规范的有意识偏离，理由见第五节）：
   - 背景与原始目标
   - 当前状态（已完成什么、进行中什么、未开始什么）
   - 关键决策及理由（为什么选这个方向、放弃了什么）
   - 识别的偏差及纠正建议
   - 方向判断（Continue/Pivot/Pause）及具体理由
   - 待办清单（接手人可直接执行的下一步）
   - 风险与未决问题
   - 附录：关键节点摘录/证据引用

### 阶段 C：周三评审会前——冻结与移交（约占可用时间 20%）

8. **周二结束前自审**：用 `directional_recommendation_validator.py` 检查内层散文段落是否通过（有方向建议、无模糊安慰、有具体证据、无制造问题）。不通过则改到通过。
9. **标记版本**：周二版本标记为「评审前草案 v0.9」。评审会可能带来新输入，接手人应知道这是评审前状态。
10. **交接**：将文档交给接手同事，附一句口头/书面说明：哪些是确定的、哪些是待评审确认的、评审会后需要重新评估什么。

### 阶段 D：周三评审会后（接手同事主导，原负责人可选参与）

11. 根据评审反馈，判断方向是否需要调整。如果评审确认了方向 → 升 v1.0 继续；如果评审提出重大异议 → 触发一次轻量 reflect（只做宏观视角+偏差检查），决定是否 Pivot。

## 五、关键取舍

| 取 | 舍 | 理由 |
|---|---|---|
| 偏差检查（尤其是确认/复杂性/近因）必做 | 5 维度等权分配、5 偏差全扫 | cognitive_bias_canon.md 明确说不查偏差的反思只是总结；时间紧张时人最容易犯这三种偏差 |
| 锚点跳读 3-5 个关键节点 | 全程逐轮重读 | conversation_reflection_practice.md 警告近因偏差，但全程逐读在减半时间内不现实；锚点跳读保留了「从原点对比」的纪律，是性价比最高的折中 |
| 外层结构化交接文档 | 严格遵守 SKILL.md「纯散文无标题」输出格式 | SKILL.md 的散文规范面向共享上下文的即时对话；交接场景下接手人没有上下文，纯散文会导致信息无法快速定位。内层核心分析仍用散文体保证思考质量，外层加结构是为交接服务的务实偏离——此偏离本身应在文档中注明 |
| 周二结束前出「评审前草案」 | 等评审会后再出完整版 | 评审会是硬约束，倒排要求周二有可交接物；评审后可能调整方向，等到评审后再写会导致交接窗口被压缩到几乎为零 |
| 方向判断必须具体（Continue/Pivot/Pause） | 「再看看」「考虑一下」 | honest_output_discipline.md 明确禁止模糊结尾；时间紧更不能模糊，接手人需要明确的起点 |
| 没发现问题就说没发现 | 为了显得反思有深度而制造问题 | honest_output_discipline.md：制造问题比诚实认可更糟；接手人会被假问题带偏 |

## 六、风险

| 风险 | 触发条件 | 缓解 |
|---|---|---|
| 精简维度导致遗漏真实问题 | 砍掉的维度恰好藏着关键问题 | 偏差检查作为安全网保留；如果偏差检查发现强信号，允许回补对应维度的深挖 |
| 交接文档变成形式主义 | 外层结构填了但内层分析空洞 | 内层散文必须过 validator；validator 检查具体证据引用数量，空洞内容过不了 |
| 周三评审会推翻周二结论 | 评审带来方向性新信息 | 文档标记为「评审前草案」；阶段 D 预留了评审后轻量 reflect 的动作；不把周二结论写成终稿 |
| 接手人误解「Pivot/Pause」的具体含义 | 方向建议写得不够具体 | 按 SKILL.md 规范，Pivot 须写明「转向 X、放弃 Y」，Pause 须写明「等回答什么问题、不回答的代价是什么」，不允许只写「建议重新考虑」 |
| 赶时间时自身犯确认偏差——把「时间不够只能这样」合理化 | 分析过程中只引用支持「继续当前方向」的证据 | 阶段 A 快速扫描的第一项就是确认偏差；写文档时主动列「最强反例是什么」 |
| 锚点跳读选点有偏——只选支持当前方向的节点 | 选择关键节点时下意识跳过不利节点 | 选点标准：起点+转折+最近，不按「哪个有利」选；如果某个节点让你不舒服，那恰恰是该选的 |

## 七、衡量方式

本次调整版 reflect 是否成功，看以下标准：

1. **接手人可独立继续**：接手同事拿到文档后，无需追问原负责人即可理解现状、方向和下一步。（可在交接后直接问接手人：「有没有什么是你看了文档仍不确定的？」）
2. **内层散文通过 validator**：`directional_recommendation_validator.py` 对内层核心分析段落的检查结果为 PASS（6 项全过）或至少无 FAIL。
3. **偏差检查有实质内容**：不是「检查过了没问题」一句话，而是对每种重点偏差明确说明「检查了什么、发现/没发现、证据是什么」。
4. **方向建议具体**：结尾是 Continue with reason / Pivot to X away from Y / Pause for Q with cost 之一，不是模糊表述。
5. **时间节点达标**：周二结束前有可交接的 v0.9 文档。

2. 今天剩余时间：完成锚点跳读和快速偏差扫描（阶段 A）。

5. 周三评审会后：接手同事主导，根据反馈决定升版或触发轻量 reflect（阶段 D）。

## 附录 A：本次实际执行的检查流程

以下为制定本方案时真实运行的 Skill 脚本及结果：

### 1. bias_pattern_detector.py（--sample 模式）

运行 `python3 scripts/bias_pattern_detector.py --sample`，使用内置多偏差样例对话验证脚本功能。结果：检测到 sunk_cost、anchoring、complexity 三种偏差（complexity 命中 9 次），confirmation 和 recency 未触发。这确认了脚本可运行，且其检测逻辑与本方案「时间紧张时重点防 complexity bias 和 confirmation bias」的判断一致——样例中 complexity 信号最密集，正是「不停加层」的赶工模式。

### 2. conversation_depth_analyzer.py（--sample 模式）

运行 `python3 scripts/conversation_depth_analyzer.py --sample`，内置样例为 19 轮调试对话。结果：OFFER_REFLECT（挫败标记 8 处、死胡同标记 4 处）。本场景中没有可喂入的真实对话记录文本，该脚本的作用是确认其判断逻辑存在，并在方案中保留「如果复盘过程本身陷入多轮死胡同，应主动提出 reflect」这一触发条件。

### 3. directional_recommendation_validator.py（--sample-pass / --sample-fail）

- `--sample-pass`：PASS（6/6 项通过），确认 validator 认可的正确形态是：有 continue 结尾、无模糊安慰、无制造问题、无标题、无列表、有 16 处具体证据引用。
- `--sample-fail`：FAIL（4 项 FAIL、1 项 WARN），反面教材特征：无方向建议、有模糊安慰（"looks good"、"on the right track"）、有标题和列表、无具体证据。

**关于本方案文档本身**：本文件是结构化 Markdown 方案文档（用户明确要求的交付物），不是一次 reflect 调用的散文输出，因此不直接适用 directional_recommendation_validator 的「无标题无列表」规则。方案中「阶段 B 第 6 步」要求内层核心分析段落按散文规范撰写并通过 validator——那一段才是 validator 的检查对象。这是对 SKILL.md 输出格式规范的有意识、有理由的偏离，已在第五节「关键取舍」中说明。
