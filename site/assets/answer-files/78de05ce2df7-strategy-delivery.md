## 2. 最小可验证版本（MVV）

> 目标：用最少的已确认素材跑通"曝光→点击→加购→结账"全链路，验证核心卖点的点击与加购转化，不依赖任何待补项。

### 2.1 MVV 范围

| 模块 | MVV 包含 | MVV 不包含 |
|---|---|---|
| 商品详情页 | 白底图 + 三大卖点文案 + 基础规格表 + 品牌主色 #176B87 视觉 | 场景图、检测报告、用户评价区 |
| 短视频 | 3 条钩子视频（纯产品展示 + 字幕卖点） | 达人合作、剧情类内容 |
| 紧迫感策略 | 真实库存提示 + 首发预告（日期待定，暂不写具体日期） | 虚假倒计时、虚构销量 |
| 结账流程 | 默认结账路径走通 + 1 个首发优惠（如立减/赠品） | 多支付方式定制、弃购挽回邮件 |

### 2.2 MVV 关键步骤与验收标准

| # | 关键步骤 | 验收标准 |
|---|---|---|
| 1 | 详情页上架审核通过 | 页面在 TikTok Shop 前台可正常访问，无审核驳回 |
| 2 | 3 条视频通过审核并获得基础曝光 | 每条视频状态为"已发布"，可正常播放 |
| 3 | 商品可被加购 | 测试账号可成功将商品加入购物车 |
| 4 | 结账全链路走通 | 测试账号可完成从加购到支付的完整流程（可使用测试支付） |
| 5 | 基础埋点可采集 | 可获取曝光量、点击率、加购率、结账完成率四项基础数据 |
| 6 | 无违规宣称 | 全链路素材中不出现防水、检测认证、销量、评价等未证实内容 |

## 6. 指标体系（KPIs）

### 6.1 MVV 阶段核心指标（必须可采集）

| 指标 | 定义 | MVV 观察目的 |
|---|---|---|
| 曝光量 | 商品/视频被展示次数 | 确认流量入口正常 |
| 点击率（CTR） | 点击数 / 曝光数 | 验证主图与视频钩子吸引力 |
| 加购率 | 加购数 / 商品页访问数 | 验证卖点与价格说服力 |
| 结账完成率 | 支付订单数 / 发起结账数 | 验证结账流程顺畅度 |
| 视频完播率 | 完播数 / 播放数 | 验证视频内容留存 |

### 6.2 优化阶段指标（MVV 后跟踪）

| 指标 | 用途 |
|---|---|
| 转化率（CVR） | 整体转化效率 |
| 客单价（AOV） | 优惠/组合策略效果 |
| 弃购率 | 结账流失定位 |
| 退款/退货率 | 产品与预期一致性 |
| 客服咨询转化率 | 答疑对成交的影响 |

> **注意**：以上为指标框架，不设具体数值目标。SKILL.md 明确建议"用你的店铺数据验证"，在无历史数据的情况下，任何目标数值均为编造，故仅定义指标与采集方式，基准值待 MVV 上线后以真实数据建立。

## 11. 结论与假设分离

### 结论（基于已确认信息）

1. 智能随行杯三大已确认卖点（12h 保温、280g、可拆洗杯盖）可直接支撑 199 元中端定位的功能价值表达。
2. 当前素材仅够搭建 MVV 版详情页，场景图与信任素材缺失，需分阶段补齐。
3. 结账链路必须在首发前用测试订单端到端验证，这是 P0 事项。
4. 紧迫感策略只能使用真实库存与真实优惠，倒计时需等首发日期确认，销量/评价类信号在有真实数据前不得使用。
5. `product_release_notes.md` 与本产品无关，不能作为方案依据。

### 假设（需用真实数据验证）

1. 目标受众年龄区间 22–40 岁为基于"通勤人群"的推断，需用店铺人群画像验证。
2. 视频时长 15–30 秒、前 3 秒钩子结构为 TikTok Shop 通用最佳实践，需用完播率与 CTR 验证。
3. 卖点排序（保温→轻量→易清洁）为基于通勤痛点的假设，需用加购率/点击热力验证。
4. 各环节转化率基准值在 MVV 数据采集前无法确定，本方案不设数值目标。
