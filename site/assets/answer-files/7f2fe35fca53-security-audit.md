## 3. 详细分析（按 SKILL.md 证据块格式）

### R1. 服务令牌作用域越界后数据外泄 —— 严重（Critical）

**信任链（principal → 权限边界 → 动作 → 影响）**

1. 主体侧：服务主体 `service-a`，来源 IP `203.0.113.8`，于 09:04:02 调用 api。
2. 权限/作用域边界：事件 `token_scope_mismatch`（high）表明该令牌被用于其授权作用域之外——即令牌所持权限与实际请求不匹配，构成越权边界。
3. 动作侧：09:07:30（间隔约 3 分 28 秒），**同一来源 IP `203.0.113.8`** 对 db 系统执行 `unexpected_export`，且 user 字段为 `unknown`（身份未认证/未关联）。
4. 影响侧：数据库发生非预期导出，severity=critical，疑似数据外泄。

**证据块**

- 主体侧：行 4 `2026-08-12T09:04:02Z,api,high,token_scope_mismatch,service-a,203.0.113.8`
- 动作侧：行 5 `2026-08-12T09:07:30Z,db,critical,unexpected_export,unknown,203.0.113.8`
- 关联依据：两事件来源 IP 相同（203.0.113.8），时间窗紧邻（< 4 分钟），且 severity 从 high 升级到 critical，user 从服务主体退化为 unknown，符合"令牌滥用/被盗用后横向到数据库导出"的链路特征。

**判定**：这是本日志中唯一的决定性（decisive）链路。依据 `references/k8s-control-plane.md` 的"Trust Chain To Reconstruct"，主体（service-a 令牌）→ 边界（scope mismatch）→ 动作（export）→ 影响（critical 数据外泄）五段中前四段已由日志证实，第五段"具体外泄数据范围"日志未提供，不做推断。

**修复建议**
1. 立即吊销/轮换 `service-a` 令牌，审查该令牌的作用域声明与实际授权是否一致。
2. 对 api 层强制令牌作用域校验：scope 不匹配应拒绝请求并告警，不应仅记录 high 后放行。
3. 对 db 层导出操作实施强身份认证与最小权限：禁止 `unknown`/匿名主体执行导出；导出需二次审批与限流。
4. 对 203.0.113.8 在该时间窗的所有会话做溯源，确认导出的数据范围与接收方。
5. 建立跨系统关联告警：同一 IP 在短时间内出现 token_scope_mismatch 后紧接 db critical 事件，应自动升级为事件响应。

### R2. admin 账户短时连续登录失败 —— 中（Medium）

**信任链**

1. 主体侧：目标账户 `admin`，来源 IP `198.51.100.23`。
2. 动作侧：09:03:45 与 09:03:49 两次 `login_failed`，间隔仅 4 秒。
3. 影响侧：未成功登录（无后续 login_success），暂无进一步横向动作记录。

**证据块**

- 行 2：`2026-08-12T09:03:45Z,web,warning,login_failed,admin,198.51.100.23`
- 行 3：`2026-08-12T09:03:49Z,web,warning,login_failed,admin,198.51.100.23`

**判定**：4 秒内两次失败符合自动化尝试特征，但样本量仅 2 次，未达典型暴力破解阈值，且无成功登录，定为中。需注意该事件发生在 R1 之前约 14 秒，但来源 IP 不同（198.51.100.23 vs 203.0.113.8），现有证据不足以将二者关联为同一攻击活动。

**修复建议**
1. 对 admin 账户启用登录失败锁定/退避策略与 CAPTCHA。
2. 禁止 admin 账户从公网直接登录，改用堡垒机/VPN + MFA。
3. 对 198.51.100.23 持续监控，若失败次数上升自动拉黑。

### R3. 畸形日志记录 / 日志完整性存疑 —— 中（Medium）

**证据块**

- 行 6：`2026-08-12T09:09:00Z,web,,malformed_record,,`
- severity、user、source_ip 三字段为空，事件名本身为 `malformed_record`。

**判定**：该记录可能是日志采集/格式化异常，也可能是日志注入或篡改尝试。在 R1 数据外泄事件后约 1.5 分钟出现，时间上敏感，不能排除掩盖痕迹的可能。日志字段缺失会削弱审计溯源能力，本身即构成完整性风险。

**修复建议**
1. 校验日志管道：确认是采集端格式错误还是上游写入异常。
2. 对日志启用完整性保护（如追加写入、哈希链/集中式日志服务），防止本地篡改。
3. 对空字段/畸形记录设置采集质量告警，畸形率超过阈值即通知。
4. 排查 09:09:00 前后 web 系统是否有异常请求或日志写入中断。
