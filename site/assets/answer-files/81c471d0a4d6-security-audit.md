## 四、风险分级与证据

### R1【严重 / Critical】数据库异常导出（疑似数据外泄）

- **证据（原始日志）**：
  `2026-08-12T09:07:30Z,db,critical,unexpected_export,unknown,203.0.113.8`
- **分析**：db 系统发生 unexpected_export，用户为 `unknown`（未认证/身份不明），来源 IP `203.0.113.8`。该 IP 在约 3.5 分钟前刚发生 api 层 token_scope_mismatch（见 R2），构成"令牌越权→数据导出"的可疑链路。
- **潜在影响**：敏感数据被未授权导出，存在数据泄露风险。

### R2【高 / High】令牌作用域不匹配（疑似令牌滥用/越权）

- **证据（原始日志）**：
  `2026-08-12T09:04:02Z,api,high,token_scope_mismatch,service-a,203.0.113.8`
- **分析**：`service-a` 的令牌在 `203.0.113.8` 上触发作用域不匹配，表明该令牌被用于其授权范围之外的资源/操作。与 R1 同源 IP、时间紧邻，疑似令牌被盗用或过度授权后被用于访问数据库并导出数据。
- **潜在影响**：服务账号令牌失陷，可导致横向访问与数据外泄。

### R3【中 / Medium】管理员账户连续登录失败（疑似暴力破解/口令喷洒）

- **证据（原始日志）**：
  `2026-08-12T09:03:45Z,web,warning,login_failed,admin,198.51.100.23`
  `2026-08-12T09:03:49Z,web,warning,login_failed,admin,198.51.100.23`
- **分析**：同一 IP `198.51.100.23` 在 4 秒内连续两次对 `admin` 账户登录失败。样本量较小（仅 2 次），未达明确暴力破解阈值，但针对管理员账户的短时重复失败应作为可疑行为跟踪。该 IP 与 R1/R2 不同，暂未发现直接关联。
- **潜在影响**：若持续尝试，管理员账户存在被攻破风险。

### R4【信息 / Info】正常登录

- **证据（原始日志）**：
  `2026-08-12T09:00:12Z,web,info,login_success,alice,192.0.2.10`
- **分析**：alice 正常登录，无异常特征，记录为基线。

### R5【数据质量 / 需排查】畸形日志记录（疑似日志篡改或采集异常）

- **证据（原始日志）**：
  `2026-08-12T09:09:00Z,web,,malformed_record,,`
- **分析**：该记录 severity、user、source_ip 字段均为空，事件类型为 malformed_record，发生在 R1 异常导出之后约 1.5 分钟。两种可能：① 日志采集/解析管道异常导致字段丢失；② 攻击者在异常操作后干扰日志以掩盖痕迹。在未排除前，应按"可能的日志完整性事件"对待。
- **潜在影响**：若为篡改，将影响事件溯源与取证完整性。

## 五、攻击链关联分析

`203.0.113.8` 在 09:04:02 触发 api 层 token_scope_mismatch（service-a 令牌越权），随后在 09:07:30 以 unknown 身份对 db 发起 unexpected_export。两事件**同源 IP、时间间隔约 3.5 分钟、跨 api→db 两层**，构成最需要优先处置的可疑链路：

> 令牌作用域越权（R2） → 未授权数据库导出（R1）

09:09:00 的畸形记录（R5）在时间上紧随其后，需排查是否与该链路相关（日志干扰）。

`198.51.100.23` 的 admin 登录失败（R3）为独立事件，当前样本不足以与上述链路并案，但应纳入监控。

## 六、修复建议

### 针对 R1（数据库异常导出）
1. 立即核查 09:07:30 前后数据库导出任务的具体内容、目标位置与操作者，确认泄露范围。
2. 临时封禁或限流来源 IP `203.0.113.8` 对数据库的访问，待排查完成后解除。
3. 撤销/轮换 `service-a` 及同期可能受影响的数据库凭据与令牌。
4. 对数据库导出操作增加审批与二次认证，禁止 unknown/匿名身份执行导出。

### 针对 R2（令牌作用域不匹配）
1. 立即轮换 `service-a` 令牌，审查其授权作用域是否遵循最小权限原则。
2. 在 API 网关/中间件强制校验令牌作用域（scope）与所请求资源的匹配关系，越权请求一律拒绝并告警。
3. 建立服务账号令牌使用基线（常用 IP、常用操作），对偏离基线的使用触发告警。

### 针对 R3（管理员登录失败）
1. 对 admin 账户启用多因素认证（MFA）。
2. 配置登录失败阈值与账户锁定/速率限制策略（如 5 次失败后临时锁定并告警）。
3. 对 `198.51.100.23` 提高监控级别，若继续尝试则封禁。

### 针对 R5（畸形日志记录）
1. 排查 09:09:00 前后日志采集代理、解析管道是否存在故障。
2. 启用日志完整性保护（集中式追加存储、传输加密、可选日志签名/校验和），防止篡改。
3. 对字段缺失或 malformed_record 类事件配置独立告警。

### 通用建议
- 将 web/api/db 三层日志接入集中 SIEM，配置跨层关联规则（如同 IP 短时间内从 api 越权到 db 导出自动升级为事件）。
- 定期审查服务账号权限与令牌生命周期。
