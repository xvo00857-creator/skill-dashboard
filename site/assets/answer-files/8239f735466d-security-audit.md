## 四、风险分级与证据分析

### R-1：服务账号令牌越权 → 数据库异常导出（严重 / Critical）

**证据链：**

1. `09:04:02` — API 系统记录 `token_scope_mismatch`，用户 `service-a`，来源 IP `203.0.113.8`，严重级 `high`。
   - 含义：服务账号 `service-a` 持有的令牌请求了超出其授权范围的资源/操作。可能原因包括令牌被窃取后滥用、服务账号权限配置错误、或令牌签发逻辑缺陷。
2. `09:07:30` — 数据库系统记录 `unexpected_export`，用户 `unknown`，来源 IP `203.0.113.8`，严重级 `critical`。
   - 含义：数据库发生了未授权或未预期的导出操作，且操作用户标识为 `unknown`（无法关联到已知账户）。
3. **关联点：** 两条事件来源 IP 相同（`203.0.113.8`），时间间隔仅 3 分 28 秒，跨 API 和 DB 两个系统。

**分析：**

同一 IP 先触发 API 层令牌越权，短时间后在数据库层触发异常导出，且数据库操作用户为 `unknown`，这一模式高度符合以下攻击路径：

> 获取/滥用服务账号令牌 → 利用令牌调用超出范围的 API → 通过 API 或直接连接数据库执行数据导出 → 导出时绕过或丢失了用户身份上下文

`unknown` 用户标识尤其值得关注：它可能意味着攻击者通过令牌直接访问数据库而未经过正常的应用层身份传递，或者数据库审计无法解析令牌对应的真实用户。

**影响评估：**

- 机密性：若导出包含用户数据、订单数据或商业数据，可能构成数据泄露。
- 合规性：若涉及个人信息，可能触发数据保护法规下的通报义务。
- 持续性：若 `service-a` 令牌未被吊销，攻击者可能持续访问。

**置信度：中。** 时间与 IP 关联强烈，但缺少数据库导出详情和网络外传证据，无法确认数据是否实际离开系统及泄露范围。

---

### R-2：admin 账户暴力破解尝试（高 / High）

**证据链：**

1. `09:03:45` — web 系统记录 `login_failed`，用户 `admin`，来源 IP `198.51.100.23`。
2. `09:03:49` — 同一 IP、同一用户，4 秒后再次 `login_failed`。

**分析：**

- 两次失败间隔仅 4 秒，手动输入不太可能达到此频率，疑似自动化工具（如 Hydra、Burp Intruder 或自定义脚本）。
- 目标为 `admin` 这一高权限默认账户名，是暴力破解的典型目标。
- 日志中仅出现 2 次失败，可能原因：(a) 攻击被速率限制/账户锁定策略中断；(b) 日志被截断，实际尝试次数更多；(c) 攻击者仅进行了少量探测。
- 该 IP（`198.51.100.23`）与 R-1 中的 IP（`203.0.113.8`）不同，目前无证据表明两起事件关联，但不能排除同一攻击者使用多个节点的可能。

**置信度：中高。** 短间隔重复失败登录指向自动化尝试，但样本量少，无法确认攻击规模和是否成功。

---

### R-3：日志记录畸形，完整性存疑（中 / Medium）

**证据链：**

1. `09:09:00` — web 系统记录 `malformed_record`，severity、user、source_ip 字段均为空。

**分析：**

该记录存在两种可能解释，风险等级不同：

| 解释 | 可能性 | 风险含义 |
|------|--------|----------|
| 日志管道/采集器故障（如字段映射错误、缓冲区截断） | 较高 | 低风险，但影响日志完整性和可观测性 |
| 攻击者主动注入畸形记录以干扰检测或掩盖痕迹 | 较低但不能排除 | 高风险，表明攻击者具备日志操作能力 |

时间上，该记录出现在 critical 事件（09:07:30）后约 1 分 30 秒，若为篡改则时机可疑。但仅凭单条记录无法区分两种解释。

**置信度：低。** 需要日志管道自身的运行指标（如采集错误率）和该时间点前后的完整日志才能判断。

---

### R-4：alice 正常登录（信息 / Info）

**证据：** `09:00:12`，web，`login_success`，用户 `alice`，IP `192.0.2.10`。

**分析：** 单条成功登录记录，无异常特征。作为日志时间窗口内的基线参照。目前无证据表明 alice 的会话被劫持，但在 R-1 攻击链路未完全排除前，不能完全排除内部人员或会话被利用的可能。

## 六、约束与冲突分析

本次分析至少涉及以下约束/冲突及其取舍：

### 冲突一：指定 Skill 与任务领域不匹配

- **冲突内容：** 任务要求"严格按 SKILL.md 执行"，但 `tiktok-shop-branding` 的 SKILL.md 是品牌建设指南，不含安全审计方法论；其声明分类为 `tiktok-shop`，与任务标注的"安全与合规"矛盾。
- **取舍：** 未强行套用品牌策略输出格式（那会产生与安全审计无关的内容），也未假装 Skill 提供了安全指导。仅借用其危机响应五步法作为报告结构骨架，所有安全分析内容基于日志数据本身。在报告中明确标注了这一偏差。
- **影响：** 报告的方法论不具备 Skill 背书；若评测要求严格按 Skill 输出格式，则本报告不满足该形式要求，但满足业务任务实质。

### 冲突二：快速遏制需求 vs. 证据保全需求

- **冲突内容：** R-1 要求立即吊销 `service-a` 令牌、阻断 IP `203.0.113.8` 以遏制潜在数据外泄；但贸然操作可能销毁攻击者会话证据、触发攻击者察觉并加速破坏，或影响依赖 `service-a` 的正常业务。
- **取舍：** 建议**先保全证据（快照数据库审计日志、API 网关日志、令牌使用记录），再执行遏制**，并在业务低峰或确认 `service-a` 非关键服务后吊销令牌。阻断 IP 建议在网络层先行（防火墙/WAF），而非在应用层踢会话，以保留会话表用于取证。
- **影响：** 遏制动作延迟数分钟至数十分钟，但换取了取证完整性和业务连续性。

### 冲突三：数据不足下的定性判断

- **冲突内容：** 日志仅 6 条，缺少导出数据详情、网络外传证据和基线数据，无法 100% 确认数据泄露成立；但若按"疑似"处理而不升级，可能延误真实泄露的响应窗口。
- **取舍：** 采用"按最坏情况假设、按证据充分程度标注置信度"的原则——将 R-1 定为严重并建议立即响应，同时明确标注置信度为"中"，避免过度断言也避免漏报。
- **影响：** 可能存在一定误报成本（如 `token_scope_mismatch` 实为配置错误、`unexpected_export` 实为计划内导出未标注），但在安全事件响应中，误报成本通常低于漏报成本。

## 九、关键取舍、依赖与风险

### 关键取舍

1. **严重级定级偏激进：** 在数据导出详情缺失的情况下仍将 R-1 定为 Critical，理由是"令牌越权 + 异常导出 + unknown 用户"的组合已足够可疑，漏报代价高于误报。
2. **先取证后遏制：** 接受最多数十分钟的遏制延迟以保全证据，前提是已在网络层快速阻断威胁 IP。
3. **未套用 Skill 输出格式：** 如实报告 Skill 不匹配，仅借用其危机响应框架结构，未生成品牌策略类无关内容。

### 依赖

- 数据库审计日志的可获取性和保留周期（决定能否确认泄露范围）。
- API 网关日志的完整性（决定能否还原 `service-a` 令牌的完整调用链）。
- 网络层日志（防火墙/代理/DNS）的可获取性（决定能否确认数据外传）。
- `service-a` 服务的业务归属确认（决定令牌轮换窗口和业务影响评估）。
- 日志管道监控指标（决定 R-3 畸形记录的归因）。

### 残余风险

- 若攻击者已在 09:04–09:07 之间完成数据外传，吊销令牌和阻断 IP 无法收回已泄露数据，需进入数据泄露响应流程（评估影响、合规通报、客户通知）。
- 若 `malformed_record` 确为日志篡改，攻击者可能已删除或修改了其他日志记录，现有证据可能不完整。
- R-2 与 R-1 来源 IP 不同，无法排除两者为协同攻击的可能；若 `admin` 爆破成功，攻击者可能拥有 web 层后台权限。
- 本报告基于模拟数据，IP 地址为 RFC 5737 保留地址，所有阻断/封禁建议在真实环境中需替换为实际威胁情报 IP。
