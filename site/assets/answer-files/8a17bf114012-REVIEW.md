- 审查对象：随消息上传的 `package.json`、`test.js`
- 运行环境：Node.js v20.20.2（本机实测）
- 遵循 Skill：`browser-testing-with-devtools`（ZIP 内仅含 `browser-testing-with-devtools/SKILL.md`）
- 结论：**测试当前无法运行，阻断于缺失的 `src/app.js`**；另有 1 个可移植性缺陷和 1 个测试缺口。最小补丁见 `review.patch`。

## 一、按优先级排序的问题

### P0 阻断：被测模块 `src/app.js` 缺失（真实缺陷）

- `test.js` 第 1 行 `import { normalizeOrder } from "./src/app.js";` 指向的文件不存在，工作目录下无 `src/` 目录。
- 实测证据（补丁前）：

  ```
  > node test.js
  Error [ERR_MODULE_NOT_FOUND]: Cannot find module
  '.../new-chat-213/src/app.js' imported from .../test.js
      code: 'ERR_MODULE_NOT_FOUND'
  Node.js v20.20.2
  退出码 1
  ```

- 影响：`npm test` 必失败；`normalizeOrder` 的实现未提供，无法审查其逻辑，也无法对其行为下任何结论。
- 处置：**本次审查在此停止**。未伪造 `normalizeOrder` 实现，未声称任何用例通过。需补充 `src/app.js`（或修正导入路径）后才能继续。

### P1 测试缺口：`test.js` 不是测试（测试缺口）

- 原文件仅 `console.log(normalizeOrder({ id: 42, amount: "19.9" }));`，无断言、无 pass/fail 判定、无测试框架。
- 即使 `src/app.js` 存在，只要不抛异常，`npm test` 退出码恒为 0，无法发现回归。
- 补丁改用 Node 内置 `node:test` + `node:assert/strict`，增加最小冒烟断言（返回值为非空对象）。更深层的行为断言（amount 是否转数值、精度、非法输入等）需待 `src/app.js` 提供后按其真实契约补充，补丁中以 TODO 标注。

### P1 可移植性缺陷：`package.json` 未声明 ESM 模式（真实缺陷）

- `test.js` 使用 ESM `import`，但 `package.json` 未设 `"type": "module"`。
- 在当前 Node v20.20.2 上，因默认开启的 ESM 语法自动检测（`--experimental-detect-module`）而侥幸被当作 ESM 解析；但这依赖版本行为：
  - 实测 `node --no-experimental-detect-module test.js` 复现：
    `SyntaxError: Cannot use import statement outside a module`（退出码 1）。
  - 在不支持该检测的 Node 版本（如 Node 18、早期 20.x）上同样直接失败。
- 补丁显式添加 `"type": "module"`，消除对版本隐式行为的依赖。

### P2 可维护性

1. 测试脚本 `node test.js` 改为 `node --test test.js`，获得 TAP 报告、正确的失败退出码和用例组织（与 P1 一并修复）。
2. 未声明 `engines` 字段：鉴于 ESM 检测行为随版本变化，建议后续声明最低 Node 版本（本次补丁未加，避免超出最小修改范围）。
3. 无 lockfile：当前无第三方依赖，影响有限；若后续引入依赖应提交 lockfile。
4. 待 `src/app.js` 提供后应补充的测试用例（本次无法编写/验证）：
   - `amount` 字符串→数值的归一化及精度/舍入；
   - `id` 类型保留；
   - 非法输入：`null`/`undefined`/缺少字段/负数/非数字 `amount`；
   - 边界值与空对象。
