## 二、实际影响交付结果的 SKILL.md 规则

**SKILL.md 第 59 行（Step 3 原文）：**

> "This verb is operator-only and runs host-side (via `/setup`, `/customize`, or `/manage-mounts`); it is rejected from inside a container."

这条规则直接决定了交付边界：`ncl groups config add-mount` 是宿主机操作员专属操作，从容器内部调用会被拒绝。本次执行环境是用户的 macOS 宿主机，但该环境未安装 `ncl`（nanoclaw 容器编排工具），也不存在 `data/v2-sessions/<group-id>/` 目录结构，因此 Step 2–5（识别 group、挂载、写 hook、重启容器）及容器内 Verify 均无法在当前环境实际执行。我没有伪造这些步骤的输出，也没有用 `rtk init -g` 等 SKILL.md 未授权的方式绕过容器集成要求。

另一条相关规则是 SKILL.md 第 18 行：该 Skill **没有内置集成测试**，其功能触达点仅为运行时操作员动作（add-mount 与 settings.json 写入），一致性靠"幂等 apply + REMOVE.md + 运行时验证"保证。这意味着在缺少 ncl 运行时的环境中，无法完成端到端验证。

## 四、受约束流程方案（含预检 / 幂等 / 重试 / 人工确认点）

### Step 1 — 宿主机安装 rtk 二进制 ✅ 已完成

```bash
# 预检（幂等保护）
test -x ~/.local/bin/rtk && ~/.local/bin/rtk --version && echo "已安装，跳过" || \
  curl -fsSL https://raw.githubusercontent.com/rtk-ai/rtk/refs/heads/master/install.sh | sh
```

- **预检**：安装前检查 `~/.local/bin/rtk` 是否已存在且可执行；已存在则跳过（幂等）。
- **人工确认点**：安装前先下载脚本到 `/tmp` 并全文审查，确认无越权写入后再执行；脚本本身会做 SHA-256 校验和验证与归档路径遍历检查，校验失败即拒绝安装。
- **重试**：网络下载失败时，安装脚本自带 GitHub API 回退；可设置 `RTK_VERSION=vX.Y.Z` 固定版本重试。
- **实际结果**：安装 rtk v0.45.0 到 `~/.local/bin/rtk`（7,928,416 字节），`rtk --version` 输出 `rtk 0.45.0`。

### Step 2 — 识别目标 agent group ⛔ 受阻

```bash
ncl groups list
```

- **受阻原因**：`ncl` 命令在当前环境不存在。这是 nanoclaw 容器编排工具，需在装有该运行时的宿主机上由操作员执行。
- **不伪造**：未编造 group ID。

### Step 3 — 挂载 rtk 到容器配置 ⛔ 受阻

```bash
ncl groups config add-mount --id <group-id> \
  --host ~/.local/bin/rtk \
  --container /usr/local/bin/rtk \
  --ro
```

- **受阻原因**：依赖 Step 2 的 group-id 与 `ncl` 命令。
- **SKILL.md 约束**：该动词为 operator-only / host-side，从容器内会被拒绝（第 59 行）。
- **前置条件**：SKILL.md 第 61 行要求 `~/.local/bin` 在 `~/.config/nanoclaw/mount-allowlist.json` 外部挂载白名单中；该文件当前不存在。
- **幂等性**：SKILL.md 说明重复执行会跳过已存在条目。
- **人工确认点**：在真实 ncl 环境执行前，需操作员确认 group-id 与白名单变更。

### Step 4 — 写入 PreToolUse hook ⛔ 受阻

```bash
SETTINGS="data/v2-sessions/<group-id>/.claude-shared/settings.json"
jq '.hooks.PreToolUse = ((.hooks.PreToolUse // [])
      | map(select((.hooks // []) | any(.command == "rtk hook claude") | not))
    + [{"matcher":"Bash","hooks":[{"type":"command","command":"rtk hook claude"}]}]' \
  "$SETTINGS" > /tmp/rtk-settings.json && mv /tmp/rtk-settings.json "$SETTINGS"
```

- **受阻原因**：`data/v2-sessions/<group-id>/.claude-shared/settings.json` 路径在当前环境不存在；group-id 未知。
- **幂等性**：jq 表达式先过滤掉已有 rtk hook 再追加，重复执行不产生重复条目。
- **人工确认点**：写入前应备份原 settings.json；写入后用 `jq '.hooks.PreToolUse'` 核验。
- **未采用替代方案**：rtk 自身提示 `rtk init -g` 可全局安装 hook，但 SKILL.md 指定的是通过 ncl 容器 settings.json 集成，二者范围不同；在受约束条件下不擅自修改全局 Claude Code 配置。

### Step 5 — 重启容器 ⛔ 受阻


- **受阻原因**：依赖 `ncl` 与 group-id。

## 七、回滚（依据 REMOVE.md，幂等）

对每个曾集成 rtk 的 group 依次执行：
1. `ncl groups config remove-mount --id <group-id> --host ~/.local/bin/rtk --container /usr/local/bin/rtk`
2. 用 jq 从 settings.json 删除 rtk PreToolUse 条目（保留其他 hook）
3. `ncl groups restart --id <group-id>`
4. （可选）`rm -f ~/.local/bin/rtk`

以上步骤在当前环境同样因 ncl 缺失而无法执行，但 rtk 二进制本身可随时手动删除。
