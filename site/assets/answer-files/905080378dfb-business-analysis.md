## 一、最小可验证版本（MVP）：关键步骤与验收标准

### 关键步骤

1. **解压并阅读 Skill**：读取 `SKILL.md` 及 `scripts/` 下三个脚本，确认分析层级、维度权重、风险阈值与输入格式。

3. **运行引擎**：调用 `analyzer.py` 的 `analyze_reviews()`，因同时具备 content + rating + date + verified_purchase，自动判定为 **L4 完整分析**，输出六维度分数、综合真实性分与高风险评论清单。
4. **交叉比对简报**：将评论文本与 `product_brief.md` 的核心卖点逐条比对，识别内容错配。
5. **人工复核证据**：对引擎标记的异常逐条回到 CSV 原文核实，补充引擎未覆盖的业务语义异常（如产品功能错配、占位评论）。

## 三、异常项与证据（逐条可溯源）

### 异常 A1：两条完全相同的英文 5 星非 VP 评论（强证据）

- **证据**：R002 与 R003 的 `review_text` 逐字一致，均为 `"Amazing product best ever"`；评分均为 5；`verified_purchase=false`；`review_date` 均为 2026-07-01；`helpful_votes` 均为 0。
- **引擎判定**：内容相似度 100/100，Jaccard 相似度 1.0；命中可疑关键词；单条风险 75%。
- **业务含义**：两条评论在同一天、用同一句模板英文发布、均无购买验证，是典型的复制粘贴刷评/水军评论特征。

### 异常 A2：发布时间高度聚集（强证据）

- **证据**：2026-07-01 当天集中 3 条（R001/R002/R003），7 月 1–3 日 48 小时内共 4 条（占总量 67%）；相邻日期间隔 ≤1 天的比例达 60%。
- **引擎判定**：时间聚集 70/100。
- **业务含义**：新品上线初期单日集中爆发评论，且其中 2 条为重复模板，符合"冲量刷评"的时间分布特征。

### 异常 A3：评论内容与商品简报卖点错配（需重点核实）

- **证据**：
  - R001（5 星，VP）称"**续航**符合描述"——暗示产品带电池/电子元件；
  - R004（1 星，VP）称"收到后**无法开机**，已申请售后"——同样指向电子设备；
  - 但 `product_brief.md` 列出的核心卖点仅为"12 小时保温、重量 280g、可拆洗杯盖"，**未提及任何电子/智能功能**；
  - 产品名虽为"智能随行杯"，但简报卖点与"智能/电子"无对应。
- **业务含义（两种可能，均需处理）**：
  1. 产品确实含电子元件（如温控/显示），但简报遗漏了该信息——属于**商品资料缺失**，会误导运营与客服；
  2. 评论属于其他商品（评论串位/污染）——属于**数据质量问题**，需平台侧核查。

### 异常 A4：无评分占位评论（数据质量问题）

- **证据**：R006 的 `rating` 为空，`review_text` 为"评价内容缺失关键信息"，`helpful_votes=0`，非 VP。
- **业务含义**：该条不像真实消费者评论，更像测试数据或占位记录，应在分析前清洗，避免干扰评分分布统计。

### 异常 A5：VP 比例偏低

- **证据**：6 条中仅 3 条为 verified_purchase=true（R001/R004/R005），VP 占比 50%，低于 Skill 内置的 60–80% 正常区间。
- **业务含义**：非 VP 评论恰好集中在两条重复模板好评和一条占位评论上，进一步削弱非 VP 评论的可信度。

### 异常 A6：语言与目标市场不一致

- **证据**：目标用户为"一二线城市通勤人群"、建议零售价 199 元（人民币），4 条评论为中文，但 R002/R003 为英文模板句。
- **业务含义**：面向国内市场的商品出现英文短平快好评，且与中文评论风格割裂，是 A1 刷评判断的辅助证据。

### 补充观察：真实负面口碑信号

- R004 为 VP 1 星评论，`helpful_votes=7`，内容为"无法开机，已申请售后"。若 A3 核实产品确有电子功能，则这是一条**真实的到货故障/售后投诉**，需优先跟进，不能因整体评论存在刷评而忽视。

## 四、运营判断

1. **存在刷评/水军评论的概率高**：R002/R003 的逐字重复 + 同日发布 + 非 VP + 模板化英文 + 0 有用票，构成完整证据链；时间聚集与 VP 比例偏低进一步佐证。综合真实性 47/100 为高风险，与人工复核一致。
2. **商品信息与评论存在错配，必须先核实产品是否含电子元件**：这直接决定 R001/R004 是"真实功能反馈"还是"串位垃圾评论"，也影响新品卖点梳理与客服话术。
3. **若产品确有电子功能，R004 代表的"开不了机"是需紧急处理的质量/售后信号**：VP + 7 有用票说明有其他用户共鸣，可能是批次性问题。
4. **当前样本量过小（6 条），统计维度结论置信度有限**：评分分布维度虽显示"正常"，但仅 5 条有效评分，不足以做分布推断；需积累更多样本后复核。
5. **评论数据治理不足**：占位评论 R006 进入数据集，说明评论采集/入库环节缺少基础校验（评分非空、内容长度阈值）。

## 六、结论与假设分离

### 有直接证据支持的结论

- R002 与 R003 为逐字重复的非 VP 5 星评论，同日发布，高度疑似刷评。
- 评论在 7 月 1 日前后存在时间聚集（48h 内 4 条）。
- VP 比例为 50%，低于 Skill 内置正常区间。
- R006 为无评分占位/测试类记录。
- R001/R004 提及"续航""开机"，而简报卖点未含电子功能，二者存在文本层面的错配。
- 综合真实性评分 47/100，高风险（该分数为 Skill 引擎按既定权重与阈值计算所得）。

### 待验证的假设（不可直接当事实）

- 假设 R002/R003 是人为组织的刷评（也可能是竞品恶意灌评或自动化测试泄漏，需平台侧账号证据确认）。
- 假设产品含电子元件（简报遗漏）；或假设 R001/R004 为其他商品串位评论。二者互斥，需产品侧确认。
- 假设 R004 代表批次性质量问题（目前仅 1 条，需更多同类投诉佐证）。

## 八、方法局限说明

1. Skill 的评分分布维度在代码中使用比例阈值启发式判断（非 SKILL.md 文字描述的卡方检验），且要求 ≥5 条评分评论才启用；本次恰好 5 条，结论"正常"的统计意义有限。
2. VP 比例维度使用内置 60–80% 固定区间，未接入真实品类基准（SKILL.md 提及"category benchmark"但代码未实现外部基准调用）。
3. 内容相似度基于英文 3-gram 与 Jaccard，对中文分词较粗（中文按标点切分为长词），因此中文评论间的相似度可能被低估；本次主要异常由英文重复对触发，不影响 A1 结论。
4. 引擎未做"评论内容与商品类目匹配"的语义校验，A3 类错配由人工结合简报发现。
5. `parser.py` 的 `Review` 类与 `analyzer.py` 的 `Review` 类定义不一致（前者缺少 `has_rating/has_date/has_vp` 属性），直接串联会报错；本次在运行脚本中做了 dataclass 转换，未修改 Skill 源码。

## 九、复现方式

```bash
# 在本目录下，使用 Skill 自带 parser 解析 CSV 后调用 analyzer
python3 run_analysis.py
```

`run_analysis.py` 通过 `ReviewParser.parse()` 读取 `commerce_reviews.csv`，转换为 `analyzer.Review` 对象后调用 `analyze_reviews()`，输出中文报告与结构化 JSON。
