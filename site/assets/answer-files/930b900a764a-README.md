# use-dom Skill 配套工具

围绕 Expo DOM Components（`"use dom"` 指令）的可复用脚手架与静态校验 CLI，严格遵循 `use-dom` Skill 的 SKILL.md 规则。

## 能力边界

本工具只做两件事：

1. **scaffold** — 按 SKILL.md 规则生成新的 DOM 组件文件
2. **validate** — 静态检查已有 DOM 组件是否符合规则

本工具**不**负责：构建 Expo 项目、安装依赖、部署、运行模拟器、修改原生配置。这些属于 Expo CLI / 开发环境的职责，超出本 Skill 范围。

## 受约束的流程保障

| 机制 | 实现 |
|------|------|
| 预检 | 检查 Expo 项目（package.json 含 expo 依赖）、组件名格式、路径不越界 |
| 幂等 | 文件已存在时拒绝覆盖；`--force` 仍需人工确认；覆盖采用临时文件 + rename |
| 重试 | 文件写入失败时指数退避重试 3 次（仅对临时错误） |
| 人工确认 | 覆盖文件、创建文件前均需确认；非交互环境未传 `--yes` 时默认拒绝 |
| Dry Run | `--dry-run` 只打印计划不写文件 |
| 不静默操作外部资源 | 所有写入限制在项目根目录内，路径穿越直接拦截 |

## 用法

```bash
# 创建组件
node bin/dom-component.mjs scaffold WebChart

# 只看不写
node bin/dom-component.mjs scaffold CodeBlock --dry-run

# 校验
node bin/dom-component.mjs validate components/WebChart.tsx
```

## 校验规则对照

| 规则 | 来源 |
|------|------|
| R1 顶部必须有 `"use dom";` | SKILL.md Rules #1 |
| R2 单个默认导出 | SKILL.md Rules #2 |
| R3 `_layout` 不能是 DOM 组件 | SKILL.md When NOT to Use |
| R4 props 仅可序列化（函数 props 警告） | SKILL.md Rules #4 |
| R5 dom 属性应声明 DOMProps 类型 | SKILL.md The dom Prop |
| R6 路由 hooks 应从原生父组件传入 | SKILL.md Router APIs That Require Props |
| R7 CSS 在组件文件内 | SKILL.md CSS in DOM Components |
