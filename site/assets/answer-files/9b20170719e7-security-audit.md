## 4. 行为关联与攻击链研判（按 Skill Workflow 第 3 步）

### 4.1 会话 C：令牌越权 → 数据导出（高危攻击链）

```
09:04:02Z  api  high     token_scope_mismatch  service-a  203.0.113.8
    │  （令牌请求越权范围，可能在试探或提升权限）
    ▼  间隔 3 分 28 秒
09:07:30Z  db   critical unexpected_export     unknown    203.0.113.8
    │  （同一 IP 对数据库执行未授权导出，用户标识为 unknown）
    ▼
结论：疑似使用 service-a 令牌越权访问后，以未知身份导出数据库内容
```

**研判依据**:
- 两事件同源 IP（203.0.113.8），时间紧邻，严重级从 high 升级到 critical；
- token_scope_mismatch 表明服务账号令牌权限配置异常或被滥用；
- unexpected_export 的用户为 `unknown`，说明导出操作未通过正常认证映射，可能利用了越权令牌；
- 这符合 Skill 要求的「将解码流绑定到主机/样本行为」原则——不把两条日志视为孤立事件，而是还原为完整行为链。

### 4.2 会话 B：管理员暴力登录尝试

- 同一 IP（198.51.100.23）对 admin 账户在 4 秒内连续两次登录失败；
- 样本量仅 2 次，尚不足以确认自动化暴力工具，但已构成针对管理员账户的可疑试探；
- 该 IP 未在后续时间窗内出现成功登录，暂未发现横向移动。

### 4.3 会话 D：畸形记录

- 发生在会话 C 高危事件后约 1 分 30 秒；
- 三字段缺失可能原因：日志采集/解析故障、日志被篡改、或应用异常崩溃前写入；
- 无法确认与攻击链的因果关系，需结合应用日志和采集端状态进一步排查。

## 6. 修复建议

### F-1 数据外泄（严重）
1. 立即吊销 `service-a` 当前令牌，重新签发最小权限令牌；
2. 核查 09:07:30Z 前后数据库导出操作的具体内容、目标表、导出量和目的地，确认是否构成实际数据泄露；
3. 对 203.0.113.8 在该时间窗内的所有 API/DB 访问做全量回溯；
4. 如确认泄露，按数据分级启动应急响应和通知流程。

### F-2 管理员暴力登录（高）
1. 对 admin 账户启用登录失败锁定策略（建议 5 次失败锁定 15 分钟）；
2. 对 198.51.100.23 实施临时封禁或加严验证码/二次认证；
3. 管理员账户强制启用 MFA。

### F-3 日志完整性（中）
1. 排查 web 系统日志采集端，确认 09:09:00Z 前后是否有采集异常或应用报错；
2. 在日志管道中增加字段非空校验和畸形记录告警；
3. 核查日志写入权限，排除被篡改可能。

### F-4 令牌范围配置（高）
1. 审计 service-a 的令牌 scope 配置，遵循最小权限原则；
2. 在 API 网关层增加 scope 异常调用的实时告警；
3. 建立服务账号令牌权限定期复核机制。
