## 一、事实 / 推断 / 待确认 区分

### 已确认事实（来自 Skill 文件实读）

1. **Skill 真实能力**：`1688-product-detail` 仅支持对**已知 offer_id 的单个商品详情页**提取数据，输出 50+ 字段（标题、阶梯价、SKU、卖家信息、店铺评分、买家保障、跨境标记、优惠券、DSR 评价汇总等）。
2. **执行方式**：4 个 Python 脚本仅负责生成 JavaScript 文本，真正的提取依赖 `browser-act` 在已打开的 1688 详情页上下文中执行 `eval`，并通过 `network requests` / `network request <id>` 抓取 shopcard 和 DSR 两个 XHR 接口。
3. **不包含搜索**：SKILL.md「Known Limitations」明确写明 `s.1688.com` 搜索需要登录和中国大陆 IP，不在本 Skill 能力范围内。
4. **成功标准**：`extract-product-detail.py` 输出无 `error` 字段、`title` 非空、`pricing.tiers` 长度 ≥ 1。
5. **批量要求**：串行、单浏览器、商品间隔 2–3 秒；先 1–2 个试跑；逐条保存断点续跑；不得在单浏览器内并行（易触发反爬）。
6. **当前环境状态**：`browser-act` 未安装；无页面 JS eval / 网络抓包工具；经验记忆文件不存在；用户未提供 offer_id。
7. **脚本本身安全**：4 个脚本仅 `print` JS 字符串，不发起网络请求、不写文件、不执行系统命令；本地语法校验通过。

### 推断（基于事实的合理判断，非确认）

1. 当前环境的 GUI 浏览器工具（点击/输入/截图）无法替代 `browser-act`，因为缺少 `eval`（页面内 JS 执行）和 XHR 响应读取能力。
2. 即使直接 `curl` 详情页 HTML 解析 `window.context`，shopcard/DSR 两个接口使用动态 `sign`，无法在无真实页面会话时复现。
3. SKILL.md 输出示例中的具体数据（如 offer 927875250705、某公司名、某价格）是**示例值**，不能作为已采集事实使用，也未在本次验证其当前有效性。

### 待确认项（需用户/授权方明确）

2. 采集用途、数据保留期限、共享范围。
3. 是否具备中国大陆 IP 出口与稳定网络环境。
4. 是否接受字段最小化（默认剔除 loginId/memberId/userId 等内部标识）。
5. 速率上限与可接受的试跑数量。

## 二、冲突与风险识别

| 编号 | 风险/冲突 | 等级 | 说明 |
|------|-----------|------|------|
| R1 | **能力不匹配** | 阻断 | Skill 依赖 `browser-act`（eval + 网络抓包），当前环境不可用，无法执行核心提取。 |
| R2 | **缺少目标输入** | 阻断 | 无 offer_id；Skill 不能搜索，无法自行发现商品。 |
| R3 | **无授权范围** | 高 | 未明确采集品类、数量、频率、用途、保留期，批量采集公开数据仍需合规依据。 |
| R4 | **个人/经营敏感信息** | 中 | Skill 输出含卖家 loginId、memberId、userId、公司名、店铺链接等。公司名与店铺链接属公开经营信息，但内部 ID 属可识别标识，市场调研非必要，应默认剔除（字段最小化）。 |
| R5 | **不可逆影响** | 高 | 批量/高频请求可能触发 1688 反爬，导致 IP 封禁、会话失效甚至账号关联限制；此类后果无法回滚。SKILL.md 提到「多开 stealth 浏览器会话」存在绕过反爬措施的嫌疑，不应在未授权时采用。 |
| R6 | **未核实事实混入** | 中 | 输入中若直接给出商品数据或 ID，需逐条经页面核验后方可采信；本次未收到任何 ID 或数据，故不涉及。 |
| R7 | **地域/登录限制** | 中 | 详情页虽声称免登录，但非中国大陆 IP 可能被风控；shopcard 接口会话过期会返回空数据。 |
| R8 | **数据时效性** | 低 | 价格、销量、评分实时变动，采集结果仅代表采集时刻，需保留 `collected_at`。 |

**关于「可能造成不可逆影响的操作」**：指在无授权、无速率控制、无回滚方案下直接对 1688 发起批量抓取，可能导致 IP/会话被封禁且无法恢复。本次预演**未执行**任何此类操作。

## 四、停止条件（Stop Conditions）

满足以下任一条件立即停止采集并通知用户：

1. `browser-act` 不可用或 `eval` 返回 `window.context not found` 连续 2 次。
2. 页面返回验证码、登录墙、风控拦截页（截图确认）。
3. 连续 3 个 offer_id 返回 `error` 或 HTTP 异常状态码。
4. shopcard/DSR 接口在重载页面后仍不可达（按 SKILL.md 重试一次后放弃该条）。
5. 用户未确认授权清单即要求开始全量采集。
6. 采集过程中收到 1688 任何形式的封禁/警告响应。
7. 实际去重后有效条目数已达 12，立即停止，不超额采集。

## 六、回滚方案

| 场景 | 回滚动作 |
|------|----------|
| 触发风控/验证码 | 立即停止；关闭会话；等待 ≥ 30 分钟或更换授权 IP；不得自动重试绕过 |
| IP/会话被封禁 | 停止全部任务；通知用户；已采集数据保留在本地，不删除、不外传；等待用户指示 |
| 采集到敏感/越权字段 | 立即从结果中剔除该字段；记录剔除日志；不写入最终交付物 |
| 数据重复/脏数据 | 按去重规则保留首条；重复条目标记 deduped 并计入日志 |
| 脚本/页面结构变更 | 停止；截图留证；按 SKILL.md 经验笔记机制记录；不擅自改写提取逻辑 |
| 误采非目标商品 | 标记 status=invalid，不计入 12 条；补充采集至满 12 条为止 |
