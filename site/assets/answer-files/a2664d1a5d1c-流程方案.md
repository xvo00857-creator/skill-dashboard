# amazon-search-listing 受约束采集流程方案

> 本文档基于 amazon-search-listing Skill 的 SKILL.md 真实能力边界编写，结合本次环境预检结果，
> 给出带预检、幂等、重试、人工确认点的可执行流程，并附一次可核验的演示结果。

---

## 一、Skill 能力边界（以 SKILL.md 为准）

| 项目 | 说明 |
|------|------|
| 输入 | 任意 Amazon 搜索 URL（`/s?k=`）、分类浏览 URL（`/s?bbn=&rh=n:`）或深链 |
| 输出 | 每页商品卡片 JSON（asin/title/url/image/price/listPrice/stars/reviewCount/badges/isAmazonChoice/isBestSeller/isSponsored/delivery/boughtInPast/positionIndex）+ 分页状态（currentPage/hasNextPage/nextPageUrl/totalResultsApprox） |
| 运行方式 | 通过 `browser-act --session {name} eval "$(python scripts/extract-search-results.py)"` 在已打开 Amazon 页面的浏览器中执行 JS |
| 数据来源 | 仅读取页面上已渲染的 DOM（`[data-component-type="s-search-result"]`），等同于用户手动复制，不绕过认证或访问控制 |
| 支持站点 | amazon.com/.co.uk/.de/.co.jp/.in/.fr/.ca/.com.au/.it/.es/.com.mx/.com.br/.nl/.se/.com.sg/.ae/.sa/.pl/.tr/.eg |
| 分页上限 | 关键词搜索硬上限 7 页（约 112 条）；分类限定 URL 可更多 |
| 不做什么 | 不登录、不点击购买、不提交表单、不绕过验证码/反爬、不调用 XHR/fetch API |

## 二、环境预检结果（2026-08-12 实测）

| 检查项 | 结果 | 影响 |
|--------|------|------|
| `browser-act` 命令 | **未安装**（`command not found`） | Skill 指定的 JS 执行通道不可用，无法按标准方式运行 |
| browser-task Skill | 存在，但仅支持 GUI 点击/输入/截图，无 `eval` JS 能力 | 无法替代 browser-act 执行提取脚本 |
| Python playwright/selenium | 未安装 | 无无头浏览器替代方案 |
| Node.js puppeteer | 未安装 | 无无头浏览器替代方案 |
| Python requests + BS4 | 已安装 | Amazon 返回 Akamai bm-verify 反爬验证页（2217 字节），无法获取商品数据 |
| GUI 浏览器打开 amazon.com | **首页可加载**；搜索 "laptop" 结果页**成功渲染**真实商品卡片 | 页面可见但无法通过 DevTools/地址栏执行 JS（嵌入浏览器限制） |
| amazon.co.jp | 连接被重置（ERR_CONNECTION_RESET） | 当前网络环境不可达 |
| amazon.cn | 仅显示 App 下载页，无搜索结果 | 不适用 |
| 经验记忆文件 | 不存在（首次运行） | 无历史经验可参考 |

**结论**：Skill 依赖的 `browser-act` 在当前环境缺失，无法完成实时 Amazon 数据采集。
本次演示采用"真实页面加载截图 + 本地测试夹具验证提取脚本逻辑"的方式，证明脚本本身正确，
待 `browser-act` 可用后即可按标准流程执行实时采集。

## 三、受约束流程设计

### 3.1 预检阶段（Pre-checks）

```
P1. 依赖检查
    ├─ 检查 browser-act 是否可用：browser-act --version
    │   └─ 不可用 → 停止，提示安装/配置 browser-act，不降级为 requests 抓取
    ├─ 检查 Python 3 可用：python3 --version
    └─ 检查提取脚本存在：scripts/extract-search-results.py

P2. 经验记忆检查
    └─ 读取 {working-directory}/browser-act-skill-forge-memories/
       amazon-scraper-amazon-search-listing.memory.md
       └─ 存在则读取，按历史异常调整策略

P3. 目标 URL 合法性检查
    ├─ URL 必须属于 SKILL.md 列出的 Amazon TLD 列表
    ├─ URL 必须是 /s?k=、/s?bbn=、/b/、/gp/browse 等搜索/分类路径
    └─ 不接受非 Amazon 域名 URL

P4. 浏览器会话检查
    ├─ browser-act --session {name} 确认会话存活
    └─ 确认目标 Amazon 页面已在浏览器中打开且无验证码/interstitial 遮挡
```

### 3.2 幂等设计（Idempotency）

```
I1. 每页结果持久化
    └─ 输出目录：output/{keyword_or_node}/page_{N}.json
       ├─ 文件已存在且 itemCount >= 1 → 跳过该页（除非 --force）
       └─ 文件不存在或为空 → 执行采集

I2. 运行状态文件
    └─ output/{keyword_or_node}/.state.json
       ├─ 记录：已完成页码列表、最后成功时间、总条数
       └─ 中断后重启时读取，从最后成功页的下一页继续

I3. ASIN 去重
    └─ 合并多页结果时按 asin 去重，保留首次出现的记录
       （SKILL.md 终止条件：同一页 ASIN 列表与上一页相同 → Amazon 回绕到第 1 页）

I4. 不重复创建外部资源
    └─ 不重复创建浏览器会话、不重复导航已加载页面、不覆盖已有结果文件
```

### 3.3 重试策略（Retry）

```
R1. 单页提取重试
    ├─ 提取返回 error 或 itemCount == 0：
    │   ├─ 第 1 次：等待 5 秒后重新 navigate + wait stable + 提取
    │   ├─ 第 2 次：等待 10 秒，刷新页面后重试
    │   └─ 第 3 次：标记该页为 failed，记录到 .state.json，继续下一页
    │
    ├─ 页面出现验证码/interstitial：
    │   ├─ 不自动绕过（Skill 边界：不绕过访问控制）
    │   └─ 暂停并触发人工确认点 H2
    │
    └─ 网络超时/导航失败：
        ├─ 最多重试 3 次，间隔 5/10/15 秒（指数退避）
        └─ 3 次均失败 → 标记 failed，继续

R2. 批量采集节奏
    ├─ 页间间隔 3-6 秒（SKILL.md: Execution Efficiency）
    ├─ 先测试 1-2 页再全量运行（SKILL.md: Test before batch execution）
    └─ 单浏览器会话内串行，不并行（避免触发反爬）

R3. 崩溃恢复
    └─ 从 .state.json 读取进度，跳过已成功页，从 failed 页或下一页继续
```

### 3.4 人工确认点（Human-in-the-loop）

```
H1. 批量采集前确认
    └─ 展示：目标 URL/关键词、计划页数上限（关键词≤7页）、预计时间、输出路径
       └─ 等待用户确认后才开始全量采集

H2. 验证码/反爬拦截
    └─ 页面出现 CAPTCHA、interstitial、"Sorry something went wrong" 时
       ├─ 暂停执行，截图通知用户
       ├─ 请用户在浏览器中手动完成验证
       └─ 用户确认后继续

H3. 跨页异常终止确认
    └─ 连续 2 页返回相同 ASIN 列表（Amazon 回绕）或连续 2 页失败时
       └─ 暂停并询问用户：继续重试 / 跳过 / 终止

H4. 结果交付前确认
    └─ 展示：总页数、总条数、失败页列表、输出文件路径
       └─ 用户确认后才标记任务完成

H5. 经验记忆写入确认
    └─ 仅当遇到 SKILL.md 定义的"意外情况"（策略失效、页面改版、反爬升级）时
       └─ 追加一行到记忆文件前，告知用户写入内容
```

### 3.5 标准执行流程

```
1. 预检 P1-P4
2. 读取经验记忆（P2）
3. 人工确认 H1（确认目标与范围）
4. 导航到第 1 页 → wait stable → 提取
5. 校验成功标准：itemCount >= 1 且 items[0].asin 匹配 /^[A-Z0-9]{10}$/
   ├─ 不通过 → 重试 R1
   └─ 通过 → 持久化 page_1.json
6. 测试 1-2 页确认正常后，循环翻页：
   for page = 2..N:
     a. 幂等检查 I1（已存在则跳过）
     b. 导航 nextPageUrl → wait stable → 提取
     c. 重试 R1（如需）
     d. 终止检查：hasNextPage == false 或 ASIN 回绕
     e. 持久化 page_{N}.json
     f. 页间等待 3-6 秒
7. 合并去重（I3），输出汇总 JSON
8. 人工确认 H4
9. 如有意外情况，写入经验记忆（H5）
```

## 四、演示结果

### 4.1 真实页面加载验证

- 在 GUI 浏览器中打开 `https://www.amazon.com`，首页正常加载
- 搜索 "laptop"，结果页成功渲染，可见真实商品卡片（含价格 SGD、评分、Sponsored 标记、配送信息）
- 截图已留存（见对话中的浏览器截图）
- **限制**：当前嵌入浏览器不支持 DevTools/地址栏 JS 执行，无法在真实页面上运行提取脚本

### 4.2 提取脚本逻辑验证（本地测试夹具）

由于 `browser-act` 不可用，构建了模拟 Amazon DOM 结构的本地 HTML 测试夹具
（`demo/test-fixture.html`），其中嵌入了 `scripts/extract-search-results.py` 输出的**原始未修改 JS**，
在浏览器中打开后自动执行并展示结果。

测试夹具覆盖 4 种场景：
1. 正常商品卡（Overall Pick 徽章、价格/划线价、评分、配送、月销量）
2. 赞助商品（Sponsored + Best Seller 徽章、辅助徽章文本）
3. 无价格无评分商品（边界情况，null 处理）
4. Amazon's Choice 徽章 + 英镑价格（多币种解析）

### 4.3 校验结果

按 SKILL.md 的 Success Criteria 独立校验（`demo/verify.py`）：

```
[PASS] itemCount >= 1  =>  itemCount = 4
[PASS] items[0].asin =~ /^[A-Z0-9]{10}$/  =>  asin = "TESTASIN01" (len=10)
[PASS] 4/4 商品卡 18 个字段全部完整
[PASS] 分页字段正确（currentPage=1, hasNextPage=true, totalResultsApprox=10000）
[PASS] null 边界、Sponsored/BestSeller 识别、多币种价格解析均正确
=== 总体结果: ALL PASS ===
```

## 五、待确认事项与限制

1. **browser-act 未安装**：需安装配置后才能执行实时 Amazon 采集。安装方式需用户确认。
2. **网络环境**：amazon.com 首页可访问但搜索页曾返回 "Sorry something went wrong"；
   amazon.co.jp 连接被重置。实时采集可能需要目标地区代理（SKILL.md 已知限制）。
3. **配送地区**：浏览器推断配送至新加坡，价格显示为 SGD。如需特定国家价格，需对应地区代理。
4. **本次演示数据为测试夹具数据**，非 Amazon 实时数据。真实采集需在 browser-act 可用后按上述流程执行。
5. 未创建、删除或覆盖任何外部资源；所有产物均在项目目录 `demo/` 下。
