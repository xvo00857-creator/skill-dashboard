## 4. 风险分级与发现

### 4.1 incident_log.csv 事件分析

#### 发现 F-01：数据库异常导出（严重 / Critical）

| 字段 | 内容 |
|---|---|
| 时间 | 2026-08-12T09:07:30Z |
| 系统 | db |
| 事件 | unexpected_export |
| 用户 | unknown（未认证/未知身份） |
| 来源 IP | 203.0.113.8 |
| 证据 | CSV 第 5 行原文：`2026-08-12T09:07:30Z,db,critical,unexpected_export,unknown,203.0.113.8` |

**分析：** 数据库层面发生未预期的导出操作，且执行身份为 unknown，表明可能存在未授权访问或凭据泄露。该 IP 在 3 分 28 秒前刚触发 API token 权限范围不匹配（F-02），时间与来源高度关联，疑似攻击者先尝试越权调用 API，随后直接对数据库执行导出。

**影响：** 若为真实环境，可能导致敏感数据批量外泄。

**修复建议：**
1. 立即核查数据库审计日志，确认导出的数据表、行数与目标位置。
2. 吊销/轮换该时段内 203.0.113.8 相关的所有凭据与 token。
3. 对数据库账户实施最小权限原则，撤销应用账户的 FILE/EXPORT 类权限。
4. 启用数据库导出操作的强制审批与告警（无人值守导出默认拒绝）。
5. 排查 service-a 及关联服务是否存在凭据泄露或 SSRF/命令注入。

#### 发现 F-02：API Token 权限范围不匹配（高危 / High）

| 字段 | 内容 |
|---|---|
| 时间 | 2026-08-12T09:04:02Z |
| 系统 | api |
| 事件 | token_scope_mismatch |
| 用户 | service-a |
| 来源 IP | 203.0.113.8 |
| 证据 | CSV 第 4 行原文：`2026-08-12T09:04:02Z,api,high,token_scope_mismatch,service-a,203.0.113.8` |

**分析：** service-a 的 token 请求了超出其被授予范围的权限，可能是凭据被盗用后尝试横向/纵向越权，也可能是配置错误。与 F-01 同源 IP、时间紧邻，倾向于攻击链的前序探测。

**修复建议：**
1. 立即冻结 service-a token，核查其近期所有 API 调用。
2. 强制 token 使用最小 scope，服务间调用采用短期凭据（如 OAuth2 client credentials + 自动轮换）。
3. 对 scope_mismatch 事件启用实时告警与自动熔断（同一 token 连续 N 次越权即吊销）。
4. 核查 service-a 的部署环境与密钥保管方式，排除泄露。

#### 发现 F-03：admin 账户连续登录失败（警告 / Warning）

| 字段 | 内容 |
|---|---|
| 时间 | 2026-08-12T09:03:45Z、09:03:49Z（间隔 4 秒） |
| 系统 | web |
| 事件 | login_failed ×2 |
| 用户 | admin |
| 来源 IP | 198.51.100.23 |
| 证据 | CSV 第 2、3 行 |

**分析：** 同一 IP 在 4 秒内对 admin 账户连续两次登录失败，具有暴力破解/口令喷洒特征，但样本量仅 2 次，尚不足以确认攻击。admin 为常见高权限用户名，应重点关注。

**修复建议：**
1. 对 admin 账户启用登录失败限速与临时锁定（如 5 次失败锁定 15 分钟）。
2. 禁止使用 admin/root 等默认用户名，或对其登录强制多因素认证（MFA）。
3. 对 198.51.100.23 持续观察，若失败次数增加则纳入黑名单/验证码挑战。
4. 核查 admin 账户是否允许从公网直接登录，必要时限制来源 IP 或走 VPN。

#### 发现 F-04：正常登录（信息 / Info，无风险）

- 时间 2026-08-12T09:00:12Z，alice 从 192.0.2.10 登录成功。无异常，留作基线。

#### 发现 F-05：格式异常记录（数据质量问题 / Medium）

| 字段 | 内容 |
|---|---|
| 时间 | 2026-08-12T09:09:00Z |
| 事件 | malformed_record |
| 缺失字段 | severity、user、source_ip |
| 证据 | CSV 第 6 行原文：`2026-08-12T09:09:00Z,web,,malformed_record,,` |

**分析：** 该记录 severity/user/source_ip 三个字段为空，无法进行风险判定与溯源。可能原因：日志采集/解析管道故障、上游字段映射错误或日志被截断。这本身是一个可观测性缺陷——若攻击者刻意制造畸形日志以掩盖痕迹，当前管道无法告警。

**修复建议：**
1. 在日志采集端增加 schema 校验：必填字段缺失时拒绝写入并产生独立告警。
2. 排查 09:09 前后日志采集服务是否有异常/重启。
3. 对 malformed 类事件单独建监控看板，统计趋势。

### 4.2 edge_cases.csv 边界与安全问题

#### 发现 E-01：重复主键（数据完整性 / Low-Medium）

- record_id=2 出现两次（第 2、3 行），status/value/notes 完全相同。
- 风险：重复记录可能导致统计翻倍、审计结论偏差；若为去重逻辑缺陷，真实环境中可能掩盖或放大事件计数。
- 建议：以 record_id 为主键建立唯一约束；入库前去重；排查上游产生重复的根因。

#### 发现 E-02：字段缺失（数据质量 / Medium）

- record_id=3 的 status 与 value 均为空，notes 为 `-`。
- 风险：缺失字段使该记录无法分类与参与统计；若批量缺失将导致监控盲区。
- 建议：必填字段非空校验；缺失记录进入隔离区（quarantine）并告警，而非静默丢弃。

#### 发现 E-03：异常负值（业务逻辑 / Medium）

- record_id=4 的 value=-999，status=error。
- 分析：-999 可能是哨兵值/错误码，也可能是传感器/业务异常。若 value 字段语义为非负度量（如计数、金额、延迟），-999 属非法值。
- 建议：明确 value 字段取值域；对越界值拒绝入库并标记；对 error 状态记录建立单独处置流程。

#### 发现 E-04：CSV 公式注入（安全 / High）

- record_id=5 的 value 字段值为：`=HYPERLINK("https://example.invalid","do not execute")`
- notes 明确标注"公式注入测试文本"。
- 风险分析：CSV 公式注入（CSV Injection / Formula Injection）。当该 CSV 被 Excel、LibreOffice、WPS、Google Sheets 等电子表格软件打开时，以 `=`、`+`、`-`、`@` 开头的单元格会被当作公式解析执行。本 Payload 使用 `=HYPERLINK`，在真实场景中可替换为指向恶意站点的链接或更危险的外部数据调用（如 `=WEBSERVICE(...)`、`=cmd|'/c ...'!A1`），导致钓鱼、数据外传甚至命令执行（取决于软件与配置）。
- 注意：本报告以纯文本方式读取该字段，**未在任何电子表格软件中打开该文件，未执行该公式**。example.invalid 为 RFC 2606 保留域名，不会实际连接。
- 修复建议：
  1. 导出 CSV 时，对以 `=`、`+`、`-`、`@`、Tab、回车开头的字段前置单引号 `'` 或进行转义，使其被当作文本。
  2. 配置电子表格软件禁用外部链接/自动公式计算，打开外部 CSV 时以文本方式导入。
  3. 在日志/数据处理管道中将公式注入作为输入校验项，与 XSS、SQLi 同等对待。
  4. 对用户可控字段输出到 CSV 时统一使用安全序列化库，而非手工拼接。
