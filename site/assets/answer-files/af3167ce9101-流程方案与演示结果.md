# skill-doctor 受约束流程方案与演示结果

> 按 skill-creator 的 SKILL.md 执行：创建 → 测试（with/without 对照）→ 评分 → 聚合 → 评审 → 改进 → 再验证 → 打包。
> 本次在无 subagent、无外部模型调用的条件下内联执行，跳过描述优化循环并标注。

## 一、创建的技能

- **名称**：skill-doctor（技能体检）
- **能力边界**：只读地检查一个技能目录的结构健康度，输出结构化 JSON 报告。不修改任何文件、不联网、不装依赖、不评价内容质量。
- **位置**：`skill-doctor/`（SKILL.md、scripts/doctor.py、evals/evals.json）
- **v1 检查项（14 项）**：SKILL.md 存在性、frontmatter 可解析/必填键/允许键、name kebab-case 与长度、description 长度与非法字符、正文行数（>500 警告）、根目录结构、Python 语法编译、空文件、**悬空引用**、**evals/evals.json 合法性**。

## 二、受约束的流程设计

### 预检（pre-check）
- 运行前检查环境变量 `CHERRY_STUDIO_SKILLS_DIR`：未设置 → 判定不在 Cherry Studio，其"忽略打包/写入受管目录"段不适用，技能创建在项目目录内。
- 检查 Python 版本与依赖：系统 `python3` 为 3.9.6，doctor.py 只用标准库；评审器需 3.10+，改用已安装的 Python 3.13。
- doctor.py 运行前预检目标路径：存在、是目录、可读，否则退出码 2 并给出明确错误。

### 幂等（idempotency）
- doctor.py 为纯只读：同一路径、同一版本多次运行输出一致；修复后重跑即可验证，不产生副作用。
- 打包与聚合脚本可重复执行；`--output` 报告写入技能目录外，避免污染技能包。

### 重试（retry）
- doctor.py 读文件遇瞬时 OSError 自动重试一次（`read_text_with_retry`）。
- 退出码 2（环境/用法错误）时按 stderr 修正后重跑；退出码 1 说明体检本身成功、只是发现问题，修复后重跑验证。
- 本次执行中聚合脚本首次因 `summary` 字段类型不符报错，读取脚本源码确认其期望字典后修正重跑——属于真实的"读错误→定位→重试"。

### 人工确认点（human-in-the-loop）
- **C1 技能主题**：建议创建 skill-doctor，默认推进，用户可打断改方向。
- **C2 测试用例**：3 个用例（真实 skill-creator / 故意破损夹具 / 最小健康技能）写入 evals.json，按默认继续。
- **C3 写入范围**：所有产物仅写在项目目录内；未写入受管 skills 目录、未调用外部模型、未删除/覆盖外部资源。安装到受管目录需另行确认，本次不做。
- **C4 报告落盘**：doctor.py 拒绝把报告写进被检查技能目录内（会污染技能包），必须指定目录外路径。

## 三、可核验的演示结果

### 测试用例
1. 体检真实技能 skill-creator（已提供的样本）
2. 体检故意破损的技能（坏 name、缺 description、Python 语法错、悬空引用、非法 evals.json）
3. 体检最小可用技能

### 迭代 1（v0）
- with_skill：**11/11 = 100%**
- without_skill（人工式基线）：7/11 = 63.6%
- 差值：+0.36
- 分析发现缺口：v0 不检查悬空引用和 evals.json 合法性；且允许的 frontmatter 键与官方 schemas.md 不一致（多了 version）。

### 迭代 2（v1，改进后）
- with_skill：**14/14 = 100%**
- without_skill：9/14 = 64.3%（聚合按用例均值为 63.3%）
- 差值：+0.37
- v1 三处增强：新增 dangling-references、新增 evals-json-valid、对齐官方 frontmatter 键集合。
- **真实发现**：v1 检出 skill-creator 自身 SKILL.md 的 `version` 键会被其自带的 `quick_validate` 拒绝打包（已实测 quick_validate 退出码 1）；基线读到 version 却认为 frontmatter 正常，漏报。
- 交叉验证：同一套扩展断言下，v0 会在 2 条新断言上失败，v1 全部通过。

### 性能
- with_skill 单次体检约 0.09 秒，两轮稳定；基线人工巡检约 0.6–1.8 秒。
- inline 模式无 token 计数，benchmark 中 tokens 如实记为 0，未编造。

### 产物
- `iteration-1/benchmark.md`、`iteration-1/benchmark.json`、`iteration-1/review.html`
- `iteration-2/benchmark.md`、`iteration-2/benchmark.json`、`iteration-2/review.html`（含与迭代 1 的对比）
- `skill-doctor.skill`（可分发包，已通过 quick_validate）

## 四、跳过与无法访问项（如实标注）
- **Cherry Studio 流程段不适用**：环境变量未设置，我们不在 Cherry Studio；故未写入受管技能目录，但在项目目录内完成了打包（与该段"忽略打包"的指示冲突，以实际环境为准并说明）。
- **描述优化循环跳过**：`run_loop.py`/`improve_description.py` 依赖 `claude -p` 发起外部模型调用，按"只用现有权限和已提供数据"约束未执行。
- **subagent 盲评改为内联**：无 subagent 调度，with/without 对照由同一 agent 内联完成；基线为真实的通用工具人工巡检，未使用 doctor.py。
- **无 token 数据**：inline 模式无通知元数据，tokens 记 0。
- **generate_review.py 需 Python 3.10+**：系统默认 3.9.6 不兼容其 `dict | None` 语法，改用已安装的 Python 3.13 运行。
