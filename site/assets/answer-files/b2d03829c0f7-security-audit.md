- **事件 4→5 构成强关联链**：同一源 IP `203.0.113.8` 在 3 分 28 秒内，先在 api 层触发 `token_scope_mismatch`（service-a 出示了作用域不匹配的令牌），随后在 db 层以 `unknown` 身份触发 `unexpected_export`。跨系统、同 IP、短间隔、高敏感动作（数据导出）组合，符合"被盗用/越权服务令牌 → 横向访问数据库 → 数据外传"的可疑模式。
- **可达性/可利用性判断**：db 层允许 `unknown`（未识别身份）执行导出，说明导出路径存在鉴权缺口或服务账号未映射到身份；令牌作用域不匹配仅被记录为 high 事件但未阻断后续 db 操作，说明 api 层"检测但未拒绝"或 service-a 可绕过 api 直达 db。

## 2. 风险分级与发现

分级口径：Critical（已确认的数据/系统失控）、High（可信的高危链，待补证）、Medium（需整改的控制弱点）、Low（提示性）、Info（基线）。

### F-1 服务令牌越权 → 数据库异常导出（疑似数据外传）

- **风险等级：High（Critical 待证实）**
- **证据（日志行）**：
  - `2026-08-12T09:04:02Z,api,high,token_scope_mismatch,service-a,203.0.113.8`
  - `2026-08-12T09:07:30Z,db,critical,unexpected_export,unknown,203.0.113.8`
- **数据流/攻击假设**：`203.0.113.8` 持 service-a 令牌访问 api，令牌作用域不匹配（可能被盗、配置错误或过度签发）→ 约 3.5 分钟后以未识别身份 `unknown` 触发 db 导出 → 数据可能已被外传。
- **人工验证结论**：跨系统同 IP + 短间隔 + 高敏感动作，关联可信；但缺导出内容/目标/流量证据，且不排除 NAT 复用，故不直接定为已确认 Critical。
- **CWE/ATT&CK 参考**：CWE-285（不当授权）、CWE-306（关键功能缺认证）、CWE-269（权限管理不当）；ATT&CK T1021（远程服务横向移动）、T1537/T1020（数据外传）。
- **修复建议**：
  1. 立即吊销并轮换 service-a 令牌，审查其令牌作用域签发策略（最小权限）。
  2. 核查 db 审计日志：导出表/行数/时间窗口/导出目标账户与目的地，确认是否含敏感数据。
  3. 核查 `203.0.113.8` 在该时段的网络出向流量与连接记录。
  4. api 网关对 `token_scope_mismatch` 改为**默认拒绝**（deny-by-default），而非仅记录。
  5. db 导出接口强制身份认证 + 服务账号与身份绑定 + 导出审批/工单；禁止 `unknown`/匿名执行导出。
  6. 网络分段：service-a 不应具备直达 db 导出路径的网络可达性。
  7. 对导出操作启用 DLP 与体量/目的地异常告警。

### F-2 admin 账户短时间登录失败

- **风险等级：Low**
- **证据**：
  - `2026-08-12T09:03:45Z,web,warning,login_failed,admin,198.51.100.23`
  - `2026-08-12T09:03:49Z,web,warning,login_failed,admin,198.51.100.23`
- **人工验证结论**：4 秒内 2 次失败，未达爆破阈值，后续无成功登录，IP 与主链不同；可能为误输或低强度撞库。保持监控即可。
- **CWE/ATT&CK 参考**：CWE-307（不当限制过度认证尝试）；ATT&CK T1110（暴力破解/撞库）。
- **修复建议**：
  1. admin 登录启用失败退避/临时锁定与速率限制。
  2. admin 强制 MFA；如非必要，禁用默认名 `admin`，改用具名管理账户。
  3. 对同一 IP 连续 N 次失败（如 5 次/5 分钟）触发告警与验证码。

### F-3 畸形日志记录（监控完整性缺口）

- **风险等级：Medium**
- **证据**：`2026-08-12T09:09:00Z,web,,malformed_record,,`（severity/user/source_ip 均为空）
- **人工验证结论**：该记录无法归因。紧接 F-1 主链之后出现，时间上可疑，但无字段证明是攻击者所为；也可能是采集/解析异常。无论哪种，说明日志管道接受了不满足 schema 的记录，削弱检测与取证能力。
- **CWE 参考**：CWE-778（日志记录不充分）/ 日志完整性弱点。
- **修复建议**：
  1. 日志接入侧增加 schema 校验，拒绝或隔离畸形记录并产生独立告警。
  2. 排查 09:09:00 web 节点采集端/应用端异常，确认是否为解析故障。
  3. 日志启用追加写入与完整性校验（如哈希链/集中式不可篡改存储），防止篡改。
  4. 对"日志中断/字段缺失率突增"配置监控。
