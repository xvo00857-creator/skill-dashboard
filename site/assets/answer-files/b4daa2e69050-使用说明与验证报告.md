# 转岗工作模式（code--career-pivot）使用说明与验证报告

> 本文件为 mode-creator Skill 的交付物之一，配套配置文件 `code--career-pivot.json`。
> 模式名称：Career Pivot　模式 ID：`code--career-pivot`（继承自内置 `code` 模式的输出协议，替换领域分类法与行为提示词）

---

## 一、模式用途

为准备转岗（内部转岗或外部跳槽）的从业者建立可复用的长期记忆：在日常准备过程中，自动把对未来有价值的信息沉淀为可检索的观察记录，避免岗位要求、人脉建议、面试反馈、决策理由等关键信息散落在聊天和文档里。

## 二、分类法（已经过官方安装脚本校验）

### 观察类型（observation_types，互斥，每条记录恰好一个）

| ID | 名称 | 记录什么 |
|----|------|----------|
| `role-signal` | 岗位信号 | JD、面试官、在职者、公开信息透露的岗位要求、团队方向、评价标准、业务重点 |
| `gap-learning` | 差距与学习 | 能力短板、学习计划、练习资源与进展、补齐能力的证据 |
| `proof-asset` | 证明素材 | 可迁移到目标岗位的过往项目、成就、数据、故事素材（用于简历/面试） |
| `relationship` | 人脉线索 | 内推人、导师、信息面谈对象等关键联系人，及其态度、建议、下一步 |
| `interaction-review` | 沟通复盘 | 面试或正式沟通中被问的问题、回答、反馈、表现复盘 |
| `decision` | 决策权衡 | 岗位/offer 比较、优先级排序、承诺、放弃及其理由 |

### 概念标签（observation_concepts，可多选，跨类型）

| ID | 含义 |
|----|------|
| `priority` | 对转岗成败关键、需优先处理 |
| `deadline` | 关联投递截止、面试时间、回复期限等具体日期 |
| `follow-up` | 需要后续行动、回复或确认 |
| `red-flag` | 团队、岗位、流程、待遇中暴露的风险或负面信号 |
| `evidence` | 有具体数据、事实或来源支撑，非主观印象 |
| `uncertain` | 尚未核实的传闻、二手信息或不确定结论 |

### 记录策略

- **记录**：对转岗决策和准备有长期价值的具体事实——岗位要求、差距、证明素材、人脉建议、沟通反馈、决策理由；每条尽量含来源、日期、相关方、目标岗位。
- **跳过**：机械投递点击、重复浏览已记录的 JD、简历排版微调、无结论的情绪宣泄、未证实的薪资传闻；无实质收获时不产生记录。

## 三、在真实 claude-mem 环境中安装与激活

> 以下命令需在已安装 claude-mem worker 的机器上执行。本次评测环境未安装 worker，因此这一步标注为**待确认**（见第六节）。

```bash
# 1. 先做非破坏性校验（不写入任何文件）
node <skill目录>/scripts/install-mode.mjs \
  --mode code--career-pivot.json \
  --mode-id code--career-pivot \
  --dry-run

# 2. 校验通过后安装并激活（不启用 Telegram）
node <skill目录>/scripts/install-mode.mjs \
  --mode code--career-pivot.json \
  --mode-id code--career-pivot

# 3. 重启 worker 使模式生效
npx claude-mem restart
npx claude-mem status
```

安装器会：把覆盖文件写入 `<数据目录>/modes/code--career-pivot.json`、在 `settings.json` 中设置 `CLAUDE_MEM_MODE=code--career-pivot`、对已有文件做带时间戳的备份。

### 启用 Telegram 提醒（可选，本次默认不启用）

如需在记录到特定类型/标签时收到 Telegram 通知，安装时追加 `--telegram-types` 和/或 `--telegram-concepts`，例如仅对决策类记录提醒：

```bash
node <skill目录>/scripts/install-mode.mjs \
  --mode code--career-pivot.json \
  --mode-id code--career-pivot \
  --telegram-types decision
```

匹配规则为 OR：命中任一选定类型或任一概念即推送。Bot 凭据需通过交互式助手安全录入（令牌通过隐藏终端输入，不进入命令行参数或聊天记录）：

```bash
node <skill目录>/scripts/configure-telegram.mjs --types decision
```

## 四、使用示例

### 示例 1：会被记录（岗位信号 + 高优先级 + 有证据）

场景：终面后，你在主会话里记下"李总监说团队 Q4 重点是跨境支付合规"。worker 会生成类似这样的观察记录（XML 为 claude-mem 官方输出结构）：

```xml
<observation>
  <type>role-signal</type>
  <title>Q4 重点转向跨境支付合规</title>
  <subtitle>终面官明确该方向为团队当前优先级，准备案例时应突出合规相关经验</subtitle>
  <facts>
    <fact>李总监在 8/12 终面表示团队 Q4 重点是跨境支付合规</fact>
    <fact>候选人需熟悉目标市场当地监管框架</fact>
  </facts>
  <narrative>该信号直接影响面试准备重心：应把过往合规相关项目作为证明素材重点梳理，并在后续沟通中确认团队对监管经验的具体要求深度。来源为终面沟通，可信度高。</narrative>
  <concepts>
    <concept>priority</concept>
    <concept>evidence</concept>
  </concepts>
  <files_read>
    <file>interview-notes/2026-08-12-final-round.md</file>
  </files_read>
  <files_modified>
  </files_modified>
</observation>
```

### 示例 2：会被记录（证明素材 + 有证据）

```xml
<observation>
  <type>proof-asset</type>
  <title>对账系统迁移项目可作为复杂项目落地证据</title>
  <subtitle>该项目将人工差错率从 3.2% 降至 0.4%，可映射岗位要求的跨团队推动能力</subtitle>
  <facts>
    <fact>2025 年主导对账系统迁移，涉及 3 个业务线协同</fact>
    <fact>上线后人工差错率从 3.2% 降至 0.4%，月均节省工时约 120 小时</fact>
  </facts>
  <narrative>该成果同时覆盖"跨团队推动"和"数据驱动改进"两个岗位高频要求，适合作为面试 STAR 故事；需补充当时的角色边界和阻力处理细节。</narrative>
  <concepts>
    <concept>evidence</concept>
  </concepts>
  <files_read>
  </files_read>
  <files_modified>
    <file>resume/star-stories.md</file>
  </files_modified>
</observation>
```

### 示例 3：会被跳过（无实质收获）

> "今天又刷了一遍脉脉上的面经帖，没什么新内容。"

属于重复浏览且无新结论，按 `skip_guidance` 返回 `<skip_summary />`，不产生记录。

### 示例 4：会被跳过（格式微调）

> "把简历字体从宋体换成了微软雅黑。"

属于 formatting-only 改动，不记录。

### 隐私边界（写入模式提示词）

薪资数字、offer 具体条款、现公司未公开的转岗意向、个人身份信息、面试官/内推人私下评价等敏感内容不应记录，也不应选作 Telegram 触发类别。

### 本次实际执行的验证命令与输出摘要

1. **dry-run（真实父模式合并校验）**
   - 命令：`CLAUDE_MEM_DATA_DIR=<临时目录> node .../install-mode.mjs --mode code--career-pivot.json --mode-id code--career-pivot --dry-run`
   - 输出：`{"ok":true,"dryRun":true,"modeId":"code--career-pivot",...}`
2. **临时目录安装（验证写入/激活/权限，不触碰真实 `~/.claude-mem`）**
   - 输出：`{"ok":true,"modeName":"Career Pivot","activated":true,...}`
   - `settings.json` 内容：`{"CLAUDE_MEM_MODE":"code--career-pivot"}`
   - 安装文件权限：`-rw-------`（0600）
3. **合并结果自检**：6 类型、6 概念、32 条 prompts；3 个父模式协议字段保留；代码语义关键词全部清除；type/concept guidance 全覆盖。
4. **负向测试**：独立模式缺 `system_identity` → `prompts.system_identity must be a non-empty string`（退出码 1）；`--telegram-types nonexistent-type` → `Telegram trigger type is not in this mode`（退出码 1）。

## 六、约束导致的方案变化与取舍

本次在"时间和资源受限"条件下执行，相对 SKILL.md 标准流程做了以下调整：

1. **访谈环节以合理默认值替代多轮交互**。SKILL.md 第 1–2 步要求用交互式问答工具逐批访谈用户（三个下周仍想要的时刻、应跳过的常规活动、检索用的名词决策、敏感项、详略偏好）。由于任务未提供具体从业者信息且要求限时交付，本模式基于"转岗准备"这一通用场景直接提出 6+6 分类法，**从业者的目标岗位、当前岗位、行业、个人敏感边界均标注为待确认**，需用户在安装前按 SKILL.md 第 3 步审批或修改分类法与隐私边界。
2. **Telegram 默认不启用**。SKILL.md 第 4 步要求在分类法批准后询问是否启用 Telegram。任务未提出通知需求，按"无需求不变更现有设置"原则保持不变，用户可后续按需开启。
3. **未在真实系统安装，改为临时目录验证**。本环境未安装 claude-mem worker（无 `~/.claude-mem`、`npx claude-mem` 不可用、无 `session_start_context` MCP 工具）。为不伪造成功，安装与重启步骤未在真实系统执行；改用官方安装脚本在临时 `CLAUDE_MEM_DATA_DIR` 中完成了完整的写入/激活/备份逻辑验证，真实环境安装命令已在第三节给出。
4. **父模式通过官方 npm 包获取**。ZIP 中不含内置 `modes/` 目录，无法直接做继承式 dry-run。为避免凭空构造父模式，从 npm 下载 `claude-mem@13.15.0` 官方包，取其真实 `plugin/modes/code.json` 作为父模式用于校验，未修改、未安装该包到系统。
5. **既有观察记录不受影响**。按 SKILL.md  ground rule，新模式仅作用于未来观察生成，不回溯改动已有记录。

## 八、回滚方法

安装器会在覆盖已有文件时生成带时间戳的备份（输出中的 `backups.mode` / `backups.settings`）。回滚：

```bash
# 恢复模式文件与 settings（把 <时间戳> 替换为安装输出中的备份时间戳）
cp <数据目录>/modes/code--career-pivot.json.backup-<时间戳> <数据目录>/modes/code--career-pivot.json
cp <数据目录>/settings.json.backup-<时间戳> <数据目录>/settings.json
npx claude-mem restart
```

若为全新安装（无备份），直接删除 `<数据目录>/modes/code--career-pivot.json` 并把 `settings.json` 中的 `CLAUDE_MEM_MODE` 改回原值（或删除该键）后重启即可。
