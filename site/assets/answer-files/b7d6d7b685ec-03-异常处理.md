# Adyntel 每周自动化 —— 异常处理

> 依据：`adyntel-automation/SKILL.md` 的 Known Pitfalls 与流程决策点。
> 原则：能重试的重试，需人工介入的暂停在"确认前步骤"，任何失败都不静默吞掉。

---

## 1. 异常清单

| 编号 | 异常 | 触发阶段 | 检测方式 | 处理动作 | 重试 | 降级/兜底 |
|------|------|----------|----------|----------|------|-----------|
| E1 | 工具未找到或 schema 变更 | 阶段 1 工具发现 | 搜索结果中缺少数据收集或通知类工具；或已知 slug 不在返回中 | 记录发现到的工具列表，中止流程并告警 | 否（schema 变了重试无意义） | 无；需人工确认 Adyntel toolkit 变更 |
| E2 | Adyntel 连接非 ACTIVE | 阶段 2 连接检查 | `RUBE_MANAGE_CONNECTIONS` 返回状态 ≠ ACTIVE 且含 auth link | 输出授权链接，**暂停流程**，不自行完成 OAuth | 否（等人授权） | 属"确认前步骤"边界；授权后下次定时自动恢复 |
| E3 | 连接检查调用失败 | 阶段 2 | 调用抛错/超时/返回不可解析 | 指数退避重试 3 次（间隔 5s/15s/45s） | 是，最多 3 次 | 仍失败则中止并告警，保留 session 供排查 |
| E4 | 参数不符合 schema | 阶段 3/5 执行 | 执行返回参数校验错误；或本地按 schema 预检发现必填缺失/类型不符 | 回到阶段 1 重新发现 schema，用新 schema 重建参数后重试一次 | 是，1 次（重新发现后） | 仍失败则中止，输出期望 schema 与实际参数 diff |
| E5 | 分页中断 | 阶段 3 数据收集 | 取下一页时失败/超时；或分页 token 丢失 | 从最后成功的 token 继续，重试 3 次 | 是，最多 3 次 | 仍失败则保留已取数据，摘要中标注"数据不完整，截止于第 N 页"，继续通知 |
| E6 | 通知发送失败 | 阶段 5 通知 | 执行返回错误/超时 | 指数退避重试 3 次 | 是，最多 3 次 | 仍失败则将摘要写入本地 `outbox/` 目录并在运行报告中标记"通知未送达"，下次运行可补发 |
| E7 | session 失效 | 任意阶段 | 返回 session 无效/过期错误 | 生成新 session，从阶段 1 重新开始整个流程 | 是，1 次 | 仍失败则中止 |
| E8 | 数据为空（本周无数据） | 阶段 4 | `total_records == 0` | 正常生成"本周无数据"摘要并通知，**不当作错误** | —— | —— |
| E9 | 原始记录字段缺失/类型异常 | 阶段 3/4 | 归一化时日期无法解析、数值字段非数字 | 跳过该字段（置 null），在摘要中标注缺失计数；原始数据完整保留在 `raw` | 否 | 不阻断流程 |
| E10 | Rube MCP 不可用 | 阶段 0/1 | `RUBE_SEARCH_TOOLS` 无响应 | 立即中止，提示检查 MCP server `https://rube.app/mcp` 配置 | 否 | 模拟模式下不触发（使用桩） |

---

## 2. 重试策略

- 仅 E3、E4、E5、E6、E7 允许自动重试；
- 退避序列：5 秒 → 15 秒 → 45 秒（约 3 倍递增）；
- 每次重试都记录：重试次数、上次错误、时间戳；
- 达到上限后进入对应降级/中止逻辑。

---

## 3. 日志与可观测性

每次运行在 `logs/` 下生成 `run-<timestamp>.json`，结构：

```json
{
  "run_id": "...",
  "session_id": "...",
  "mode": "simulate | live",
  "started_at": "...",
  "finished_at": "...",
  "stages": [
    {"name": "discover", "status": "ok|error|skipped", "duration_ms": 0, "error": null},
    {"name": "connect",  "status": "...", "...": "..."},
    {"name": "collect",  "status": "...", "pages_fetched": 0, "records": 0},
    {"name": "summarize","status": "...", "...": "..."},
    {"name": "notify",   "status": "...", "...": "..."}
  ],
  "exceptions": [{"code": "E5", "message": "...", "retries": 2, "resolved": true}],
  "summary": { },
  "final_status": "success | partial | failed | awaiting_auth"
}
```

- `final_status` 取值：
  - `success`：全部阶段成功；
  - `partial`：数据不完整或通知降级（E5/E6 兜底后）；
  - `failed`：不可恢复错误；
  - `awaiting_auth`：E2，等待人工授权。

---

## 4. 人工介入点

仅两处需要人工：
1. **E2**：点击 `RUBE_MANAGE_CONNECTIONS` 返回的 auth link 完成 Adyntel 授权；
2. **E1**：工具/schema 变更后确认新的工具用途并更新 use_case 描述。

其余异常均自动处理或降级，不阻断下次定时运行。

---

## 5. 幂等与安全

- 同一周重复运行：以 `week_start` 为幂等键，已成功通知的周不重复发（模拟模式下通过 `outbox/.sent` 记录判断）；
- 通知降级写入本地 `outbox/`，不外发，不泄露数据；
- 不在日志中记录授权链接之外的凭据；配置文件 `config.json` 仅本机读取。
