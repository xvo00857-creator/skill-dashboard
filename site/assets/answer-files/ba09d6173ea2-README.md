## 1. 实验目标与范围取舍

### 1.1 目标（两周内可证伪的单一假设）

在**同一留出测试集、同一解码配置**下，比较"基础模型"与"在公开指令数据上经 QLoRA 微调后的模型"，检验微调是否带来任务指标变化。

- 可回答：在该公开数据与该评测集上，微调后模型的困惑度/任务指标/延迟相对基线如何变化。
- 不可回答：微调是否在真实业务中"导致"用户体验提升、是否具有跨领域普适性——这些需要上线实验，不在本范围内。

### 1.2 范围取舍（受 2 周 / 3 人 / 仅公开资料约束）

| 维度 | 纳入 | 不纳入（原因） |
|---|---|---|
| 方法 | QLoRA 4-bit 微调 7B 级开源模型（Skill 参考：8B QLoRA 约需 6GB 显存） | 全量微调、70B 模型（显存/时间不足）；RLHF/DPO（需奖励模型与偏好数据，两周不可控） |
| 数据 | 1 个公开指令数据集，清洗后约 3k–5k 条（Skill 建议指令跟随最少 1k、推荐 5k–10k） | 多数据混合、自爬数据（许可证与清洗成本高）；数据增强仅作备选，不默认使用 |
| 实验 | 1 个主实验 + 1 个小型消融（LoRA rank 或 target_modules） | 大规模超参搜索（Optuna 20 trials 以上）；多模型横向对比 |
| 评测 | 留出集困惑度 + 任务指标（生成类用 ROUGE/BLEU，分类类用 Accuracy/F1）+ 延迟基准 | 大规模标准 benchmark 套件（MMLU 等耗时长）；人工大规模标注 |
| 部署 | 合并 adapter、按需 4-bit 量化、延迟测量 | vLLM/TGI/K8s 生产部署（两周内无上线需求，Skill 的部署部分仅用到合并与量化） |

### 1.3 三人分工

- **成员 A（数据与评测）**：数据获取与许可证审查、校验/清洗/切分、评测集构建、评测脚本与结果复核。
- **成员 B（训练与基础设施）**：环境搭建、训练脚本、GPU 任务、checkpoint 管理、adapter 合并与量化。
- **成员 C（负责人/分析）**：方案与质量门把关、基线评测、消融设计、结果分析与报告、可复现性打包。

代码与数据评审采用交叉评审：A 的数据 B 跑通，B 的训练 C 复核配置。

## 2. 资料与数据选择标准

### 2.1 基础模型选择标准

1. 公开可下载、许可证允许研究与微调（优先 Apache-2.0 / MIT / 宽松许可；需团队法务确认）。
2. 7B–8B 量级，bf16 权重，社区有 QLoRA 成功先例。
3. 候选（需确认许可证与可用性，非指定）：Llama 系列（需注意 Meta 许可）、Mistral 7B、Qwen2 7B 等开源选项。**最终模型由团队按许可证与硬件确认。**
4. 固定一个模型版本与 commit/hash，实验期间不升级。

### 2.2 数据集选择标准

1. **公开且许可证明确**：优先 HuggingFace Hub 上带 license 字段、允许再分发与微调的数据集；许可证不明或仅限非商业研究用途的，需记录并确认。
2. **与任务匹配**：指令跟随类任务优先 Alpaca/ShareGPT 格式的成熟数据集；若做分类/摘要等具体任务，选带标准切分的公开集。
3. **质量可验**：有来源说明、字段完整、可程序化校验（schema、长度、语言）。
4. **规模适中**：原始 1 万条以内，清洗后目标 3k–5k，保证两周内可完成校验、训练与消融。
5. **可切分留出集**：能按 Skill 要求做 train/validation/test 切分；测试集不得在训练或调参中出现。
6. **排除**：含个人隐私、需登录/爬取、来源不可追溯、与评测集高度重叠的数据。

### 2.3 公开资料使用规范

- 仅使用公开文档、论文、模型卡、数据集卡；记录每条资料的 URL、访问日期、版本。
- 不使用内部/付费/未授权数据；不使用任何无法说明来源的"现成语料"。
- 引用第三方代码与数据时保留 LICENSE 与归属。

## 4. 质量检查方法

### 4.1 数据质量门（对应 Skill "MUST: 训练前校验数据"）

- **Schema 校验**：每条必须含 `instruction`/`output` 或 `messages`；空字段、缺字段直接剔除并计数。
- **长度检查**：用实际 tokenizer 统计 token 长度，输出直方图；总长 > 4096 的样本截断或剔除（脚本默认告警并剔除超限项）。
- **去重**：先按 instruction 精确去重，再按 output 做 MinHash 模糊去重（阈值 0.85，Skill 默认）。
- **质量过滤**：过滤空输出、拒答模板（"I cannot"/"As an AI" 等，中文数据需补充中文拒答模式）、过短样本。
- **切分**：90/10 切 train/val，另从来源预留或同分布切出 test；有类别字段时分层抽样；固定随机种子 42。
- **泄漏检查**：确认 test 与 train 无重叠（精确 + 模糊）；记录数据来源与版本 hash。

### 4.2 训练质量门（对应 Skill 训练 checkpoint）

- 训练前 `model.print_trainable_parameters()` 确认可训练参数占比约 0.1%–1%。
- **必须启用 warmup**（Skill MUST）：`warmup_ratio=0.03`，小数据集可提到 0.1。
- 监控 train/val loss 曲线：val loss 必须下降；平台期或上升即过拟合，按 Skill 建议减 epoch、加 dropout/weight decay、早停。
- `load_best_model_at_end=True`，以 `eval_loss` 选最佳 checkpoint。
- 小数据集防过拟合：LoRA dropout 0.05–0.1、weight decay、不盲目加 epoch。
- 完整记录超参与配置（`configs/experiment_config.yaml` + 训练日志），数据与 checkpoint 版本化。

### 4.3 评测质量门（对应 Skill "MUST NOT: 未在留出集评测就部署"）

- 测试集在训练与调参全程不可见；val 仅用于选 checkpoint 与早停。
- 基线与微调模型使用**完全相同**的测试样本、解码参数（`do_sample=False` 贪心解码保证可复现，Skill 示例采用）、max_new_tokens。
- 报告：困惑度、任务指标（生成类 ROUGE/BLEU/BERTScore，分类类 Accuracy/F1）、延迟（含预热、报告均值与标准差）。
- 关键指标至少跑 2 次或固定所有随机种子，记录方差；异常值人工抽查。
- 延迟基准按 Skill：先 warmup 3 次，再 benchmark 10 次，报告平均延迟、tokens/s、显存占用。

### 4.4 可复现性检查

- 固定随机种子（Python、NumPy、PyTorch）；记录 GPU 型号、CUDA/PyTorch/transformers/peft/trl 版本。
- 数据、配置、代码、checkpoint 用同一实验 ID 归档；`results/` 下每次评测写 JSON 并带时间戳。
- 第三人仅凭 README 与配置能重跑数据准备、训练、评测三条主命令。

## 5. 相关性 ≠ 因果的护栏

1. **结论措辞**：只写"在 X 公开测试集上，微调模型指标相对基线变化 Δ（数值）"，不写"微调导致模型能力提升"之外的泛化因果。
2. **内部比较才接近因果**：基线 vs 微调在同数据、同解码、同硬件下的差异，是受控对比；但这只支持"该次训练干预在该评测上的效果"，不支持对真实世界效果的因果断言。
3. **混淆变量显式列出**：数据分布、prompt 格式、解码参数、随机种子、checkpoint 选择都可能影响结果；报告中固定并披露这些变量。
4. **不把 benchmark 相关当业务因果**：评测分数与线上效果是相关关系，非因果；上线效果需 A/B 实验，明确列为后续工作。
5. **不把单次运行当规律**：消融与重复运行用于检验稳定性；样本量小、方差大时不下定论。
6. **负面/无效结果同样报告**：若无显著差异，如实报告，不选择性呈现。

## 7. 设计理由（why this method / rank / LR）

- **为何 QLoRA**：7B–8B 模型在单张消费级 GPU（24GB 级）上，全量微调约需 56–64GB 显存（Skill 参考表），不可行；LoRA 约 16–18GB 可行但余量小；QLoRA 4-bit 约 5–6GB，留足 batch 与长序列空间，最稳妥。
- **为何 r=16、alpha=32**：Skill 建议中等复杂度任务从 r=16 起步、alpha 取 2×r；数据量 3k–5k 属中小规模，不盲目加大 rank 以防过拟合。消融对比 r=8。
- **为何 LR=2e-4（QLoRA 起步 1e-4）**：Skill 给 LoRA 区间 1e-5–3e-4、起步 2e-4，QLoRA 起步 1e-4；脚本默认 QLoRA 用 1e-4，cosine 调度 + 3% warmup（Skill MUST）。
- **为何 target_modules 先注意力后 MLP**：默认 q/k/v/o_proj（Skill 最小示例），消融再加 gate/up/down_proj 比较容量与显存。
- **为何贪心解码评测**：`do_sample=False` 保证可复现（Skill 评测示例采用），避免采样噪声干扰对比。
- **为何只做一个消融**：两周内一个受控主实验 + 一个单变量消融，证据强度高于多个未控变量的零散对比。
