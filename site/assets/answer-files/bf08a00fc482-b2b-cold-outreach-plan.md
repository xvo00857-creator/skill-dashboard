## 0. 关键前提与错配说明（务必先读）

### 0.1 输入中可确认的事实（结论）
- 产品：智能随行杯；核心卖点：12 小时保温、重量 280g、可拆洗杯盖。
- 建议零售价：199 元。
- 已确认素材：产品白底图、基础规格、品牌主色 `#176B87`。
- 简报明确**禁止编造**：第三方检测结论、销量、用户评价、竞品价格。
- 简报明确**不完整信息**：首发日期未定；防水等级、食品接触材料报告未提供。
- 交付语言：中文；结论与假设分开；外部数据列为待补项。

### 0.2 必须标注的错配与假设
1. **B2C 产品 vs B2B 外联**：简报目标用户是"一二线城市通勤人群"（B2C），并未定义 B2B 报价、批量政策或企业采购话术。本方案把 B2B 切入点**假设**为"企业行政/HR 的员工福利与商务伴手礼采购"，其余 B2B 角度（渠道经销、异业联名）列为备选。**该假设未经任何真实外联验证。**
2. **欧美工具栈/合规框架 vs 中国执行环境**：Skill 引用的 Instantly、Smartlead、Clay、Apollo、G2、Bombora 及 CAN-SPAM/GDPR/CASL 均以欧美市场为背景。本方案沿用其**方法论框架**，但具体工具采购、账号开通、中国《个人信息保护法》《广告法》及商业邮件合规要求需另行落实与法务确认——当前环境无任何上述账号。
3. **无社会证明可用**：Skill 的"3 行邮件"要求第二行写"同类公司的具体结果"，但简报禁止编造销量/评价，且为新品无客户案例。本方案以**可核实的产品规格**替代客户结果证明，并在邮件中避免任何未经证实的效果宣称。
4. **规模与目标未量化**：用户要求"小规模"，但未给每日发信量、月度会议目标、预算。Skill"Before Starting"清单中的 8 项有 6 项缺失（见第 7 节），无法做基础设施容量测算。

## 2. 触发信号（Trigger Signals）

> Skill 规则：单信号回复率约 3–5%，叠加两个及以上信号可达 8–15%；信号决定"联系谁、何时联系"。
> 下表为**信号定义与可观察来源**，本轮未实际采购/接入任何信号源，亦未据此抓取任何真实公司。

| 信号 | 意图等级 | 时机窗口 | 可观察来源（需接入/人工核实） |
|---|---|---|---|
| 节日福利采购季临近（中秋/春节/端午/女神节/公司周年庆） | 高 | 节前 4–8 周 | 企业公众号/官网公告、招聘描述中的福利说明 |
| 招聘高峰 / 大规模扩招（新员工入职礼包需求） | 高 | 14–30 天 | Boss 直聘、猎聘、拉勾、公司招聘页 |
| 新融资 / 扩张 / 新办公室启用 | 中高 | 30–60 天 | 36 氪、IT 桔子、天眼查、企业公告 |
| 领导层/行政 HR 负责人新到任 | 中 | 30–45 天 | 领英、企业公众号 |
| 内容/社媒提及员工福利、办公环境升级 | 中 | 7–14 天 | 微信公众号、微博、领英 |

**叠加规则**：至少满足 1 个高意图信号方可进入序列；满足 2 个及以上信号优先发送并使用更具体的个性化首句。
**中国本地化说明**：Skill 原表的 G2/Bombora/Crunchbase/BuiltWith 在本场景不适用，上表为对应方法论的本地化映射，实际可用性需逐个核实。

## 4. 三封邮件序列

> 依据 Skill：3 行框架（观察/痛点 → 可信证明 → 低门槛 CTA）；邮件间距 2–4 个工作日（3 天最佳）；主题行简短、无垃圾词；首封零链接/零图片/零附件；每封一个 CTA；签名仅姓名+职位+公司。
> Skill 数据：第 1/2/3 封分别贡献 58%/18%/12% 的回复，三封累计约 88%，故"小规模测试用 3 封"在方法论上成立。
> 发送时间建议：收件人当地时间周二/周三 8:00–10:00（Skill 基准：周二回复指数 122、周三 118 为最高）。

### 邮件 1（Day 0，周二或周三）— 开场
- **主题**：通勤杯福利选型
- **正文**：

> {{first_name}}你好，
>
> 看到{{company}}最近{{trigger_event}}，通勤的同事不少，行政在福利杯选型上通常要在轻便、保温、好清洗之间做取舍。
>
> 我们的随行杯重 280g、12 小时保温，杯盖可拆洗，建议零售价 199 元，适合员工福利或商务伴手礼。
>
> 方便发你一份规格资料看看是否合适吗？
>
> {{sender_name}} / {{sender_title}} / 公司名

- **合规页脚**：公司实体邮寄地址 + 一键退订链接（List-Unsubscribe）。
- **说明**：首封不含任何链接/图片/附件（白底图、`#176B87` 素材不在首封使用）；"证明"行仅引用简报已确认规格，未编造客户结果。

### 邮件 2（Day 3）— 价值补充
- **主题**：一个选型细节
- **正文**：

> {{first_name}}你好，
>
> 补充一个行政常问的细节：杯盖可拆洗，茶渍咖啡垢能拆开清理；280g 约一部手机的重量，通勤包无负担。
>
> 如果{{company}}今年有员工福利或商务伴手礼预算，199 元价位可走企业采购，我可以按你们人数整理一份采购方案。
>
> 需要我先按 {{employee_count}} 人做个方案参考吗？
>
> {{sender_name}} / {{sender_title}} / 公司名

- **说明**：未声称食品接触认证或防水等级（报告未提供）；未编造批量折扣，仅表示"可整理方案"。

### 邮件 3（Day 7）— 许可式收尾 / Breakup
- **主题**：收尾确认
- **正文**：

> {{first_name}}你好，
>
> 两次邮件没收到回复，猜测福利选型可能不是你目前在负责的事，或时机不对。
>
> 若后续有员工福利或伴手礼需求，随时联系我即可；如果不属于你的范围，烦请转发给相关同事，或回复"不需要"，我便不再打扰。
>
> 祝顺利。
>
> {{sender_name}} / {{sender_title}} / 公司名

- **说明**：对应 Skill 的 permission-based close（"Should I close this out?"），给收件人低成本退出方式。

### 序列条件分支（规则定义，未执行）
- **打开未回复**：按计划进入下一封（已体现在 Day 3/Day 7）。
- **点击链接**：本轮邮件不含链接，不适用；后续若加入链接，点击后转人工跟进。
- **未打开**：不重发，仅在复盘时测试不同主题行。
- **正面回复**：立即转人工，停止序列。
- **异议/提问**：人工回复，不使用自动 AI 回信（本轮无 AI Reply Agent 配置）。
- **退订/"不需要"/垃圾举报**：立即停止全部邮件（见第 5 节）。
- **自动回复/OOO**：暂停，待回归后再续。

## 5. 退订与停止规则

> 综合 SKILL.md 与 references/benchmarks-deliverability-tactics.md 的合规与故障规则。

### 5.1 退订规则
1. 每封邮件携带 **List-Unsubscribe 头**与页脚一键退订链接（Skill：Google/Yahoo/Microsoft 要求）。
2. 退订请求 **24 小时内生效**，从全部序列与列表移除。
3. 回复"不需要""退订""停止"等同义表述，按退订处理（Skill：auto-remove "not interested" is a compliance requirement）。
4. 页脚包含发件公司实体邮寄地址（Skill 要求）。

### 5.2 自动停止规则（阈值触发即停，需人工复核后再恢复）
| 指标 | 停止阈值 | 依据 |
|---|---|---|
| 退信率（bounce） | >2% 立即停发排查；目标 <1% | Skill：>2% 触发垃圾邮件过滤 |
| 垃圾举报率 | >0.3% 停发；目标 <0.1% | Skill 合规红线 |
| 退订率 | >1% 停发并收紧 ICP/加大间距 | Skill failure modes |
| 域名垃圾 placement | >5% 轮换该域名 | Skill 监控规则 |
| 单邮箱日发信量 | 冷邮件 ≤25–30 封/天，绝不超 40 | Skill per-mailbox limit |

### 5.3 其他停止情形
- 任一收件人回复（无论正负）即停止其后续邮件。
- 邮箱不存在/退信 → 标记无效，不再发送。
- OOO/自动回复 → 暂停至回归日期。
- 序列三封发完未回复 → 停止；30–45 天后可考虑 reactivation（本轮不做）。

### 5.4 中国合规待确认项（未自行下法律结论）
- 《个人信息保护法》下联系人个人信息处理的合法性基础与同意要求。
- 商业性电子邮件的明示同意与退订要求（需对照现行有效法规原文）。
- 《广告法》对宣传用语的限制（尤其不得使用简报禁止的第三方检测/销量/评价表述）。
- **以上需法务/合规确认后再执行；本方案不构成法律意见。**

## 6. 执行前置条件（基础设施与账号，当前全部缺失）

> Skill 要求基础设施需 14–21 天预热，且"Day 1"完成 SPF/DKIM/DMARC、自定义跟踪域、MX、PTR 等。当前环境**无任何下列资源**，因此方案停留在"定义"阶段。

1. 发信域名：二级域名（不可用主域名冷邮件）+ SPF/DKIM/DMARC 配置。
2. 发信邮箱：每域名 2 个，按 `日发量/150×1.5` 估算域名数（因无日发量目标，暂无法测算）。
3. 预热：新邮箱需 14–21 天预热后方可冷发送。
4. 发信平台：Instantly 或 Smartlead（需采购账号；中国网络环境可用性需确认）。
5. 信号与 enrichment：Clay + Apollo/Hunter/ZoomInfo 等（均需账号；或采用中国本地数据源人工核实）。
6. 邮箱验证：ZeroBounce/NeverBounce/MillionVerifier 等，发送前逐封验证（退信率须 <2%）。
7. 联系人名单：**本轮未获取、未生成任何真实联系人**；需先有合法来源名单并完成验证。
8. 法务/合规确认：见 5.4。
9. 产品侧待补：首发日期、防水等级、食品接触材料报告（在补齐前，邮件不得涉及相关宣称）。

### 影响本次结果的具体 Skill 规则
- **Before Starting 8 问**：ICP/现状/量级/工具/预算/offer/合规/时间线——多数缺失，直接导致方案停在定义阶段并产生第 7 节待补项。

- **序列长度与时序**（4–7 封、2–4 工作日间距、14–25 天；第 1/2/3 封贡献 58%/18%/12%）：支撑"3 封小规模测试"的选择与 Day 0/3/7 节奏。

- **合规规则**（List-Unsubscribe 头、24 小时退订、页脚实体地址、自动移除"not interested"、垃圾举报 <0.3%、退信 <2%）：决定第 5 节。
- **故障模式**（退订率 >1% 收紧 ICP、域名 >5% 垃圾 placement 轮换）：决定第 5.2 节阈值。
- **"先用 10 次人工外联验证 offer"**：因新品无案例、B2B offer 未验证，第 0.2 节标注假设并建议先小规模人工验证。
