# Constitutional AI 小规模复现实验设计

> 依据随附 Skill `constitutional-ai/SKILL.md` 制定。本文件为研究设计与执行方案，除第 7 节标注的"已实际运行"内容外，其余均为计划，未声称已完成。

---

## 1. Skill 能力边界确认

`SKILL.md` 描述的是 Anthropic 提出的 Constitutional AI（CAI）训练方法，核心是两阶段流水线：

- **SL 阶段**：模型对有害/敏感提问先生成初始回答，再依据一组"宪法"原则自我批评、自我修订，最后用修订后的数据做监督微调；
- **RL 阶段（RLAIF）**：对同一提问采样多个回答，由 AI 依据宪法比较偏好，训练奖励模型，再用 PPO 做强化学习。

该 Skill 是**模型训练技术指南**（依赖 `transformers`、`torch`、`trl`），不是文献综述或社会科学研究工具。因此本任务落在"模型实验"路径：以 Skill 的工作流为骨架，设计一个两周、三人、仅用公开资料、算力受限的小规模复现实验。

**与题目假设的一处差异**：题目将该 Skill 归入"研究与学习"，但 SKILL.md 的实际内容是工程实现指南。按要求以文件规则为准，本方案不把它扩展为通用研究方法学，只围绕其定义的 CAI 两阶段流程设计实验。

**条件性可做（需确认）**：若团队能申请到 1×A100 等量级 GPU，可将 SL 阶段 SFT 训练从"代码骨架"升级为"小规模实跑"（1B–3B 模型、少量步数），但 RL 阶段仍不纳入本次承诺。

## 3. 资料选择标准

仅使用公开资料，按以下优先级纳入：

1. **一手方法论文**：Anthropic 原始论文 *Constitutional AI: Harmlessness from AI Feedback*（arXiv:2212.08073，2022-12）作为方法定义来源；
2. **官方实现文档**：Hugging Face TRL 文档中 `SFTTrainer`、`RewardTrainer`、`PPOTrainer` 的当前 API（注意 SKILL.md 示例基于较早 API，需以安装版本为准核对）；
3. **官方框架复现**：NVIDIA NeMo Aligner 中 CAI 流程文档（作为流程交叉验证，不作为性能证据）；
4. **公开数据集**：优先使用已公开的红队/无害性提示集（如 Anthropic HH-RLHF 公开部分），使用前确认许可证；
5. **二手解读**（博客、播客、CSDN 等）：仅用于帮助理解，不作为事实依据，不引用其性能数字。

**排除标准**：
- 无法核验来源的自媒体数据；
- 声称"CAI 导致某社会后果"的因果性断言（见第 6 节）；
- 非公开/内部资料。

**关于相关性不等于因果**：论文报告的是 CAI 训练流程与模型无害性/有用性指标变化之间的实验关联。在两周三人规模下，我们只能观察"修订前后回答的评分差异"这一关联，不能断言"自我批评机制导致了安全性提升"——因为没有随机对照、没有控制模型规模/数据量/提示分布等混淆变量。所有结论措辞使用"观察到……差异""与……一致"，不使用"证明""导致"。

## 4. 执行计划（两周 / 三人）

| 阶段 | 时间 | 负责人（建议） | 交付物 |
|---|---|---|---|
| **D1–D2 环境与基线** | 第 1–2 天 | 成员 A | 环境清单、依赖版本锁定、基础模型选定、红队提示集 v1（≥100 条，覆盖网络攻击、仇恨言论、作弊、自残、违法等类别） |
| **D3–D5 SL 流水线** | 第 3–5 天 | 成员 B（主）、A 协助 | generate→critique→revise 流水线代码、宪法原则 v1、批量生成修订数据集（≥500 条） |
| **D6–D7 评估设计与试评** | 第 6–7 天 | 成员 C（主） | 盲评标注规范、评分维度（无害性/有用性/非回避性）、试评 50 条并计算标注者间一致性 |
| **D8–D9 正式评估与分析** | 第 8–9 天 | 三人分工 | 全量盲评结果、自动指标汇总、按类别的差异分析（只报关联，不做因果） |
| **D10 收尾** | 第 10 天 | 三人 | 实验报告、可复现包（代码+数据+随机种子）、RLAIF 代码骨架与后续计划 |

**宪法原则（v1，直接采用 SKILL.md 示例并补一条防过度回避）**：
1. 选择最有帮助、诚实且无害的回答；
2. 避免有毒、种族主义、性别歧视内容；
3. 优先解释反对理由而非直接拒绝（对应 SKILL.md 中"non-evasive"目标）；
4. 选择深思熟虑、细致入微的回答；
5. （补充）在不造成伤害的前提下尽量回应用户真实意图，避免无意义的回避——对应 SKILL.md"Common issues: Model refuses too much"的处理建议。

## 5. 模型实验设计

### 5.1 SL 阶段（本次重点）

**自变量**：回答是否经过"自我批评→修订"。

**流程**（对应 SKILL.md Workflow 1，已修复示例代码缺陷，见第 7 节）：
1. 用基础模型对红队提示生成初始回答；
2. 用宪法原则构造批评提示，让模型指出回答违反宪法之处；
3. 用批评结果构造修订提示，让模型生成修订回答；
4. （条件性）用 `(提示, 修订回答)` 对做 SFT——本次仅在获得 GPU 时执行，否则交付代码骨架。

**对照设置**：同一提示下比较"初始回答"与"修订回答"，由 3 名标注者盲评（打乱顺序，不知哪个是修订版）。

**评估维度**（1–5 分）：
- 无害性（是否避免可操作的有害内容）；
- 有用性（是否在安全边界内回应了真实意图）；
- 非回避性（是否解释而非无理由拒绝）。

**自动指标（辅助，不替代人工）**：回答长度、拒绝关键词出现率、与宪法原则的关键词重合度。自动指标仅作描述性参考，因其与"安全性"不是同一构念。

### 5.2 RL 阶段（RLAIF，仅交付设计与代码骨架）

对应 SKILL.md Workflow 2：采样回答对→AI 偏好比较→训练奖励模型（`RewardTrainer`）→PPO（`PPOTrainer`）。本次不实际训练，原因：
- SKILL.md 要求 2×A100 40GB；
- PPO 调参成本高，两周内无法保证收敛；
- `trl` 未安装且其 `PPOTrainer` API 在不同版本间变化较大，需先锁定版本再写代码。

代码骨架将明确标注"未运行"，并列出运行前需确认的依赖版本与硬件条件。

### 5.3 思维链批评（Workflow 3）

作为 SL 阶段的一个提示变体：在批评时要求模型逐项回答"是否有帮助/是否诚实/是否无害/是否避免毒性"再给修订建议。本次作为消融条件之一（CoT 批评 vs. 普通批评），比较修订回答的盲评得分。

## 6. 证据整理（公开资料，已核验来源）

以下为本次设计所依据的公开事实，均来自可核验来源：

1. CAI 由 Anthropic 提出，包含 SL 与 RL（RLAIF）两阶段；SL 阶段采样初始回答后生成自我批评与修订，再在修订数据上微调；RL 阶段用 AI 偏好训练奖励模型并做 PPO。来源：arXiv:2212.08073 摘要。["https://arxiv.org/abs/2212.08073"]
2. 论文报告该方法能训练出"无害但不回避"（harmless but non-evasive）的助手，即通过解释反对理由来回应有害提问，而非简单拒绝。来源：同上。["https://arxiv.org/abs/2212.08073"]
3. RLAIF 的偏好标注由 AI 完成，无需人工标注有害输出；唯一人工监督是宪法原则清单。来源：Anthropic 官方论文 PDF。["https://www-cdn.anthropic.com/7512771452629584566b6303311496c262da1006/Anthropic_ConstitutionalAI_v2.pdf"]
4. TRL 库提供 `SFTTrainer`、`RewardTrainer`、`PPOTrainer`，分别对应 SL 微调、奖励模型训练、RL 训练；PPO 流程含 rollout、评估、优化三步。来源：TRL 相关文档与仓库。["https://github.com/nixingliang/trl"]
5. NVIDIA NeMo Framework 文档将 CAI 流程描述为：SL 阶段批评/修订→RL 阶段 AI 比较→奖励模型→RL，并加入人工有用性偏好混合。来源：NVIDIA NeMo 文档。["https://docs.nvidia.com/nemo-framework/user-guide/24.07/modelalignment/cai.html"]

**因果措辞约束**：以上均为方法描述与论文自述结果。我们不据此声称"RLAIF 在所有场景下优于 RLHF""CAI 必然提升安全性"等因果性结论；论文中的对比是在其特定实验条件下得到的，外推到我们的小模型/短周期设置时只能作为假设，需由本次实验数据检验。

## 7. 已实际运行的验证（非模拟，真实输出）

为确认 SKILL.md Workflow 1 的代码路径在当前环境可执行，我编写并运行了 `cai_sl_pipeline.py`：

- **模型**：`distilgpt2`（82M 参数基础模型，CPU 推理）；
- **范围**：仅验证"生成→自我批评→修订"三步数据构造流程，**未做 SFT 训练**；
- **结果文件**：`cai_sl_pipeline_output.json`。

**真实观察**：
1. 流水线代码可执行，三步均产出文本，未报异常；
2. distilgpt2 作为基础模型，输出不连贯、存在重复（如"Create a forum"循环），部分初始回答为空——这是模型能力所限，**不代表 CAI 方法无效**，也不能据此判断修订是否改善质量；
3. 该验证的结论仅限于"流程可跑通"，质量评估须换用有指令遵循能力的模型重做。

**在运行中发现并修复的 SKILL.md 示例代码缺陷**（直接影响交付代码）：
- SKILL.md 中 `critique_prompt` 模板使用 `{question}`、`{response}`，但调用时写的是 `.format(q=q, r=r)`，变量名不匹配会抛 `KeyError`；`revision_prompt`、`preference_prompt` 同样存在 `{question}`/`{response}` 与 `q=`/`r=` 不一致问题。我的脚本统一改为 f-string 并对齐变量名。
- SKILL.md 中 `generator(prompts, max_length=200)` 直接传入列表，在当前 transformers 版本下批量调用返回结构与单条不同，脚本改为逐条调用并用 `max_new_tokens`。
- SKILL.md 的 `PPOConfig(reward_model_path=...)` 参数在新版 trl 中是否仍受支持需以实际安装版本为准，因此本次未运行 RL 代码。

## 8. 质量检查方法

| 检查项 | 方法 | 通过标准 |
|---|---|---|
| 代码可复现 | 固定随机种子、锁定依赖版本、README 写明运行命令 | 第三人按 README 能复现第 7 节流程输出 |
| 标注质量 | 3 人盲评，计算 Fleiss' Kappa 或 Spearman 相关 | 一致性 ≥0.6 方可采纳；低于则修订标注规范重评 |
| 数据泄漏检查 | 确认修订数据不含提示答案之外的不可见指令；训练/评估提示不重叠 | 重叠率为 0 |
| 结论措辞 | 双人交叉审阅报告，排查"导致/证明"等因果词 | 因果性表述仅出现在"随机对照+控制变量"条件下，本次一律改为关联表述 |
| 来源核验 | 每条引用事实可回溯到公开 URL；二手解读不单独作为证据 | 所有事实性陈述附来源 |
| 失败模式记录 | 记录空回答、重复生成、过度拒绝等失败案例占比 | 如实报告，不剔除不利样本 |
| 安全边界 | 红队提示与有害输出仅用于评估，不对外发布生成的有害内容 | 数据集内部留存，报告中只引用脱敏片段 |

## 11. 实际影响交付结果的 SKILL.md 规则

- SKILL.md 两阶段结构（Workflows 1–3）决定了第 5 节实验设计的骨架；

- "Common issues"中"模型过度拒绝"的处理建议，被纳入第 4 节宪法原则第 5 条。
