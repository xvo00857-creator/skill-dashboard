# Cosmos Policy 评估辅助脚本

本目录为 SKILL.md 工作流的辅助工程脚本，不改变任何既有评估接口、参数或目录结构。所有评估仍通过官方公开入口 `cosmos_policy.experiments.robot.libero.run_libero_eval` 与 `cosmos_policy.experiments.robot.robocasa.run_robocasa_eval` 执行。

## 设计原则

- **不升级主版本、不引入新依赖**：Python 脚本仅用标准库；Shell 脚本仅依赖 `bash` 与 SKILL.md 已要求的 `uv`。
- **固定参数逐字保留**：封装脚本中的评估参数与 SKILL.md 文档完全一致，仅将任务套件/任务名、trial 数、run 标记参数化。
- **不修改上游代码**：脚本位于 Skill 目录下，不触碰 cosmos-policy 仓库源码；遇二进制兼容问题仍按 SKILL.md 回到官方容器。
- **不编造结果**：结果解析脚本不假设 JSON schema，原样输出并仅高亮常见字段。

## 文件清单

| 文件 | 作用 | 对应 SKILL.md 章节 |
|------|------|--------------------|
| `preflight_check.py` | 评估前检查 EGL 环境变量对齐、缓存一致性、uv/Python/仓库结构/GPU 可见性、RoboCasa 资产 | Non-negotiable rules、Common issues |
| `run_libero.sh` | 封装 LIBERO 评估命令，参数化 suite/trials/run_note，自动设置 EGL 与缓存变量并先跑预检 | Workflow 1 |
| `run_robocasa.sh` | 封装 RoboCasa 评估命令，参数化 task/split/trials/run_note | Workflow 2 |
| `parse_results.py` | 在官方日志目录查找 JSON 结果与日志中的 Success rate 行，按修改时间排序展示 | Workflow 1 Step 4、Workflow 2 Step 3 |

## 典型用法

以下命令均需在 cosmos-policy 仓库根目录执行（已按 SKILL.md 完成 `uv sync` 并进入支持的运行时）。

```bash
# 1. 预检（LIBERO）
python3 scripts/preflight_check.py --benchmark libero

# 2. LIBERO smoke 评估
bash scripts/run_libero.sh

# 3. LIBERO 全量评估（某套件 50 trials）
bash scripts/run_libero.sh -s libero_spatial -n 50 -r full

# 4. 查看最新结果
python3 scripts/parse_results.py --benchmark libero

# RoboCasa 同理
python3 scripts/preflight_check.py --benchmark robocasa
bash scripts/run_robocasa.sh
bash scripts/run_robocasa.sh -t TurnOffMicrowave -s A -n 50 -r full
python3 scripts/parse_results.py --benchmark robocasa
```

## 环境变量

封装脚本会在未设置时给出以下默认值，已在环境中设置的值不会被覆盖：

- `CUDA_VISIBLE_DEVICES` / `MUJOCO_EGL_DEVICE_ID`：默认 `0`（可用 `-g` 覆盖）
- `MUJOCO_GL=egl`、`PYOPENGL_PLATFORM=egl`
- `HF_HOME`：默认 `~/.cache/huggingface`
- `TRANSFORMERS_CACHE`：默认与 `HF_HOME` 一致

## 限制与未验证项

- 这些脚本未在真实 GPU / cosmos-policy 环境中端到端运行过（编写环境无 GPU、无该仓库）；仅做了语法检查。
- `parse_results.py` 不假设结果 JSON 的字段结构；若上游字段名与常见命名不同，会原样输出完整 JSON 供人工查看。
- `preflight_check.py` 对 RoboCasa `macros_private.py` 的位置做了两种常见路径探测，实际位置以 `python -m robocasa.scripts.setup_macros` 生成为准。
