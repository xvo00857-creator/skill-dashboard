# 回滚方案与操作说明

> 对应 SKILL.md 规则："Every deployment should be reversible"、"Production deployment (manual trigger)"、"Monitor for errors"。
> 本流程的"发送"等同于一次部署，必须可回滚、有监控窗口。

## 一、停止条件（满足任一即停止运行）

1. 数据校验失败（必填字段缺失、状态非法、日期格式错误）
2. 待办数量为 0 或异常激增（超过上周 200%，可能是数据源错误）
3. 逾期项中出现非团队成员（数据源越权或配置错误）
4. 发送凭据缺失或无效
5. 人工确认环节未输入 YES
6. 发送接口返回非 2xx，重试 3 次仍失败

## 二、回滚方案

### 场景 A：摘要尚未发送
- 回滚动作：无需操作。流程在人工确认前中止，无副作用。

### 场景 B：摘要已发送但内容有误
- 飞书群消息：2 分钟内可调用消息撤回接口撤回（需记录发送时返回的 message_id）
- 邮件：发送"更正通知"邮件说明错误，原邮件无法撤回
- 通用措施：在群内发送更正说明，附正确版本

### 场景 C：发送到了错误的接收方
- 立即撤回（如渠道支持）
- 通知接收方该消息为误发，请忽略
- 检查配置中的接收方 ID，修正后重新 dry-run 验证

### 回滚记录
每次回滚需记录：时间、操作人、原因、影响范围、补救措施。

## 三、人工复核点

| 复核点 | 时机 | 复核人 | 复核内容 |
|---|---|---|---|
| 复核点 1 | 摘要生成后、发送前 | 流程运行人 | 逾期项是否准确、有无遗漏或误判、负责人是否正确 |
| 复核点 2 | 发送后 5 分钟内 | 流程运行人 | 消息是否送达正确群聊、格式是否正常 |
| 复核点 3 | 每周首次运行 | 团队负责人 | 规则是否需要调整（如节假日、人员变动） |

## 四、操作说明

### 4.1 只读预演（默认，安全）

```bash
cd task-weekly-digest
python3 weekly_digest.py --today 2026-08-12
```

- 不读取任何外部系统，不发送任何消息
- 使用 `sample_tasks.json` 中的模拟数据
- `--today` 用于固定基准日期，方便复现预演结果

### 4.2 接入真实数据后的预演

```bash
# 1. 配置数据源（复制模板，不提交版本库）
cp config.example.json config.json
# 编辑 config.json 指定数据源

# 2. 设置凭据（环境变量，不写入文件）
export TASK_API_TOKEN="你的只读token"

# 3. dry-run 预演（仍不发送）
python3 weekly_digest.py
```

### 4.3 真实发送（需全部授权后）

```bash
# 1. 设置发送凭据
export DIGEST_WEBHOOK_URL="群机器人webhook"

# 2. 带 --confirm 运行，仍需在终端输入 YES 确认
python3 weekly_digest.py --confirm
```

**注意：** 当前版本的 `send_summary()` 为占位实现，会主动拒绝真实发送。
接入真实发送渠道前，需补充：消息发送代码、发送日志、撤回逻辑、失败告警。
