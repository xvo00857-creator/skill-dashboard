## 1. 最小可验证版本（MVV）

### 1.1 关键步骤

1. **读取并校验日志**：确认 6 条记录、6 个字段（timestamp, system, severity, event, user, source_ip），标记字段缺失记录。
2. **风险分级**：按 severity 结合事件性质分级（critical/high/medium/low/info）。
3. **关联分析**：以 source_ip + 时间窗（5 分钟内）关联同源事件，构建证据链；不同源 IP 不强行并链。
4. **证据链落位**：对 critical/high 事件按"触发源 → 认证主体 → 目标 → 接受点 → 影响"五段归档，区分"已证实"与"日志不足以证实"的环节。
5. **输出修复建议与复测清单**：每条建议可复测、不含攻击步骤。
6. **声明局限**：仅 6 条日志、无网络流/认证明细/主机取证数据，不臆测未观测到的事实。

### 1.2 验收标准

- 每条 critical/high 事件均引用具体日志行（时间戳）作为证据，不使用日志外数据。
- `203.0.113.8` 的两个事件被关联为一条链，并明确标注哪些环节已证实、哪些未证实。
- `198.51.100.23` 的 admin 登录失败因源 IP 不同，**不**并入上述链。
- 修复建议均为防御性配置/流程项，可通过复测清单逐项验证。
- 报告不含任何破坏性或攻击性操作指令；不编造外部凭据、平台数据或执行结果。

## 4. 证据链分析

### 4.1 链 A（R1+R2）：203.0.113.8 认证滥用 → 数据库异常导出

按 Skill 五段模型落位：

| 链段 | 观测证据 | 状态 |
|---|---|---|
| ① 触发源 / Trigger | 09:04:02Z，`api` 系统收到来自 `203.0.113.8` 的请求，事件 `token_scope_mismatch`，关联身份 `service-a` | 已证实（第 4 行） |
| ② 被捕获/转发的认证 | `service-a` 的凭据/Token 在超出其作用域的上下文被使用 | 部分证实：作用域不匹配已证实；**是否为被中继/被转发的认证，日志未提供协议、握手或转发记录，无法证实** |
| ③ 中继/访问目标 | 同一源 IP `203.0.113.8` 在 09:07:30Z 触及 `db` 系统 | 已证实（第 5 行同源 IP） |
| ④ 接受点 / Acceptance | `db` 接受了该访问并执行操作，用户字段为 `unknown`（身份未识别/未映射） | 已证实（第 5 行；`unknown` 表明 DB 侧未有效鉴别调用身份） |
| ⑤ 最终影响 / Effect | 事件 `unexpected_export`——产生了非预期的数据导出物（数据外泄风险） | 已证实（第 5 行）；导出范围、数据量、是否落地外发**日志未记录，无法证实** |

- 无法证明第 4 行的 Token 是被"中继/强制认证"所得，还是被盗用/配置错误；Skill 误区规则要求不得在未证明接受机制时断言"中继成功"。

## 5. 修复建议

### 5.1 针对链 A（R1/R2，严重/高）

1. **数据库侧（接受点加固，最高优先级）**
   - 撤销/禁用匿名或 `unknown` 身份对 DB 的访问能力；所有 DB 连接必须绑定到可审计的具体服务账号。
   - 对导出类操作（export/dump/批量 SELECT INTO OUTFILE 等）实施最小权限与白名单：`service-a` 等应用账号默认无导出权限。
   - 启用 DB 审计日志，记录：操作账号、源 IP、SQL/操作类型、影响行数、导出目标路径。
2. **API 侧（认证与授权）**
   - 将 `token_scope_mismatch` 从"仅记录"改为"**默认拒绝**"，并在网关层校验 scope/audience，不匹配则 403 并告警。
   - 对 `service-a` 等服务账号实施凭据轮换，排查是否已泄露；检查 Token 签发与作用域配置是否过宽。
3. **网络与横向移动**
   - 复核 API → DB 的网络访问策略，遵循最小可达原则；DB 不应被非预期网段直接访问。
   - 若环境使用 Windows/NTLM 类认证，按纵深防御启用签名与 EPA（扩展保护），降低中继类风险（本日志未证实该类攻击，仅作通用加固建议）。
4. **数据外泄检测**
   - 对 09:07:30Z 前后的 DB 导出物进行追溯：定位导出文件/路径、校验数据量与敏感度、检查是否外发。

### 5.2 针对 R3（admin 登录失败，中）

- 对 admin 账户启用登录失败锁定/限速与 MFA；禁止 admin 从非管理网段登录。
- 将短时同源多次失败接入实时告警（当前仅 2 次，建议阈值化监控）。

### 5.3 针对 R4（日志质量，低）

- 修复日志采集管道，确保 severity/user/source_ip 必填；对畸形记录建立丢弃率监控与死信队列。
- 统一时间戳为 UTC 并确保时钟同步，保证跨系统关联准确性。
