# gws-calendar-insert 评测与最小可用预演说明

评测对象：gws-calendar-insert（分类：个人效率 / productivity，版本 0.22.5）
日期：2026-08-12（周三）

---

## 一、Skill 真实能力核实（基于 SKILL.md 原文）

该 Skill 只做一件事：通过命令 `gws calendar +insert` 在 Google Calendar 创建**一个**新事件。

- 必填参数：`--summary`、`--start`、`--end`（RFC3339/ISO 8601，如 `2026-06-17T09:00:00-07:00`）
- 可选参数：`--calendar`（默认 primary）、`--location`、`--description`、`--attendee`（可多次）、`--meet`
- 前置依赖：
  1. 本机需安装 `gws` 二进制（metadata.requires.bins）
  2. 需先阅读 `../gws-shared/SKILL.md`（认证、全局标志、安全规则）；缺失时需 `gws generate-skills`
- 关键安全规则：SKILL.md 末尾 CAUTION 明确——这是**写命令，执行前必须与用户确认**。

**能力边界（重要）**：该 Skill **不具备**以下能力，不能用它直接完成用户设想的全流程：
- 不能收集/拉取待办事项（无 list/search/任务系统对接）
- 不能筛选逾期项（无查询与过滤能力）
- 不能生成自然语言摘要（这是上层逻辑/LLM 的工作）
- 不能实现"发送前审批流"，仅要求单次写前确认
- 无 dry-run、无回滚标志

它在整个自动化里只能承担最后一步：**把已生成并经人工确认的摘要，作为一个日历事件写入 Google 日历**。

## 二、冲突、缺失与风险识别

### 事实（已核实）
1. `gws` 二进制未安装（`which gws` 返回 command not found）。
2. 上传的 ZIP 内仅含 `gws-calendar-insert/SKILL.md`，**不含** `gws-shared/SKILL.md`，认证方式与全局安全规则无法核实。
3. 未提供任何 Google 账号授权、生产凭据或 token。
4. 用户未提供五人团队的真实名单、邮箱、待办数据源。
5. 当前日期 2026-08-12（周三），本周范围 2026-08-10 ~ 2026-08-16。

### 推断
1. `--attendee` 带邮箱创建事件时，Google 会向被邀请人发送真实邀请邮件/通知——这是外发行为，影响他人，且删除事件会再发取消通知，非静默可逆。
2. 在 gws 与 gws-shared 缺失的情况下，任何"已执行"的说法都不成立。

### 待确认项（执行真实写入前必须补齐）
1. 五人团队成员姓名与邮箱（需本人确认可被邀请）。
2. 待办数据来源（飞书任务 / Jira / Sheets / 手工清单）及读取授权。
3. "本周"时区与截止口径（按工作日还是自然周）。
4. 目标日历 ID（primary 还是团队共享日历）。
5. 是否需要 Google Meet 链接。
6. 谁是审批人、通过何种渠道留痕确认。

### 风险点
- **不可逆/外发**：创建带参会人的事件会向 5 人发邀请邮件，无法静默回滚。
- **敏感信息**：成员邮箱、个人待办内容属个人信息；预演脚本已全部使用 example.com 虚构数据。
- **未核实事实**：输入中"五人产品团队"无成员、无数据源，不能当作已授权事实直接执行。
- **越权风险**：无授权范围与凭据时执行写入，可能违反账号使用规范。

## 三、最小可用交付物（只读预演）

文件：`weekly_todo_dryrun.sh`

流程：收集本周待办 → 筛逾期（截止日 < 今天且未完成）→ 生成摘要 → 打印待执行命令 → 人工确认 → （仅在前置检查通过且 DRY_RUN=0 时）执行。

安全默认：
- `DRY_RUN=1`：只打印 `gws` 命令，不调用 gws，不写日历，不发邮件。
- 前置检查失败即停止（本次运行已因 gws 未安装、gws-shared 缺失而停止）。
- 真实写入需手动输入 `YES`。

预演结果（虚构数据）：本周 6 条待办，其中逾期 3 条（张伟 08-10、李娜 08-11、刘洋 08-09）。

## 四、权限清单（真实执行前必须具备）

1. 本机安装 `gws` 并完成 `gws auth login`（具体流程以 gws-shared 为准）。
2. 对目标 Google 日历拥有"创建事件/修改活动"权限。
3. 有权读取待办数据源（飞书任务/Jira/Sheets 等）的对应 API 或视图权限。
4. 获得 5 名团队成员同意被加入日历邀请（个人信息处理授权）。
5. 获得直属负责人/审批人对本次自动化写入的书面或消息留痕授权。

## 五、失败回滚方案

| 阶段 | 失败情形 | 回滚动作 |
|------|----------|----------|
| 收集/筛选 | 数据源不可达、字段缺失 | 中止，不进入写入；无副作用 |
| 摘要生成 | 内容有误 | 人工修正后重新预演，无副作用 |
| 人工确认 | 未输入 YES | 直接退出，无副作用 |
| gws 写入失败 | 网络/认证/参数错误 | 事件未创建，无需回滚；检查凭据后重试 |
| 事件已创建但内容错误 | 标题/时间/参会人有误 | 用 `gws calendar` 删除或更新该事件（会向参会人发送取消/更改通知，需提前告知） |
| 误邀请了无关人员 | 参会人邮箱错误 | 立即移除该参会人或删除事件，并通知相关人员 |

建议：首次真实执行时先只对 1 名测试人（自己）创建事件验证，再扩大到 5 人。

## 六、操作说明

```bash
# 1. 只读预演（默认，安全）
bash weekly_todo_dryrun.sh

# 2. 真实执行（需先完成第四节授权清单，并安装 gws、补齐 gws-shared）
DRY_RUN=0 bash weekly_todo_dryrun.sh
# 按提示核对命令，输入 YES 才会真正创建
```

真实接入数据源时，将脚本第 2 节的 `TASKS` heredoc 替换为从授权数据源拉取的结果，字段保持 `负责人|邮箱|任务|截止日|状态`。

## 七、停止条件、授权清单与人工复核点

**停止条件（任一触发即中止，不写入）**
- gws 未安装或未认证
- gws-shared/SKILL.md 缺失
- 待办数据源不可达或字段不全
- 任一参会人邮箱未核实/未授权
- 审批人未确认
- 操作者未输入 YES

**授权清单**
- [ ] Google 账号与日历写入权限
- [ ] 待办数据源读取权限
- [ ] 5 名成员的邀请同意
- [ ] 负责人书面/留痕审批

**人工复核点**
1. 数据源拉取后：核对名单与待办是否完整、有无敏感内容。
2. 逾期筛选后：确认逾期口径与状态字段准确。
3. 摘要生成后：确认标题、时间、正文、参会人列表无误。
4. 命令预览后：逐条核对 gws 参数，再输入 YES。
