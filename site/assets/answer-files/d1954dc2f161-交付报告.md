## 二、Skill 实际能力核实

已完整阅读解压后的全部文件。该 Skill 是一个**方法论/分析流程类 Skill**，不包含可执行脚本、CLI 或外部工具调用，其核心是一套五阶段人工/辅助分析流程：

| 阶段 | 名称 | 实际要求 |
| --- | --- | --- |
| 1 | 命名空间叶子节点模式识别 | 提取组件命名空间末段（如 `*/notification`），按同名分组，过滤基础设施模式（`.util/.helper/.common`） |
| 2 | 共享类/文件检测 | 扫描 import/require，找出被 2+ 组件引用的类，区分领域类与基础设施类 |
| 3 | 功能相似度分析 | 阅读源码，判断同名组件功能是否真相似、差异能否抽象 |
| 4 | 耦合影响评估 | 计算合并前传入耦合 CA 总和，估算合并后 CA，判断是否产生瓶颈 |
| 5 | 合并方式建议 | 共享服务（频繁变更/复杂）、共享库（稳定/简单）、组件合并（高度相关/低耦合） |

关键约束（来自 SKILL.md 原文）：
- **不合并基础设施功能**（日志、配置、鉴权等），只处理领域功能；
- **合并前必须做耦合分析**，CA 上升过大则不合并；
- **不能仅凭同名就合并**，必须验证功能确实相似；
- 部分重复可接受，如果它能降低耦合。

## 五、可重复验证命令

脚本路径：`./common-domain-detect.js`（与本报告同目录）。运行环境：Node.js ≥ 14（本地验证版本 v20.19.2）。

```bash
# 1. 语法检查
node --check common-domain-detect.js

# 2. 对目标仓库生成 Markdown 报告
node common-domain-detect.js /path/to/your/repo

# 3. 生成 JSON 报告（可用于回归对比或 CI 适应度函数）
node common-domain-detect.js /path/to/your/repo --json > report.json

# 4. 退出码约定：0=成功，1=目标不存在，2=未发现组件
```

脚本覆盖的五阶段映射：
- 阶段 1：`groupByLeafNode()` + `detectFilenamePatterns()`（目录名与文件名双重模式）
- 阶段 2：`detectSharedFiles()`（解析相对/别名导入，排除基础设施包）
- 阶段 3：`functionFingerprint()` + `jaccardSimilarity()`（函数名指纹相似度，作为人工读码前的线索排序）
- 阶段 4：`computeCoupling()` + `estimateConsolidatedCA()`（合并前后 CA 对比）
- 阶段 5：`generateReport()` 中的合并机会表（按领域/CA/相似度排序，给出共享服务/共享库建议）
