# Discovery Interview Plan：用户旅程、需求澄清与产品验证

> 本方案严格依据 `discovery-interview-prep` Skill 的能力边界生成。该 Skill 的定位是"客户发现访谈的战略准备流程"，输出访谈方法论、问题框架、偏差规避与成功标准；它不是脚本生成器、不是用户测试、不是销售演示、也不是大规模问卷。以下内容在该边界内，结合当事人的真实约束（每周 3 小时、无正式管理头衔、不得虚构项目成绩）做了裁剪。

---

## 0. 输入映射（按 Skill 四步问答）

Skill 规定：随调用提供的信息视为已回答，不再追问。据此映射如下：

| Skill 步骤 | 题目给定信息 | 判定 |
|---|---|---|
| Q1 研究目标 | "用户旅程、需求澄清与产品验证" | 对应 **问题验证（Problem validation）+ JTBD 发现 + 时间线/旅程走查** 的组合目标 |
| Q2 目标客群 | 未明确给出（角色、公司规模、行为特征均未知） | **待确认假设**：暂以"近期完整经历过目标任务/旅程的真实用户"为工作定义，见下方假设清单 |
| Q3 约束 | 每周 3 小时；无正式管理头衔；不能虚构项目成绩 | 对应 Skill 选项 1"有限接触"叠加选项 3"需冷启动/无权调度"；证据必须来自真实访谈 |
| Q4 方法论 | 需推荐 | 推荐 **Mom Test 式问题验证为主干，融合 JTBD 动机追问与时间线旅程走查**，见下 |

## 1. 聚焦方案

### 1.1 研究目标（一句话）

> 通过 8 场深度访谈，还原目标用户完成[核心任务]的真实旅程，识别其中高频、高痛、用户已在自行花钱/花时间解决的环节，为需求优先级和产品方向提供**基于过去行为而非观点**的证据。

### 1.2 推荐方法论与理由

**主干：Mom Test 式问题验证访谈**（Skill 明确推荐用于"验证问题是否真实且足够痛"）
- 只问过去发生的具体行为，不问假设性意愿
- 不推销方案、不透露产品设想直到最后 5 分钟

**融合：JTBD 动机追问**（Skill 推荐用于"理解用户要完成什么、现有方案为何失败"）
- 在关键节点追问"当时你最想搞定什么""是什么让你选了/放弃了它"

**融合：时间线/旅程走查**（Skill 推荐用于"还原完整上下文和痛点"）
- 让用户按时间顺序讲最近一次完整经历，天然产出用户旅程素材

**为什么不是其他方法：**
- 不做可用性测试/原型测试（Skill 明确排除：发现=学问题，测试=验方案）
- 不做大规模问卷（Skill 明确排除：深度质性访谈 5–10 人，不是 100+ 问卷）
- 不做功能优先级排序访谈（当前阶段先确认问题空间，功能排序是后续步骤）

### 1.3 范围裁剪（适配每周 3 小时）

| 维度 | 标准做法（Skill） | 本方案裁剪 |
|---|---|---|
| 访谈人数 | 5–10 人 | **8 人**（落在区间内，足够识别 3+ 人重复模式） |
| 单场时长 | 45–60 分钟 | **45 分钟**（30 分钟核心 + 开场/收尾） |
| 节奏 | 每天最多 2–3 场 | **每周 1 场**（3 小时预算：1 小时访谈+准备+复盘，2 小时招募/排期/跟进） |
| 周期 | 2 周快攻 | **12 周**（2 周准备 + 8 周访谈 + 2 周综合） |
| 招募 | 联系 20–30 人获 5–10 场（约 33% 回应率） | 同样按此比例准备，因无头衔需更靠个人关系与社区冷启动 |

### 1.4 无正式管理头衔的应对原则

无头衔意味着不能命令同事配合、不能调度用户资源。方案据此设计：
- **以"个人学习/研究"身份邀约**，不代表官方项目，降低对方审批门槛（也符合 Skill"这不是销售电话"的开场原则）
- **走轻量渠道**：直接触达用户的社区、社群、产品内反馈入口、客服/销售同事的私人引荐（请人帮忙而非指派）
- **不占用他人 KPI**：所有排期、记录、跟进自己完成，同事只需转介绍
- **产出先给帮助过你的人**：把综合结论分享给引荐人，形成正向循环

## 2. 可收集证据（真实、可验证、不可虚构）

Skill 的成功标准本身就是"听到具体故事而非泛泛抱怨""发现过去行为而非假设愿望""3 场以上出现相同模式""被意外发现""能逐字引用用户原话"。以下证据全部由真实访谈自然产生，**不需要任何虚构的项目成绩**：

### 2.1 过程证据（证明你真的做了）

| 证据 | 形式 | 说明 |
|---|---|---|
| 访谈邀约与回应记录 | 表格：联系人数/回应数/约成数/拒绝原因 | Skill 给出 33% 回应率基准，你的真实数据可对比 |
| 访谈排期表 | 日历或表格 | 8 场，含时间、对象、渠道 |
| 逐场访谈纪要 | 每场 1 份，含原话引述 | Skill 要求每场后立即记录（记忆消退快） |
| 录音（经同意） | 音频文件 | Skill 建议"在征得同意后录音"；**若对方不同意则只做笔记** |

### 2.2 发现证据（证明你学到了什么）

| 证据 | 形式 | 对应 Skill 成功标准 |
|---|---|---|
| 具体行为故事集 | "上周二我花了 3 小时……"类叙述，带时间、场景、动作 | ✅ 具体故事而非泛泛抱怨 |
| 现有应对方式清单 | 用户正在用的工具/绕法/人工流程，含时间与金钱成本 | ✅ 过去行为而非假设愿望 |
| 用户旅程图（实证版） | 按访谈还原的阶段图，每个节点标注来源访谈编号 | 由时间线走查直接产出 |
| 重复痛点模式表 | 痛点 × 出现于哪几场访谈，3 场以上独立出现才算模式 | ✅ 3+ 场重复模式 |
| 意外发现清单 | 与你初始假设矛盾的发现 | ✅ 被意外发现（若全被证实说明你在问诱导性问题） |
| 逐字引语库 | 用户原话，标注访谈编号与时间戳 | ✅ 能逐字引用 |
| 问题陈述（problem statement） | 用证据框定的问题，每条结论可回溯到具体访谈 | Skill 建议用 `problem-statement.md` 框架（该依赖文件未随包提供，见假设清单） |

### 2.3 什么不算证据（Skill 明确排除）

- ❌ "我觉得""大家都说"类观点——不是具体行为
- ❌ "如果有我会用/会买"类假设性回答——Skill 列为典型偏差
- ❌ 单场访谈的孤例——Skill 要求 5–10 场看模式
- ❌ 功能请求清单——Skill："客户不知道解决方案，你得到的是功能请求不是问题"
- ❌ 任何未经访谈发生的"成绩"——本方案不产生也不需要虚构数据

## 3. 沟通脚本

### 3.1 招募邀约脚本（冷启动/无头衔版）

**场景 A：通过社区/社群/产品反馈入口直接触达用户**

> 你好，我是 [姓名]，在做 [产品/领域] 相关的用户研究。我注意到你最近 [提到过/经历过] [具体场景]，想请你花 30 分钟聊聊你平时怎么处理这件事——不是推销，也没有预设答案，就是想了解真实情况。时间你定，可以线上语音。方便的话回复一个你合适的时间段就行，谢谢！

**场景 B：请同事（客服/销售/运营）转介绍**

> 我在做一个小范围的用户研究，想找最近 30 天内 [经历过某场景] 的用户聊 30 分钟。你手头如果有合适的客户，能不能帮我引荐一下？所有沟通我来安排，不会占用你太多时间，结束后我把整理的发现同步给你。

**邀约要点（来自 Skill 偏差规避）：**
- 不说"我们正在做一个功能想听听你意见"——这会把对方带入讨好模式
- 强调"不是销售""没有标准答案"——降低戒备
- 30 分钟而非 60 分钟——降低答应门槛（实际核心访谈 30 分钟）

### 3.2 访谈开场脚本（5 分钟，Skill 原文框架本地化）

> 谢谢你抽时间。我是 [姓名]，在研究 [问题领域]。先说明一下，这不是销售电话，我是来向你学习的。我会问一些你平时处理 [某任务] 的经历，没有对错答案，越真实、越不客气越好，批评的意见对我最有帮助。我可以做笔记/录音吗？只用于整理，不会外传。

### 3.3 核心问题脚本（30 分钟，Mom Test + JTBD + 旅程走查）

> 以下 [ ] 处替换为你的具体任务/场景。每题附"追问"和"不要问"（Skill 要求每个问题标注理由、追问、避免项）。

**Q1. 请回忆最近一次你做 [核心任务] 的经历，从头到尾是怎么个过程？**
- 理由：获取具体、近期的真实行为，而非抽象观点（Mom Test 核心）
- 追问：从哪儿开始的？接下来发生了什么？在哪儿卡住了？当时最想搞定的是什么？
- 不要问："你觉得这个流程麻烦吗？"（诱导性 + 是非问）

**Q2. 你现在一般怎么处理这件事？用什么工具、什么办法？**
- 理由：暴露现有绕法、替代方案和痛点强度；愿意花时间/钱绕开=真痛点
- 追问：大概花多少时间/钱？最烦的是哪一步？有没有凑合着用的时候？
- 不要问："你不觉得现在的方式很低效吗？"（诱导）

**Q3. 能带我一步步走一遍吗？每一步你具体做了什么？**
- 理由：还原细节、边界情况和上下文，直接产出旅程图素材
- 追问：这一步之后呢？在哪一步停下来或绕路了？为什么？
- 不要问："是不是很难？"（是非问，无信息量）

**Q4. 之前为了解决这个问题，你还试过什么别的办法？**
- 理由：了解竞争格局、未被满足的需求和放弃原因
- 追问：用了多久？喜欢什么、不喜欢什么？后来为什么不用了？
- 不要问："如果有更好的方案你会付费吗？"（假设性，Skill 列为典型偏差）

**Q5. 上一次因为这件事着急、出错或耽误事是什么情况？**
- 理由：用具体事件锚定痛点频率和严重程度
- 追问：造成了什么影响？后来怎么补救的？这种情况多久发生一次？
- 不要问："这个问题对你严重吗？"（诱导，对方会客气）

**Q6.（JTBD 动机）当时你最想完成的是什么？是什么让你决定用/不用某个办法？**
- 理由：理解动机和切换行为，而非功能偏好
- 追问：你最看重什么？什么让你放弃了之前的办法？如果只能改善一件事你选哪个？
- 不要问："你最想要什么功能？"（Skill：功能请求≠问题）

> 提问顺序按旅程时间线推进（Q1→Q3→Q5→Q2→Q4→Q6），让对方像讲故事一样自然展开。

### 3.4 访谈收尾脚本（5 分钟，Skill 原文框架本地化）

> 我复述一下刚才听到的：[关键发现 1、2、3]，我理解得对吗？
> 最后两个小问题：你还认不认识有类似经历的人？方便的话能不能帮我引荐一下？
> 今天非常有帮助，谢谢你的时间。整理完如果有有价值的发现，我同步给你。

### 3.5 全程偏差规避清单（Skill 明确列出，贴在访谈时可见处）

1. **确认偏差**：不问"你不觉得 X 是个问题吗？"→ 问"讲讲你经历 X 的过程"
2. **诱导性问题**：不问"你会用这个吗？"→ 问"你试过什么？为什么成了/没成？"
3. **假设性问题**：不问"如果我们做 Y 你会买吗？"→ 问"你现在在为什么付费？为什么？"
4. **伪装成研究的推销**：不说"我们在做 Z 来解决 X"→ 说"我在研究 X，讲讲你的经历"
5. **是非问**：不问"开票难吗？"→ 问"带我走一遍你的开票流程"

## 4. 十二周行动计划（每周 3 小时）

> 时间基准：2026-08-12（周三）起算。每周 3 小时 = 180 分钟。访谈周固定分配：约 60 分钟（访谈 45 分钟 + 当场准备 15 分钟）+ 约 30 分钟（访谈后立即写纪要）+ 约 90 分钟（招募跟进/排期/下周准备）。

### 第一阶段：准备（第 1–2 周）

**第 1 周（8/12–8/18）：框定假设与目标用户**
- [ ] 写下 1–3 条待验证的问题假设（你认为用户在哪一步最痛）
- [ ] 用一句话定义目标受访者画像（角色、近期行为、场景）——**此项若不确定，先按"最近 30 天内完整经历过 [核心任务] 的人"操作**
- [ ] 列出 3 个可触达用户的渠道（社区/社群/产品反馈/同事引荐）
- [ ] 产出：假设清单 + 受访者定义 + 渠道清单

**第 2 周（8/19–8/25）：定稿提纲与启动招募**
- [ ] 用第 3 节脚本定稿访谈提纲（把 [ ] 替换为真实场景）
- [ ] 向 20–30 人发出邀约（Skill：联系 20–30 人约成 5–10 场，约 33% 回应率）
- [ ] 建招募跟踪表（联系/回应/约成/拒绝原因）
- [ ] 约出前 2 场访谈
- [ ] 产出：终版提纲 + 招募表 + 首批 2 场排期

### 第二阶段：访谈（第 3–10 周，每周 1 场）

> 每场后 30 分钟内必须写完纪要（Skill：记忆消退快）。每完成 1 场，在模式表里更新痛点出现频次。

| 周次 | 日期 | 任务 | 当周 3 小时分配 |
|---|---|---|---|
| 第 3 周 | 8/26–9/1 | 访谈 #1 + 纪要；继续约后续场次 | 访谈 45 分 + 准备 15 分 + 纪要 30 分 + 招募跟进 90 分 |
| 第 4 周 | 9/2–9/8 | 访谈 #2 + 纪要；初步对比 #1#2 | 同上 |
| 第 5 周 | 9/9–9/15 | 访谈 #3 + 纪要；**检查点：是否出现 2 场以上重复痛点** | 同上 |
| 第 6 周 | 9/16–9/22 | 访谈 #4 + 纪要 | 同上 |
| 第 7 周 | 9/23–9/29 | 访谈 #5 + 纪要；**检查点：按 Skill，5 场后开始找模式** | 同上 |
| 第 8 周 | 9/30–10/6 | 访谈 #6 + 纪要；若招募不足本周补邀约 | 同上 |
| 第 9 周 | 10/7–10/13 | 访谈 #7 + 纪要 | 同上 |
| 第 10 周 | 10/14–10/20 | 访谈 #8 + 纪要 | 同上 |

**访谈中的纪律：**
- 每天最多 2–3 场是 Skill 上限；本方案每周 1 场远低于此，保证复盘质量
- 若某周受访者取消，用空出的时间补招募或整理，不跳过复盘
- 若 8 场中提前在 5–6 场达到模式饱和（新访谈不再产生新痛点），可提前进入综合阶段——但**不得少于 5 场**（Skill 最低要求）

### 第三阶段：综合与产出（第 11–12 周）

**第 11 周（10/21–10/27）：跨访谈模式分析**
- [ ] 汇总 8 场纪要，按旅程阶段归类痛点
- [ ] 标注每个痛点出现在哪几场（3 场以上独立出现=模式）
- [ ] 整理意外发现清单（与假设矛盾的点）
- [ ] 提炼逐字引语库
- [ ] 产出：痛点模式表 + 旅程图（实证版）+ 意外清单

**第 12 周（10/28–11/3）：问题陈述与证据包**
- [ ] 撰写问题陈述：用证据框定"谁在什么场景下，因为什么痛点，正在用什么绕法，付出什么成本"
- [ ] 每条结论标注来源访谈编号，确保可回溯
- [ ] 把发现同步给所有引荐人和受访者（承诺过的回馈）
- [ ] 产出：问题陈述 + 完整证据包（纪要/引语/旅程图/模式表/招募数据）

### 里程碑与成功判定（来自 Skill）

| 节点 | 判定标准 |
|---|---|
| 第 5 周末 | 已完成 5 场，能开始识别重复模式 |
| 第 10 周末 | 8 场完成，每场有含原话的纪要 |
| 第 12 周末 | 至少 1 个痛点在 3+ 场独立出现；至少 1 个意外发现；问题陈述每条可回溯到具体访谈 |

## 5. 仍需确认的假设与无法访问的资源

**需你确认后才能进一步细化的假设：**
1. **目标客群未明确**：角色、公司/团队规模、具体场景行为均未知。当前以"最近 30 天内完整经历过 [核心任务] 的真实用户"为工作定义。
2. **核心任务/问题领域未明确**：脚本中 [核心任务]、[问题领域] 为占位符，需替换为真实场景。
3. **是否有现有用户基础未知**：若有存量用户，招募走产品内渠道+同事引荐；若完全冷启动，走社区/社群。第 2 周渠道选择依赖此判断。
4. **录音许可未知**：脚本默认"征得同意后录音"；若所在环境合规不允许录音，则全程做详细笔记。
5. **当事人具体角色与可触达渠道未知**：影响邀约身份表述和渠道清单。
