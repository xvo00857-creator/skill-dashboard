## 2. 证据链映射（按 Skill 方法论）

Skill 参考文档 `references/dpapi-credential-chain.md` 要求重建的链条为：受保护产物 → 匹配的 masterkey/解包上下文 → 明文秘密 → 接受方服务/数据集 → 复现的能力。将其映射到本次日志事件关联：

| 链条环节 | DPAPI 原语 | 本日志对应事件 |
|---|---|---|
| ① 受保护产物/入口 | 受保护 blob | 对 `admin` 的连续登录失败（暴力尝试信号）；`service-a` 令牌作用域不匹配（凭据滥用信号） |
| ② 解包上下文 | masterkey/解包上下文 | 令牌从 `203.0.113.8` 送达 API 网关，作用域校验未通过但请求已到达边界 |
| ③ 获得的访问 | 明文秘密 | 同一 IP 在 208 秒后以 `unknown` 身份触达数据库层 |
| ④ 接受方 | 接受秘密的服务/数据集 | 数据库执行了 `unexpected_export`（非预期导出） |
| ⑤ 最终能力 | 重放得到的会话/权限 | 数据被未知主体导出（疑似数据外泄） |

**最小决定性链条（决定性边缘）：**

```
203.0.113.8  token_scope_mismatch (api, high, 09:04:02Z)
   └─ 208 秒后 ─▶ 203.0.113.8  unexpected_export (db, critical, 09:07:30Z, user=unknown)
```

判定依据：SKILL.md 第 34 行"区分 blob 解密成功与真正被接受的访问"，以及参考文档"常见陷阱"第 1 条"把 DPAPI 解密当成终点，而不去证明存在接受方服务或数据集"。对应到本案：`token_scope_mismatch` 只是边界告警（类比"解密尝试"），**不能单独证明危害**；同一 IP 紧随其后的数据库 `unexpected_export` 才是"被接受的访问/数据集"，是证明实际影响的决定性环节。因此最高风险定级锚定在完整链而非单条告警。

## 4. 关键发现详述

### R1（严重）疑似令牌滥用 → 数据库非预期导出

- **证据：**
  - `2026-08-12T09:04:02Z, api, high, token_scope_mismatch, service-a, 203.0.113.8`
  - `2026-08-12T09:07:30Z, db, critical, unexpected_export, unknown, 203.0.113.8`
- **推理链：** 同一外部 IP 先在 API 层触发服务账号 `service-a` 的令牌作用域不匹配（说明持有/伪造了令牌但权限越界），208 秒后在 DB 层以 `unknown` 身份触发非预期导出。IP 一致性 + 时间邻近性 + 严重度递增（high→critical）构成完整入侵-影响链。
- **影响：** 数据库内容可能已被未授权主体导出，构成数据保密性事件。
- **不确定性（如实声明）：** 仅凭该日志无法确认令牌是否被真实接受、导出是否成功完成、导出数据范围；也无法确认 `198.51.100.23` 的 admin 暴力尝试与 `203.0.113.8` 是否协同（两 IP 不同，最后一次 admin 失败距 token 异常仅 13 秒，存在关联可能但证据不足，不臆断）。

### R2（高）admin 账户短时暴力登录

- **证据：** `198.51.100.23` 在 09:03:45Z 与 09:03:49Z 对 `admin` 连续两次登录失败，间隔 4 秒。
- **影响：** 自动化撞库/暴力破解特征；虽未成功，但属活跃攻击信号。
- **局限：** 样本仅 2 条，无法判断是否持续或是否命中账户锁定策略。

### R3（中）日志完整性缺陷

- **证据：** 第 6 行 `2026-08-12T09:09:00Z, web, (空), malformed_record, (空), (空)`，severity/user/source_ip 三字段缺失。
- **影响：** 发生在 R1 之后约 90 秒，可能是日志管道故障，也可能是攻击者干扰审计痕迹；当前无法区分，需排查采集链路。该缺陷直接削弱证据链完整性（对应 Skill"证据保全"要求）。

### R4（中）数据库导出身份不可归因

- **证据：** R1 中 DB 事件 user=`unknown`。
- **影响：** 无法将导出操作归因到具体账户，说明 DB 访问可能绕过了应用层身份透传，或存在共享/匿名凭据。

## 5. 修复建议

| 编号 | 建议 | 优先级 |
|---|---|---|
| R1-1 | 立即吊销/轮换 `service-a` 相关令牌，核查该令牌在 09:04–09:08Z 的全部调用记录 | 紧急 |
| R1-2 | 核查数据库在 09:07:30Z 前后的导出任务、备份作业与批量查询记录，确认是否有真实数据流出及范围 | 紧急 |
| R1-3 | API 网关强制校验令牌作用域（scope），作用域不匹配直接拒绝并告警，不应放行至后端 | 高 |
| R1-4 | 数据库层禁用匿名/`unknown` 身份执行导出，所有导出必须绑定可归因的应用身份与审批单号 | 高 |
| R2-1 | 对 `admin` 登录启用账户锁定/速率限制与 MFA；对 `198.51.100.23` 临时封禁并调查 | 高 |
| R3-1 | 排查 web 日志采集管道，修复畸形记录；对缺失关键字段的日志设置质量监控与告警 | 中 |
| R3-2 | 日志启用防篡改存储（只追加/WORM）与时间同步，排除攻击者干扰审计可能 | 中 |
| R4-1 | 应用到 DB 的连接启用身份透传与最小权限账号，禁止共享高权限账号 | 中 |

## 7. 最小可验证版本（MVV）关键步骤与验收标准

**关键步骤：**
1. 只读加载并校验 `incident_log.csv` 结构（6 行、6 字段），标记字段缺失行。
2. 按 IP 聚合事件，计算同 IP 事件时间差，识别跨系统关联（`203.0.113.8` 横跨 api/db）。
3. 按 Skill 证据链模型将事件映射为"入口→边界→接受方→影响"，定位决定性边缘。
4. 按严重度分级并逐项绑定原始日志行作为证据，不引入日志外假设。
5. 产出修复建议与复测清单。

**验收标准：**
- 每条风险均可回溯到具体 CSV 行号与时间戳，无凭空结论。
- 最高风险项以"被接受的访问"（DB 导出）而非单条边界告警定级，体现 Skill 第 34 行规则。
- 明确列出证据不足之处（如两 IP 是否协同、导出是否成功），不臆断。
- 全程只读，未对日志文件或任何外部系统做修改/利用。
- 报告文件 `security-audit.md` 可独立阅读，包含风险分级、证据、修复建议、复测清单四要素。

## 10. 影响结果的 SKILL.md 规则（至少一条）

**SKILL.md 第 34 行："Distinguish successful blob decryption from actual accepted access."（区分 blob 解密成功与真正被接受的访问）**，配合参考文档"常见陷阱"第 1 条"把解密当成终点而不证明接受方服务/数据集"。

该规则直接决定了本报告的定级方式：没有把 `token_scope_mismatch`（high）单独作为最高结论，而是沿同 IP 向下追踪到数据库 `unexpected_export`（critical）这一"被接受的访问"，以完整链条锚定严重风险。若忽略此规则，结论会停留在边界告警层面，漏掉真正的数据外泄影响。

此外，SKILL.md 第 8 行关于"仅作为 `$ctf-sandbox-orchestrator` 下游使用"的前置规则，促使本报告第 1 节如实声明前置条件未满足并以用户授权约束等效替代，限定了全程只读、不利用的边界。
