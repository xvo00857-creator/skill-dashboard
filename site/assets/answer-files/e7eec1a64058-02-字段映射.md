# Adyntel 每周自动化 —— 字段映射

> 依据：`adyntel-automation/SKILL.md`
> 核心原则：**工具 slug、参数字段名与类型必须来自 `RUBE_SEARCH_TOOLS` 的实时返回，不得硬编码**（SKILL.md Known Pitfalls: "Always search first"、"Schema compliance"）。

---

## 1. 映射总览

数据在流程中经历四次形态转换：

```
RUBE_SEARCH_TOOLS 返回的 schema
        │  ① 动态提取工具 slug 与参数定义
        ↓
RUBE_MULTI_EXECUTE_TOOL 请求参数（arguments）
        │  ② 执行返回原始记录
        ↓
raw_records（原始数据页，多页合并）
        │  ③ 归一化映射
        ↓
normalized_records（内部标准结构）
        │  ④ 聚合
        ↓
summary（摘要对象 + 文本）
        │  ⑤ 按通知工具 schema 组装
        ↓
notification arguments（通知请求参数）
```

---

## 2. 映射 ①：从工具发现结果到执行参数

`RUBE_SEARCH_TOOLS` 返回结构（按 SKILL.md 描述）包含：工具 slug、输入 schema、推荐执行计划、已知陷阱。

| 目标位置 | 来源 | 映射规则 |
|----------|------|----------|
| `tools[].tool_slug` | 搜索结果中匹配"use_case"的工具条目 | 取条目的 slug 字段原值，**不做任何改写或猜测** |
| `tools[].arguments` | 该工具条目的 input schema | 按 schema 的 `properties` 填充：必填字段必须提供；枚举字段取 `enum` 内值；时间范围字段由运行时 `run_meta` 计算本周起止 |
| `memory` | —— | 固定传 `{}`（SKILL.md："Always include `memory`, even if empty"） |
| `session_id` | 阶段 0 生成 | 全流程复用同一个 |

**动态绑定逻辑（伪代码）：**

```python
discovered = rube_search_tools(use_case="...", session_id=sid)
data_tool = select_tool(discovered, role="data_collection")  # 按推荐执行计划/描述匹配
notify_tool = select_tool(discovered, role="notification")

# 参数键名完全来自 schema.properties，不硬编码
args = {}
for field_name, field_def in data_tool.input_schema["properties"].items():
    if field_name in TIME_RANGE_FIELDS:        # 时间类字段运行时填本周范围
        args[field_name] = this_week_range()
    elif field_def.get("required"):
        args[field_name] = resolve_from_run_meta(field_name, field_def)
```

> 注意：`TIME_RANGE_FIELDS` 等匹配集合只用于**判断字段语义**（如字段名包含 date/start/end），实际写入 `arguments` 的键名仍取自 schema 原值。

---

## 3. 映射 ②：执行返回 → raw_records

| 目标位置 | 来源 | 映射规则 |
|----------|------|----------|
| `raw_records` | `RUBE_MULTI_EXECUTE_TOOL` 响应体 | 提取数据列表（键名以当次返回为准，通常在 `results` / `data` / `items` 中，按实际响应解析） |
| 多页合并 | 响应中的分页 token | 存在分页 token 时继续请求，将各页列表追加合并；无 token 时结束（SKILL.md "Pagination"） |

---

## 4. 映射 ③：raw_records → normalized_records（内部标准结构）

由于真实字段名需运行时从 schema 获知，内部采用"宽松归一化"策略：保留原始字段，同时抽取通用维度。

**内部标准记录结构：**

| 内部字段 | 类型 | 来源/映射规则 | 缺失兜底 |
|----------|------|---------------|----------|
| `record_id` | string | 原始记录中的 id/uid/key 类字段（按存在的键取） | 自动生成 `rec_<序号>` |
| `record_date` | string(YYYY-MM-DD) | 原始记录中的 date/time/created_at 类字段，解析为日期 | `null`，摘要中标注"日期缺失 N 条" |
| `category` | string | 原始记录中的 type/category/status 类字段 | `"unknown"` |
| `amount` | number | 原始记录中的 amount/value/count 类数值字段 | `null`（不计入数值汇总） |
| `raw` | object | **原始记录完整保留** | —— |

映射规则：
- 字段名匹配不区分大小写，容忍下划线/驼峰差异；
- 同一语义存在多个候选字段时，优先取非空值；
- 原始记录完整保存在 `raw` 中，保证可追溯，不丢信息。

---

## 5. 映射 ④：normalized_records → summary

**摘要对象结构：**

| 摘要字段 | 类型 | 计算规则 |
|----------|------|----------|
| `week_start` / `week_end` | date | 本周一 / 本周日（运行时计算） |
| `total_records` | int | `len(normalized_records)` |
| `date_missing_count` | int | `record_date is null` 的条数 |
| `categories` | object | 按 `category` 分组计数 |
| `amount_sum` / `amount_avg` | number | 对非 null `amount` 求和/均值；无有效值时为 `null` |
| `empty_week` | bool | `total_records == 0` |
| `generated_at` | datetime | 摘要生成时间 |

**可读文本模板：**

```
【Adyntel 周报】{week_start} ~ {week_end}
本周共 {total_records} 条记录。
分类分布：{categories}
金额合计：{amount_sum}，均值：{amount_avg}
{若 date_missing_count>0}注意：{date_missing_count} 条记录日期缺失。
{若 empty_week}本周无数据。
生成时间：{generated_at}
```

---

## 6. 映射 ⑤：summary → notification arguments

| 目标位置 | 来源 | 映射规则 |
|----------|------|----------|
| 通知工具 `tool_slug` | 阶段 1 发现结果 | 取通知类工具 slug 原值 |
| `arguments` 接收人字段 | 运行配置 `owner_contact` | 按通知工具 schema 中"接收人/收件人/to"类字段填充；字段名以 schema 为准 |
| `arguments` 正文/消息字段 | summary 可读文本 | 按 schema 中"message/content/body/text"类字段填充 |
| `memory` | —— | 固定 `{}` |

负责人联系方式来自本地配置文件 `config.json`（不写入代码、不上传外部），键为 `owner_contact`。
