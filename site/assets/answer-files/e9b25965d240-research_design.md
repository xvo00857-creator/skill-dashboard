# 基于 CELLxGENE Census 的 COVID-19 免疫细胞跨组织转录组描述性研究方案

> 数据来源：CZ CELLxGENE Census 2025-11-08 稳定 LTS 版
> 工具版本：cellxgene-census 1.17.x，Python 3.11
> 团队：3 人 | 周期：2 周 | 资料范围：仅公开数据

---

## 一、研究问题与定位

### 1.1 核心问题

在公开单细胞转录组数据中，COVID-19 患者与正常对照的免疫细胞在**外周血**与**肺组织**中的细胞类型组成和已知标记基因表达存在哪些可重复的跨数据集差异？

### 1.2 研究类型

**描述性、跨数据集比较研究**，不是因果推断研究。

- 我们描述不同疾病标注组之间在细胞组成和基因表达上的**关联模式**；
- 数据来自不同研究、不同采样时间、不同严重程度的患者，混杂因素无法在本设计中完全控制；
- 任何"COVID-19 导致某变化"的表述均超出本研究证据等级，全文使用"与……相关""在……组中观察到"等措辞。

### 1.3 为什么选这个题目

基于实际运行 Census 元数据探索得到的真实数据分布：

| 维度 | 实际数值（2025-11-08 LTS，人类原代细胞） |
|---|---|
| COVID-19 标注细胞 | 4,688,586 |
| long COVID-19 | 2,306 |
| post-COVID-19 disorder | 97,224 |
| 正常对照细胞 | 64,381,160 |
| blood 组织细胞 | 25,872,063 |
| lung 组织细胞 | 6,443,005 |
| T cell 细胞 | 1,330,245（含各亚型更多） |
| 人类数据集总数 | 1,845（全物种） |

COVID-19 细胞量充足（469 万），blood 和 lung 是数据量最大的两个相关组织，免疫细胞注释丰富，适合在两周内完成聚焦分析。

## 二、范围取舍

### 2.1 纳入范围

- **物种**：仅人类（homo_sapiens），99,633,637 个原代细胞，数据量最充足
- **组织**：blood（外周血）和 lung（肺），分别代表系统性免疫应答和局部免疫应答
- **疾病分组**：
  - 病例组：`disease == 'COVID-19'`（4,688,586 细胞）
  - 对照组：`disease == 'normal'`，且组织为 blood 或 lung
- **细胞类型**：免疫细胞大类，包括 T cell、B cell、monocyte/macrophage、NK cell、neutrophil 等（以 ontology term ID 为准）
- **基因**：先查 `feature_dataset_presence_matrix` 确认覆盖度，再选约 20-50 个已知免疫标记基因和细胞因子基因
- **Census 版本**：固定 `2025-11-08`，所有脚本显式指定

### 2.2 排除范围及理由

| 排除项 | 理由 |
|---|---|
| long COVID-19 / post-COVID-19 | 细胞量仅 2,306 / 97,224，且定义与急性期不同，两周内无法充分分层 |
| 其他物种 | 跨物种比较需要额外的同源基因映射，超出两周人力 |
| 空间转录组数据 | 需要 `[spatial]` 额外依赖和不同的分析流程，且 COVID-19 空间数据有限 |
| 全转录组差异表达 | 数万基因的跨数据集整合需要大量批次校正和计算资源，两周内不可靠 |
| 疾病严重程度分层 | Census 元数据中无统一的严重程度字段，需逐篇查原文，超出公开资料范围 |
| 因果推断/机制验证 | 观察性跨数据集数据无法支持，且无湿实验验证条件 |
| 机器学习细胞类型分类器 | 训练需要 GPU 和大量调参时间，与描述性研究目标不匹配 |

### 2.3 主要妥协

1. **不做全转录组差异表达**，只做预设标记基因集的表达比较——降低计算量和多重比较负担，但可能遗漏新发现
2. **不做复杂批次校正**（如 scVI、Harmony），改用数据集层面的汇总统计和随机效应——保守但可解释
3. **不区分疾病严重程度和病程阶段**——这是最大的混杂来源，在局限性中明确声明

## 三、资料选择标准

### 3.1 数据集纳入标准

从 Census 的 `census_info["datasets"]` 表中筛选：

1. 物种为 Homo sapiens
2. 组织为 blood 或 lung（含 PBMC 等 blood 子类）
3. 疾病标注包含 COVID-19 或 normal
4. 细胞数 ≥ 100（避免极小数据集引入不稳定估计）
5. 检测技术为 10x 3' v2/v3 或 10x 5' v1/v2（占人类数据 80% 以上，技术同质性较好）
6. 元数据中 `donor_id` 非空且可区分不同供体

### 3.2 数据集排除标准

1. 仅含细胞核（`suspension_type == 'nucleus'`）的数据集——本次探索显示人类数据全部为 `cell` 悬液，但仍需逐数据集确认
2. 无法区分供体的数据集（`donor_id` 全部相同或缺失）
3. 疾病标注为多值（含 ` || ` 分隔符）且无法判断主诊断的数据集

### 3.3 基因选择标准

1. 先用 `get_presence_matrix()` 检查基因在纳入数据集中的覆盖率，要求 ≥ 80% 数据集检测到
2. 从文献中选择已知免疫标记基因：
   - T 细胞：CD3D, CD3E, CD4, CD8A, IL7R, CCR7, FOXP3
   - B 细胞：CD19, MS4A1, CD79A
   - 髓系：CD14, CD16/FCGR3A, CD68, FCGR3A, LYZ
   - NK：NCAM1, NKG7, GNLY
   - 细胞因子/炎症：IL6, TNF, IFNG, CXCL8, CCL2
3. 基因名使用 Ensembl ID（`feature_id`）查询，避免符号歧义

### 3.4 外部文献

仅使用公开文献支持标记基因选择和结果解读，不使用任何付费数据库或需登录的资源。文献检索在 PubMed 和 Google Scholar 进行。

## 五、分析方案

### 5.1 分析流程

```
步骤 1：元数据探索（第 1-2 天）
  ├─ 固定 census_version="2025-11-08"
  ├─ 读取 obs 表，筛选 blood/lung 中 COVID-19 和 normal 细胞
  ├─ 所有查询加 is_primary_data == True
  ├─ 统计：细胞数、供体数、数据集数、组织分布、细胞类型分布
  └─ 输出：数据清单表（每个数据集的细胞数、供体数、技术、疾病标注）

步骤 2：基因覆盖度检查（第 2 天）
  ├─ get_presence_matrix() 检查候选基因
  ├─ 要求 ≥80% 数据集检测到
  └─ 确定最终基因列表（约 20-50 个）

步骤 3：细胞组成比较（第 3-5 天）
  ├─ 按数据集 × 疾病组 × 组织 统计细胞类型比例
  ├─ 使用供体层面的汇总（非细胞层面），避免伪重复
  ├─ 统计检验：Mann-Whitney U 或混合效应模型（数据集为随机效应）
  └─ 可视化：分组箱线图 + 散点

步骤 4：标记基因表达比较（第 5-8 天）
  ├─ get_anndata() 分批查询表达量（每批 <10 万细胞）
  ├─ 按 SKILL.md 建议：先估计查询大小，超 10 万细胞用 axis_query() 流式处理
  ├─ 标准化：按数据集分别 normalize_total + log1p（注意 UMI vs read count 差异）
  ├─ 按供体计算平均表达，再做组间比较
  └─ 统计检验：同上，供体为统计单位

步骤 5：批次效应诊断（第 8-9 天）
  ├─ 检查数据集间异质性（UMAP 按数据集着色）
  ├─ 按 assay 分层分析（10x 3' v2 vs v3）
  ├─ 敏感性分析：仅纳入 10x 3' v3 数据集重复主要结果
  └─ 记录无法消除的批次混杂

步骤 6：结果整理与报告（第 10-14 天）
  ├─ 生成图表和表格
  ├─ 撰写描述性报告
  ├─ 代码和数据清单归档
  └─ 内部交叉审核
```

### 5.2 关键技术决策（受 SKILL.md 规则影响）

1. **所有查询固定 `census_version="2025-11-08"`**——SKILL.md 要求可重复分析
2. **所有细胞查询加 `is_primary_data == True`**——避免重复计数（SKILL.md 核心规则）
3. **两步工作流：先探索元数据再查表达量**——SKILL.md 推荐模式
4. **大查询使用 `axis_query()` 流式处理**——COVID-19 T 细胞可能超 10 万，不适合一次性 `get_anndata()`
5. **使用 `obs_column_names` 只选必要列**——减少数据传输
6. **用 `feature_id`（Ensembl ID）而非 `feature_name` 查询基因**——避免符号歧义
7. **注意 UMI vs read count 计数类型差异**——不同技术需分别标准化
8. **`disease` 字段可能含 ` || ` 多值**——先检查再决定过滤策略

### 5.3 统计分析原则

- **统计单位是供体，不是细胞**——同一供体的数千个细胞不是独立样本
- 每个数据集内，先按供体汇总（细胞比例或平均表达），再做组间比较
- 使用混合效应模型：`~ disease_group + (1|dataset_id)`，数据集为随机效应
- 多重比较使用 Benjamini-Hochberg 校正
- 报告效应量（中位数差异、Cliff's delta），不仅报告 p 值
- **不做因果声明**，所有结论表述为"在 COVID-19 组中观察到……与疾病标注相关"

## 七、质量检查方法

### 7.1 数据层面

| 检查项 | 方法 | 通过标准 |
|---|---|---|
| 细胞唯一性 | 确认所有查询含 `is_primary_data == True` | 无重复计数 |
| 版本一致性 | 所有脚本头部固定 `census_version="2025-11-08"` | 版本号一致 |
| 基因覆盖度 | `get_presence_matrix()` | 每个基因 ≥80% 数据集检测到 |
| 供体独立性 | 检查 `donor_id` 是否跨数据集重复 | 同一供体不跨组出现 |
| 计数类型 | 检查 `assay` 字段，区分 UMI 和 read count | 标准化时分层处理 |
| 疾病标注完整性 | 检查 `disease` 字段是否含 ` || ` 多值 | 多值记录单独标记 |

### 7.2 分析层面

| 检查项 | 方法 |
|---|---|
| 伪重复 | 统计单位为供体，非细胞；混合效应模型含数据集随机效应 |
| 批次效应 | UMAP 按数据集着色；按 assay 分层；仅 10x 3' v3 敏感性分析 |
| 多重比较 | BH 校正，报告 FDR 和效应量 |
| 代码复现 | 所有脚本从 Census 版本号开始可一键重跑；随机种子固定 |
| 交叉审核 | 成员 B 审核成员 A 的数据提取，成员 A 审核成员 B 的统计代码 |

### 7.3 报告层面

- 每个数字标注来源（Census 表名或脚本输出）
- 每个图表标注数据集数和供体数
- 局限性章节明确列出：观察性设计、无法控制严重程度/病程/治疗、批次效应、疾病标注异质性
- 不使用"导致""引起""证明"等因果性措辞

## 八、因果推断边界声明

本研究的数据是多个独立研究的集合，存在以下无法控制的混杂：

1. **适应症混杂**：COVID-19 患者和正常对照的采样指征不同
2. **批次与技术混杂**：不同数据集使用不同技术、不同测序深度
3. **人群混杂**：年龄、性别、种族、合并症分布不均
4. **时间混杂**：采样时间点（感染后天数）未统一记录
5. **治疗混杂**：患者接受的治疗未在元数据中记录

因此，本研究只能报告**跨数据集的关联模式**，不能推断 COVID-19 与任何转录组变化之间的因果关系。任何发现都需要通过前瞻性队列研究或实验验证。

### 实际影响交付结果的 SKILL.md 规则

**"Always Filter for Primary Data"（始终过滤原代数据）规则**直接影响了本方案的全部数据获取设计：

> SKILL.md 原文："Unless analyzing duplicates, always include `is_primary_data == True` in queries to avoid counting cells multiple times"

这一规则的影响体现在：
- 所有细胞计数均基于 `unique_cell_count`（125,463,259）而非 `total_cell_count`（217,768,036），两者相差近一倍——如果不过滤，细胞类型比例和疾病组样本量都会被严重高估
- 研究方案中每个查询模板都显式包含 `is_primary_data == True`
- 质量检查表将此列为第一项检查

此外，SKILL.md 中关于 **"disease 字段可能含 ` || ` 分隔多值"** 的提示（来自 census_schema.md 和 core_workflow_patterns.md）直接影响了疾病分组策略：方案要求在正式查询前先检查多值标注，而非直接使用 `disease == 'COVID-19'` 假定精确匹配。
