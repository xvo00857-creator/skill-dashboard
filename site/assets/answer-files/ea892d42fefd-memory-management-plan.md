# memory-management 最小流程与一周试运行方案

> 依据附件 `memory-management/SKILL.md` 制定。下面所有"记忆/Tape/Skill/定时任务"的表述均以该文件规则为准。

## 一、能力边界声明（先于一切）

1. **SKILL.md 的真实职责**：指导 agent 把"持久学习"路由到四类载体——Memory（持久结论）、Skill（可复用流程）、Scheduled Task（周期事项）、Tape（原始证据）。它是一套记忆分类与最小化规则，**不是**笔记软件、任务管理器或自动复盘工具。
2. **与题目假设的冲突**：题目归类为"个人效率"并要求"承诺追踪、阶段复盘"，但 SKILL.md 没有这两项直接功能：
   - 承诺只能以 `task_outcome` 类记忆记录状态（含阻塞/延期）；SKILL.md 第 42 行明确 Memory 不唤醒 agent、不安排未来工作、不产生自动化副作用，因此**不能依赖 Memory 自动提醒承诺**。
   - 复盘只能靠"任务结束学习检查"（6 问）+ 建议用户在设置中创建 Scheduled Task 周期触发；Memory 本身不做复盘。
3. **当前环境工具可用性（已实测检索）**：`memory_recall`、`memory_remember`、`tape_search`、`tape_context`、`skill_manage` 均不可用。因此本方案中的"写入记忆""检索 Tape""起草 Skill"步骤目前无法由我实际执行，需在支持这些工具的环境中运行，或先用本地文件作为过渡载体（模板已按本地文件可用设计）。
4. **旧资料未提供**：附件 zip 仅含 SKILL.md，无任何旧资料内容。迁移步骤为通用流程，需你确认旧资料位置后才能实际执行；我不会编造旧资料内容或迁移结果。
5. **未实际创建定时任务**：你未指定每日维护时段，我未代为创建任何提醒；如需我用本地定时任务能力创建提醒，请告知时间。

## 二、最小流程（每日 ≤15 分钟）

依据 SKILL.md：只记最小持久结论；原始过程留 Tape；敏感信息不记。

| 步骤 | 时长 | 动作 | 说明 |
|---|---|---|---|
| 1 收集 | 2 分钟 | 列出当天新增：决策、承诺、可复用经验、踩坑 | 先入收集箱，不急着分类 |
| 2 路由 | 5 分钟 | 逐条按路由树判断去向 | 见下方路由树 |
| 3 承诺核对 | 5 分钟 | 更新每条承诺状态 | 以 `task_outcome` 记录 |
| 4 收尾 | 3 分钟 | 回答 6 问，最多存 1 条持久结论 | 无结论则不存 |

**路由树（严格按 SKILL.md 第 18–42 行）**：

- 是密钥/凭证/隐私/原始工具输出/一次性失败/仅本轮有用 → **不记**
- 是可复用多步流程 → `skill_manage` 草稿（Memory 只放一行指针）
- 是周期/未来重复事项 → Scheduled Task（不进 Memory）
- 需要原始措辞/证据/日志/命令输出 → Tape（`tape_search`/`tape_context`）
- 是改变未来行为的持久结论 → `memory_remember`，选最具体分类：
  - `user_preference`：稳定偏好、约束、沟通风格、环境选择
  - `project_fact`：项目约定、架构入口、命令、依赖、路径、运维约束
  - `task_outcome`：已完成/阻塞/主动延期的任务结果（含状态与阻塞原因）
  - `heuristic`：可复用排障策略、工作流、决策规则、工程经验
  - `anti_pattern`：重复错误、不安全做法、脆弱模式、过时假设

**任务结束 6 问（SKILL.md 第 46–53 行）**：①是否有稳定偏好/约束；②是否有持久项目事实；③是否有任务结果/阻塞/延期值得保留；④是否有奏效的启发式；⑤是否出现反模式或过时假设；⑥这究竟该进 Skill 还是 Scheduled Task 而非 Memory。

## 三、迁移步骤（旧资料 → 新结构）

针对"旧资料结构混乱"，按 SKILL.md 第 32 行"规范化为简洁记忆内容、去重、不保留原始对话文本"原则：

1. **定位**：确认旧资料所在目录/文件（**待你提供路径**）。
2. **只读扫描**：不改动原文件，列出清单与体量。
3. **提取结论**：逐条只抽取"改变未来行为"的持久结论；丢弃原始对话、日志全文、临时输出。
4. **分类**：归入上述 5 类；无法归类的默认丢弃（宁可少记，SKILL.md 要求只记最小结论）。
5. **去重合并**：相近条目合并为一条简洁表述。
6. **敏感清洗**：剔除密码、token、凭证、个人隐私（SKILL.md 第 26 行禁止记忆，且你要求不上传外部服务）。
7. **流程上收**：多步可复用流程抽成 skill 草稿，Memory 只留一行指针。
8. **周期事项上收**：重复提醒类转 Scheduled Task。
9. **原始归档**：旧资料原文移到只读归档区（Tape 定位），备查但不进 Memory。
10. **验收**：迁移后条目数应远少于原始条数；每条都能回答"它未来会改变什么行为"。

> 迁移分批进行，每天 ≤15 分钟，不做一次性大扫除。

## 七、实际影响交付结果的 SKILL.md 规则

1. **第 26 行**："Do not remember raw tool results, bash output, grep output, file contents, transient mechanics, one-off failures, secrets, credentials, hidden reasoning, or anything only useful for the current turn."
   → 直接决定迁移采用"只抽持久结论、不搬原文"策略，模板不设"原文粘贴"字段，并把敏感信息排除在记忆外，与你"敏感信息不上传外部服务"一致。
2. **第 42 行**："Memory does not wake the agent, schedule future work, or create automation side effects."
   → 决定了承诺追踪不能依赖 Memory 自动提醒、阶段复盘必须借助 Scheduled Task 外部触发，这是本方案把"提醒/复盘"与"记忆"明确拆开的原因。
3. **第 32 行**：自动提取应"normalize…into concise memory content, deduplicate…avoid preserving raw transcript text"
   → 决定了迁移第 3–5 步的提取、分类、去重做法。
