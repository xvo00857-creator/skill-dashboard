# API 安全审计报告（模拟日志分析）

- **审计对象**：`incident_log.csv`（模拟安全事件日志，6 条记录）
- **审计依据 Skill**：`api-security`（分类：安全与合规）
- **审计时间**：2026-08-13
- **审计范围**：仅对随附的模拟日志文件进行**被动分析**，不进行任何主动探测、利用或破坏性操作
- **授权声明**：本任务由用户明确授权，且输入数据全部使用 RFC 5737 文档保留 IP 段（192.0.2.0/24、198.51.100.0/24、203.0.113.0/24），确认为模拟数据

## 一、最小可验证版本（MVP）：关键步骤与验收标准

### 关键步骤

1. **读取 Skill 与输入**：解压 `api-security.zip`，完整读取 `SKILL.md` 及 `references/` 下两份参考文件；读取 `incident_log.csv` 全部 6 条记录。
2. **数据完整性校验**：用脚本解析 CSV，校验字段缺失、时间戳连续性、IP 归属（确认均为 RFC 5737 文档段）。
3. **按 Skill 阶段分类**：将每条事件映射到 SKILL.md 的 10 阶段方法论（Phase 2 认证、Phase 3 授权、Phase 8 限速、Phase 9 数据暴露）。
4. **单事件风险定级**：依据日志自带 severity 字段 + 事件类型 + 上下文，逐条给出风险等级与证据。
5. **关联分析**：按源 IP 与时间窗口聚合，识别攻击链。
6. **产出报告**：形成风险分级表、证据、修复建议、复测清单，保存为 `security-audit.md`。

### 验收标准

| 编号 | 验收项 | 标准 |
|------|--------|------|
| AC-1 | 日志记录全覆盖 | 6 条记录逐条分析，无遗漏 |
| AC-2 | 风险分级 | 每条事件给出 Critical/High/Medium/Low/Info 之一及理由 |
| AC-3 | 证据可复现 | 引用原始 CSV 行的时间戳、system、event、user、source_ip |
| AC-4 | 攻击链识别 | 至少识别出一组跨事件关联（同 IP + 时间邻近） |
| AC-5 | 修复建议可操作 | 每条风险给出具体修复方向，对应 Skill 阶段 |
| AC-6 | 复测清单 | 每条修复项给出可验证的复测步骤 |
| AC-7 | 无破坏性操作 | 全程仅读取与分析，未发起任何网络请求或修改目标系统 |
| AC-8 | 缺失文件如实声明 | 未读取的引用文件明确列出，不编造内容 |

### 原始数据

### 事件 1：alice 正常登录

- **风险等级**：Info（基线事件）
- **证据**：`2026-08-12T09:00:12Z,web,info,login_success,alice,192.0.2.10`
- **分析**：单次成功登录，severity=info，无异常特征。作为正常基线参考。
- **处置**：无需处置，保留基线。

### 事件 2–3：admin 账户连续登录失败（疑似暴力破解）

- **风险等级**：High
- **证据**：
  - `2026-08-12T09:03:45Z,web,warning,login_failed,admin,198.51.100.23`
  - `2026-08-12T09:03:49Z,web,warning,login_failed,admin,198.51.100.23`
  - 两次失败间隔 **4 秒**，同一源 IP，目标均为高权限账户 `admin`
- **Skill 阶段映射**：Phase 2（认证测试——弱口令/暴力枚举）、Phase 8（限速与 DoS——登录接口限速缺失或被绕过）
- **分析**：4 秒内对 admin 账户连续两次失败登录，符合自动化暴力破解/密码喷洒的早期特征。日志中仅见 2 次，可能是截取窗口内的片段，不能排除窗口外存在更多尝试。参考 jwt-oauth-testing.md 中「无 client 限速 → 暴力枚举」的攻击面描述。
- **影响**：若 admin 口令被破解，攻击者可获得管理权限，进一步导致 BFLA（Phase 3）。

### 事件 4：service-a 令牌 scope 不匹配

- **风险等级**：High（单独看）；与事件 5 关联后升为 **Critical**
- **证据**：`2026-08-12T09:04:02Z,api,high,token_scope_mismatch,service-a,203.0.113.8`
- **Skill 阶段映射**：Phase 2（JWT/OAuth——scope 提升/过度授权）、Phase 3（BFLA——功能级授权绕过）
- **分析**：服务账户 `service-a` 持有的令牌被用于请求超出其授予 scope 的资源。jwt-oauth-testing.md 明确将「测试 scope 提升: scope=read → scope=read write」「过度 scope 授予」列为攻击面。该事件表明令牌校验层检测到了越权尝试，但事件本身被记录为 high 而非被阻断，需确认该请求是被拒绝还是仅告警后放行。
- **关键疑点**：若 scope 校验仅告警未阻断，则事件 5 的数据导出可能直接由此越权令牌完成。

### 事件 5：数据库异常导出（疑似数据外泄）

- **风险等级**：Critical
- **证据**：`2026-08-12T09:07:30Z,db,critical,unexpected_export,unknown,203.0.113.8`
- **Skill 阶段映射**：Phase 3（BOLA——对象级授权绕过）、Phase 9（数据暴露——分页枚举/响应过度暴露/未授权数据导出）
- **分析**：
  - 用户字段为 `unknown`，表明导出操作未关联到任何已认证身份，或身份信息已丢失/被伪造。
  - 源 IP `203.0.113.8` 与事件 4 **完全相同**，且时间仅相隔 **208 秒（约 3 分 28 秒）**。
  - 这构成一条完整攻击链：**令牌 scope 越权尝试（事件 4）→ 数据库异常导出（事件 5）**。
  - 结合 rest-graphql-testing.md 中「分页枚举 ?page=1&limit=10000」「响应过度暴露」的攻击模式，攻击者可能通过越权令牌批量拉取数据。
- **影响**：潜在的数据泄露，需立即确认导出的数据范围、记录数与敏感级别。

### 事件 6：畸形日志记录

- **风险等级**：Medium（日志完整性/监控缺口）
- **证据**：`2026-08-12T09:09:00Z,web,,malformed_record,,`
- **Skill 阶段映射**：影响全阶段检测能力；与 SKILL.md 自检要求「可复现证据」直接相关
- **分析**：
  - 该记录的 `severity`、`user`、`source_ip` 三个关键字段全部为空，无法用于溯源。
  - 发生时间在事件 5（critical 数据导出）之后 **90 秒**，存在两种可能：
    1. **日志管道故障**：采集/序列化/转发环节异常，导致字段丢失；
    2. **日志篡改/干扰**：攻击者在数据导出后制造畸形记录以干扰审计（无法从单条记录确认，需结合日志系统访问记录排查）。
  - 无论哪种原因，该缺口直接削弱了事件溯源能力，违反 SKILL.md 自检中「产出可复现证据」的要求。

## 四、关联分析（攻击链）

### 攻击链 A：203.0.113.8 — 越权令牌 → 数据外泄

```
09:04:02  api   high     token_scope_mismatch  service-a  203.0.113.8
              │  （208 秒后，同一 IP）
09:07:30  db    critical unexpected_export     unknown    203.0.113.8
```

- **推断**：同一攻击源使用 service-a 账户的令牌尝试越权访问 scope 外资源，随后（或利用未被阻断的越权会话）对数据库执行了未授权导出。
- **置信度**：中高。两事件共享源 IP 且时间邻近，但日志未提供请求 ID / 令牌哈希 / 导出数据量等强关联字段，无法 100% 确认同一令牌链路。
- **待补充证据**：API 网关的令牌校验日志（事件 4 的请求是否被实际拒绝）、数据库导出审计（导出表名、行数、目标位置）。

### 攻击链 B：198.51.100.23 — admin 暴力破解

```
09:03:45  web  warning  login_failed  admin  198.51.100.23
              │  （4 秒后，同一 IP）
09:03:49  web  warning  login_failed  admin  198.51.100.23
```

- **推断**：对 admin 账户的自动化口令猜测。当前窗口仅 2 次，需拉取更长时间窗口确认是否持续。
- **与攻击链 A 的关系**：源 IP 不同（198.51.100.23 vs 203.0.113.8），暂无直接证据表明两链相关，但不排除协同攻击的可能。

### 事件 6 与攻击链 A 的时间关系

畸形记录发生在 critical 导出后 90 秒，时间上接近但缺乏字段关联，列为可疑线索而非确证。

## 六、修复建议

### R-1（Critical）：越权令牌 → 数据外泄

1. **立即响应**：
   - 吊销 `service-a` 当前所有有效令牌，强制重新签发。
   - 在数据库侧核查 2026-08-12 09:07:30 前后的导出操作：导出表、行数、数据敏感级别、导出目标（文件/网络位置）。
   - 临时封禁源 IP `203.0.113.8`（模拟环境中为记录处置决策，非真实封禁）。
2. **令牌 scope 强制阻断**（对应 Phase 2/3）：
   - scope 校验必须在 API 网关**强制拒绝**越权请求，不得仅告警放行；参考 jwt-oauth-testing.md「scope 提升」测试项，将其加入回归测试。
   - 服务账户遵循最小权限原则，逐服务审查授予 scope。
3. **数据导出管控**（对应 Phase 9）：
   - 数据库导出操作必须绑定已认证身份，禁止 `unknown` 身份执行导出。
   - 对批量导出设置行数阈值与审批流；参考 rest-graphql-testing.md「分页枚举 limit=10000」攻击模式，限制单次拉取上限。

### R-2（High）：admin 暴力破解

1. 登录接口实施账户级 + IP 级限速（对应 Phase 8）：N 次失败后临时锁定或引入验证码/二次验证。
2. admin 账户强制使用强口令并启用多因素认证（MFA）。
3. 拉取 198.51.100.23 在更长时间窗口（建议 24 小时）的全部登录记录，确认尝试总次数。
4. 参考 SKILL.md Phase 8，检查 `X-Forwarded-For` / `X-Real-IP` 等头是否被用于绕过限速。

### R-3（Medium）：日志完整性

1. 在日志采集管道增加字段校验：`severity`、`user`、`source_ip` 为必填，缺失时拒绝写入并告警。
2. 日志写入采用追加/只增存储，防止篡改；对关键日志加哈希链或集中式日志服务（WORM）。
3. 排查 09:09:00 前后日志系统自身的运行日志，确认畸形记录是管道故障还是人为干扰。
4. 建立日志字段完整率监控指标，低于阈值告警。

### R-4（High）：scope 管理策略

1. 明确 `token_scope_mismatch` 事件的处置逻辑：拒绝连接还是告警放行？若为后者，立即改为拒绝。
2. 建立服务账户 scope 清单与定期轮换/审查机制。
3. 将 jwt-oauth-testing.md 中的 scope 提升测试（`scope=read → scope=read write`）纳入 CI/CD 回归（对应 Phase 10）。

## 十、影响结果的 SKILL.md 规则
