# Adyntel 每周数据收集与通知自动化 —— 流程定义

> 依据：`adyntel-automation/SKILL.md`（通过 Rube MCP / Composio 自动化 Adyntel 操作）
> 版本：2026-08-12
> 约束：不新增非必要依赖、不改动无关文件；外部账号仅做到安全模拟或授权确认前步骤

---

## 1. 流程目标

每周自动完成三件事：
1. 从 Adyntel 收集本周数据；
2. 基于收集结果生成摘要；
3. 将摘要通知负责人。

所有与 Adyntel 的交互**必须**经过 Rube MCP 的三步模式，不得直连 Adyntel API、不得硬编码工具 slug 或参数（SKILL.md "Known Pitfalls" 第一条）。

---

## 2. 前置条件检查（运行前一次性确认）

| 编号 | 检查项 | 来源 | 不满足时的处理 |
|------|--------|------|----------------|
| P1 | Rube MCP 已连接，`RUBE_SEARCH_TOOLS` 可响应 | SKILL.md Prerequisites / Setup 第 1 步 | 中止，提示添加 `https://rube.app/mcp` 为 MCP server |
| P2 | Adyntel toolkit 连接状态为 ACTIVE | SKILL.md Setup 第 2–4 步 | 中止，返回授权链接，等待人工完成授权（属于"确认前步骤"边界） |
| P3 | 运行环境具备 Python 3 标准库（模拟/编排脚本） | 本流程约束 | 中止，提示安装 Python 3 |

---

## 3. 每周流程阶段定义

流程复用**同一个 session ID**（SKILL.md "Session reuse"），新一周运行时生成新 session。

### 阶段 0：触发与初始化

- **触发**：每周定时（如周一 09:00），由 cron / 计划任务调用编排脚本。
- **动作**：
  1. 生成新 session ID（`RUBE_SEARCH_TOOLS` 的 `session: {generate_id: true}`）；
  2. 记录运行开始时间、周次标识。
- **输出**：`session_id`、`run_meta`。

### 阶段 1：工具发现（必须最先执行）

- **工具**：`RUBE_SEARCH_TOOLS`
- **参数**（按 SKILL.md 示例）：
  ```
  queries: [{use_case: "每周收集 Adyntel 数据并生成摘要通知负责人", known_fields: ""}]
  session: {id: "<session_id>"}
  ```
- **输出**：可用工具 slug 列表、各工具输入 schema、推荐执行计划、已知陷阱。
- **决策点**：
  - 若返回中**不包含**数据收集类工具或通知类工具 → 进入异常 E1（工具缺失/schema 变更）；
  - 若返回中工具带 `schemaRef` → 按需调用 `RUBE_GET_TOOL_SCHEMAS` 获取完整 schema（SKILL.md Quick Reference）。
- **关键规则**：后续阶段使用的 `tool_slug` 与参数字段名**只能**来自本阶段返回，不得硬编码。

### 阶段 2：连接检查

- **工具**：`RUBE_MANAGE_CONNECTIONS`
- **参数**：
  ```
  toolkits: ["adyntel"]
  session_id: "<session_id>"
  ```
- **输出**：连接状态。
- **决策点**：
  - 状态为 ACTIVE → 继续；
  - 非 ACTIVE 且返回 auth link → 进入异常 E2（需人工授权），流程暂停在"确认前步骤"，不自行完成授权；
  - 调用失败 → 进入异常 E3。

### 阶段 3：数据收集（含分页）

- **工具**：`RUBE_MULTI_EXECUTE_TOOL`
- **参数骨架**（具体 `tool_slug` 与 `arguments` 来自阶段 1 的 schema）：
  ```
  tools: [{
    tool_slug: "<阶段1发现的数据收集工具 slug>",
    arguments: { <严格按阶段1返回的字段名与类型填充，含本周时间范围> }
  }]
  memory: {}
  session_id: "<session_id>"
  ```
- **分页处理**（SKILL.md "Pagination"）：检查响应中的分页 token；若存在，以上一页 token 继续请求，直到无下一页，将所有页合并。
- **输出**：本周原始数据集 `raw_records`。
- **决策点**：
  - 工具 slug 不在阶段 1 结果中 → E1；
  - 参数校验失败（字段名/类型不符）→ E4；
  - 分页中断 → E5。

### 阶段 4：摘要生成

- **输入**：阶段 3 合并后的 `raw_records`。
- **动作**：按"字段映射"文档将原始记录归一化，生成本周摘要（记录总数、关键指标汇总、异常/空数据提示）。
- **输出**：`summary`（结构化对象 + 可读文本）。
- **决策点**：
  - 原始数据为空 → 生成"本周无数据"摘要并继续通知（不静默跳过）；
  - 字段缺失 → 按字段映射中的兜底规则处理并在摘要中标注。

### 阶段 5：通知负责人

- **工具**：`RUBE_MULTI_EXECUTE_TOOL`
- **参数骨架**（通知工具 slug 同样来自阶段 1）：
  ```
  tools: [{
    tool_slug: "<阶段1发现的通知/消息工具 slug>",
    arguments: { <按 schema 填充，正文为 summary 文本> }
  }]
  memory: {}
  session_id: "<session_id>"
  ```
- **输出**：通知发送结果。
- **决策点**：
  - 通知工具未发现 → E1（流程降级：将摘要写入本地文件并在日志中告警）；
  - 发送失败 → E6（重试，见异常处理）。

### 阶段 6：收尾

- 记录运行结束时间、各阶段状态、收集记录数、通知状态；
- 输出运行报告（JSON + 可读日志）；
- 清理临时数据（保留摘要与报告）。

---

## 4. 流程状态机

```
[初始化] → [工具发现] ──失败──→ E1(中止/降级)
              │
              ↓
           [连接检查] ──非ACTIVE──→ E2(暂停,等待授权)
              │
              ↓
           [数据收集] ──参数错──→ E4     ──分页中断──→ E5
              │
              ↓
           [摘要生成]
              │
              ↓
           [通知负责人] ──失败──→ E6(重试→降级写文件)
              │
              ↓
           [收尾/报告]
```

## 5. 定时调度（本地可重复）

使用系统 cron，无需新增依赖：

```cron
# 每周一 09:00 运行 Adyntel 每周自动化（模拟/编排脚本）
0 9 * * 1 /usr/bin/python3 /path/to/adyntel-weekly-automation/weekly_run.py --mode simulate >> /path/to/adyntel-weekly-automation/logs/cron.log 2>&1
```

- `--mode simulate`：本地模拟（不连真实 Rube MCP，不需要账号）；
- `--mode live`：真实运行（要求 P1/P2 满足，且 Rube MCP 工具在运行环境中可用）。

## 6. 本次约束导致的方案变化说明

| 约束 | 对方案的影响 |
|------|--------------|
| 不新增非必要依赖 | 编排与测试脚本仅使用 Python 3 标准库（`json`、`subprocess`、`datetime`、`argparse`、`pathlib`、`unittest`）；不安装 requests、pytest 等第三方包 |
| 不改动无关文件 | 所有新增文件仅放在 `adyntel-weekly-automation/` 目录内；不修改解压出的 Skill 原文件，不修改系统配置 |
| 本地/沙盒可重复验证 | 提供 `weekly_run.py --mode simulate` 与 `python3 -m unittest` 两条命令，结果确定性可复现 |
| 外部账号只做到模拟或确认前步骤 | 真实 Adyntel 连接需要通过 `RUBE_MANAGE_CONNECTIONS` 返回的 auth link 人工授权；本交付在阶段 2 暂停于授权前，不自行完成 OAuth；数据收集与通知在模拟模式下用桩数据验证编排逻辑 |
| 当前环境无 Rube MCP 工具 | `RUBE_SEARCH_TOOLS` 等工具在当前环境不可用，无法获取真实工具 slug 与 schema；因此流程定义中的工具名以"阶段 1 发现结果"占位，字段映射采用"动态映射规则"而非硬编码字段表——这正是 SKILL.md "Always search first / Never hardcode" 规则的要求 |
