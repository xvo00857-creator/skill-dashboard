# fixing-motion-performance 受约束执行流程方案

> 本方案依据 Skill `fixing-motion-performance` 的 SKILL.md 制定。
> Skill 性质：**代码审查/修复建议类 Skill**，对给定 CSS/JS/HTML 文件按 9 类规则审计，输出「违规点（引用原行）+ 原因 + 代码级修复」。
> 关键边界（SKILL.md 第 32、129–131、166–168 行）：不擅自迁移动画库；在现有技术栈内修复；不部分迁移或混用 API；变更前需验证命令、生成代码、依赖与外部服务行为；破坏性或高成本操作需用户批准。

## 0. 适用前提与不做事项

- 仅在任务明确匹配「CSS/JS/WAPI/Motion/rAF/GSAP 动画卡顿审查」时启用。
- 不替换、不升级、不迁移既有动画库（除非用户明确要求）。
- 不访问网络、不安装依赖、不调用外部服务，除非用户明确授权。
- 不静默创建、删除、覆盖工作目录以外的任何资源。
- 不编造文件内容、运行结果或已完成操作；无法访问的资源与待确认假设必须显式标注。

## 1. 预检（Pre-check，全部通过才进入审查）

| 编号 | 检查项 | 不通过处理 |
|------|--------|-----------|
| P1 | 目标文件存在且可读 | 停止，报告缺失路径，请用户提供 |
| P2 | 文件类型在范围内（.html/.css/.js/.jsx/.ts/.tsx/.vue/.svelte） | 停止，说明不在范围 |
| P3 | 文件大小可处理（< 2 MB，纯文本） | 停止，建议拆分或指定片段 |
| P4 | 识别当前动画技术栈（原生 CSS / WAAPI / rAF / GSAP / Motion 等） | 记录到报告头，作为「不迁移」依据 |
| P5 | 检查是否存在版本控制（git）或已有备份 | 无 git 时强制生成本地 `.bak` 备份 |
| P6 | 确认写权限与目标输出路径不冲突 | 无权限则停止并说明，不尝试越权 |
| P7 | 标注文件中是否含第三方/压缩代码 | 对压缩代码只报告不自动改写，需人工确认 |

预检结果必须以清单形式向用户展示，P5/P6/P7 任一异常需用户确认后才能继续。

## 2. 审查（Audit，只读，不改文件）

按 SKILL.md 的优先级顺序检查，每条违规记录：

1. 规则编号与类别（如 `R1-never / R4-scroll`）
2. 违规原行或片段（逐字引用，带行号）
3. 一句话原因
4. 代码级修复建议（在现有技术栈内）

优先级顺序（SKILL.md 第 49–61 行）：
1. never patterns（critical）→ 2. choose the mechanism（critical）→ 3. measurement（high）→ 4. scroll（high）→ 5. paint（medium-high）→ 6. layers（medium）→ 7. blur and filters（medium）→ 8. view transitions（low）→ 9. tool boundaries（critical）

审查阶段**不写任何文件**，仅产出报告文本。

## 3. 人工确认点（Gate）

- **Gate A（审查后、修复前）**：向用户展示完整违规清单与拟议修复，用户确认后才生成修复文件。
- **Gate B（库/API 边界）**：任何涉及替换动画库、引入新 API、改变动画系统的建议，默认只在报告中提示，不写入修复文件；仅当用户明确授权才执行。
- **Gate C（修复后、交付前）**：展示修复前后差异（diff 摘要），用户确认后才视为交付完成。

## 4. 幂等（Idempotency）

- 原文件**永不被覆盖**：修复结果写入 `<name>.fixed.<ext>`，原文件保持不变。
- 备份幂等：备份文件名为 `<name>.bak.<sha8>.<ext>`，以内容哈希前 8 位区分；相同内容重复执行不产生新备份。
- 修复幂等：修复器对已修复的模式做「特征检测」——若目标代码已符合规则（如已使用 `transform` 而非 `width`、已存在停止条件），则跳过，不重复改写。
- 重复执行同一输入，产出字节级一致的报告与修复文件（确定性输出）。

## 5. 重试（Retry，有界）

| 场景 | 策略 | 上限 |
|------|------|------|
| 文件读取编码错误 | 以 UTF-8 重试，仍失败则报告 | 1 次 |
| 写入临时文件失败 | 退避 1s 后重试 | 1 次 |
| 临时文件原子替换失败 | 回退为直接写 `.fixed` 并标注 | 1 次 |
| 规则匹配异常 | 跳过该规则，在报告中标注「未完成检查」 | 不重试，避免误改 |

所有重试均记录在报告的「执行日志」段，含时间、操作、结果。

## 6. 修复应用规则

- 仅在现有技术栈内改写（SKILL.md 第 32、130 行）。
- 优先降级技术而非删除动效（SKILL.md 第 79 行：prefer downgrading over removing）。
- 连续动画优先 `transform`/`opacity`；`width`/`left`/`top`/`margin` 等布局属性改为 `transform`。
- 滚动驱动优先 `animation-timeline: scroll()/view()`；不可用时用 `IntersectionObserver` 暂停/恢复，不轮询 scroll。
- `rAF` 循环必须有停止条件，离屏暂停。
- 模糊动画 ≤8px、仅一次性、不大面积连续动画；优先 opacity/translate。
- `will-change` 临时、外科手术式使用，不长期挂在多个大层上。
- 不动画用于 transform/opacity/position 的 CSS 变量，不动画继承变量。

## 7. 交付物

1. 审查报告（违规清单 + 原因 + 修复建议 + 执行日志）
2. `<name>.fixed.<ext>` 修复文件（原文件不动）
3. 备份文件（如需）
4. 本流程方案文档
