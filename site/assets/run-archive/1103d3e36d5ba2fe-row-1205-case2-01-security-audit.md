### 5.2 短期修复（P1，1 周内）

5. **服务令牌最小权限审计**：全面审查所有服务账户令牌的 scope 配置，确保遵循最小权限原则。对 `service-a` 令牌的签发流程、存储方式和使用日志进行专项审计，排查泄露途径（代码仓库硬编码、配置文件泄露、日志泄露等）。
6. **数据库导出管控**：对数据库导出操作实施白名单+审批机制，禁止 unknown/匿名用户执行导出。所有导出操作必须记录操作人、目标表、行数、时间和客户端 IP。
7. **登录暴力破解防护**：对 admin 等特权账户启用账户锁定策略（如 5 次失败锁定 15 分钟）、验证码和 IP 速率限制。配置实时告警。

### 5.3 长期改进（P2，1 个月内）

9. **跨系统关联检测**：部署 SIEM 规则，当同一 IP 在 N 分钟内先后触发 API 越权和数据库异常操作时自动生成高优先级告警。本次事件中 #4→#5 的模式应被自动关联。
10. **服务令牌生命周期管理**：建立服务令牌的自动过期、轮换和异常使用检测机制（如非工作时间使用、异常地理来源、scope 突变）。
11. **零信任架构评估**：对数据库访问实施零信任策略，即使来自内部服务的请求也需逐次验证身份和权限，避免"一个令牌泄露即全链路可达"。
12. **日志质量监控**：建立日志字段完整性 SLA，对缺失关键字段（severity、user、source_ip）的记录比例设置阈值告警。
