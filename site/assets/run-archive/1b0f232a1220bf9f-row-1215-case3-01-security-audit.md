## 一、执行摘要

本次审计在授权范围内对两份模拟安全日志进行静态分析，共识别 **6 类安全/数据质量问题**，其中 **严重（Critical）1 项、高危（High）1 项、中危（Medium）2 项、低危/信息（Low/Info）2 项**。

核心结论：

1. **存在关联攻击链**：`token_scope_mismatch`（高危）与 `unexpected_export`（严重）来自同一源 IP `203.0.113.8`，时间间隔约 3 分 28 秒，疑似服务令牌被滥用后进一步导致数据库异常导出，需优先处置。
2. **存在暴力破解迹象**：`admin` 账号在 4 秒内连续 2 次登录失败，源 IP `198.51.100.23`，虽样本量小但频率异常。
3. **日志完整性受损**：存在 1 条字段残缺记录（severity/user/source_ip 均为空），可能影响事件追溯与告警准确性。
4. **边界数据存在公式注入载荷**：`edge_cases.csv` 中 `=HYPERLINK(...)` 字段若被电子表格软件直接打开并执行，存在 CSV 注入风险。
5. **thick-client Skill 核心流程无法执行**：该 Skill 面向桌面厚客户端渗透测试，而本次输入为纯日志文件，无客户端二进制、无测试账号、无逆向/代理工具环境，且 Skill 要求的前置文件 `../field-journal/precedent-pentest.md` 不存在。详见第二节。

## 二、thick-client Skill 适用性评估与阻断项

### 2.1 Skill 定位

根据实际读取的 `thick-client/SKILL.md`，该 Skill 适用于：

- C/S 架构桌面客户端（Electron / Qt / .NET WinForms / WPF）
- 本地配置与凭证存储、IPC、命名管道
- 客户端强制校验绕过研究（授权）
- 自动更新通道与代码签名验证

其强制工作流为：建边界（进程树/端口/本地敏感路径）→ 本地攻击面（明文配置/DLL 劫持/SQLite 权限/IPC）→ 网络面（代理/TLS 钉扎/API 越权）→ 逆向验证（.NET/原生/Electron）。

## 三、incident_log.csv 分析

### 3.1 文件基本信息

- 文件名：incident_log.csv
- 格式：标准 CSV，逗号分隔，UTF-8 文本
- 总行数：7（1 行表头 + 6 行数据）
- 字段：timestamp, system, severity, event, user, source_ip

### 3.2 事件清单与风险分级

| 行号 | 时间 (UTC) | 系统 | 严重级别 | 事件 | 用户 | 源 IP | 审计风险等级 | 说明 |
|------|------|------|------|------|------|------|------|------|
| 2 | 2026-08-12T09:00:12Z | web | info | login_success | alice | 192.0.2.10 | Info | 正常登录，无异常 |
| 3 | 2026-08-12T09:03:45Z | web | warning | login_failed | admin | 198.51.100.23 | Medium | 管理员账号登录失败 |
| 4 | 2026-08-12T09:03:49Z | web | warning | login_failed | admin | 198.51.100.23 | Medium | 4 秒内第 2 次失败，频率异常 |
| 5 | 2026-08-12T09:04:02Z | api | high | token_scope_mismatch | service-a | 203.0.113.8 | High | 服务令牌权限范围不匹配 |
| 6 | 2026-08-12T09:07:30Z | db | critical | unexpected_export | unknown | 203.0.113.8 | **Critical** | 未知用户触发数据库异常导出 |
| 7 | 2026-08-12T09:09:00Z | web | *(空)* | malformed_record | *(空)* | *(空)* | Low | 字段残缺，日志完整性问题 |

### 3.3 关键发现

#### 发现 1：关联攻击链——令牌滥用导致数据外泄（Critical）

**证据**：
- 行 5：`2026-08-12T09:04:02Z`，`api` 系统，`token_scope_mismatch`，用户 `service-a`，源 IP `203.0.113.8`，严重级别 `high`。
- 行 6：`2026-08-12T09:07:30Z`，`db` 系统，`unexpected_export`，用户 `unknown`，源 IP `203.0.113.8`，严重级别 `critical`。
- 两事件源 IP 完全相同（`203.0.113.8`），时间间隔 3 分 28 秒。
- 行 6 用户为 `unknown`，表明导出操作未关联到有效身份，可能使用了窃取/伪造的令牌或绕过了认证。

**分析**：`service-a` 的令牌出现权限范围不匹配后，同一 IP 很快发起数据库异常导出。高度疑似攻击者利用越权令牌（或被窃取的服务令牌）从 API 层横向移动至数据库层，执行未授权数据导出。这是本次审计中风险最高的事件。

**修复建议**：
1. 立即吊销或轮换 `service-a` 的所有令牌，排查该服务账号的令牌签发与使用日志。
2. 对 `203.0.113.8` 实施临时封禁，确认其是否为已知合法出口 IP。
3. 核查数据库导出操作的审批与审计记录，确认导出的数据范围与流向。
4. 在 API 网关层增加令牌 scope 校验的强制拒绝策略，scope 不匹配时直接阻断而非仅告警。
5. 数据库导出操作应强制二次身份验证（MFA），并限制可导出的 IP 白名单。

#### 发现 2：管理员账号暴力破解迹象（Medium）

**证据**：
- 行 3：`2026-08-12T09:03:45Z`，`admin` 登录失败，源 IP `198.51.100.23`。
- 行 4：`2026-08-12T09:03:49Z`，`admin` 登录失败，同一源 IP。
- 两次失败间隔仅 4 秒，针对高权限 `admin` 账号。

**分析**：虽然仅观测到 2 次失败尝试，但 4 秒间隔对人工登录而言异常偏快，符合自动化暴力破解或凭证填充的特征。因日志窗口有限，不排除存在更多未被采集的尝试。

**修复建议**：
1. 对 `admin` 账号启用登录失败限流（如 5 次失败后锁定 15 分钟）。
2. 为管理员账号强制启用 MFA。
3. 对 `198.51.100.23` 进行威胁情报比对，确认是否为已知恶意 IP。
4. 扩展日志采集窗口，确认该 IP 在更长时间范围内的尝试次数。

#### 发现 3：日志字段残缺（Low）

**证据**：
- 行 7：`2026-08-12T09:09:00Z`，`web` 系统，事件 `malformed_record`，但 `severity`、`user`、`source_ip` 三个字段均为空。

**分析**：残缺记录可能由日志采集器异常、网络丢包或日志被篡改导致。若为真实安全事件被截断，将导致告警遗漏与溯源困难。

**修复建议**：
1. 检查日志采集管道（agent / shipper）在 `09:09:00Z` 前后的健康状态与错误日志。
2. 对入库日志增加字段非空校验，残缺记录应进入隔离队列而非直接丢弃。
3. 启用日志完整性校验（如逐条哈希或签名），防止篡改。

## 四、edge_cases.csv 分析

### 4.1 文件基本信息

- 文件名：edge_cases.csv
- 格式：标准 CSV，逗号分隔，含引号包裹字段
- 总行数：7（1 行表头 + 5 行数据，其中 1 条重复）
- 字段：record_id, status, value, notes

### 4.2 边界与失败场景识别

| 行号 | record_id | status | value | notes | 问题类型 | 风险等级 |
|------|------|------|------|------|------|------|
| 2 | 1 | ok | 120 | 正常记录 | 无 | — |
| 3 | 2 | ok | 120 | 重复记录 | **重复** | Low |
| 4 | 2 | ok | 120 | 重复记录 | **重复**（与行 3 完全相同） | Low |
| 5 | 3 | *(空)* | *(空)* | - | **缺失** | Medium |
| 6 | 4 | error | -999 | 异常负值 | **异常值** | Medium |
| 7 | 5 | ok | `=HYPERLINK("https://example.invalid","do not execute")` | 公式注入测试文本 | **不安全输入（CSV 注入）** | High |

### 4.3 详细分析

#### 发现 4：重复记录（Low）

**证据**：行 3 与行 4 的 `record_id`、`status`、`value`、`notes` 完全一致，均为 `2,ok,120,重复记录`。

**影响**：重复数据会导致统计指标失真（如计数翻倍、均值偏移），在安全场景下可能虚增事件量或掩盖真实趋势。

**修复建议**：
1. 在数据入库前基于 `record_id` 做去重校验。
2. 若 `record_id` 非唯一键，应增加复合唯一键（如 record_id + 时间戳）。
3. 对重复写入率设置监控告警。

#### 发现 5：字段缺失（Medium）

**证据**：行 5（record_id=3）的 `status` 和 `value` 字段为空，`notes` 为 `-`。

**影响**：缺失关键字段会导致下游分析逻辑出错（如空值参与数值计算产生 NaN），或使状态判断逻辑静默失败。

**修复建议**：
1. 对 `status` 和 `value` 设置 NOT NULL 约束或默认值。
2. 在 ETL 管道中增加缺失值检测，异常记录进入隔离区并告警。
3. 追溯 record_id=3 的原始数据源，确认缺失是采集问题还是业务侧未填写。

#### 发现 6：异常负值（Medium）

**证据**：行 6（record_id=4），`status=error`，`value=-999`，notes 标注"异常负值"。

**影响**：若 `value` 字段语义为计数、时长或其他非负指标，`-999` 可能是错误码被误写入业务字段，或代表某种异常状态。若参与聚合计算会拉低均值、扭曲分布。

**修复建议**：
1. 明确 `value` 字段的取值域（如是否允许负值、取值范围）。
2. 若 `-999` 为错误哨兵值，应将其迁移至独立的 `error_code` 字段，避免与业务值混用。
3. 增加取值范围校验，超出合法域的值进入异常队列。

#### 发现 7：CSV 公式注入（High）

**证据**：行 7（record_id=5），`value` 字段内容为：
```
=HYPERLINK("https://example.invalid","do not execute")
```
该字段以 `=` 开头，是电子表格公式语法。notes 明确标注为"公式注入测试文本"。

**影响**：若此 CSV 文件被 Microsoft Excel、LibreOffice Calc 或 Google Sheets 等电子表格软件直接打开，公式可能被自动执行。`HYPERLINK` 可诱导用户点击钓鱼链接；更危险的载荷（如 `=CMD|'/c calc'!A1` 或外部数据引用）可导致命令执行或数据外泄。这是典型的 CSV 注入（Formula Injection）漏洞。

**修复建议**：
1. **输出端转义**：对以 `=`、`+`、`-`、`@` 开头的单元格内容，在前面添加单引号 `'`（Excel 文本前缀）或制表符，防止被解析为公式。
2. **输入端校验**：在数据采集时检测公式特征字符，对可疑内容进行告警或清洗。
3. **用户教育**：告知使用者不要直接从未知来源打开 CSV 文件，应在文本编辑器中预览或禁用自动公式执行。
4. **内容安全策略**：对导出的 CSV 文件进行公式注入扫描，确保导出数据不含可执行公式。
