## 二、约束与冲突分析（至少两种）

- **风险**：降级分析可能遗漏客户端侧攻击面（如本地凭证泄露导致的 token 滥用），但在当前输入下这是不可避免的信息缺口。

### 冲突二：SKILL.md 强制前置文件缺失（依赖冲突）

### 3.2 证据链与关联分析

#### 攻击链 A：Token 越权 → 数据外泄（高置信度关联）

```
09:04:02  api   token_scope_mismatch   service-a   203.0.113.8
                │
                ▼ （同一源 IP，间隔 3 分 28 秒）
09:07:30  db    unexpected_export       unknown     203.0.113.8
```

- **关联依据**：两事件源 IP 完全相同（203.0.113.8），时间上 token 异常在先、数据导出在后，逻辑上可构成"利用权限范围不符的 service-a token 访问数据库并导出数据"的攻击链。
- **关键证据**：
  - `token_scope_mismatch` 表明 service-a 的 token 被用于超出其授权范围的操作；
  - `unexpected_export` 的用户字段为 `unknown`，说明导出操作未通过正常身份认证，或身份字段被篡改/缺失；
  - 两事件均来自 203.0.113.8（文档保留地址段，模拟外部 IP）。
- **不确定性**：日志未记录 token 具体 scope 值、导出的数据量/表名、以及 service-a 与 db 之间是否存在合法调用关系。需补充 API 网关日志和 DB 审计日志确认。

#### 攻击链 B：管理员账号暴力破解（中等置信度）

```
09:03:45  web  login_failed  admin  198.51.100.23
09:03:49  web  login_failed  admin  198.51.100.23  （间隔 4 秒）
```

- **关联依据**：同一外部 IP（198.51.100.23）在 4 秒内对 `admin` 账号发起两次登录失败。
- **风险判断**：仅两次失败尚不足以确认暴力破解（可能是用户输错密码），但针对管理员账号的快速重试需要触发告警和账号锁定策略。
- **不确定性**：日志窗口仅 9 分钟，无法判断该 IP 在窗口前后是否有更多尝试。需扩展时间范围查询。

#### 数据质量事件：malformed_record

- 第 6 条记录缺少 severity、user、source_ip 三个关键字段，event 类型为 `malformed_record`。
- 两种可能：(a) 日志采集管道本身的格式错误；(b) 攻击者篡改/注入日志以干扰审计。
- 当前证据不足以区分，标记为"需排查"。

### 3.3 修复建议

#### 针对攻击链 A（Token 越权 + 数据外泄）

| P0 | 吊销并轮换 service-a 的 token | 立即作废当前 token，重新签发最小权限 scope 的新 token；排查 token 是否泄露 |
| P0 | 核查数据库导出内容 | 确认 09:07:30 的导出涉及哪些表、多少行数据，评估数据泄露范围；如含敏感数据，启动数据泄露响应流程 |
| P1 | 实施 token scope 强校验 | 在 API 网关层对每个 endpoint 要求精确 scope 匹配，拒绝 scope 不足或过量的请求 |
| P1 | 数据库导出操作强制身份认证 | 禁止 unknown 用户执行导出；所有导出操作必须绑定可审计的身份，并触发二次审批 |

1. **严重风险（1 项）**：`unexpected_export`（事件 #5）疑似数据外泄，与 `token_scope_mismatch`（事件 #4）构成高置信度攻击链，源 IP 均为 203.0.113.8。需立即响应。
