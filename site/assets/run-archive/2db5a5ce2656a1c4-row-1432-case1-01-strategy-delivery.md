## 1. 第一步：追问价值本质

> Skill 规则：必须先挖到价值本质，禁止用户说了一句话就开始画图。

### 1.1 复述输入

新品简报定义的产品：
- 品类：智能随行杯
- 目标用户：一二线城市通勤人群
- 核心卖点：12 小时保温、重量 280g、可拆洗杯盖
- 建议零售价：199 元
- 已确认素材：产品白底图、基础规格、品牌主色 #176B87

### 1.2 逐层追问

| 层级 | 问题 | 推导 |
|---|---|---|
| 表面 | 这是什么？ | 一个保温随行杯 |
| 追一层 | 通勤人群为什么需要它？ | 通勤途中想喝到温度合适的饮品；不想背太重的东西；杯盖难洗会产生异味 |
| 再追一层 | 用户"根本不想做但不得不做"的事是什么？ | 用户根本不想"管理一杯水的温度"——保温是不得已的手段。真正的痛点是：**通勤路上饮品体验的不确定性**（温度失控、重量负担、清洁焦虑） |

### 1.3 价值定位（结论）

> **这个产品的价值不是"卖一个保温杯子"，而是"卖通勤路上确定性的饮品体验"。**

12 小时保温 = 温度确定性；280g = 携带确定性；可拆洗杯盖 = 清洁确定性。三者共同支撑"通勤饮品体验的确定性"这一价值锚点。

## 2. 第二步：挖掘真实用户动机

> Skill 规则：禁止 AI 自己猜动机，必须从用户嘴里挖出来。
> 适配说明：以下动机为基于目标用户画像的**推导假设**，非真实用户访谈结论。每条均附验证方法，上市前须完成验证。

### 2.1 动机假设清单

| 编号 | 动机假设 | 触发场景 | 对应产品卖点 | 验证方法 |
|---|---|---|---|---|
| M1 | 晨间通勤想喝热咖啡/热茶 | 出门前冲泡，地铁/公交上饮用 | 12h 保温 | 目标用户问卷 + 小红书关键词热度分析 |
| M2 | 杯子太重，通勤包负担大 | 每日背负电脑+饭盒+水杯 | 280g 轻量化 | 竞品重量对比（仅公开规格，不编造价格） |
| M3 | 杯盖缝隙难清洗，有异味 | 使用一周后杯盖出现茶渍/咖啡渍 | 可拆洗杯盖 | 用户访谈聚焦"清洁痛点" |
| M4 | 办公室续杯，一杯喝半天 | 上午到工位后反复接水 | 12h 保温 + 容量（待确认） | 办公场景饮水行为观察 |
| M5 | 环保意识，减少一次性杯使用 | 买咖啡时自带杯 | 便携 + 外观（待确认） | 环保人群渗透率数据（待补外部数据） |
| M6 | 健身/运动后补水 | 通勤前或通勤后健身 | 便携 + 保冷（待确认是否支持保冷） | 产品规格确认 |

### 2.2 动机优先级（假设）

基于通勤人群的日常行为密度，初步假设优先级为：
**M1（热饮需求）> M3（清洁痛点）> M2（轻量化）> M4（办公续杯）> M5（环保）> M6（运动补水）**

> 此排序为假设，须经用户验证后调整。

## 3. 第三步：推导自然演化路径

> Skill 规则：每一步必须是上一步的自然延伸，有明确的"因为用户遇到 X 问题，所以需要 Y"。禁止跳过演化路径直接画终局。

### 3.1 演化链路

```
V1 基础保温随行杯
  → V2 智能温度感知
    → V3 个性化饮品管理
      → V4 通勤场景联动
        → V5 个人饮品生态中枢（终局）
```

### 3.2 每一步的自然延伸逻辑

| 阶段 | 形态 | 因为用户遇到了什么问题 | 所以需要什么 |
|---|---|---|---|
| V1 | 基础保温随行杯（当前产品） | 通勤路上饮品温度失控、杯子太重、杯盖难洗 | 12h 保温 + 280g + 可拆洗杯盖 |
| V2 | 智能温度感知杯 | 用户不知道杯里现在多少度，喝的时候烫嘴或凉了 | 杯盖/杯身温度显示 + 最佳饮用温度提醒 |
| V3 | 个性化饮品管理杯 | 用户喝什么、什么时候喝全凭感觉，没有规律 | 饮水记录 + 饮品配方推荐 + 个性化保温曲线（咖啡/茶/水不同温度策略） |
| V4 | 通勤场景联动杯 | 用户出门前忘了提前准备饮品，到了路上才想喝 | 与日历/导航联动，根据通勤时间提前预热/制冷；到办公室前提醒续杯 |
| V5 | 个人饮品生态中枢（终局） | 用户的饮品行为分散在杯子、咖啡机、饮水机、健康APP里，没有统一视图 | 杯子成为个人饮品数据中枢，连接所有饮品设备与健康数据，实现全链路饮品管理 |

### 3.3 确认检查点

> Skill 要求：向用户展示演化链路，确认逻辑对不对，再往下走。
> 当前状态：链路已推导，**待产品负责人确认**。确认后进入终局愿景设计。

## 4. 第四步：终局愿景维度（文字规格）

> Skill 规则：终局之间必须是不同维度（不同的信息架构和交互范式），不是布局变体。通常 4–6 个。
> 适配说明：以下为终局愿景的文字规格，完整执行需输出 4–6 个单文件自包含 HTML。本最小可验证版本先交付内容规格。

### 维度一：健康数据中枢型

- **核心理念**：杯子不是容器，是个人健康数据的采集终端
- **信息架构**：以"今日饮水健康看板"为中心，展示饮水量、温度曲线、咖啡因摄入、与健康目标的差距
- **交互范式**：数据可视化驱动，杯身屏幕为极简数据入口，手机端为深度分析面板
- **终局形态**：杯子自动识别饮品类型（咖啡/茶/水），同步至健康APP，生成个人饮品健康报告，联动医生/营养师

### 维度二：社交分享型

- **核心理念**：杯子是社交货币，饮品时刻是分享载体
- **信息架构**：以"饮品动态流"为中心，展示好友正在喝什么、今日饮品打卡、配方分享
- **交互范式**：内容流驱动，杯盖一键打卡，手机端为社区浏览与互动
- **终局形态**：杯子成为饮品社交平台入口，用户分享配方、打卡、挑战，品牌方发起饮品活动，形成饮品社区

### 维度三：极简仪式型

- **核心理念**：杯子是通勤仪式的道具，极致减法，只保留最本质的感官体验
- **信息架构**：无屏幕、无APP、以材质和触感为核心信息载体。杯身温度通过颜色变化（热敏材料）传达
- **交互范式**：物理直觉驱动，拧开即喝，无需学习
- **终局形态**：杯子成为个人生活美学的符号，与设计师/艺术家联名，限量发售，进入生活方式零售渠道

### 维度四：场景联动型

- **核心理念**：杯子是通勤场景的智能节点，主动适应用户的日程与环境
- **信息架构**：以"今日场景时间线"为中心，展示每个时段的饮品建议与准备状态
- **交互范式**：时间线驱动，杯子根据日历/导航/天气自动调整保温策略，主动提醒
- **终局形态**：杯子与智能家居（咖啡机、冰箱）、办公设备（饮水机）、出行工具（车机）全面联动，实现"人未到，饮品已备好"的全场景体验

### 维度五：订阅服务型

- **核心理念**：杯子是饮品订阅服务的入口，硬件是获客手段，持续服务是商业模式
- **信息架构**：以"订阅管理面板"为中心，展示本月饮品配额、下次配送、配方订阅、口味偏好
- **交互范式**：订阅周期驱动，杯子自动识别耗材余量，触发补货
- **终局形态**：品牌从"卖杯子"转型为"卖饮品订阅服务"，杯子免费/低价，按月收取饮品订阅费，形成 recurring revenue

### 4.1 维度差异确认

| 维度 | 信息架构核心 | 交互范式 | 商业模式暗示 |
|---|---|---|---|
| 健康数据中枢型 | 健康看板 | 数据可视化 | 硬件 + 健康数据服务 |
| 社交分享型 | 饮品动态流 | 内容流 | 硬件 + 社区/广告 |
| 极简仪式型 | 无数字界面 | 物理直觉 | 硬件溢价 + 联名 |
| 场景联动型 | 场景时间线 | 主动智能 | 硬件 + 生态合作 |
| 订阅服务型 | 订阅面板 | 周期触发 | 硬件 + 订阅费 |

> 五个维度在信息架构、交互范式、商业模式上均有本质差异，符合 Skill"不同维度"要求。

## 5. 可执行策略（收敛层）

> 说明：以下为基于愿景探索的收敛性策略，用于指导 V1（当前产品）上市。Vision-exploration Skill 本身不做收敛，但业务任务要求可执行方案，故在愿景基础上提炼收敛层策略。

### 5.1 受众

**核心受众（结论）**：一二线城市 22–35 岁通勤人群，每日公共交通/自驾通勤 30 分钟以上。

**受众分层（假设）**：

| 层级 | 画像 | 核心动机 | 占比假设 |
|---|---|---|---|
| 种子用户 | 咖啡/茶爱好者，已有随行杯使用习惯，对温度和清洁敏感 | M1 + M3 | 15% |
| 核心用户 | 日常通勤白领，追求效率与品质，愿意为好体验付费 | M1 + M2 + M4 | 50% |
| 泛用户 | 有环保意识或送礼需求，对价格敏感 | M5 + 送礼场景 | 35% |

> 占比为假设，须经市场调研验证。

### 5.2 信息结构

基于价值定位"通勤路上确定性的饮品体验"，信息传递按以下层级组织：

```
第一层（情感共鸣）：通勤路上，喝一口刚好温度的饮品
第二层（价值证明）：12h 保温 · 280g 轻量 · 可拆洗杯盖
第三层（信任背书）：产品规格 + 品牌主色视觉体系
第四层（行动召唤）：199 元 · 首发渠道 · 购买入口
```

**禁止项**（来自 product_brief.md）：
- 不得编造第三方检测结论
- 不得编造销量
- 不得编造用户评价
- 不得编造竞品价格

**待补项**：
- 防水等级（产品简报标注"尚未提供"）
- 食品接触材料报告（产品简报标注"尚未提供"）
- 首发日期（产品简报标注"尚未确定"）
- 容量规格（简报未提及）
- 是否支持保冷（简报仅提"保温"）

## 6. 最小可验证版本（MVP）

### 6.1 MVP 定义

**最小可验证版本 = 完成 V1 产品上市策略的核心闭环，验证"通勤饮品确定性"价值主张是否能驱动目标用户购买。**

不包含：V2 及以上智能功能、终局愿景 HTML 全套、全渠道铺开、品牌长期建设。

### 6.2 关键步骤

| 步骤 | 动作 | 产出 | 负责人 | 前置依赖 |
|---|---|---|---|---|
| S1 | 确认缺失信息 | 防水等级、食品接触材料报告、首发日期、容量、保冷支持 | 产品方 | — |
| S2 | 验证用户动机假设 | M1–M6 问卷/访谈结果，动机优先级排序 | 用研/市场 | S1（产品规格确认） |
| S3 | 制作核心素材 | 场景图、短视频、详情页文案（按信息结构四层） | 设计/内容 | S1 + S2 |
| S4 | 小红书种子种草 | 10–20 篇真实用户种草内容 | 市场/运营 | S3 |
| S5 | 电商详情页上线 | 天猫/京东详情页 | 电商运营 | S3 |
| S6 | 首发 + 数据收集 | 首发执行，UV/转化率/销量/NPS 数据收集 | 全团队 | S4 + S5 |
| S7 | 复盘与决策 | 基于数据判断是否进入 V2 或调整 V1 策略 | 产品/市场 | S6 |

### 6.3 验收标准

| 验收项 | 标准 | 验证方式 |
|---|---|---|
