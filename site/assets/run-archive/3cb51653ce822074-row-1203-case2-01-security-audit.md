### 冲突一：Skill 适用范围 vs. 业务任务范围

**事实**：`mobile-reverse/SKILL.md` 的"适用场景"明确列出 7 项，全部围绕 Android/iOS 移动应用逆向（APK/IPA 分析、Frida 插桩、SSL Pinning 绕过、Root/越狱检测、移动端加密提取、OWASP MASTG 渗透测试）。输入文件 `incident_log.csv` 包含的事件为 `web.login_success`、`web.login_failed`、`api.token_scope_mismatch`、`db.unexpected_export`、`web.malformed_record`，全部是服务端（web/api/db）安全事件，无任何移动应用制品。

**SKILL.md 规则影响**：ACTION REQUIRED 第 2 步要求"确认当前任务是否命中本 Skill 的适用范围"。严格执行该规则的结论是**不命中**。这直接决定了不能将日志分析强行套入移动逆向四阶段工作流，也不能虚构 APK/IPA 分析步骤。

**取舍**：在"严格按 Skill 执行"与"完成业务任务"之间，选择**如实记录范围不匹配 + 以通用安全审计方法完成日志分析**，而非假装 Skill 适用或编造移动逆向流程。这是风险最低的方案：既遵守了 Skill 的范围判定规则，又交付了业务所需的审计结论。

### 冲突二：强制前置依赖文件缺失 vs. 工作流可执行性

**事实**：SKILL.md ACTION REQUIRED 第 1 步要求读取 `../field-journal/precedent-reverse.md` 以"确认本 Skill 的操作是已授权的常规操作"，第 3 步要求读取 `../tool-index.md` 以"校验工具可用性和实际路径"。经全局检索，两个文件均不存在于 ZIP 包、工作区或任何可访问路径。第 4 步要求"缺工具时调用 bootstrap"，但 SKILL.md 全文未定义 bootstrap 的入口、命令、脚本路径或参数。

### 4.2 逐事件分析

#### 事件 1：alice 正常登录（Info）

- **时间**：09:00:12
- **证据**：`web.login_success`，用户 alice，IP 192.0.2.10
- **判定**：正常业务事件，无风险。alice 的登录时间早于后续异常事件，暂未发现关联。
- **建议**：保留作为基线对照。

#### 事件 2-3：admin 登录失败（Medium — 暴力破解尝试）

- **时间**：09:03:45 和 09:03:49（间隔 4 秒）
- **证据**：同一 IP `198.51.100.23` 对 `admin` 账号连续两次登录失败
- **判定**：2 次失败尚不足以确认暴力破解，但针对高权限 `admin` 账号、来源 IP 与正常用户 alice 不同、间隔极短（4 秒），符合自动化登录尝试的早期特征。
- **风险**：若该 IP 持续尝试，可能导致 admin 账号被破解或锁定。
- **建议**：
  1. 检查该 IP 在 09:03:49 之后是否有更多登录尝试（本日志仅截取到 09:09:00）。
  2. 对 admin 账号启用账户锁定策略（如 5 次失败后锁定 15 分钟）。
  3. 对来源 IP `198.51.100.23` 实施临时限流或封禁。
  4. 确认 admin 账号是否已启用多因素认证（MFA）。

#### 事件 4：API 令牌权限越界（High）

- **时间**：09:04:02
- **证据**：`api.token_scope_mismatch`，服务账号 `service-a`，来源 IP `203.0.113.8`
- **判定**：服务账号 service-a 使用的令牌请求了超出其授权范围（scope）的 API 操作。这可能意味着：(a) 令牌被窃取并被用于越权访问；(b) service-a 的配置错误导致令牌 scope 与实际需求不匹配；(c) 攻击者通过令牌注入或重放尝试扩大权限。
- **风险**：令牌越界是横向移动和权限提升的前兆。结合事件 5，此事件很可能是数据外泄的前置步骤。
- **建议**：
  1. 立即吊销 service-a 的当前令牌并重新签发。
  2. 审计 service-a 的授权 scope，确认最小权限原则。
  3. 检查 API 网关日志，确认该令牌在 09:04:02 前后调用了哪些具体接口。
  4. 对 service-a 启用令牌短时有效期（如 15 分钟）和刷新机制。

#### 事件 5：数据库异常导出（Critical — 疑似数据外泄）

- **时间**：09:07:30
- **证据**：`db.unexpected_export`，用户 `unknown`，来源 IP `203.0.113.8`
- **判定**：**最高优先级事件**。未知用户从 `203.0.113.8`（与事件 4 同源 IP）执行了数据库导出操作。`unknown` 用户身份表明：(a) 可能使用了窃取的服务账号令牌但未正确映射到数据库用户；(b) 直接通过数据库连接且未经过应用层认证；(c) 日志中用户字段丢失。
- **攻击链关联**：事件 4（09:04:02，同源 IP，令牌越界）→ 事件 5（09:07:30，同源 IP，数据导出），间隔 3 分 28 秒。高度疑似攻击者先通过越权令牌获取数据库访问凭证或连接信息，随后执行数据导出。
- **风险**：数据外泄可能导致敏感信息（用户数据、业务数据、凭证）泄露，合规风险极高。
- **建议**：
  1. **立即**：封禁来源 IP `203.0.113.8`，阻止进一步数据传输。
  2. **立即**：检查数据库审计日志，确认导出的具体表、数据量和导出目标位置（本地文件 / 远程传输）。
  3. **立即**：若数据已外传，启动数据泄露应急响应流程，评估影响范围并通知相关方。
  4. 短期：对数据库导出操作启用强制审批和 MFA。
  5. 短期：限制数据库服务仅允许应用服务器 IP 访问，禁止直接外部连接。
  6. 长期：实施数据库活动监控（DAM），对异常导出行为实时告警。

#### 事件 6：畸形日志记录（Anomaly — 日志完整性存疑）

- **时间**：09:09:00
- **证据**：`web.malformed_record`，`severity`、`user`、`source_ip` 字段均为空
- **判定**：可能原因包括：(a) 日志采集系统解析错误；(b) 攻击者尝试注入或篡改日志以掩盖痕迹；(c) 应用程序异常导致日志格式损坏。考虑到此记录紧跟在 critical 数据外泄事件之后（09:07:30 → 09:09:00，间隔 1 分 30 秒），不能排除日志篡改的可能性。
- **风险**：若为日志篡改，意味着攻击者已获得日志系统访问权限，且可能存在更多未被记录的恶意行为。
- **建议**：
  1. 检查日志采集管道（Fluentd / Logstash / Filebeat 等）在 09:09:00 前后的健康状态。
  2. 对比原始日志源（如应用服务器本地日志）与集中式日志系统中的记录，确认是否存在丢失或篡改。
  3. 对日志系统启用写保护和完整性校验（如哈希链）。
  4. 检查 09:09:00 之后是否有更多畸形记录或日志中断。

## 六、修复建议

### 6.1 立即执行（0-24 小时）

1. **封禁 IP `203.0.113.8`**：在防火墙、WAF、API 网关和数据库安全组中同时封禁。
2. **吊销 service-a 令牌**：立即作废旧令牌，重新签发并缩小 scope。
3. **排查数据外泄范围**：查询数据库审计日志，确认导出的表名、行数、时间范围和导出目标。
4. **检查 admin 账号安全**：确认 admin 未被登录成功，强制轮换密码，启用 MFA。
5. **封禁 IP `198.51.100.23`**：对暴力破解来源实施临时封禁（建议 24 小时）。

### 6.2 短期修复（1-7 天）

1. **API 令牌治理**：
   - 所有服务账号令牌启用最短有效期（≤15 分钟）+ 刷新令牌机制。
   - 实施令牌 scope 白名单，API 网关强制校验 scope 与请求路径的匹配。
   - 对 `token_scope_mismatch` 事件配置实时告警（阈值：1 次即告警）。
2. **数据库访问控制**：
   - 数据库服务禁止直接公网访问，仅允许应用服务器内网 IP 连接。
   - 数据库导出操作启用审批工作流和 MFA。
   - 部署数据库活动监控（DAM）工具。
3. **Web 登录防护**：
   - 对 admin 等特权账号启用账户锁定（5 次失败锁定 15 分钟）。
   - 所有账号强制启用 MFA。
   - 部署登录速率限制（同一 IP 每分钟最多 5 次登录尝试）。
4. **日志完整性**：
   - 排查 09:09:00 畸形记录的根因。
   - 对集中式日志系统启用写保护和哈希链完整性校验。
   - 配置日志中断 / 畸形记录告警。

### 6.3 长期改进（1-3 个月）

1. **零信任架构**：对服务间通信实施 mTLS 和 SPIFFE 身份认证，减少静态令牌依赖。
2. **数据分类与脱敏**：对数据库中敏感数据实施分类标记，导出时自动脱敏或阻断。
3. **威胁狩猎**：基于本次攻击链特征（令牌越界 → 同源 IP 数据导出）建立威胁狩猎规则，定期回溯历史日志。
4. **应急响应演练**：针对数据外泄场景开展桌面演练，缩短 MTTR。
5. **Skill 包完整性治理**：本次审计发现 `mobile-reverse` Skill 包缺少 `field-journal/precedent-reverse.md` 和 `tool-index.md` 两个强制前置文件，建议补充或修正 SKILL.md 中的引用路径。
