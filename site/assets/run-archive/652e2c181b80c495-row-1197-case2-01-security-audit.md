## 3. 约束、冲突与关键取舍

### 冲突一：Skill 适用范围与业务任务输入不匹配

- **描述**：`ida-reverse` 专为二进制逆向设计，而任务输入是 CSV 安全日志。
- **取舍**：严格遵循 SKILL.md 的适用性检查规则，判定 Skill 不适用后，**不强行套用逆向工作流**（如对 CSV 调用 `survey_binary` 会产生无意义结果或报错），转而使用与输入类型匹配的日志关联分析方法。
- **风险**：若忽略适用性检查强行执行 Skill，会产生伪造的工具调用结果或空转，违反"不得编造执行结果"的约束。

### 冲突二：平台与商业依赖缺失 vs. "严格按 SKILL.md 执行"

- **描述**：SKILL.md 要求使用 `scripts/start.ps1` 启动服务器、`scripts/open.ps1` 打开文件，并明确"不要写 ad-hoc PowerShell 命令"。但当前环境无 PowerShell、无 IDA Pro、无 idalib-mcp，且 IDA Pro 为不可自动安装的商业软件。
- **取舍**：遵循 SKILL.md "缺工具时调用 bootstrap，不要猜路径"的规则，核验后确认 bootstrap 也无法解决 IDA Pro 本体缺失问题，因此**如实记录阻断**，不伪造服务器启动输出（如 `OK:72`）或文件打开结果（如 `OK:file.exe:session_id`）。
- **风险**：若假装执行了 start.ps1 并输出 `OK:72`，将构成编造执行结果，且后续所有 `idapro_*` 调用均为虚假。

### 冲突三：日志数据量有限 vs. "接近真实业务的复杂场景"

- **描述**：输入仅 6 条日志，其中 1 条为畸形记录。真实业务中安全事件通常涉及跨系统、跨时间窗口的海量数据。

- **风险**：过度推断可能导致误报；本报告对每条结论均标注证据来源与置信度。

## 5. 风险分级与事件分析

### 5.1 严重 (Critical) — 疑似数据外泄

**证据 ID**：E-CRIT-001

| 字段 | 值 |
|-----|---|
| 时间 | 2026-08-12T09:07:30Z |
| 系统 | db |
| 事件 | `unexpected_export` |
| 用户 | `unknown`（未认证或认证丢失） |
| 来源 IP | `203.0.113.8` |

**分析**：
- `unexpected_export` 表示数据库发生了未在预期白名单内的导出操作，是数据外泄的强信号。
- 用户字段为 `unknown`，说明该操作可能未经过正常认证流程，或使用了被盗/越权令牌导致身份映射失败。
- 来源 IP `203.0.113.8` 与 3 分 28 秒前的高危事件 `token_scope_mismatch`（E-HIGH-001）**完全同源**，构成攻击链关联（详见第 6 节）。
- 从 `token_scope_mismatch` 到 `unexpected_export` 间隔约 3 分 28 秒，符合"先获取越权访问、再定位并导出数据"的攻击时间线。

**置信度**：高（IP 同源 + 时间序列吻合 + 事件语义直接指向数据外泄）

**潜在影响**：敏感数据泄露，可能违反数据保护法规，导致合规风险与业务损失。

### 5.2 高危 (High) — 服务账户令牌越权

| 系统 | api |
| 事件 | `token_scope_mismatch` |

- 可能场景：(a) 令牌被盗后被攻击者尝试扩大权限；(b) 令牌本身配置错误，被用于非预期操作；(c) 服务账户被攻陷后横向移动。

- 服务账户通常具有较高的系统级权限，一旦被越权使用，影响面大于普通用户账户。

**置信度**：高（事件语义明确 + 与后续 critical 事件强关联）

**潜在影响**：权限越界、服务账户被用于横向移动、作为数据外泄的前置步骤。

## 6. 攻击链关联分析

### 6.1 主攻击链（高置信度）

```
203.0.113.8
    │
    ├─ 09:04:02  api  token_scope_mismatch (service-a)   [高危]
    │                │
    │                ▼  间隔 3分28秒
    │
    └─ 09:07:30  db   unexpected_export (unknown)        [严重]
```

**关联依据**：
1. **IP 同源**：两条事件来源 IP 均为 `203.0.113.8`。
2. **时间递进**：令牌越权在前，数据导出在后，符合"权限获取 → 数据窃取"的典型攻击顺序。
3. **身份断裂**：数据库导出时用户为 `unknown`，与令牌越权导致的身份映射异常一致——越权令牌可能无法正确映射到数据库审计用户。
4. **系统跨越**：从 api 层到 db 层，表明攻击者已突破应用边界到达数据层。

**推断**：攻击者可能通过 `service-a` 的越权令牌获得了数据库访问能力，进而执行了未授权导出。`service-a` 令牌的泄露或滥用是本次事件的核心切入点。

### 6.2 次要事件（待关联）

- `198.51.100.23` 的 admin 爆破与主攻击链无直接 IP 关联，但时间窗口重叠（09:03:45-09:03:49），不能排除多源协同攻击的可能。
- `malformed_record`（09:09:00）在数据外泄之后，可能是日志干扰行为，也可能是独立的管道故障。
