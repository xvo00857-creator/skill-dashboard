# 轻量协作软件市场小样本研究：120人演示数据告诉我们什么

> 本文基于 market_research.md（120人演示数据）与 edge_cases.csv（边界测试数据）撰写。文中严格区分三类信息：**【事实】** 为原始文件可直接验证的陈述，**【推断】** 为基于事实的合理推论，**【待核实】** 为需更多数据或外部验证才能确认的判断。不编造任何引用。

---

## 一、研究背景与范围

这是一份小样本演示研究，不是真实市场规模报告。【事实】数据采集于2026年6月，共120名受访者，原始文件明确标注"不代表真实市场规模"。

在解读之前需要先说清楚：这份研究的价值不在于给出定论，而在于提供一个可验证的观察起点——哪些信号值得放大样本去追，哪些结论目前还站不住脚。

## 二、核心发现

【事实】三个核心数据点：

- 78% 的受访者每周使用协作工具
- 46% 的受访者最关心"导入可靠性"
- 31% 的受访者愿意为"自动摘要"功能付费

【推断】从这组数据可以看出一个基本格局：协作工具已经是高频刚需（近八成每周使用），但用户的核心痛点不在"有没有功能"，而在"功能靠不靠谱"——接近半数人把导入可靠性放在第一位。这意味着，对轻量协作产品来说，基础体验的稳定性可能比新增花哨功能更能决定用户去留。

【待核实】31% 的付费意愿能否转化为实际付费行为？小样本下的意愿表达和真实付费之间通常存在差距，需要更大样本或实际转化数据来验证。

## 三、分组结构观察

【事实】受访者按团队规模分为三组：

| 团队规模 | 人数 | 占比 |
|---|---:|---:|
| 10-50人 | 52 | 43.3% |
| 51-200人 | 44 | 36.7% |
| 200人以上 | 24 | 20.0% |

三组合计120人，数据自洽。

【推断】样本明显偏向中小团队（10-200人合计占80%），这与"轻量协作软件"的目标客群定位一致。但也意味着，这份研究对大型企业场景的参考价值有限，不能直接外推。

【待核实】不同规模团队在"导入可靠性"和"自动摘要付费意愿"上是否存在显著差异？原始数据未提供交叉分析结果，无法判断。

## 四、数据质量与边界说明

配套的 edge_cases.csv 包含6条测试记录，逐条审计结果如下：

【事实】

- **重复数据**：record_id=2 出现两次，内容完全一致（status=ok，value=120）。去重后只计1条。
- **缺失数据**：record_id=3 的 status 和 value 均为空，notes 为"-"，属于无效记录。
- **异常数据**：record_id=4 的 status=error，value=-999（负值），属于采集异常。
- **不安全输入**：record_id=5 的 value 字段包含 `=HYPERLINK("https://example.invalid","do not execute")` 公式注入测试文本。虽然 status 标记为 ok，但若直接导入电子表格软件可能触发公式执行，存在安全风险，应按纯文本处理或拦截。

【事实】去重并剔除缺失、异常、不安全记录后，6条原始记录中仅2条为唯一有效记录（record_id=1 和 record_id=2），有效率约33%。

【推断】这一边界测试说明：如果数据流水线缺少去重、空值校验、值域校验和公式注入检测，约三分之二的记录可能是脏数据。对市场研究而言，数据清洗环节的质量直接决定结论的可信度——garbage in, garbage out。

## 五、建议与下一步

【推断】基于现有数据，最合理的产品策略是：优先投入资源验证和提升导入可靠性，因为这是近半数用户的首要关切；自动摘要功能可以作为付费增值点探索，但需先验证付费意愿的真实转化率。

【待核实】以下事项需要更大样本或外部数据支撑：

1. 120人样本的结论是否可推广到真实市场？
2. 不同团队规模的需求差异具体是什么？
3. 付费意愿到实际付费的转化率有多高？
4. 导入可靠性的具体痛点场景——是格式丢失、数据错乱还是速度慢？

【事实】原始研究给出的建议是："先验证导入可靠性与团队协作场景，再扩大样本。"这与上述推断方向一致。
