  - 时间序列符合「令牌越权 → 利用越权令牌导出数据」的典型攻击链。
- **风险判断**：攻击者可能利用 `service-a` 的越权令牌访问数据库并执行未授权导出，存在数据泄露风险。

## 三、edge_cases.csv 分析

### 3.1 数据概览

- 总行数：5 条数据记录 + 1 行表头（其中 record_id=2 重复出现，实际唯一 record_id 为 4 个）
- 字段：`record_id, status, value, notes`

### 3.2 边界与失败场景识别

#### 场景 1：重复记录

- **证据**：`record_id=2` 的行完全重复出现两次（status=ok, value=120, notes=重复记录）。
- **处理**：去重，保留一条。重复数据会导致统计指标虚高（如计数、求和）。
- **复测方法**：对 `record_id` 做唯一性约束校验，重复时告警或自动去重。

#### 场景 2：缺失字段

- **证据**：`record_id=3` 的 `status` 和 `value` 均为空，`notes="-"`。
- **处理**：标记为不完整记录，不纳入数值统计；降级为仅记录存在性。
- **复测方法**：入库前校验 `status` 非空且 `value` 可解析为数值；不合格记录进入隔离区并告警。

#### 场景 3：异常负值

- **证据**：`record_id=4`，`status=error`，`value=-999`，notes 标注「异常负值」。
- **处理**：在计数/时长等非负业务场景下，-999 为非法值，应排除或映射为错误码。需确认 -999 是否为系统约定的哨兵值（sentinel），若是则应文档化并在分析时特殊处理。
- **复测方法**：对 `value` 设置业务合法范围（如 ≥0），超范围值触发校验失败。

#### 场景 4：CSV 公式注入（不安全输入）

- **证据**：`record_id=5`，`value="=HYPERLINK(\"https://example.invalid\",\"do not execute\")"`，notes 标注「公式注入测试文本」。
- **风险**：该字段以 `=` 开头，当 CSV 被 Excel / LibreOffice / WPS 打开时，可能被解析为公式并执行。`HYPERLINK` 可诱导用户点击钓鱼链接；更危险的 `=cmd|' /c calc'!A1` 等可执行外部命令。
- **处理**：
  - 输出/导出 CSV 时，对以 `=`、`+`、`-`、`@` 开头的单元格内容前置单引号 `'` 进行转义。
  - 数据入库时检测公式注入特征并标记。
  - 本记录 notes 已明确标注为测试文本，确认是测试用例而非真实攻击，但处理逻辑必须覆盖。
- **复测方法**：构造含 `=HYPERLINK()`、`=cmd|...`、`+CMD|...` 的测试行，验证导出文件在 Excel 中不会自动执行公式。

### 3.3 修复建议汇总

| 场景 | 修复措施 | 优先级 |
|---|---|---|
| 重复记录 | 对 `record_id` 加唯一约束，ETL 层去重 | P2 |
| 缺失字段 | 非空校验 + 隔离区 | P2 |
| 异常负值 | 业务范围校验 + 哨兵值文档化 | P2 |
| CSV 公式注入 | 导出时转义危险前缀，入库时检测告警 | P1 |
