# 新品上市可执行方案（strategy-delivery）

> 生成日期：2026-08-26
> 方法论依据：Skill `prd-auto-test-loop`（PRD 驱动的自动化测试编排）
> 本文将该 Skill 的"范围锁定 → 分层边界 → 增量动作 → 执行闭环 → 门禁结论"方法论迁移至新品上市方案制定场景。
> **结论与假设分开标注**：凡标注【假设】的内容为方案制定者基于已有信息的推断，非输入文件确认事实；凡标注【待补】的内容为必须由外部提供方可闭环的缺失项。

---

## 1. 范围锁定（对应 Skill 步骤 1：从 PRD 锁定范围）

### 1.1 输入源

| 编号 | 文件 | 产品 | 性质 |
|---|---|---|---|
| I-1 | `product_brief.md` | 智能随行杯 | 新品任务简报（核心输入） |
| I-2 | `product_release_notes.md` | 星河笔记 2.3 | 版本发布说明（并发约束输入） |

### 1.2 范围内

- 基于 I-1 制定智能随行杯的上市可执行方案，覆盖：受众定位、信息结构、渠道动作、指标体系、风险与门禁。
- 将 I-2 作为同期并发发布事件纳入资源冲突与节奏协调分析。
- 方案仅使用输入文件中已确认的信息（产品白底图、基础规格、品牌主色 `#176B87`、12 小时保温、280g、可拆洗杯盖、建议零售价 199 元）。

### 1.3 非范围

- 不涉及产品硬件设计变更、供应链选型、生产排期。
- 不虚构第三方检测结论、销量数据、用户评价、竞品价格（I-1 明确禁止）。
- 不制定星河笔记 2.3 的独立上市方案（I-2 仅作为并发约束分析对象）。
- 不包含需要登录、付费或外部凭据才能执行的渠道投放操作细节。

### 1.4 验收标准（方案目标）

映射自 Skill 的"验收标准"概念，本方案的成功验收标准为：

1. **受众明确**：核心受众与次级受众的画像、场景、痛点均有输入文件依据或明确标注为假设。
2. **信息结构可执行**：每条信息点均有来源标注（已确认 / 假设 / 待补），无虚构卖点。
3. **渠道动作有节奏**：每个渠道动作均标注前置依赖、执行层级（Unit/Integration/E2E）和边界标记（A/H/A+H）。
4. **指标可量化**：指标体系区分过程指标（可内部确定）与结果指标（需外部数据，标注待补）。
5. **风险有兜底**：至少覆盖两种约束或冲突，每项均有关键取舍、依赖和风险说明。
6. **门禁有结论**：给出当前状态下的发布门禁判定（PASS / FAIL / 条件性 PASS），不模糊。

## 2. 约束与冲突分析（至少两种，含关键取舍、依赖、风险）

### 2.1 冲突一：双产品异质并发——硬件新品与软件版本更新同期争夺资源

**现象**：I-1（智能随行杯，硬件消费品）与 I-2（星河笔记 2.3，桌面软件更新）为两个完全异质的产品，若同期发布，将在以下维度产生冲突：

| 维度 | 智能随行杯（I-1） | 星河笔记 2.3（I-2） | 冲突点 |
|---|---|---|---|
| 产品类型 | 实物硬件 | 桌面软件 | 受众重叠度低，品牌心智分散 |
| 核心卖点 | 12h 保温 / 280g / 可拆洗 | 批量导入 Markdown / 标签筛选 / 快捷键 | 信息架构完全不同，无法共用素材 |
| 渠道依赖 | 电商平台、线下零售、KOL 开箱 | 软件下载站、开发者社区、更新推送 | 渠道资源不可复用 |
| 指标体系 | 售罄率、复购率、退货率 | 激活率、留存率、功能渗透率 | 无法统一考核 |
| 已知风险 | 防水等级/材料报告缺失 | >500 文件索引慢（I-2 已知问题） | 风险性质不同，兜底方案不同 |

**关键取舍**：
- **取舍 A（推荐）**：以智能随行杯为本次方案的主发布对象，星河笔记 2.3 错开至少 2 周发布或采用"静默更新"策略（仅通过应用内更新推送，不做大规模市场宣传），避免品牌注意力稀释。
  - 依据：I-1 为"新品任务简报"，明确需要上市方案；I-2 为已有产品的版本更新，已有用户基础，可依赖更新通知触达。
  - 代价：星河笔记 2.3 的新功能（批量导入、标签筛选）可能错失一次集中曝光机会。
- **取舍 B（备选）**：双产品同期发布，但严格分线运营——独立素材包、独立渠道预算、独立指标看板，品牌层面仅共用统一视觉规范（品牌主色 `#176B87`）。
  - 代价：资源投入翻倍，且两个异质产品同期出现在品牌传播中可能造成用户认知混淆。

**依赖**：
- 需品牌负责人确认发布排期优先级【待补：首发日期，I-1 明确"尚未确定"】。
- 需市场团队确认可用预算与人力是否支持双线运营【待补】。

**风险**：
- 若强行同期发布且资源不足，两个产品的传播效果均低于预期。
- 异质产品共用品牌渠道可能导致受众定位模糊，降低转化效率。

### 2.2 冲突二：关键合规信息缺失——防水等级与食品接触材料报告未到位

**现象**：I-1 明确标注"不完整信息"：
- 首发日期尚未确定。
- 防水等级尚未提供。
- 食品接触材料报告尚未提供。

这三项缺失直接影响方案的以下环节：

| 缺失项 | 影响的方案环节 | 具体影响 |
|---|---|---|
| 首发日期 | 渠道排期、预热节奏、媒体合作时间窗 | 无法确定任何有时间锚点的动作 |
| 防水等级 | 信息结构中的使用场景描述、卖点话术 | 无法宣称"防水""可水洗"等特性；可拆洗杯盖的清洗方式描述受限 |
| 食品接触材料报告 | 合规宣传、安全卖点、电商平台上架资质 | 无法以"食品级安全""母婴可用"等作为卖点；部分电商平台可能要求提供报告方可上架 |

**关键取舍**：
- **取舍 A（推荐）**：方案按"信息到位前/后"两阶段设计。信息到位前仅使用已确认卖点（12h 保温、280g、可拆洗杯盖、199 元）进行预热和素材准备；信息到位后再补充合规相关卖点和渠道上架动作。
  - 依据：Skill 规则"若被环境阻塞，明确记录阻塞项并停止宣称通过"——在缺失项未补齐前，不宣称方案完整可执行，而是给出条件性门禁结论。
  - 代价：首发前的预热内容可能缺少安全/防水维度的差异化卖点，竞争力受限。
- **取舍 B（备选）**：推迟方案定稿，等待所有缺失信息到位后再制定完整方案。
  - 代价：可能错失最佳发布窗口；且首发日期本身也在等待中，形成循环依赖。

**依赖**：
- 研发/品质团队提供防水等级说明【待补】。
- 供应链/合规团队提供食品接触材料检测报告【待补】。
- 产品负责人确认首发日期【待补】。

**风险**：
- 若食品接触材料报告长期无法提供，部分电商平台（如要求资质审核的平台）可能无法上架，严重影响渠道覆盖。
- 若防水等级与"可拆洗杯盖"的清洗预期不一致（例如杯盖可洗但杯身不可水洗），可能导致用户使用不当和售后纠纷。
- 首发日期不确定导致渠道资源（如 KOL 档期、电商平台活动位）无法锁定，可能临时找不到优质资源。

---

### 2.3 冲突三：禁止编造约束 vs 方案证据需求

**现象**：I-1 明确禁止编造"第三方检测结论、销量、用户评价、竞品价格"。但一份可执行的上市方案通常需要竞品定位分析、市场容量估算、用户痛点验证等支撑。

**关键取舍**：
- **取舍 A（推荐，且必须）**：严格遵守禁止编造规则。方案中所有涉及竞品、市场、用户反馈的内容均标注为【待补】或【假设】，并明确列出需要补充的外部数据类型和获取渠道建议。方案的可执行性建立在"已确认信息 + 明确待补项"的基础上，而非虚构数据。
  - 依据：I-1 明确禁止；Skill 规则"必须给出可复现命令和结果摘要，禁止模糊结论"迁移为"必须给出可追溯的信息来源，禁止虚构依据"。
- 不采用任何基于编造数据的方案变体。

**依赖**：
- 市场研究团队提供竞品价格带分析【待补】。
- 用户研究团队提供目标用户痛点访谈摘要【待补】。
- 第三方检测机构提供保温性能/材料安全检测报告【待补，与冲突二重叠】。

**风险**：
- 方案在竞品对比维度缺乏数据支撑，定价策略（199 元）的合理性无法通过竞品对标验证。
- 渠道谈判时缺乏市场容量数据支撑，可能影响议价能力。

## 3. 方案分层与边界标记（对应 Skill 步骤 2：定义测试分层与边界 + A/H/A+H 标记法）

将 Skill 的"Unit / Integration / E2E"三层测试架构迁移为方案执行的三层动作架构，并采用 `A / H / A+H` 边界标记法：

- **A（可确定性执行）**：动作有明确输入输出，可按标准流程执行，结果可量化验证。
- **H（需人工判断）**：动作依赖主观判断、创意决策或外部协商，无法完全标准化。
- **A+H（联合执行）**：部分环节可标准化执行，部分环节需人工判断或审批。

### 3.1 受众分层

| 层级 | 受众 | 核心场景 | 痛点（基于 I-1 推断） | 标记 |
|---|---|---|---|---|
| 核心 | 一二线城市 25-40 岁通勤人群【假设：年龄区间为推断】 | 地铁/公交通勤、办公室全天饮水 | 保温杯过重、杯盖难清洗、水温不可控 | A+H |
| 次级 | 一二线城市户外/健身爱好者【假设】 | 健身房、短途户外 | 便携性、清洗便利性 | H |
| 排除 | 对价格极度敏感的下沉市场用户、婴幼儿喂养场景（无材料报告支撑） | — | — | A |

> 受众画像的年龄、收入等细分维度均为【假设】，需用户研究验证【待补】。核心受众"一二线城市通勤人群"为 I-1 已确认信息。

### 3.2 信息结构分层

| 层级 | 信息点 | 来源 | 标记 |
|---|---|---|---|
| L1 核心卖点（必须传达） | 12 小时保温 | I-1 已确认 | A |
| L1 核心卖点 | 重量 280g（轻量化） | I-1 已确认 | A |
| L1 核心卖点 | 可拆洗杯盖 | I-1 已确认 | A+H（清洗方式描述受防水等级缺失影响） |
| L2 价格信息 | 建议零售价 199 元 | I-1 已确认 | A |
| L2 视觉规范 | 品牌主色 #176B87、产品白底图 | I-1 已确认 | A |
| L3 扩展卖点（条件性） | 防水性能 | 【待补：防水等级】 | H（信息缺失，暂不可用） |
| L3 扩展卖点 | 食品级材料安全 | 【待补：材料报告】 | H（信息缺失，暂不可用） |
| L4 禁止使用 | 第三方检测结论、销量、用户评价、竞品价格 | I-1 明确禁止 | A（硬性约束） |

### 3.3 渠道动作分层

| 层级 | 渠道 | 动作类型 | 标记 |
|---|---|---|---|
| Unit 层（单触点） | 电商详情页 | 素材制作与上架 | A+H |

| 标记 | 数量 | 典型动作 |
|---|---|---|

## 5. 执行顺序与依赖（对应 Skill：执行顺序 Unit → Integration → E2E + 自动修复循环最多 3 轮）

### 5.1 阶段化执行计划

严格遵循 Skill 的固定执行顺序原则：**Unit → Integration → E2E**，不得跳层执行。

```
阶段 0：信息补齐（阻塞项处理）
  ├── 等待首发日期确认【待补】
  ├── 等待防水等级确认【待补】
  └── 等待食品接触材料报告【待补】
  │
```

## 6. 指标与完成门槛（对应 Skill：完成门槛）

### 6.1 量化指标体系

区分**过程指标**（可内部确定，无需外部数据）与**结果指标**（需外部数据支撑，标注待补）。

#### 过程指标（方案执行质量）

| 指标 | 定义 | 目标值 | 数据来源 |
|---|---|---|---|
| 素材完成率 | 已完成 Unit 层动作数 / 计划 Unit 层动作数 | 100%（7/7） | 内部项目管理 |
| 合规检查通过率 | 通过 UT-07 禁止项检查的素材数 / 送检素材数 | 100% | 内部审核 |

#### 结果指标（上市效果，需真实数据，禁止编造）

| 指标 | 定义 | 目标值 | 数据来源 |
|---|---|---|---|
| 首发期销量 | 首发后 7 天累计销量 | 【待补：需基于市场容量和历史同类产品数据设定，禁止编造】 | 电商平台后台 |
| 详情页转化率 | 下单用户数 / 详情页浏览用户数 | 【待补：需行业基准数据】 | 电商平台后台 |
| 退货率 | 退货订单数 / 总订单数 | 【待补：需品类基准数据】 | 电商平台后台 |
| 社媒互动率 | 互动数（点赞+评论+转发）/ 曝光数 | 【待补：需账号历史基准】 | 社媒平台后台 |
| KOL 内容 ROI | 带货销售额 / KOL 合作成本 | 【待补：需预算和历史数据】 | 电商 + 合作记录 |

### 6.2 完成门槛（对应 Skill：P0 用例通过率 100%、连续两轮稳定通过、无阻断缺陷遗留）

方案达到以下全部条件方可判定为"可执行"：

1. **P0 动作完成率 100%**：UT-01、UT-02、UT-07（核心素材与合规检查）必须完成。
2. **阻塞项清零或有降级方案**：首发日期、防水等级、材料报告三项中，未到位的项必须有明确的降级方案（见 5.3）。
3. **连续两轮合规检查通过**：所有对外素材连续两次通过 UT-07 禁止项检查，无编造内容。
4. **无阻断级风险遗留**：IT-01（电商上架）的资质问题必须解决或有替代渠道方案。
