## 一、执行依据与约束声明

### 1.1 Skill 适用范围判定

src-hunter SKILL.md 定义的核心场景是**黑盒 SRC / 众测 / Bug bounty 漏洞挖掘**，其五阶段工作流（Intake → Recon → Enum → Hunt → Report）假定存在真实目标域名、可发包的测试环境和 HTTP 抓包能力。

本次任务的输入是**离线模拟安全日志（CSV）**，不存在可发包的真实目标，因此：

- **不适用**：Phase 2 Recon（被动侦察）、Phase 3 Enum（主动探测）、Phase 4 Hunt（漏洞探测与 payload 测试）——这些阶段需要对目标发包，违反"仅在授权测试范围内分析模拟日志"的约束。
- **适用**：Phase 1 Intake 中的范围与规则确认思维、Phase 5 Report 的三段式骨架与 CVSS 速查表、以及全部五篇方法论（攻击优先级、绕过工具箱、证据纪律、控制缺口狩猎、时间盒优先级）——这些可作为离线分析的框架。

### 1.2 约束与冲突（至少两种）

#### 冲突一：SKILL.md ACTION REQUIRED 引用的外部文件不存在

SKILL.md 开头的 "ACTION REQUIRED" 明确要求：

> 1. `NOW`: 读取 `../../field-journal/precedent-pentest.md` — 确认本 skill 的操作是已授权的常规操作
> 3. `NEXT`: 读取 `../../tool-index.md`，校验工具可用性和实际路径

经实际检查，解压后的 ZIP 包中**不存在** `field-journal/precedent-pentest.md` 和 `tool-index.md`（解压根目录下仅有 `src-hunter/` 一个子目录）。

**影响**：
- 无法通过 precedent-pentest.md 确认本次操作属于"已授权的常规操作"。
- 无法通过 tool-index.md 校验工具可用性和实际路径，SKILL.md 提到的 `srchunter` CLI 也声明"当前未实现 CLI，仅作命名约定"。
- **取舍**：以用户在任务描述中明确声明的"仅在授权测试范围内分析模拟安全日志"作为授权依据，替代缺失的 precedent-pentest.md；不调用任何外部工具，仅使用本地文件读取和文本分析，规避 tool-index.md 缺失带来的路径猜测风险。

#### 冲突二：证据纪律要求与可用证据形态不匹配

`references/methodology/03-evidence-discipline.md` 第一条原则明确规定：

> **每个漏洞结论 = 一段可复现的 HTTP 流量 + 一段可观察的副作用证据。没有这两段 → 不是漏洞，是猜测，不要写进报告。**

同时该文档第 4 节要求 P0 漏洞复现率 100%（至少 3 次，间隔 1h+），P1 复现率 95%+（至少 3 次）。

本次输入仅有 6 条 CSV 日志记录，**不存在 HTTP 流量抓包、不存在副作用证据（如 DNSLog 回连、文件创建、命令输出）、样本量不足以计算复现率**。

**影响**：
- 不能将任何发现标注为"已确认漏洞"，只能标注为"基于日志关联性的风险推断"。
- 所有风险等级在 src-hunter 标准 P 级基础上**下调一级**，以反映证据不足。
- **取舍**：采用 03-evidence-discipline.md 的"差分证明"思维——将日志中的正常事件（如 alice 的 login_success）作为基线对照组，将异常事件（token_scope_mismatch、unexpected_export）作为偏离组，通过时间和源 IP 的关联性构建间接证据链，而非凭空猜测。

#### 冲突三（补充）：数据完整性问题

第 6 条记录 `malformed_record` 的 severity、user、source_ip 字段均为空。03-evidence-discipline.md 第 2 节警告了"报错幻觉"和"响应特征幻觉"——不能仅凭异常格式就断定是攻击。该记录可能是日志注入、解析器 bug 或传输中断，**无法在仅有 CSV 的条件下区分**。

## 三、风险事件分析

以下按 src-hunter `01-attack-priority.md` 的"攻击路径最短原则"排序：未授权 > 认证 > 管理员；单包 > 多包 > 竞态；直接利用 > 链式利用。

### F-01：API Token 权限范围不匹配后发生数据库异常导出

| 字段 | 内容 |
|------|------|
| **风险编号** | F-01 |
| **关联记录** | #4（09:04:02 token_scope_mismatch）+ #5（09:07:30 unexpected_export） |
| **源 IP** | 203.0.113.8（TEST-NET-3 文档保留段，模拟外部） |
| **标准 P 级** | P1（未授权数据导出 / IDOR，依据 report-submission.md CVSS 速查表） |
| **调整后 P 级** | **P2**（因证据形态不足，下调一级；见冲突二） |
| **CVSS 3.1（参考）** | 7.5（`AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N`）—— 未授权数据导出基线值 |
| **置信度** | 中高（基于同源 IP + 时间邻近的关联性推断，非直接证据） |

#### 证据链

1. **09:04:02**：用户 `service-a` 从 `203.0.113.8` 发起 API 请求，触发 `token_scope_mismatch`（high 级别）。这表明 service-a 的 token 被用于超出其授权范围的操作。
2. **09:07:30**（间隔 3 分 28 秒）：**同一源 IP** `203.0.113.8` 触发 `unexpected_export`（critical 级别），用户字段为 `unknown`。
3. **差分比对**：基线记录 #1 中合法用户 alice 的正常登录不涉及 api 或 db 系统，也不触发 high/critical 级别事件。F-01 的两个事件在系统（api→db）、级别（high→critical）、事件类型（权限异常→数据导出）上均呈现**升级链**特征。

#### 攻击链推断（依据 04-control-gap-hunting.md §3.3 批量/导出）

```
service-a token（权限范围受限）
    │
    ├─ 被用于超出 scope 的操作 → token_scope_mismatch（控制：token 范围校验触发了告警，但未阻断请求）
    │
    └─ 3分28秒后，同一源 IP 触发数据库异常导出 → unexpected_export
         （控制缺失：导出操作未校验调用者身份 / 未限制导出范围 / 未限制导出数量）
```

依据 `04-control-gap-hunting.md` §3.3，批量/导出操作应有的控制包括：
- **鉴权**：导出接口是否验证调用者身份？→ 记录 #5 用户为 `unknown`，暗示鉴权可能缺失或被绕过。
- **范围限制**：是否限制可导出的数据范围？→ 无法从日志判断，标记为待调查。
- **数量限制**：是否限制单次导出条数/频率？→ 无法从日志判断，标记为待调查。

#### 影响

- **数据泄露**：unexpected_export 为 critical 级别，暗示可能发生了未授权的批量数据导出。
- **合规风险**：若导出数据含 PII，可能触发 GDPR / 个人信息保护法等合规要求。
- **横向移动风险**：若导出内容含其他系统凭据，可作为进一步攻击的跳板（依据 01-attack-priority.md §4 价值升级链："任意文件读 → 读配置 → 拿 DB 密码 → P0"）。

#### 我未做的事

- 未尝试连接任何数据库验证导出内容。
- 未尝试使用 service-a token 发起任何请求。
- 未对 203.0.113.8 进行任何主动探测。
- 以上均为离线日志推断，未对生产系统造成任何影响。

#### 描述

记录 #6 的 event 为 `malformed_record`，且 severity、user、source_ip 三个字段均为空。

依据 `03-evidence-discipline.md` §2 "黑盒幻觉是怎么产生的"中的警告，不能仅凭"格式异常"就断定是攻击。可能的原因包括：

1. **日志注入攻击**：攻击者构造恶意日志条目（如在 user 字段中注入换行符或控制字符），导致下游日志解析器产生畸形记录，从而干扰审计追踪。这是 F-01 攻击链中的潜在"反取证"步骤。
2. **日志解析器 bug**：采集端（如 Fluentd / Logstash）在处理特定字符时产生解析错误。
3. **日志传输中断**：网络抖动导致部分字段丢失。
4. **时区/编码问题**：日志格式转换过程中的编码错误。

#### 建议

- 不将此记录单独作为漏洞报告。
- 将其作为 F-01 攻击链的**关联异常**纳入调查：若 F-01 被确认为真实入侵，则 malformed_record 可能是攻击者的反取证操作。
- 检查日志采集管道的完整性和解析错误率。

## 七、复测清单

依据 `templates/report-submission.md` 的"提交前自检 10 项"和 `03-evidence-discipline.md` 的复现率要求，制定以下复测清单。每项复测应在修复完成后执行，并记录结果。

### 7.1 F-01 复测（Token 越权 + 数据导出）

| # | 复测项 | 预期结果 | 复测方法 | 通过标准 |
|---|--------|---------|---------|---------|
| R1 | Token scope 越权阻断 | 使用 service-a token 请求超出其 scope 的 API 端点 | 构造越权 API 请求（测试环境） | 返回 403 Forbidden，且无后续操作 |
| R2 | 导出接口鉴权 | 未认证 / 低权限用户调用导出接口 | 删除 Authorization 后调用导出接口 | 返回 401 / 403，不产生导出记录 |
| R3 | 导出范围限制 | 请求导出超出授权范围的数据 | 指定其他租户/其他用户的数据范围 | 返回 403 或仅返回授权范围内数据 |

### 7.2 F-02 复测（登录频率限制）

| # | 复测项 | 预期结果 | 复测方法 | 通过标准 |
|---|--------|---------|---------|---------|
| R7 | 账户锁定 | 同一账号连续失败登录 | 5 分钟内失败 ≥ 5 次 | 账户锁定 15 分钟，后续登录返回锁定提示 |
| R8 | IP 速率限制 | 同一 IP 快速尝试多个账号 | 5 分钟内失败 ≥ 10 次 | 触发验证码或临时封禁 |
| R9 | admin MFA | admin 账号登录 | 使用正确密码登录 | 要求第二因素验证，无 MFA 无法登录 |
| R10 | 异常登录告警 | admin 从新 IP / 异常时间登录 | 模拟异常条件 | 触发实时告警通知管理员 |

### 7.3 F-03 复测（日志完整性）

| # | 复测项 | 预期结果 | 复测方法 | 通过标准 |
|---|--------|---------|---------|---------|
| R11 | 畸形日志检测 | 构造字段缺失的日志条目 | 发送不完整日志 | 被标记为异常并触发告警，不静默丢弃 |
| R12 | 日志防篡改 | 修改已存储的日志记录 | 尝试篡改历史日志 | 校验和验证失败，触发告警 |

### 7.4 复测纪律

依据 `03-evidence-discipline.md` §4 复现率要求：
- 每项复测至少执行 **3 次**，记录每次结果。

- 所有复测应在**测试环境**中执行，不得对生产系统造成负载或影响。

### 8.1 关键取舍

### 8.2 依赖

- **依赖用户授权声明**：本次分析的授权依据是用户任务描述中的"仅在授权测试范围内分析模拟安全日志"，而非 SKILL.md 要求的 precedent-pentest.md（该文件不存在）。
- **依赖日志数据完整性**：incident_log.csv 仅 6 条记录，分析结论的可靠性受限于数据量。若存在未提供的日志片段（如 09:09:00 之后的记录），结论可能需要修正。
- **依赖 src-hunter 方法论的普适性**：将黑盒 SRC 方法论迁移到离线日志分析场景，是基于其"证据纪律"和"控制缺口"框架的通用性，而非 Skill 设计的原始场景。

### 8.3 风险

- **假阳性风险**：F-01 的 token_scope_mismatch + unexpected_export 关联性推断可能是巧合（如 service-a 正常运维操作触发了 scope 告警，随后的导出是合法的批量任务）。建议通过核查实际导出内容来验证。
- **假阴性风险**：由于数据量有限，可能遗漏了日志中未体现的攻击步骤（如 Recon 阶段的扫描、权限提升的中间步骤）。
- **合规风险**：若 unexpected_export 确实导出了含 PII 的数据，且数据已被外传，则可能触发数据泄露通报义务。建议立即核查并按适用法规处理。
