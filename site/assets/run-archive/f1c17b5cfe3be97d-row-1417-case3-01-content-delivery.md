## 三、边界与失败场景处理

### 3.1 重复记录（record_id = 2）

- **现象**：两行完全相同（`2,ok,120,重复记录`），经逐字符比对确认。
- **处理**：分析时去重，仅保留一条；原始文件不做修改（遵循"确认再动"原则，未获授权不删除源文件）。
- **降级方案**：若后续需统计，以去重后的 record_id 集合为准；若业务上"重复记录"本身是测试意图（如验证系统去重能力），则保留两份并在统计中标注。
- **复测方法**：对 CSV 执行 `awk -F',' 'NR>1{print}' file | sort | uniq -d` 检查重复行；或按 record_id 分组计数。

### 3.2 缺失记录（record_id = 3）

- **现象**：status 和 value 字段为空，notes 为 `-`。
- **处理**：不填充默认值，不推断，标注为"缺失"并排除出定量分析。
- **降级方案**：若缺失比例低（本次 1/6 ≈ 16.7%），可做完整案例分析（complete-case analysis）；若缺失比例高，需考虑缺失机制（MCAR/MAR/MNAR）后再决定插补策略。
- **复测方法**：用 `awk -F',' '$2=="" || $3==""' file` 筛查空值行；对比数据源确认是否为导出截断。

### 3.3 异常值（record_id = 4）

- **现象**：status=error，value=-999，notes 自标"异常负值"。
- **处理**：排除出定量分析；-999 在部分系统中是哨兵值（sentinel value），但本文件未提供编码手册，不做假设。
- **降级方案**：若能确认 -999 为"缺失/错误"哨兵值，则按缺失处理；否则保留为异常标记并单独报告。
- **复测方法**：检查 value 字段的分布（min/max/分位数），确认 -999 是否为离群点；查阅数据字典确认哨兵值约定。

### 3.4 不安全输入（record_id = 5）

- **现象**：value 字段为 `=HYPERLINK("https://example.invalid","do not execute")`，是典型的 CSV 公式注入（CSV Injection）payload。
- **处理**：
  - **不执行、不渲染、不点击链接**。
  - 在本文档中以纯文本代码格式展示，防止被下游工具解析为公式。
  - 该记录不纳入任何数值统计。
- **风险说明**：若此 CSV 被 Excel/WPS 等电子表格软件打开且未禁用公式，HYPERLINK 可能诱导用户访问恶意链接；更危险的 payload（如 `=CMD|...`）可执行系统命令。
- **降级方案**：在数据导入管道中对以 `=`、`+`、`-`、`@` 开头的单元格加前缀单引号 `'` 进行转义；或使用 CSV 解析库而非直接用 Excel 打开。
- **复测方法**：用正则 `^[=+\-@]` 扫描 value 字段；在沙箱环境中用 LibreOffice headless 打开并检查是否有公式执行。

- 自动摘要的付费意愿为 31%，不足三分之一，若作为核心付费功能需谨慎评估转化率（推断）。

### 5.3 分组分析

由于原文未提供分组与各发现指标的交叉数据，无法进行分组维度的深入分析。以下仅为样本构成描述：

- **10-50 人团队**：52 人，占比最高。这类团队通常预算有限但需求灵活，可能对轻量、易用、性价比敏感（推断，非数据支撑）。
