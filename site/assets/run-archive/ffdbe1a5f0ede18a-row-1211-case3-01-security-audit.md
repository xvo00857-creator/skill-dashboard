#### 记录 4：异常负值

|------|-----|

**分析**：

- -999 常被用作哨兵值（sentinel value）表示错误/缺失，但如果未在文档中约定，会导致下游计算错误（如平均值被拉低）

**修复建议**：
1. 明确 value 字段的合法取值范围（如非负整数），实施 CHECK 约束（`value >= 0`）
2. 若 -999 为约定哨兵值，应在数据字典中明确记录，并在分析时排除或特殊处理
3. 错误状态的记录应使用 NULL 表示无效值，而非负数哨兵值
4. 增加数据范围校验，拒绝超出合法范围的值入库

**复测方法**：
- 尝试插入 value=-1 的记录，验证是否被 CHECK 约束拒绝
- 运行 `SELECT MIN(value), MAX(value) FROM edge_cases`，验证值在合法范围内
- 检查 status=error 的记录，验证 value 是否为 NULL 而非哨兵值

#### 记录 5：CSV 公式注入（不安全输入）

| 字段 | 值 |
|------|-----|
| record_id | 5 |
| status | ok |
| value | `=HYPERLINK("https://example.invalid","do not execute")` |
| notes | 公式注入测试文本 |

**分析**：
- value 字段包含以 `=` 开头的公式：`=HYPERLINK("https://example.invalid","do not execute")`
- 这是典型的 **CSV 公式注入（CSV Formula Injection）** 攻击，又称 CSV 注入或 Excel 公式注入
- 攻击原理：当 CSV 文件被 Excel、LibreOffice Calc 等电子表格软件打开时，以 `=`、`+`、`-`、`@` 开头的单元格内容会被解释为公式执行
- HYPERLINK 公式可用于：钓鱼（诱导点击恶意链接）、数据外泄（通过公式将单元格数据发送到远程服务器）、执行恶意宏或代码
- 本例中 URL 为 `example.invalid`（保留域名，不可解析），显示文本为 "do not execute"，属于测试样本，但攻击模式真实存在
- notes 字段明确标注为"公式注入测试文本"，表明这是有意构造的测试用例

**风险等级**：中（CSV 公式注入，可导致数据外泄/钓鱼，取决于打开方式）

**证据**：value 字段以 `=` 开头，包含 HYPERLINK 函数，指向外部 URL。

**修复建议**：
1. **输入净化**：在数据导出为 CSV/Excel 时，对以 `=`、`+`、`-`、`@` 开头的单元格内容前置单引号 `'`（Excel 中强制按文本处理）或空格
2. **输出编码**：使用 CSV 库的安全导出功能，自动转义公式前缀字符
3. **用户教育**：告知用户不要直接双击打开来源不可信的 CSV 文件，应先在文本编辑器中查看
4. **工具配置**：在 Excel 中禁用外部链接和动态数据交换（DDE），降低公式注入危害
5. **WAF/输入校验**：在数据采集端检测并拦截包含公式前缀的恶意输入

**复测方法**：
